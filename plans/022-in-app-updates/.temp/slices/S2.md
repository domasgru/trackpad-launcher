# S2: Opening the settings window shows the update card

Worktree: `/Users/dominykasgrubys/code/trackpad-launcher/.claude/worktrees/022-in-app-updates` (branch `feature/022-in-app-updates`). Do not commit; the orchestrator commits your work. Do not switch branches. Use absolute paths. Package root: `LauncherKit/`. App target: `TrackpadLauncher/`.

## Goal

A Developer ID build in /Applications reads the public release list once each time its settings window opens from closed. When a newer full release runs on this Mac, the window's first group is the update card, "Version X is available" with *Update now*. Nothing else, in any build, makes a request. *Update now* is drawn but does nothing yet (the next slice gives it its action).

## Requirements

- **R1.** "Each time the settings window opens, a release build running from /Applications MUST make one update check. Every opening counts, including the one an update opens (R9), except an opening while an update installs (R7's installing state): the card then keeps showing the install, and that opening makes no check. A release build is one signed with a Developer ID, as the release process produces; any other build is a development build. The window MUST open at once, without waiting for the check. A window that stays open MUST NOT check again. The next opening checks again. A check still running when the window closes MUST be dropped, and its result MUST NOT be kept for the next opening." (The installing exemption is the next slice's; this slice has no installing state yet.)
  - Scenario "A newer version is out": 1.0.0 runs from /Applications with its window closed, 1.1.0 released → opened from Spotlight → the window opens at once, and the card appears at the top moments later, reading "Version 1.1.0 is available".
  - "A version released while the window stays open": the open window still shows no card; after *Close* and opening again, the card shows.
  - "Reopening an open window": the window comes to the front and no second check is made.
- **R2.** "Trackpad Launcher MUST make no network request at any time other than an update check from R1 and a download the user started with *Update now* or *Try again*. A login start, a running app with its settings window closed, a development build and a copy running from anywhere outside /Applications MUST make none." Scenarios: login start; development build (no request, no card); release build in ~/Applications started at login, then opened by hand and answered *Quit* in its move dialog; a release build from ~/Downloads with the move dialog unanswered.
- **R3** (the check's request). "An update check MUST read only the public list of Trackpad Launcher releases. The request MUST carry nothing that identifies the user, the Mac, the app's version or the macOS version: no identifying User-Agent, no cookie and no query string. It MUST send no setting and no usage data. The Mac's network address, the time of the request, and what the system itself adds to every connection (its secure-connection handshake and its transport headers, such as the encodings it accepts) are inherent to any request. Beyond them, the request's address, the headers Trackpad Launcher sets, and the body MUST be the same on every Mac and every version."
- **R4.** "A *newer version* MUST be a published full release with a higher version than the running one, whose minimum macOS this Mac meets. Drafts, pre-releases, the same version and older versions MUST NOT count. A release with no declared minimum macOS or no downloadable app MUST NOT count. When several count, the update card MUST offer the highest." Versions compare numerically, part by part (1.9.0 < 1.10.0).
- **R5.** "While a newer version is known, the settings window MUST show the update card as its first group, above the gesture rows, as in the design: the text "Version <version> is available" on the left and the *Update now* button on the right. The card MUST NOT be dismissable. While no newer version is known, the card MUST NOT show and the gesture rows MUST be the first group." Scenario: the card appears above the gesture rows, in its own rounded group, and the rest of the window moves down to make room.
- **R6.** "When an update check fails, for example offline or with no answer, the settings window MUST show no update card and no error." The next opening checks again.
- **R14** (the contract older copies read): each release declares its minimum macOS and carries a downloadable app; the asset name `TrackpadLauncher-<version>-macOS-<minimum>.aar` and the repository path are a permanent contract.

## Design

### Shape (the parts this slice builds)

- `Version` is the one ordering: dotted whole numbers compared part by part. Trailing zeros are dropped for comparison, so `==`, hashing and `<` agree (1.1 == 1.1.0). `description` is the text as written, for the card.
- `Release` is a release as the app understands it, built only in a form that counts. The list's adapter builds one only for a published full release that carries an uploaded archive whose name declares both a version and a minimum macOS. A draft, a pre-release, a release with no app and a release with no declared minimum therefore never reach the model.
- `InstalledRelease` is the running copy as an update sees it: its version and this Mac's macOS, read once at start. Its initializer is the whole R1/R2 gate, pure, in one place: it builds only for a copy truly signed with a Developer ID, at `Placement.installed`, with a version that parses. `Updater` takes one, so an `Updater` can exist only where R1 allows a check. The composition root and the test harness call the same initializer. (Read once: after a later swap, `Bundle.main` would read the new bundle.)
- `UpdateCard` holds the four visible states; its `layout` is the card with progress erased, which the window refits on.
- `Updater` (`LauncherCore`, `@MainActor @Observable`), a third model beside `Lifecycle` and `Launcher`. This slice builds its check half: `card`, and the internal `windowOpened()` / `windowClosed()` called only by `Launcher`. Its private `Phase` in this slice has `idle`, `checking(ticket:)` and `offering(Release)`; the next slice adds downloading, installing, opening and failed (keep the shape below so they slot in).
- `Launcher` only reports its own two window transitions. It learns nothing about builds, placement, versions or the network. The edge lives where the window state lives; the shell is no place for it, because Observation coalesces a `.closed` then `.open` within one turn.
- Port `ReleaseList.fetch` hides everything about the list: the address, the headers, the privacy configuration, GitHub's JSON, the asset-name contract and every R4 wire filter. It answers `[Release]`, empty on any failure. Asynchronous delivery keeps model tests synchronous: the port takes an `@escaping @MainActor` completion; the model sets its phase before calling, since the in-memory adapter may answer inline. The real adapter starts a `Task` that awaits a `@concurrent` static and calls back on the main actor.

The check (R1, R2, R4, R6):
- `windowOpened()` starts a check from every phase (the installing exemption comes next slice). So any card left from earlier is replaced by a fresh check. A re-front is not an edge, so it never checks.
- `windowClosed()` drops a check or an offer (phase → idle). A late answer carries a ticket that no longer matches the live one and is dropped.
- A failed request delivers `[]`. The model stays idle: no card, no error, and the next opening checks again.
- `Release.newerVersion(in:than:on:)` is the pure R4 rule.
- Eligibility is decided at construction: no `Updater` without an `InstalledRelease`. That covers development builds (Xcode, Debug, the perf build, all Apple Development-signed under the release team), ~/Applications, the move dialog and `--as-release-build`. A login start never opens the window, so it never checks.

The request (R3):
- Exactly one `GET https://api.github.com/repos/domasgru/trackpad-launcher/releases`, no query string; the default first page (newest 30).
- Each request gets its own `URLSessionConfiguration.ephemeral` session, invalidated when the request ends, with: cookies neither set nor accepted (`httpShouldSetCookies = false`, `httpCookieAcceptPolicy = .never`), and `httpCookieStorage`, `urlCache` and `urlCredentialStorage` all nil; `requestCachePolicy = .reloadIgnoringLocalAndRemoteCacheData`; `waitsForConnectivity = false` (offline fails at once, R6); `timeoutIntervalForRequest = stall` (30 shipped).
- Constant headers replace the identifying defaults, including across a redirect: `User-Agent: TrackpadLauncher`, `Accept-Language: en`, `X-GitHub-Api-Version: 2022-11-28`, and `Accept: application/vnd.github+json` (the archive download, next slice, uses `application/octet-stream`). GitHub refuses a request with no User-Agent, and URLSession's default User-Agent names the Darwin version and Accept-Language the user's languages (probed: `plans/022-in-app-updates/.temp/architect/grounding/probes/urlsession-probe.out`).
- Pinning the API version keeps every shipped version parsing the same JSON. The list is parsed into `[Release]` inside the adapter; no wire type crosses the port.

### Types (LauncherCore)

```swift
/// A version as releases and Info.plists write it: dotted whole numbers ("1.10.0"). Compared part by part, a
/// missing part counting as zero: 1.9.0 < 1.10.0, 1.1 == 1.1.0. "1.1.0-beta", "v1.1" and "" are not versions, so a
/// release named with one never counts (R4).
public struct Version: Comparable, Hashable, Sendable, CustomStringConvertible {
    /// As written, for the card: "Version 1.10.0 is available".
    public let description: String
    /// Trailing zeros dropped, so ==, hash and < agree.
    private let parts: [Int]
    /// Non-empty by construction: this Mac's macOS, fixtures.
    public init(_ first: Int, _ rest: Int...)
    /// Digits and single dots only; each part at most 9 digits.
    public init?(_ text: String)
    public static func < (a: Version, b: Version) -> Bool { a.parts.lexicographicallyPrecedes(b.parts) }
    public static func == (a: Version, b: Version) -> Bool { a.parts == b.parts }
    public func hash(into hasher: inout Hasher) { hasher.combine(parts) }
}

/// A published full release that carries an app and declares the macOS it needs. Built only by the release list's
/// adapter: a draft, a pre-release, an asset still uploading, or a release without a well-named archive never
/// becomes one.
public struct Release: Equatable, Sendable {
    public let version: Version
    public let minimumMacOS: Version
    /// Where the app's archive downloads from: this repository's release downloads.
    public let archive: URL
    /// The archive's size as the list declares it: the progress denominator and the exact expected length.
    public let archiveSize: Int
    public init(version: Version, minimumMacOS: Version, archive: URL, archiveSize: Int)

    /// R4, the one rule: the highest release above `running` whose minimum `macOS` meets; nil when none.
    public static func newerVersion(in releases: [Release], than running: Version, on macOS: Version) -> Release? {
        releases.filter { $0.version > running && $0.minimumMacOS <= macOS }.max { $0.version < $1.version }
    }
}

/// The running copy as an update check sees it. The R1/R2 gate, whole: exists only for a copy truly signed with a
/// Developer ID, in /Applications (`Placement.installed`), whose version parses. The composition root and the tests
/// call this one rule. Read once at start: after a swap, `Bundle.main` would read the new bundle.
public struct InstalledRelease: Equatable, Sendable {
    public let version: Version
    public let macOS: Version
    public init?(placement: Placement, developerIDSigned: Bool, version: String?, macOS: Version) {
        guard developerIDSigned, placement == .installed, let version = version.flatMap(Version.init) else { return nil }
        self.version = version
        self.macOS = macOS
    }
}

/// The update card, the settings window's first group while a newer version is known. Not dismissable.
public enum UpdateCard: Equatable, Sendable {
    /// "Version 1.1.0 is available" · *Update now*
    case available(Version)
    /// "Downloading version 1.1.0…" · a bar at `progress` (0...1) · *Cancel*. The only state with *Cancel*.
    case downloading(Version, progress: Double)
    /// "Installing version 1.1.0…": no bar, no *Cancel*; *Quit Trackpad Launcher* is disabled.
    case installing(Version)
    /// "The update couldn't be installed." · *Try again*
    case failed(Version)

    /// The card with its progress erased: what decides its height, so the window refits when the card appears,
    /// goes or changes state, never on a progress push.
    public enum Layout: Equatable, Sendable { case available, downloading, installing, failed }
    public var layout: Layout
}

// Ports.swift (every port is declared there), beside the existing eight:
/// The public list of Trackpad Launcher releases. Real: GitHubReleases. Test: InMemoryReleaseList.
@MainActor public protocol ReleaseList: AnyObject {
    /// One request for the list. Returns at once; `done` runs once on the main actor, possibly inside this call, with
    /// every release that counts (see `Release`), or none when the request failed (offline, no answer, any status but
    /// 200, a body that does not parse). Sends nothing about the user, the Mac, this version or macOS.
    func fetch(then done: @escaping @MainActor ([Release]) -> Void)
}
```

### The model (this slice's half)

```swift
@MainActor @Observable
public final class Updater {
    private enum Phase {
        case idle
        case checking(ticket: Int)
        case offering(Release)
        // next slice: downloading(Release, ticket:, progress:), installing(Release, ticket:), opening(Release), failed(Release)
    }
    private var phase: Phase = .idle
    @ObservationIgnored private var tickets = 0
    @ObservationIgnored private let installed: InstalledRelease
    @ObservationIgnored private let releases: any ReleaseList

    public init(_ installed: InstalledRelease, releases: any ReleaseList)   // next slice adds `installer:`

    /// nil while no newer version is known (R5).
    public var card: UpdateCard? {
        switch phase {
        case .idle, .checking: nil
        case .offering(let r): .available(r.version)
        }
    }

    /// From `Launcher`, only when the window goes from closed to open, after it has opened (R1: at once).
    func windowOpened() {
        let ticket = nextTicket()
        phase = .checking(ticket: ticket)  // first: an in-memory list may answer inside `fetch`
        releases.fetch { [unowned self] in checked($0, ticket: ticket) }
    }

    /// From `Launcher`, only when the window goes from open to closed. A check's result is never kept (R1).
    func windowClosed() {
        switch phase {
        case .checking, .offering: phase = .idle
        case .idle: break
        }
    }

    private var liveTicket: Int? { if case .checking(let t) = phase { t } else { nil } }
    private func nextTicket() -> Int { tickets += 1; return tickets }

    /// R1: a check from an earlier opening, or one the window closed on, is dropped. R4: pure choice. R6: [] is silent.
    private func checked(_ list: [Release], ticket: Int) {
        guard ticket == liveTicket else { return }
        phase = Release.newerVersion(in: list, than: installed.version, on: installed.macOS).map(Phase.offering) ?? .idle
    }
}
```

```swift
/// The public release list and a release's archive. Every request uses its own ephemeral session (no cookie, cache or
/// credential store, nothing on disk) and HTTPS to GitHub, with no query string and constant headers that name neither
/// the user, the Mac, this version nor macOS, and fails after 30 s in which no byte arrives (the request's own idle
/// timeout: no timer of ours).
@MainActor public final class GitHubReleases: ReleaseList {
    static let listURL = URL(string: "https://api.github.com/repos/domasgru/trackpad-launcher/releases")!
    static let downloadsPrefix = "https://github.com/domasgru/trackpad-launcher/releases/download/"
    static let headers = ["User-Agent": "TrackpadLauncher", "Accept-Language": "en", "X-GitHub-Api-Version": "2022-11-28"]
    private let endpoint: URL
    private let stall: TimeInterval

    public convenience init() { self.init(endpoint: Self.listURL, stall: 30) }
    /// Tests: a listener on 127.0.0.1 and a short stall.
    init(endpoint: URL, stall: TimeInterval)

    public func fetch(then done: @escaping @MainActor ([Release]) -> Void) {
        Task { done(await Self.list(at: endpoint, stall: stall) ?? []) }
    }

    @concurrent static func list(at url: URL, stall: TimeInterval) async -> [Release]?
    // session(accept: "application/vnd.github+json", stall:) → data(for: GET url) → 200 → parse; invalidate.

    /// The wire half of R4, pure: each element that is not a draft and not a pre-release, with an asset whose `state`
    /// is "uploaded", whose `browser_download_url` starts with `downloadsPrefix`, and whose `name` parses with
    /// `archiveName`; the first such asset counts. Tag, title and body are ignored. nil only when the JSON is not a
    /// release array.
    static func parse(_ json: Data) -> [Release]?

    /// "TrackpadLauncher-<version>-macOS-<minimum>.aar", the contract with every shipped version; nil for any other.
    static func archiveName(_ name: String) -> (version: Version, minimumMacOS: Version)?

    /// Ephemeral; cookies off and storage nil; urlCache nil; credential storage nil; reload ignoring caches;
    /// waitsForConnectivity false; timeoutIntervalForRequest = stall; httpAdditionalHeaders = headers + Accept.
    private static func session(accept: String, stall: TimeInterval) -> URLSession
}
```

### Seams and harness

1. **Model seam, `LifecycleWorld` / `OneProcess`** (`LauncherKit/Tests/LauncherCoreTests/LifecycleWorld.swift`, adapters in `InMemoryAdapters.swift`), as `LifecycleTests.swift` and `MoveToApplicationsTests.swift` use it. A process there is a real `Lifecycle`, `Launcher` and `Updater` over in-memory adapters, driven synchronously by the intents the shell sends.
   - `launch(_:others:alreadyExited:placement:running:)` gains `running:`, taking `.release("1.0.0", macOS: "26.0")` or `.development` (default `.development`, so existing rows are unchanged). Both go through the real gate, `InstalledRelease(placement:developerIDSigned:version:macOS:)`, with `developerIDSigned` true or false. Where it answers nil, the process has no `Updater`. The harness applies the rule rather than repeating it.
   - Each intent appends `(window, card)` to the process's `history` (the next slice adds `isInstalling`). Rows about "at no moment" read every published state, in order. Keep existing rows that read `history` as windows working (e.g. a `windows` projection), without weakening them.
   - `InMemoryReleaseList` counts `fetches` and keeps each fetch's completion in order: `deliver(_:)` answers the oldest fetch still open; `deliver(_:toFetch:)` answers the fetch it names; `fail()` answers `[]`; `answersInline(_:)` makes the next fetch answer inside the call.
   - Model rows run on this Mac's macOS 26.0 and use releases that need macOS 26.0, unless the row says otherwise. A test helper such as `.version("1.1.0", needs: "26.0")` builds a `Release`.
   - "No network request" here means `releases.fetches == 0` (the next slice adds `&& updates.requests.isEmpty`).
2. **The release list, `GitHubReleases.fetch`**, built with `init(endpoint:stall:)` pointed at a `LocalReleaseServer`: a test-only HTTP/1.1 server on 127.0.0.1 built on `NWListener` (tests are not source-scanned, so it may use the Network framework). Per path it answers a scripted status, headers and body; it can accept and never answer; it records each request's line, headers and body. Build it so the next slice can extend it (hold a body in chunks the row releases, trickle, close mid-body, 302 redirect, notice the client closing). Put it in `LauncherKit/Tests/LauncherPlatformTests/LocalReleaseServer.swift`.
3. **The gate**: the pure `InstalledRelease.init?`, and `CodeSignature.developerIDSigner(of:)` cross-checked against `codesign -dvv`, as `CodeSignatureTests.swift` does for `build(of:)`.
