# S1: Picking an app grows its icon into place

Repo root (worktree): `/Users/dominykasgrubys/code/trackpad-launcher/.claude/worktrees/023-app-selection-grow-animation`. Package: `LauncherKit/`. Run tests with `Scripts/test.sh` (wraps `swift test`). Do not commit; the orchestrator commits.

## Goal

Picking an app in an app picker (the settings window's popup in each gesture row), from the menu or through *Other…*, the same app included, plays the **pick animation** on that picker's icon: from 40% to 110% of its side in 0.2 s, then back to 100% by 0.35 s, the icon alone, uncut, restarted by a quicker second pick, skipped under Reduce motion, whatever the launch animation setting. Nothing else that changes an icon animates. Release builds ship this with the shipped values; the Debug tuner is not involved yet (a later slice wires it). The picker gets its own new test target, `LauncherUITests`.

## Requirements

- **R1. Picking an app plays the pick animation.** When the user picks an app in an app picker, from the menu or through *Other…*, that picker's icon MUST play the pick animation.
  - Pick from the menu: GIVEN gesture 2 has Safari, WHEN the user picks Mail from gesture 2's picker menu, THEN gesture 2's picker shows Mail's icon playing the pick animation.
  - Pick through Other…: WHEN the user picks an app on disk through *Other…*, THEN that picker shows the chosen app's icon playing the pick animation.
  - First assignment: GIVEN gesture 3's picker shows "Choose app…", WHEN the user picks Calendar, THEN Calendar's icon grows from 40% in the spot where it rests, and "Calendar" and the chevron show at once in their final places.
  - Other… cancelled: GIVEN gesture 2 has Safari, WHEN the user opens *Other…* and cancels, THEN Safari's icon stays, with no animation.
- **R2. Re-picking the same app plays it again.** Picking the app the picker already shows MUST play the pick animation again.
- **R3. Picking None plays nothing.** Picking *None* MUST play no animation: the picker shows "Choose app…" at once.
- **R4. Only the user's pick plays it.** A picker's icon MUST NOT animate when it changes for any reason other than the user's pick in that picker. This includes the settings window opening, a missing app being installed, and the hand-mode toggle. (Exception, built in S2: Debug tuner previews.) Other pickers stay still when one picker is picked in.
- **R5. Only the icon animates.** During the pick animation, only the icon MUST change size. The app's name and the chevron MUST show at once in their final places and not move.
- **R6. The pick animation's shape.**
  - The icon appears at 40% of its side, centred on its slot.
  - It grows to 110% of its side in 0.2 seconds, starting fast and slowing down.
  - It settles back to 100% by 0.35 seconds after the pick, slowing smoothly into 100%, with no second wobble.
  - It is fully opaque throughout.
  The grow uses a fixed curve that starts fast and slows down, like the launch animation's pop. The tuner's Launch values do not affect it.
- **R7. The overshoot is not clipped.** At its peak the whole icon MUST be visible. Where it is bigger than its slot, it MUST draw past the slot, uncut at any edge.
- **R8. A new pick restarts the animation.** When the user picks an app while that picker's pick animation still plays, the new icon MUST replace the old one at once and play its own pick animation from the start.
- **R9. Reduce motion turns it off.** With the system's Reduce motion setting on, picking an app MUST play no animation. The icon MUST swap at once. In Debug builds, the tuner's *Simulate Reduce motion* switch, when on, MUST do the same (this slice builds the rule; S2 wires the tuner into it).
- **R10. The launch animation setting does not affect it.** The pick animation MUST play whether the *Animate app launch* switch is on or off.
- **R13, in part.** Four knobs shape the curve: start size (share of the icon's side), peak size, grow time (pick to peak), settle time (peak to rest); shipped 40%, 110%, 0.2 s, 0.15 s. (The tuner sliders are S2's.)

## Design

### D1. `PickAnimation` in `LauncherCore` (new file, e.g. `LauncherKit/Sources/LauncherCore/PickAnimation.swift`)

- `public struct PickAnimation: Equatable, Sendable` with four `public var` `Double`s: `startScale` (0.4), `peakScale` (1.1), `growTime` (0.2 s), `settleTime` (0.15 s); a public memberwise init `PickAnimation(startScale:peakScale:growTime:settleTime:)`; `public static let shipped`; `public var duration` = `growTime + settleTime`; `public func scale(at t: Double) -> Double` (the icon's side as a share of its resting side, `t` seconds after the pick); and `public func keyframes(perSecond: Double) -> (keyTimes: [Double], scales: [Double])` (or a small public struct with those two arrays, your choice): the curve sampled for Core Animation with `steps = max(10, Int((duration × perSecond).rounded()))` steps, so `steps + 1` samples; key time `i / steps` (0 to 1, shares of the duration, Core Animation's convention) and scale `scale(at: i / steps × duration)`. Match the launch flight's sampling rule; see how `LauncherKit/Sources/LauncherPlatform/LaunchFlight*.swift` (grep `perSecond` / `steps`) samples, and keep the same "at least ten steps" rule. At shipped values, 240/s gives 84 steps, 85 samples.
- Doc comment names the glossary term "pick animation".
- Not `Codable` (S2 adds a Debug-only retroactive conformance in the tuner). Everything numeric about R6/R13 lives in this type only; the view only maps each scale to a transform.
- The curve (from the planning prototype `plans/023-app-selection-grow-animation/.temp/pick-curve-check.swift`; the grow is the launch pop's quadratic ease-out, the settle a smoothstep, so both have zero speed at the peak and nothing goes below 100% after; zero grow or settle time is instant):

  ```swift
  func scale(at t: Double) -> Double {
      if t <= 0 { return startScale }
      if t < growTime {                                   // fast start, slowing: the pop's 1 − (1 − p)²
          let p = t / growTime
          return startScale + (peakScale - startScale) * (1 - (1 - p) * (1 - p))
      }
      if t < growTime + settleTime {                      // smoothstep: at rest at the peak and at 100%
          let q = (t - growTime) / settleTime
          return peakScale + (1 - peakScale) * (3 * q * q - 2 * q * q * q)
      }
      return 1
  }
  ```
  Make sure the last sample (key time 1, t == duration) is exactly 1.0 and the sample at t ≈ growTime is the peak (with times like `84/84 × 0.35` floating-point can land a hair below a boundary; the tests compare times within 1e-9 and expect the sample nearest 0.2 s to equal 1.1 and the last to equal 1.0: clamp or compute so these hold exactly).

### D4. The model answers the pick: `Launcher.setAssignment(_:for:)` in `LauncherKit/Sources/LauncherCore/Launcher.swift`

- Becomes `@discardableResult public func setAssignment(_ choice: AppChoice?, for gesture: Gesture) -> AppEntry?`: after the pick, returns the gesture's app when the row shows it `.present` (the menu's app, or the bundle Other… chose once the catalog has parsed and located it). Returns nil for `nil` (None), for a bundle that is no app (ignored as today, no change), and for an app the catalog cannot locate (e.g. in the Trash, picked through Other…), whose row shows `.missing` ("not found" never animates). Every existing caller compiles unchanged.
- Nothing on this path reads the launch animation setting (R10).

### D2. The picker draws its icon on a layer of its own (`LauncherKit/Sources/LauncherUI/AppPicker.swift`)

- `PickerView` becomes layer-backed and owns one icon `CALayer`, a sublayer of the picker view's own layer, drawn above the pop-up button over the button's image slot. For `.present`, the button's closed item carries a *clear* image of the spaced icon's size (today `spaced(icon)` is 17 × 16: 16 pt icon plus 1 pt trailing space) and the layer shows the icon; for "Choose app…" (`.unassigned`) and for `.missing` the button draws exactly as today and the layer is hidden. The button's layout, name shortening, 128 pt cap and menu alignment are unchanged: the image slot is still there, only empty.
- The layer's implicit actions are off (e.g. `actions` dictionary mapping keys to `NSNull`, or a delegate returning `NSNull`), so a change of contents, bounds, position or hidden never animates by itself. The pick animation is the only animation this layer ever plays.
- Its frame is the leading 16 pt square of the cell's image rect, converted to the picker view's coordinates (the planning probe `plans/023-app-selection-grow-animation/.temp/picker-seam-probe.swift` measured the cell's image rect at (3, 0, 17 × 16) for today's spaced icon, so the icon sits exactly where it draws today; use `NSPopUpButtonCell.imageRect(forBounds:)` on the button's bounds, then convert). Set whenever the closed item changes and on layout (`layout()` override). Anchor point is its centre (0.5, 0.5), so it grows about its slot's centre. `contentsScale` follows the window's backing scale (update in `viewDidChangeBackingProperties` too; default to 2 or the main screen's when there is no window); contents are the icon `NSImage` (assign the `NSImage` to `contents` so the layer resolves it at its scale, or `layerContents(forContentsScale:)`). `masksToBounds` false on both the picker's own layer and the icon layer, so the 110% peak (0.8 pt past a 16 pt slot) draws uncut (R7). `NSView.clipsToBounds` defaults to false since macOS 14; leave the picker's at false.
- The representable's make and update bodies become two internal functions that take the coordinator, e.g. `func makeView(coordinator: Coordinator) -> PickerView` and `func update(_ view: PickerView, coordinator: Coordinator)`; `makeNSView(context:)` and `updateNSView(_:context:)` call them with `context.coordinator`. Tests call the same two functions with a coordinator they hold, so they run the code SwiftUI runs, minus SwiftUI.
- Why: the pop-up button draws icon and name as one cell, so scaling the button would scale the name and the chevron (R5), and redrawing per frame is banned. Keeping the icon on its own layer permanently means one place draws the icon and nothing to hand back when the animation ends.

### D3. The pick animation is one `CAKeyframeAnimation` on the icon layer's `transform`

- Built from `PickAnimation.keyframes(perSecond: 240)`: each scale becomes `CATransform3DMakeScale(s, s, 1)` (as `NSValue`), `keyTimes` the key times (`NSNumber`), `duration` the animation's `duration`, `calculationMode = .linear`, added under one fixed key (a `static let` such as `"pick"`; tests read it). The layer's model transform stays identity, so when the animation is removed (default `isRemovedOnCompletion`) the icon rests at full size with nothing to clean up: no completion callback needed. Only `transform` animates; opacity is never touched.
- Adding under the same key replaces a running one: a new pick shows the new icon and plays from the start (R8). Showing the current app without a pick (a model render via update, the menu closing's deferred `showCurrentOnly`) only sets contents/hidden/frame and leaves a running animation alone (do not remove animations there).
- The picker plays when, and only when, a pick's answer is an entry (D4) and the supplier (D5) returns an animation. It reads no system setting itself.
- The Launch tuner values are never read.

### D4 (picker side). The picker decides from the model's answer

- The picker's interface changes to `let choose: (AppChoice?) -> AppEntry?` and `let chooseOther: (@escaping (AppEntry?) -> Void) -> Void`, plus a new `let pickAnimation: () -> PickAnimation?`. The coordinator holds the same three (update copies them in as today).
- Menu pick (`pick(_:)`): call `choose(entry.map(AppChoice.app))`; for the answer: if it is an entry, set `current = .present(answer)`, show it, and play if the supplier gives an animation; for None (nil choice) show "Choose app…" at once (`current = .unassigned`), no animation. Keep today's "the button shows the pick at once rather than at the model's next update" behaviour. Decide what an ignored nil answer for a non-nil choice does: change nothing (it can only arise for Other… in practice).
- Other… (`pickOther`): calls `chooseOther { answer in ... }` and shows the current app again immediately (today's behaviour, no animation). When the completion is called with an entry: show it and play as above. Called with nil (ignored bundle / not found): nothing changes, nothing plays. A cancelled Other… never calls back.
- Why the answer rather than watching the row: the same app re-picked changes no row (R2), and an ignored Other… pick changes no row either.

The gesture row in `LauncherKit/Sources/LauncherUI/SettingsView.swift` (`GestureRowView`, around line 133) forwards both to the model and hands the supplier:
```swift
choose: { launcher.setAssignment($0, for: row.gesture) },
chooseOther: { completion in actions.chooseOtherApp { completion(launcher.setAssignment(.appBundle(at: $0), for: row.gesture)) } },
pickAnimation: actions.pickAnimation
```

### D5. The shell supplies the pick animation (`LauncherActions.swift`, `SettingsShell.swift`)

- `LauncherActions` gains `let pickAnimation: () -> PickAnimation?`: the animation to play for a pick now, or nil for none.
- The rule is one pure function on the shell: `static func pickAnimation(reduceMotion: Bool, tuned: (animation: PickAnimation, simulateReduceMotion: Bool)?) -> PickAnimation?` (internal is fine; tests use `@testable import`): nil while `reduceMotion`; otherwise, when `tuned` is non-nil, its animation unless `simulateReduceMotion` is true (then nil); otherwise `.shipped`.
- The shell's closure calls it with `NSWorkspace.shared.accessibilityDisplayShouldReduceMotion`, read at that moment (as `SwitcherPresenter` reads it), and with the Debug hook's answer (nil in Release).
- Debug builds only, inside `#if DEBUG`: the shell exposes `public var pickTuning: (() -> (animation: PickAnimation, simulateReduceMotion: Bool))?`, read at every pick (never cached). Nothing sets it in this slice (S2 has the composition root set it). Release builds carry none of it: in Release the closure passes `tuned: nil`. Note `makeActions` is static and built before `super.init()`; the closure must read the hook from the shell instance at call time (e.g. a `[weak self]` set up after init, or a small reference box owned by the shell). Keep it simple and keep every reference to the hook inside `#if DEBUG`.
