# S4: Two ports on the tap thread, gated for real

Worktree: `/Users/dominykasgrubys/code/trackpad-launcher/.claude/worktrees/014-gate-event-tap` (branch `feature/014-gate-event-tap`). Swift package in `LauncherKit/`. Do not commit; the orchestrator commits your work.

## Goal

Ordinary pointing, dragging and scrolling no longer reach the app. The real `ClickTap` (`LauncherKit/Sources/LauncherPlatform/ClickTap.swift`) creates two active session event taps on its one `userInteractive` thread: a *press port* enabled for its whole life and a *gated port* disabled at install and switched only by that thread, on what the pure `TapFilters` value (S2) says. Frame threads (`DeviceSession`) wake the tap thread through a coalescing run-loop source only when their trackpad's `Blocking.wantsTap` flips. `ClickTap` stops owning three filters and routing rules: it parses `CGEvent`s, reads the merged level, calls one of `TapFilters`' three entry points, applies the gate change, and rewrites the event.

Why (measured): today the one tap is enabled for the whole armed run, so every scroll, drag, pressure and system gesture event makes a synchronous round trip through the app — 84% of its CPU (2.2–2.7% of a core) while any finger touches the trackpad. A disabled tap costs what no tap costs: the window server applies the event mask on its side; `CGEvent.tapEnable` takes about 0.1 ms from any thread and is in effect when it returns (70–130 µs, one 2.6 ms outlier). `CGEvent.tapIsEnabled` costs 20–47 µs. Every `tapEnable(false)` we issue ourselves echoes a `tapDisabledByUserInput` into the callback (today's handler re-enables unconditionally on it, which would defeat the gate).

## Design

### Call site 1: the frame thread (`DeviceSession.receive`, `Sources/LauncherPlatform/FrameStream.swift`)

One write with a compare per frame, and a wake-up of the tap thread only when this trackpad's `wantsTap` flips. It never touches a port:

```swift
let recognition = recognizer.withLock { /* answer, step, travel: as today */ }
let flipped = level.withLock { was in defer { was = recognition.blocking }; return was.wantsTap != recognition.blocking.wantsTap }
if flipped { tap?.wake() }
```

```swift
/// What a session needs from the click tap: the press summary and a wake-up. `ClickTap` satisfies it; the
/// `DeviceSession` tests pass a stub that counts wakes per frame (one per `wantsTap` flip, none otherwise).
protocol TapLink: Sendable {
    var holding: ClickFilter.Holding { get }
    func wake()
}
extension ClickTap: TapLink {}
```

- `DeviceSession.init(trackpad:recognizer:pointerCurves:tap: (any TapLink)?, deliver:)` — the `clickTap:` label becomes `tap:` (update `MultitouchTrackpads.run` and the two `DeviceSession` test suites' constructors: `DeviceSessionAnswerTests.swift`, `DeviceSessionTravelTests.swift`, label only).
- `var holding: ClickFilter.Holding? { tap?.holding }` as today.
- `mergedBlocking()` (S1) stays: "Tap thread: the highest level of any running trackpad. Copies the sessions out first: never two locks at once."

### Call site 2: the tap thread (`ClickTap`)

```swift
/// The app's event taps: two active session taps on one `userInteractive` thread. The press port listens for the
/// tap's whole life; the gated port only while `TapFilters` says so. Threads: installed and removed on main. The
/// callback, `follow()` and `recover()` run on the tap thread, the only caller of `tapEnable` on the gated port.
/// Frame threads only read `holding` and call `wake()`.
final class ClickTap: Sendable {
    /// Writer: the tap thread. Reader: frame threads (`holding`).
    private let filters = Mutex(TapFilters())                    // replaces today's three filter mutexes
    /// Writer: main (install, remove). The tap thread switches `gated` and re-enables `presses`, under this lock.
    private let ports = Mutex<Unchecked<(presses: CFMachPort, gated: CFMachPort)>?>(nil)
    /// Writer: the tap thread, once, before its first turn. Readers: main (remove), frame threads (`wake`).
    private let runLoop = Mutex<Unchecked<CFRunLoop>?>(nil)
    /// A version-0 run-loop source whose perform is `follow()`. Created with the tap, added to the loop by the tap
    /// thread, signalled by frame threads. Signals coalesce; one before the loop runs is honoured by the first `follow()`.
    private let wakeUp: Unchecked<CFRunLoopSource>

    /// Main. Two `tapCreate` calls (press mask, gated mask) or nil; if only one succeeded, it is invalidated and nil is
    /// returned. The gated port is disabled at once. One thread: add the three sources, publish the loop, `follow()`,
    /// then `CFRunLoopRun`.
    @MainActor static func install() -> ClickTap?
    /// Frame thread.
    var holding: ClickFilter.Holding { filters.withLock { $0.holding } }
    /// Frame thread, when its trackpad's `wantsTap` flipped: `CFRunLoopSourceSignal(wakeUp)` then `CFRunLoopWakeUp`
    /// on the published loop, if any. Never waits; a no-op after removal.
    func wake()
    /// Main. Idempotent. Disables and invalidates both ports, invalidates the source, stops the loop.
    @MainActor func remove()
    /// Tap thread, also the wake-up source's perform.
    private func follow() { apply(filters.withLock { $0.follow(TapContext.estimated(from: mergedBlocking())) }) }
    /// Tap thread, on a disabled notice: read both ports' `tapIsEnabled`, call `portsWereDisabled`, re-enable the
    /// press port if it read off, apply the change. Nothing when the ports are gone.
    private func recover()
    /// Tap thread, after the filters' lock is released: `tapEnable(gated, change == .open)` under the ports lock.
    private func apply(_ change: GateChange?)

    fileprivate func handle(_ type: CGEventType, _ event: CGEvent) -> Unmanaged<CGEvent>? {
        if type == .tapDisabledByTimeout || type == .tapDisabledByUserInput { recover(); return .passUnretained(event) }
        guard let parsed = TapEvent(type, event) else { return .passUnretained(event) }   // a non-Dock gesture event: no lock
        let context = TapContext.estimated(from: mergedBlocking())                        // read before the filters' lock
        let decision = filters.withLock { $0.decide(parsed, in: context) }
        apply(decision.gate)                                                              // before the verdict returns to the window server
        return decision.verdict.apply(to: event)                                          // add a TapVerdict.apply(to:) over the three existing ones
    }
}
```

- **Two ports.** Press port mask `TapEvent.pressMask` (types 1, 2, 3, 4, 25, 26), enabled for as long as the tap exists. Gated port mask `TapEvent.gatedMask` (6, 7, 27, 34, 22, 29, 30). Both `.cgSessionEventTap`, `.headInsertEventTap`, `.defaultTap`, one callback, one `userInfo` (the `ClickTap`). Both sources and the wake-up source sit on the existing `userInteractive` thread named "ClickTap". The thread retains the `ClickTap`, so no callback outlives the object behind its `userInfo` (keep that property; the wake-up source's context `info` must also be valid as long as the source can fire — e.g. retain/release callbacks in the `CFRunLoopSourceContext`, or rely on the thread's retain and invalidate the source before release).
- **Install.** `install` (main) creates both ports; if either `tapCreate` fails, invalidate the other and return nil. Disable the gated port at once on main (main is the ports' writer at install and remove). Start the thread, which adds the three sources, publishes its loop, runs `follow()` (opening the gate if a frame already wants it) and then `CFRunLoopRun()`. A fresh `TapFilters` is closed and converges from there; nothing queues before the thread runs. If removed before the thread starts, the run loop must return at once (as today).
- **The gate.** Only the tap thread switches the gated port. It decides each event against the level it read for that event and settles on the same thread straight after; `apply` runs after releasing the filters' lock and before the verdict returns. No two of the tap's locks are held at once (`mergedBlocking()` takes the sessions lock then each session's level lock one at a time; it is called before the filters' lock; `apply` takes the ports lock after the filters' lock is released).
- **Notices.** `recover()` treats a disabled notice as a prompt to reconcile, not a command, and counts nothing: under the ports lock read `CGEvent.tapIsEnabled` on both ports (on a notice only), release, call `filters.withLock { $0.portsWereDisabled(pressPortIsOn:gatedPortIsOn:in: .estimated(from: mergedBlocking())) }` (read the level before taking the filters' lock), re-enable the press port if it read off, apply the returned change. Nothing when the ports are gone (after `remove`). Each notice re-reads the truth, so a lost or coalesced echo cannot strand the state.
- **Remove** (main, idempotent): under the ports lock disable and invalidate both ports and set nil; invalidate the wake-up source; stop the loop. A wake or an echo after `remove` finds no ports and does nothing; a stale session after `run` only wakes its own removed tap.
- **Lifecycle.** `MultitouchTrackpads.run` still installs one `ClickTap` and removes it before the next; revoke, hot-plug, wake and setting changes all go through `run`. Sleep latches the level and may leave the gated port on, which is free while no events flow, until the wake's `run`.
- Keep the `Unchecked` wrapper for CF references. Keep the parsing extensions and the three verdict rewrites as they are.

## Rules that apply

- `docs/architecture.md`, Concurrency: "Multitouch frames are recognised on the framework's own thread … the frame thread never waits for it. State shared with that thread lives behind a `Mutex` with one writer." — `wake()` must never wait or block; each field has one writer (level: frame thread; filters: tap thread; ports: main, with the tap thread switching `gated`/re-enabling `presses` under the ports lock).
- `docs/architecture.md`, Concurrency: "No timers, no polling, no background loops … The one extra thread is the click tap's run loop, which exists only while click blocking is armed and serves two event taps. … A trackpad's frame thread only wakes that thread when what it needs flips; no frame thread enables or disables a tap." — no `Timer`, `asyncAfter`, `CFRunLoopPerformBlock` per frame; `tapEnable` only on the tap thread (and on main at install/remove).
- `docs/architecture.md`, Shape: "Framework and wire types never cross a port: … `CGEvent`, `CFMachPort` … stay inside adapters." `TapLink` exposes only `holding` and `wake()`.
- `docs/architecture.md`, Privacy: "the event taps and the scroll-event API are each confined to one file by the source-scan test." All `CGEvent.tap*` and `scrollWheel` stay in `ClickTap.swift`.
- `docs/architecture.md`, Privacy: no logging of any kind (`print`, `NSLog`, `os_log`, `Logger`, signposts).
