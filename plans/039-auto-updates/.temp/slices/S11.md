# S11: Real builds prove the hand-over

## Goal

The remaining rows in `Scripts/update-e2e.sh`: the full silent update, real contact, lost and failing requests, refused updates, failed installs, random kills and a dead helper. A person with the Developer ID, the notary profile and `sudo` runs them; you do not. All the app code is in. This slice adds rows and the extra build variants they need to the frame, and changes nothing under `LauncherKit` or `TrackpadLauncher`.

## Requirements

The proof on notarised builds of R1, R5, R6, R7, R8, R9, R11, R12 and R13:

- R5: "A download that fails or stops MUST be retried at a later check."
- R6: "...install a download only when it carries a signature made with the publisher's update key and is signed with the same Developer ID and bundle identifier as the running copy. Otherwise it MUST install nothing and show nothing, and a later check MUST try again."
- R8: "no finger has made contact of any kind with any trackpad for 1 minute, and the settings window is closed."
- R9: "After installing, the new version MUST run with no settings window, no Dock icon, no dialog and no permission prompt. It MUST stop the old version. Gestures MUST work again within 10 seconds."
- R11: "At every moment /Applications MUST hold either the whole old version or the whole new one. A failed install MUST end with a working copy running again within 10 seconds."

## Design

### The frame, as S6 built it

- `Scripts/update-e2e.sh`, 959 lines. **`rows_table`** is the one place rows are listed: `T63|row_T63|<title>`. Each row is a `row_T63` function ending through `row_done`, `row_fail` or `row_skip`; `check` and `expect_count` record one line of evidence.
- Helpers already there: `reset_world`, `install_copy`, `launch_hidden`, `start_sampler`, `stop_sampler`, `use_feed`, `stage_assets`, `set_control`, `set_last_check`, `ask_person`, `wait_for`, `wait_count`, `count_in`, `count_at_least`, `app_processes`, `count_jobs`, `no_app_running`, `analyze`, `version_of`, `aar_of`, `render_feed`, `make_archive`, `ensure_build`.
- `Scripts/update-e2e/server.py`: the control file, read on every request, holds the fault switches (503, 404, reset, hold). Read its header.
- `Scripts/update-e2e/analyze.py`: reads the sampler's file. Extend it for new questions, rather than parsing samples in bash.
- Read rows T57, T60 and T62 first; they are the models.

Under `--check` every new row is SKIPPED, and `--check` must stay green.

### What the hand-over looks like from outside

- Label of the job: `<bundle identifier>.hand-over`. Sparkle's installer job: `<bundle identifier>-sparkle-updater`, and `<bundle identifier>-sparkle-progress`.
- The new version is opened with `/usr/bin/open -g -a <bundle> --args --after-update`, so `ps` shows that argument.
- The job waits for the old pid, then at least 5 s and at most 6 s on wall time for `CFBundleVersion` to change, then opens whatever is there, the old copy included, with the same argument.
- An `--after-update` start makes no check of its own: this is what T63's "no feed request from v2 for 180 s" and T68's "no hand-over loop" prove. Sparkle's own schedule does the next one.
- The idle minute counts from the later of the hold and the window closing. A hold is visible in Sparkle's cache and from the `<id>-sparkle-updater` job being listed.
- Nothing outside the app shows that gestures run, so T63 and T68 time a person's gesture: `ask_person` prompts, the person taps the 1-finger gesture assigned to an app of the script's choosing (seed the assignment or have the person pick it during setup), and the script times that app reaching the front from the sampler. Do this with the app's real settings UI or the person's hand. **Do not add hooks, arguments or environment checks to the app.**
- This Mac's frontmost app flips on its own, so a row asserts only that the app and Sparkle's helpers never become frontmost.

### Extra builds

Cached by commit like v1 and v2. Each carries the patched spec's `.e2e` identifier unless the row says otherwise. Notarising them all costs minutes each, once, so build only what a selected row needs.

- T67: a v2 signed with Apple Development and a valid EdDSA signature; a v2 signed with the Developer ID and **not** notarised; a v2 with another bundle identifier whose bundle has the host's file name. Plus a tampered EdDSA signature in the feed for the real v2, and an enclosure of a `.dmg` or another host, which needs only feed edits.
- T72: a build with an empty `SUPublicEDKey`.

Each row's feed is rendered as S6 does: `release.sh --feed-only`, then only the address or a named value edited. Keep `feed.py` as the one place for those edits.

### Rows needing a person

T63, T64, T65 and T68 prompt through `ask_person`. T64 asks for a finger resting 90 s, then a palm resting 90 s.

**Do not run anything here that signs with the Developer ID, submits to Apple, uses `sudo`, or writes to /Applications.** Run `--check` only.

## Rules that apply

- `docs/domain-model.md`, Hand-over: "Once the install has finished, or within a few seconds if it failed, the job opens whichever whole copy /Applications holds. The opened copy starts silently: no window, no Dock icon, no dialog and no permission prompt, and the keyboard focus stays in the user's app. It stops any other copy, makes no update check of its own, and gestures work again within 10 seconds."
- `docs/domain-model.md`, Automatic update: "At every moment /Applications holds either the whole old version or the whole new one."
- Nothing in `Sources` changes for this script. If a row seems to need a hook in the app, the row changes.
- The Scripts tree is not under the source scan. Generated archives go in their own new empty folder; run Python with `-I`.
- Do not commit: the orchestrator commits your work.
- Worktree guard: write each Bash command with literal arguments, no shell variables, `$(…)` or loops; create and edit files with Write and Edit; absolute paths. Shell syntax inside the scripts you write is fine.
