# Product Overview

Trackpad launcher is an app to launch apps on MacOS using gestures on trackpad. It is a background app with no menu bar icon: opening the app, from Spotlight, Finder, Launchpad or anywhere else, opens its settings window, and while that window is open the app shows in the Dock like any app; closing the window removes the Dock icon and gestures keep working. It starts by itself at every login, with no window and no Dock icon. Of the app's own controls, only the *Quit Trackpad Launcher* button at the end of the settings window stops it, and an update also stops the old version and opens the new one. It ships as a signed, notarised disk image that shows "drag to Applications", and when opened by hand from anywhere outside /Applications it first moves itself there. In the settings window you can select an app for each available gesture. Trackpad launcher has 5 tap gestures: the thumb held in the chosen corner of the trackpad (top left by default, or top right, bottom left or bottom right, chosen in the settings window) and tapping the rest of the trackpad with 1, 2, 3, 4 or 5 fingers - each gesture launches or focuses its app, or, when it holds a second app, brings both apps to front side by side: the first in the left half and the second in the right half of the display under the pointer - plus the swipe: with the thumb held in the corner, sliding two fingers sideways shows up to 10 running apps like ⌘-Tab (the switcher), the app in front first and the others from most to least recently used, leaving out the apps that a gesture holds alone, since those are one tap away (apps held only in a split gesture stay in the row); an app with several windows shows a stack of its icon, one icon per window up to four; sliding right reaches older apps, and lifting brings the selected one to the front - the window swipe: with the thumb held in the corner, sliding two fingers up or down shows the frontmost app's windows in the top-left corner, in the app's window order, set by the first window swipe into the app and kept until the app quits, with the selection starting on the window in front; an app with fewer than two windows shows a card saying it has no other windows; each visible window comes to the front as the fingers pass it, and lifting keeps the selected window in front (restoring it if it is minimised) with the window that was in front just behind it - and the swap: resting two fingers on the trackpad and tapping the thumb in the corner swaps the two most recently used apps, like a quick ⌘-Tab, with nothing shown on screen; while the fingers stay down, each further thumb tap swaps back again. The swipe, the window swipe and the swap each have their own switch in the settings window. A *Hide background apps* switch, off by default, makes every one of these actions that brings an app or a window to the front also hide every other app, like ⌘⌥H, so one app, or a split gesture's two apps, on screen at a time; an app a gesture launches hides the others once it shows its window, and hidden apps stay reachable through the gestures, the switcher and the swap.

### Additional notes
- After installation trackpad should continously run in the background
- Accessibility: the permission is also used to place a split gesture's windows: to move them, resize them and take them out of full screen, and, while hide background apps is on, to raise the second app's window without making it active.
- Trackpad launcher should be as performant as possible, consuming the least possible resources as it's technically possible. We don't need performance tests, but we should just pick the most performant technical path available when doin technical research.
- Trackpad launcher should be secure and privat - Trackpad Launcher makes no network calls but one kind: a copy signed with a Developer ID in /Applications checks a public update list on GitHub at each login start, if it can write to its own bundle, and each time its settings window opens, and downloads a new version from GitHub releases at a login start or when the user presses *Update now*, which reads the list once more first; no logging, except what Sparkle writes to the Mac's local system log, which never leaves the Mac. It may ask for Screen Recording, only from a button in the settings window, and uses it only to draw window previews while the window switcher shows: one picture of each window when the window swipe begins, kept in memory and dropped when it ends, never saved. Without it the window switcher shows app icons instead.
- Each gesture, should be followed by a smooth haptic feedback and a subtle gentle sound effect (the sound effect is still deferred). The one exception: a swipe or window swipe lift or a thumb tap that changes nothing is silent, whether the user lifts on the starting app, on an app that quit, or with no switcher showing, lifts a window swipe on the window that was in front, or on a window that closed while the window in front stayed in front, or on the card that says the app has no other windows, or taps the thumb with nothing to swap to. A cancelled window swipe is silent too.
- We should use the latest liquid glass human interface design.
- All the design assets needed for this app are kept in /assets directory.
