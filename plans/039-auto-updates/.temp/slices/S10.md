# S10: A failed request retries when the connection returns

## Goal

A request that failed, the feed's or the archive's, runs again once a connection is there, not at the next 24-hour mark, with no timer and no hot loop. A connection watch exists only while a failed request waits. `SparkleEngine.check` remembers a check refused in Sparkle's end-of-cycle window and runs it once the session is off.

## Requirements

- R1 (the retry): "A check that fails for lack of a network connection MUST run again once a connection is available, not at the next 24-hour mark."
- R5 (the later try): "A download that fails or stops MUST be retried at a later check."

## Design

### The mechanism

`Sparkle` stamps `SULastCheckTime` even on a failed check, so nothing public forces a check when a connection arrives except `checkForUpdatesInBackground`. Sparkle's docs warn that calling it later "could interfere with Sparkle's scheduler": it invalidates and re-arms the 24-hour timer, so the mark moves to the retry, which is what R1 means. That departure is deliberate.

`NWPathMonitor` is the push. It reports the present reading at once (2.5 ms measured), which closes the race where the path came up before the watch armed. `SCNetworkReachability` is deprecated. A path monitor makes no request, so the ban on `import Network` becomes a confinement, on purpose; `NWConnection` stays banned.

**No hot loop.** `retrySpent` is set as the retry is made, so a check needs a fresh reading. The first failure earns one retry on the first "connected" reading. That reading lands while Sparkle's session is still on for its end-of-cycle probe, so `check()` remembers it and fires from `willScheduleUpdateCheckAfterDelay`, the moment the session is off; the retry that ran there re-armed the 24-hour timer (proof: `plans/039-auto-updates/.temp/architect/checks/sparkle/pendingcheck.out`). A retry that fails on a steady path needs a real drop and return; a drop during the retry earns the next one, so a link that falls mid-retry still comes back. A persistent failure on a steady path (DNS, a captive portal, a 404) therefore makes one extra request, then waits for the 24-hour mark. There is no floor, backoff or timer. A cycle that ends some other way (a bad signature, a veto) waits for the next check. A download lost mid-way is `.requestFailed` too, so it retries when the connection returns.

### LauncherCore

`Ports.swift`:

```swift
/// Whether a network path exists. Real: SystemConnection. Test: InMemoryConnection.
@MainActor public protocol Connection: AnyObject {
    var onChange: (@MainActor (Bool) -> Void)? { get set }
    /// Pushes the present reading, then every change, until `stop`. Nothing runs before or after.
    func watch()
    func stop()
}
```

And `UpdateEngine.check`'s doc becomes: "One background check. Asked while a cycle runs or is ending, it runs once that cycle has finished, so a retry is never lost. It never runs while an update is held."

`Updater.swift`. `init(_ copy:, engine:, connection:, clock:)`. `Phase` gains a case, and needs an explicit `Equatable`:

```swift
/// R1. The last cycle's request failed, and the connection watch runs. `retrySpent`: this reading's one retry has
/// been made, so only a drop and a return earn another. One bit; no timer, no backoff.
case awaitingConnection(retrySpent: Bool)
```

```swift

    // .cycleEnded(.requestFailed) → already awaiting: stay as it is, so a drop during the retry still earns the next
    //                               one. Otherwise enter(.awaitingConnection(retrySpent: false)).
    // .cycleEnded(other)          → enter(.resting)
}

    //   !connected           → spent = false
    //   connected && !spent  → spent = true; engine.check()
    // No hot loop: a check spends the reading before it runs, and a spent reading needs a real drop.
}

private func enter(_ next: Phase) {
    // leaving .awaitingConnection for anything else → connection.stop()
    // leaving .ready                                → clock.cancel(); launcher.watchUse(nil)
    // phase = next
    // entering .awaitingConnection from outside it  → connection.watch()
    // entering .ready                               → launcher.watchUse { useChanged($0) }

```

`phase` is assigned **before** `connection.watch()`, because `watch` may push inside the call. In `connectionChanged`, `phase` is written before `engine.check()`, for the same reason. Flipping `retrySpent` writes `phase` directly and does not go through `enter`: the watch stays up. `connection.onChange` is wired in `start`.

| `Launcher.watchUse`, contact pushes | `.ready` |
| The 60 s wait | `.ready` and not in use |

### LauncherPlatform

New `Sources/LauncherPlatform/SystemConnection.swift`, the only file with `import Network`:

```swift
/// NWPathMonitor on the main queue; a reading is `path.status == .satisfied`. Exists only between `watch` and `stop`.
@MainActor public final class SystemConnection: Connection
```

A cancelled `NWPathMonitor` cannot start again, so `watch` makes a fresh one and `stop` cancels and drops it. A path push already queued when `stop` runs must do nothing: the handler checks that its monitor is still the current one. `public init()`.

## Rules that apply

- `docs/architecture.md`, Concurrency: "No timers, no polling, no background loops: every input is a push (... Sparkle's answers, a network path change while a failed request waits, ...)".
- `docs/architecture.md`, Shape: "`LauncherPlatform` (... Network (the path monitor, one file) ...)".
- `docs/architecture.md`, Shape: "Every port has exactly two adapters"; Concurrency: "the model, the ports and the public surface of every real adapter are `@MainActor`."
- `docs/architecture.md`, Shape: "Concrete types that can be pointed at a temp directory... are not put behind a port, unless they deliver asynchronously: those sit behind a port so the model's tests stay synchronous."
- `docs/domain-model.md`, Update check: "...and once more when a connection arrives after a request failed... A check that fails is silent."
- Do not commit: the orchestrator commits your work.
- Worktree guard: write each Bash command with literal arguments, no shell variables, `$(…)` or loops; create and edit files with Write and Edit; absolute paths.

## Starting point

- S4: `SparkleEngine.check()` is `updater?.checkForUpdatesInBackground()`, where `updater` is kept only after a successful `start()`. Delegate `UpdaterDelegate`, private, with `emit`, `found`.
- S7: `IdleClock`, `Launcher.watchUse`, `.ready`.
- S8: `.held(.notGenuine)` calls `engine.discardHeldUpdate()`.
- S9: `Updater.start` skips `check()` for `.afterUpdate`. `handle` first guards `phase != .handedOver`. `Phase` is a payload-free enum today, so its `==` is synthesised; the new payload needs an explicit `Equatable`.
