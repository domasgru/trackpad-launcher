## Goal

On an account that cannot write to /Applications, *Move to Applications* asks for an administrator's name and password the way Finder does, and Cancel stops the app with nothing moved. A copy moved from a disk image ejects the image once the mover has exited; it leaves the image mounted when a file on it is in use.

## Requirements

- **R19 (ejecting the disk image).** A copy on a disk image stays there. The disk image SHOULD be ejected. If it cannot be, because other files on it are in use, it stays mounted and the move still completes.
  - Opening the app from the disk image and pressing *Move to Applications* → /Applications holds Trackpad Launcher, the disk image is no longer mounted, and the settings window opens.
- **R21.** When the user's account cannot write to /Applications by itself, *Move to Applications* MUST ask for an administrator's name and password the way Finder does. Cancelling MUST stop Trackpad Launcher with nothing moved.
  - On a standard account, *Move to Applications* then Cancel in the password prompt → Trackpad Launcher stops and /Applications is unchanged.

## Design

### Why this API

`NSWorkspace.requestAuthorization(to: .replaceFile)` needs the restricted Privileged File Operation entitlement Apple grants on request, so it is out. The administrator path is the deprecated-but-exported `AuthorizationExecuteWithPrivileges`, resolved with `dlsym` (no public Swift import), under `AuthorizationCopyRights(kAuthorizationRightExecute, interaction allowed | extend rights | preauthorize)`; a cancelled prompt is `errAuthorizationCanceled`. Accepted tradeoff: during the privileged swap's gap between its two renames /Applications holds no copy (the old one waits in the staging folder); the next Move installs again.

### `ApplicationsInstaller.install` (completes the S5 adapter)

```
// 1. destination = the bundle with this bundle identifier already inside /Applications, if any, else
//    /Applications/<location.original's name>
// 2. staged = BundleInstall.stage(location.running, near: destination): a copy in the item-replacement directory of
//    the /Applications volume, quarantine cleared on every item; an unreadable source → .failed before anything else
// 3. if /Applications or destination is not writable by this user:
//        PrivilegedInstall.swap(staged, into: destination, asideIn: staged's folder, by: administrator)
//        .cancelled → BundleInstall.discard(staged); .cancelled, nothing touched
//        .failed → BundleInstall.discard(staged); .failed, destination as it was
//    else BundleInstall.swap(staged, into: destination): one atomic replace, or a move when there is none (S5)
// 4. any error before the swap → BundleInstall.discard(staged); .failed(localizedDescription), destination untouched
```

"Not writable" means `FileManager.isWritableFile(atPath:)` false for the /Applications folder, or for the existing destination bundle when there is one (a copy owned by another user/root).

### `PrivilegedInstall.swift` (new, LauncherPlatform)

```swift
/// The one privileged call, placed below the script so a test runs the real script. Real: `AuthorizationAdministrator`
/// (AuthorizationCreate, AuthorizationCopyRights with execute and interaction allowed, then
/// AuthorizationExecuteWithPrivileges resolved with dlsym). Test: runs the same command unprivileged.
protocol Administrator: Sendable {
    /// Asks for an administrator's name and password the way Finder does, then runs `/bin/sh -c script sh arguments…`
    /// as root. Blocks; called off the main actor.
    func run(script: String, arguments: [String]) -> AdministratorResult
}
enum AdministratorResult: Equatable { case ran(exitStatus: Int32), cancelled, failed }

enum PrivilegedInstall {
    /// The script takes the paths as "$1" (destination), "$2" (staged) and "$3" (aside, inside the staging folder),
    /// never interpolated: move an existing destination to the aside path; move the staged copy in, and when that
    /// fails move the aside copy back and exit non-zero (`.failed`, /Applications as it was); then remove the aside
    /// copy, ignoring a failure there, and exit zero (`.installed`). So a status matches what /Applications holds. Only
    /// a kill between the two moves leaves /Applications without the app and the old copy in the staging folder,
    /// never inside /Applications.
    static let script: String
    static func swap(_ staged: URL, into destination: URL, asideIn folder: URL, by administrator: any Administrator)
        -> InstallOutcome   // .ran(0) → .installed; .ran(non-zero) → .failed(reason:); .cancelled → .cancelled; .failed → .failed(reason:)
}
```

- The script uses `/bin/mv` and `/bin/rm -rf`, quotes every `"$n"`, uses `--` where appropriate, and never builds a command from a path string. Paths are passed as separate argv entries (`/bin/sh -c script sh "$1" "$2" "$3"`).
- `AuthorizationAdministrator` (real): `AuthorizationCreate` with no rights, `AuthorizationCopyRights` for `kAuthorizationRightExecute` with flags `[.interactionAllowed, .extendRights, .preAuthorize]` (cancel → `.cancelled`), then call the `dlsym`'d `AuthorizationExecuteWithPrivileges(auth, "/bin/sh", [], ["-c", script, "sh", args…, nil], &pipe)`. Read the child's exit status: `AuthorizationExecuteWithPrivileges` does not return it, so wait on the child with `wait(&status)` (or `waitpid(-1,…)`) after the pipe closes — this is a blocking wait on a child process, not a poll or a timer, and runs off the main actor. A missing symbol → `.failed`. Free the authorization ref.
- Confines `AuthorizationExecuteWithPrivileges` and `AuthorizationCopyRights`.

### `DiskImages.swift` (new, LauncherPlatform)

```swift
enum DiskImages {
    /// The disk image a path lies on: statfs → f_mntfromname (e.g. /dev/disk4s1) → DADiskCreateFromBSDName →
    /// DADiskCopyDescription → kDADiskDescriptionDeviceModelKey == "Disk Image" → DiskImage(volume: mount point,
    /// f_mntonname). nil anywhere else, or when any step fails.
    static func image(holding url: URL) -> DiskImage?
    /// Returns at once: FileManager.default.unmountVolume(at: volume, options: .allPartitionsAndEjectDisk) { _ in }.
    /// A file on it in use makes the unmount fail; the image stays mounted (R19). A push, never a wait.
    static func eject(_ diskImage: DiskImage)
}
```
Confines `statfs`, `DADisk` and `unmountVolume`. `ThisCopy.location()` uses `DiskImages.image(holding:)` as its real disk-image lookup (on the original).

### The eject argument and `Lifecycle`

- `ThisCopy.launch(event:arguments:)` reads `--eject-disk-image <volume>` from `arguments` into `Launch.diskImageToEject`: the flag followed by a value → `DiskImage(volume: URL(filePath: value))`; the flag with no value → nil; unrelated arguments (Xcode's `-NSDocumentRevisionsDebugMode YES`) ignored.
- `Launch` gains `public var diskImageToEject: DiskImage?` with `init(opening:diskImageToEject: DiskImage? = nil)`. Doc: "Only on the copy a move just installed: the disk image the mover ran from, ejected once the mover has exited."
- `Installer` gains `func eject(_ diskImage: DiskImage)` ("Ejects it; returns at once. A file on it in use leaves it mounted (R19)."). `InMemoryInstaller` records it in the shared log.
- `Lifecycle`: `replacingOthers(opensWindow: Bool, eject: DiskImage?)`; `launched` passes `launch.diskImageToEject` into `replace`; `openedAgain` keeps `eject` when upgrading `opensWindow`; `othersExited()` ends with `if let eject { installer.eject(eject) }` — the mover has exited, so its volume is free. The installed copy is an opening by hand, so it always goes through `replace` (the mover is among `others`).

## Rules that apply

- `docs/architecture.md` § Shape: `LauncherPlatform` covers "Security (the code signature, Authorization, two private translocation functions), DiskArbitration". Use no framework beyond that list.
- § Privacy: "no files written other than settings in `UserDefaults`, and the app's own bundle copied into /Applications when the user chooses *Move to Applications*; every file operation of that move is confined to one file." The unprivileged file operations stay in `BundleInstall.swift`; the privileged ones are the script's, in `PrivilegedInstall.swift`. Do not spell `copyItem(`, `moveItem(`, `replaceItemAt(`, `removeItem(` outside `BundleInstall.swift` (the source scan reads comments too).
- § Concurrency: "No timers, no polling, no background loops: every input is a push (… the move's install and eject completions …)." `Timer`, `asyncAfter`, `Task.sleep` banned. The admin call blocks off the main actor; only `done` hops back.
- § Shape: "Every port has exactly two adapters" — `Administrator` is an internal seam inside the installer adapter (real `AuthorizationAdministrator`, test administrator), not a Core port.
- § Privacy: no logging of any kind.
- Domain model, *Move dialog*: "*Quit*, or cancelling the administrator prompt, stops it with nothing changed. *Move to Applications* puts the copy in /Applications, replacing and stopping any copy there whatever its version, asking for an administrator's name and password when the account cannot write there; … removes the opened copy where it can (a copy on a disk image stays, and the disk image is ejected unless a file on it is in use), and opens the installed copy."
