## Goal

One command builds a disk image that is signed with Developer ID, notarised and stapled. Opened, it shows Trackpad Launcher beside an Applications shortcut, over a background picture with a cue to drag one onto the other. The background picture is committed, kept out of the app's bundled assets.

## Requirements

- **R24.** Each release MUST be a disk image signed with a Developer ID and notarised by Apple. Opening it MUST show Trackpad Launcher beside a shortcut to the Applications folder, with a cue to drag one onto the other. A Mac MUST open the downloaded disk image and the app inside it with no Gatekeeper warning about an unverified developer. One command MUST build the release disk image from the repository.
  - A Mac that has never seen Trackpad Launcher; the user downloads the release disk image with Safari, opens it, drags Trackpad Launcher onto the Applications shortcut and opens it from Launchpad → no warning about an unverified developer shows, no move dialog shows, and the first run follows.

## Design

**`Scripts/release.sh`**, one command from a clean checkout (rewrite the existing script, which today stops at a notarised zip, never runs `xcodegen generate`, and has never run end to end):

1. Preflight: a Developer ID Application identity in the keychain, `NOTARY_PROFILE` set and usable by `notarytool`, `xcodegen` on the PATH. Each failure prints a clear message and exits non-zero (as the script's `fail` does today).
2. `xcodegen generate` (in the repo root).
3. Archive and export with the developer-id method (as today).
4. Verify the signature authority (`Authority=Developer ID Application`) and the hardened runtime flag (as today).
5. Notarise the app as a zip, then staple and validate the **app**, so a copy dragged out of the image opens offline.
6. Stage `TrackpadLauncher.app` beside an `Applications` symlink (`ln -s /Applications`) and `.background/dmg-background.png`.
7. `hdiutil create -format UDRW` (volume name "Trackpad Launcher") from the stage, attach it (`-readwrite -noverify -noautoopen`, note the mount point), and lay it out with a Finder `osascript`: icon view, toolbar and status bar hidden, the background picture (`set background picture of viewOptions to file ".background:dmg-background.png"`), icon size, both icons' positions (the app on the left, Applications on the right, matching the arrow in the picture), the window's bounds matching the picture's size. `sync` after the layout.
8. Detach, then `hdiutil convert -format UDZO` to `build/release/TrackpadLauncher.dmg`.
9. `codesign --timestamp -s "Developer ID Application"` the image (never `--deep`).
10. `notarytool submit --wait` the image, then `stapler staple` and `stapler validate` it.
11. `spctl --assess --type open --context context:primary-signature -vv` the image and `spctl --assess --type execute -vv` the app.

The output is `build/release/TrackpadLauncher.dmg` (`build/` is git-ignored). No `--deep`, no entitlements, the main executable signed last by Xcode. Keep `set -euo pipefail`, `DEVELOPER_DIR`, `TEAM_ID`/`RELEASE_OUT` overrides. Detach the image on any failure after attaching (a `trap`), and remove the temporary read-write image. Accepted tradeoff: the Finder script needs the release machine's Automation permission for Finder once; no committed `.DS_Store`, no third-party tool (`create-dmg`, `dmgbuild`, `appdmg` are not installed and not wanted).

**`Scripts/release/dmg-background.png`** (new, committed): the drag cue. A light background with an arrow from the app's slot (left) to the Applications slot (right) and, optionally, short text "Drag to Applications". Size it for the window (e.g. 600×400 pt; provide a 2× variant `dmg-background@2x.png` too, or a single 1200×800 image combined into a multi-resolution TIFF with `tiffutil -cathidpicheck` if you prefer — keep it simple). Generate it reproducibly with a small Swift script under `Scripts/release/` (e.g. `make-dmg-background.swift`, drawing with Core Graphics / AppKit into a PNG), run it once, and commit both the script and the PNG. It must live outside `assets/`, because `project.yml` bundles `assets/*.png` into the app.

## Rules that apply

- `docs/architecture.md` § Distribution: "Direct download only, as a disk image: the app and the image are each signed with Developer ID, notarized with `notarytool` and stapled; hardened runtime, no entitlements. One command builds it from the repository. Never sign with `--deep`; the main executable is signed last."
- `docs/architecture.md` § Privacy: no network code in the app (the release script's `notarytool` calls are tooling, not the app).
- `project.yml` bundles `assets/*.png` and `*.svg` as app resources: nothing for the disk image goes there.
- A helper Swift script under `Scripts/` is not part of the scanned sources (`SourcePolicyTests` scans `LauncherKit/Sources` and `TrackpadLauncher/` only); still, write no file other than its output PNG.
