# S8: Only a genuine update installs

## Goal

Sparkle checks only that an update carries the update key's signature and a valid code signature with any identity. This slice adds the rest of R6. At `willInstallUpdateOnQuit`, `SparkleEngine` runs `CodeSignature.isGenuine` on the extracted bundle against the feed's offer, inside the delegate call, so no main-actor turn exists in which an unchecked update is held. A `.notGenuine` verdict discards the update through two independent layers, inside that same call.

## Requirements

- R6: "Trackpad Launcher MUST install a download only when it carries a signature made with the publisher's update key and is signed with the same Developer ID and bundle identifier as the running copy. Otherwise it MUST install nothing and show nothing, and a later check MUST try again."
- R7, the client's half: "The release process MUST notarise every update." `isGenuine` requires the `notarized` ticket, offline.

## Design

### What Sparkle does not do

With `SUVerifyUpdateBeforeExtraction` on, Sparkle checks the EdDSA signature and then requires only a valid code signature, with any identity. It finds the update bundle by file name first, so a bundle with the host's file name and another identifier passes. The update-key half of R6 is already held: `SUVerifyUpdateBeforeExtraction` plus `isPinned` (S4), which keeps the disk-image key-rotation door shut. This slice adds the Developer ID and identifier half.

`<the offer>` is `ExpectedUpdate(version: item.displayVersionString, build: item.versionString, minimumMacOS: item.minimumSystemVersion ?? "")`, built in this file: a Sparkle type must not reach `CodeSignature.swift`. An empty minimum simply fails the comparison, which is fail-closed.

The engine remembers `found` until `discardHeldUpdate`. The check runs synchronously on main, 18 to 31 ms on the stapled app, once per release. That is a named exception to "work that would delay a click runs off main", on purpose: it is the moment that leaves no phase in which *Quit* could install an unchecked update.

**Fail closed.** No bundle found, two bundles, a stale layout or an unreadable signature all read `.notGenuine`.

### `SparkleInternals`, same file

Each names its proof in its doc comment. The proofs are `plans/039-auto-updates/.temp/architect/checks/sparkle/vetonow.out`, `discardquit.out` and the spike's `selfquit.out`, `veto.out`.

```swift
/// `Installation/<random>/<random>/` under Sparkle's cache. nil unless the newest such folder holding `build`
/// holds exactly one bundle: a logout leaves stale folders, and two bundles cannot be told apart from what Sparkle
/// would choose.
static func extractedUpdate(identifier: String, build: String, caches: URL) -> URL?

/// Removing this job ends the installer; Sparkle then aborts with 4005.
static func installerJob(of identifier: String) -> String { "\(identifier)-sparkle-updater" }

/// Both layers, each whatever the other did: remove the job, then discard the extracted bundle. Takes what it acts
/// on, so a test can drive either layer alone. Inside the delegate call.
static func veto(job: String, extracted: URL?)
```

The full layout is `<caches>/<identifier>/org.sparkle-project.Sparkle/Installation/<random>/<random>/<name>.app`. `caches` is `~/Library/Caches` in production, a temp folder in tests. "Holding `build`": the bundle's `CFBundleVersion` equals `build`. "Newest": by the inner folder's modification date. Read a bundle's plist with `Bundle(url:)`: `Data(contentsOf:` is confined elsewhere by the scan. Any unreadable thing is skipped, never a crash.

`veto` calls `LaunchdJob.remove(label: job)`, then `BundleInstall.discard(extracted)` when it has one. Neither result stops the other.

**The two layers, each proven alone.** Layer 1: removing the installer job makes Sparkle abort with 4005, the cycle ends, nothing installs, a later check runs normally. Layer 2: with the job left alive, the bundle gone makes stage 3 fail and the old app stays whole. Both together inside the delegate call: the cycle ended with 4005 a millisecond later, and ending the process three seconds on installed nothing. If both fail, which needs Sparkle's label and layout to change together and `provenOn` blocks that, the update installs at the next end of the process, still carrying the publisher's EdDSA signature. That is an accepted, named gap.

### `LaunchdJob`

New `Sources/LauncherPlatform/LaunchdJob.swift`, the only file with `SMJob`:

```swift
/// `SMJob` lives in this file and nowhere else. Deprecated since 10.10, and the only way to submit a non-permanent job:
/// Sparkle's own comment says so, and it shares this API's fate.
enum LaunchdJob {
    static func remove(label: String) -> Bool
    /// Removes any stale job of this label first.
    static func submit(label: String, arguments: [String]) -> Bool
}
```

Both use `kSMDomainUserLaunchd` with an `AuthorizationCreate` of no rights, as `removeInstallerJob` and `submitRelauncher` do in `plans/039-auto-updates/.temp/architect/checks/sparkle/SpikeHost.swift`. `SMJobRemove(..., wait: true)`. A submitted job is `Label`, `ProgramArguments`, `RunAtLoad: true`, `LaunchOnlyOnce: true`, `EnableTransactions: false`, `ProcessType: "Interactive"`. The next slice adds the hand-over script here; T34 needs `submit` now for its dummy job.

## Rules that apply

- `docs/architecture.md`, Concurrency: "The update's signature check is one exception: it runs on the main actor, 18 to 31 ms once per release, so that no unchecked update is ever held."
- `docs/architecture.md`, Shape: "Sparkle sits behind one port, and what depends on its private behaviour sits in one type, proven against one pinned version." So everything about the cache layout and the job label is in `SparkleInternals`.
- `docs/architecture.md`, Shape: "Framework and wire types never cross a port". `SUAppcastItem` stops in `SparkleEngine.swift`.
- `docs/domain-model.md`, Automatic update: "It installs only when it is genuine: signed with the publisher's update key, and signed with the same Developer ID and bundle identifier as the running copy, and notarised. Otherwise nothing installs, nothing shows, and a later check tries again."
- The scan: `removeItem(` is confined to `BundleInstall.swift` and `CardContract.swift`, `SecCode` and friends to `CodeSignature.swift` and `CardContract.swift`. Call `BundleInstall.discard` and `CodeSignature.isGenuine`; do not reach past them.
- No logging. Failures are silent.
- Do not commit: the orchestrator commits your work.
- Worktree guard: write each Bash command with literal arguments, no shell variables, `$(…)` or loops; create and edit files with Write and Edit; absolute paths.

## Done when

- `extractedUpdate` and `installerJob` live in `SparkleInternals`, each naming its proof.
- Every failure to find or read a bundle reads `.notGenuine`.
- The app target builds: `xcodegen generate`, then `xcodebuild build -project TrackpadLauncher.xcodeproj -scheme TrackpadLauncher -configuration Debug -derivedDataPath build/dev -quiet -packageAuthorizationProvider netrc`.
- The quick gate, `Scripts/test.sh`, is green. It takes minutes: use a long Bash timeout (up to 600000 ms) or `run_in_background`.
