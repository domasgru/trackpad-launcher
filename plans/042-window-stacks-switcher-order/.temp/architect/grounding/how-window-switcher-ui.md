## Flow

### A. Per trackpad frame: model to panel (window switcher)

1. `Launcher.windowSwipe(_:)` `.began` (`LauncherKit/Sources/LauncherCore/Launcher.swift:374-386`): reads `system.frontmostWindows()` once, parses it with `WindowSwitcher.Content.init?(_:)` (`WindowSwitcher.swift:145-165`; returns nil for fewer than two rows, full-screen front window, `.noApp`), confirms the window swipe, increments `windowSwipesBegun`, sets `shown = .windows(WindowSwitcher(content, showsPreviews: isScreenRecordingGranted, serial: windowSwipesBegun, trackpad:))`.
2. `.moved(let travel)` (`Launcher.swift:387-393`): `let crossed = open.selection.follow(travel)`; `shown = .windows(open)` (re-assigned every frame, so the observable `windowSwitcher` changes every frame); one `.lightTick` per crossed row; on a crossing, raises `selectedVisibleWindow`.
3. `.ended` (`Launcher.swift:394-403`): `shown = nil`, second read, `open.lift(now:)`, gesture haptic if `lift.playsHaptic`, raises. `.cancelled` (`404-406`): `shown = nil`, silent.
4. `Launcher.windowSwitcher` (`Launcher.swift:18-20`) is a computed view of the private `shown: ShownSwitcher?` (`Launcher.swift:66-69`, `private enum ShownSwitcher: Equatable { case apps(Switcher), windows(WindowSwitcher) }`). `Launcher` is `@MainActor @Observable` (`Launcher.swift:10-11`).
5. `WindowSwitcherPresenter.init` (`WindowSwitcherPresenter.swift:22-28`) runs `for await shown in Observations({ launcher.windowSwitcher }) { self?.render(shown) }`.
6. `render(_ switcher: WindowSwitcher?)` (`WindowSwitcherPresenter.swift:38-54`):
   - nil: cancel capture, `shownSerial = nil`, `panel.dismiss()` (fade, then `emptied()` drops pictures).
   - `if switcher.serial != shownSerial { open(switcher) }` — layout happens once per window swipe, keyed by `serial`.
   - `panel.show(position: selection.position, selected: selection.selected)` every render.
   - `if selection.stretch != lastStretch, selection.stretch != 0, !reduceMotion { panel.springHighlight(fromY: selection.stretch * layout.pitch) }`; `lastStretch = selection.stretch`.
7. `open(_:)` (`WindowSwitcherPresenter.swift:59-78`): `Displays.screen(under: NSEvent.mouseLocation)`, `visible = screen?.visibleFrame`, `layout = WindowColumnLayout(rowCount: rows.count, displayHeight: Double(visible.height))`, `shownSerial = serial`, `lastStretch = 0`, starts `capture(...)` FIRST, then `panel.lay(out: rows, icon: icons.icon(forSwitcher: switcher.app), layout: layout, topLeft: NSPoint(x: visible.minX + WindowColumnLayout.margin, y: visible.maxY - WindowColumnLayout.margin))`, then `panel.awaitPreviews(rows:)` for rows whose window is in `previewWindows`, then `panel.present(appear: reduceMotion ? nil : OverlayAppear(duration: look.appearDuration, fromScale: look.appearScale, stiffness: look.springStiffness, damping: look.springDamping))`.

### B. The panel's layout (`WindowSwitcherPanel`)

- `init(look:)` (`WindowSwitcherPanel.swift:31-41`): creates `GestureRules.windowSwitcherMaxRows` (10) `WindowRowView`s up front, `super.init(cornerRadius: look.panelRadius, content: content)`, highlight `.style = .clear`, `.tintColor = .labelColor.withAlphaComponent(look.highlightTint)` (0.08), adds highlight then rows to `content` (highlight is under the rows).
- Signature: `func lay(out rows: [WindowSwitcher.Row], icon: NSImage, layout: WindowColumnLayout, topLeft: NSPoint)` (`:47-71`). Sets the window frame `NSRect(x: topLeft.x, y: topLeft.y - size.height, ...)` (top-left anchoring in AppKit's bottom-left coordinates), inside `CATransaction.setDisableActions(true)`: `content.frame`, `highlight.cornerRadius = look.highlightRadius * layout.scale`, `highlight.frame = rowFrame(at: 0)`, every row view `dropPreview()`, rows past `shownRows` hidden, the rest `frame = rowFrame(at: index)` + `fill(...)`. Then `invalidateShadow()`.
- `private func rowFrame(at position: Double) -> NSRect` (`:123-127`): `x: layout.padding, y: layout.panelSize.height - layout.rowTop(at: position) - layout.rowHeight, width: layout.panelSize.width - 2 * layout.padding, height: layout.rowHeight`. Rows AND highlight are positioned through this single function (content is not flipped).
- Signature: `func show(position: Double, selected: Int)` (`:98-104`): highlight `frame = rowFrame(at: position)` with actions disabled (so it tracks fractional position, no animation); `isSelected` per row sets title colour `.labelColor` vs `.secondaryLabelColor` (`:142-144`).
- Signature: `func springHighlight(fromY offset: Double)` (`:108-120`): `CASpringAnimation(keyPath: "position.y")`, `isAdditive = true`, `fromValue = -offset` ("The content is not flipped: down is negative"), `toValue = 0`, mass 1, `stiffness = look.springStiffness` (420), `damping = look.springDamping` (22), `duration = spring.settlingDuration`, `layer.add(spring, forKey: "stretch")` — keyed, so each replaces the previous one.
- `WindowRowView.fill(_:icon:layout:font:)` (`:217-247`): minimised rows get `alphaValue = look.minimisedAlpha` (0.55) on the whole row; slot frame `(inset, inset, slot.width, slot.height)` with `cornerRadius = look.previewRadius * scale` (6); icon centred in the slot at `layout.icon` (44 pt × scale); title font = system 13 pt × scale, `.medium` (`titleWeight`, `:14`, `:43`); title one line (`maximumNumberOfLines = 1`, `.byTruncatingTail`, `:156-157`), vertically centred; for a minimised row the title and a pill badge (`Copy.minimisedBadge` "Minimised", font `look.badgeSize * scale` = 10 pt medium, background `quaternaryLabelColor`, corner radius half its height) are stacked and centred together (`:231-246`).

Geometry in numbers (`WindowColumnLayout.swift:8-16`, verified by `WindowColumnLayoutTests.swift`):
- `margin = 12`, `panelPadding = 8`, `rowGap = 2`, `rowInset = 6`, `previewWidth = 120`, `previewHeight = 60`, `iconSide = 44`, `titleGap = 12`, `titleSize = 13`, `fullPanelWidth = 360`.
- `fullRowHeight = 60 + 2*6 = 72`; `pitch = (72 + 2) * scale = 74 * scale`; `fullTitleWidth = 360 - 16 - 12 - 120 - 12 = 200`; `titleLeading = inset + slot.width + 12*scale` = 138 at full size.
- `fullPanelHeight(rowCount:) = 2*8 + n*72 + max(n-1,0)*2`. One row = 88 pt; ten rows = 754 pt.
- Shrink: `scale = displayHeight > 0 && full > 0 ? min(1, (displayHeight - 2 * margin) / full) : 1` (`:23-27`), applied uniformly to rows, gaps, padding, fonts, width (`panelSize.width = 360 * scale`), slot, icon, title width. NOT applied to: `margin` (top-left placement), and the panel's corner radius (`OverlayPanel` gets the fixed `look.panelRadius` 22 at init, `WindowSwitcherPanel.swift:34`). The highlight radius IS scaled (`:56`).
- `previewSize(aspect:)` (`:57-63`): 60 tall, or 120 wide if wider than 2:1, times scale; slot stays 120 wide so titles never move.
- `previewPixels(scale backing:)` (`:66-68`): slot × backing scale, rounded up (240×120 at 2x).

### C. Previews (ScreenCaptureKit)

1. `WindowSwitcherPresenter.capture(_:rows:scale:)` (`WindowSwitcherPresenter.swift:82-99`): cancels any earlier capture; `windows = switcher.previewWindows` (visible rows only, only when `showsPreviews`, `WindowSwitcher.swift:122-125`); `PreviewCapture.pictures(of: windows, fitting: layout.previewPixels(scale: scale))`; a `Task` consumes the stream; each `(window, picture)` checked against `shownSerial == serial`, mapped to its row index, `panel.setPreview(picture, row: row, animated: !reduceMotion)`; at stream end (not cancelled, same serial) `panel.showIconsWithoutPreview(animated: !reduceMotion)`.
2. `PreviewCapture.pictures(of:fitting:)` (`PreviewCapture.swift:13-22`, `nonisolated static`): `AsyncStream` whose builder starts a `Task` immediately (capture starts before `lay` runs); `onTermination` cancels it. `capture` (`:24-46`, `@concurrent`): `SCShareableContent.excludingDesktopWindows(true, onScreenWindowsOnly: true)` once (~14 ms), then a task group capturing each wanted window with `SCContentFilter(desktopIndependentWindow:)` and `SCScreenshotManager.captureImage`. Config (`:49-60`): aspect-fit inside the pixel box, `scalesToFit`, no cursor, `ignoreShadowsSingleWindow`, `.best` resolution. A failed capture yields nothing.
3. Panel side: `awaitPreviews(rows:)` (`WindowSwitcherPanel.swift:75-77`) sets the icon alpha 0 so a slot waits empty; `setPreview(_:row:animated:)` (`:80-85`) sizes via `layout.previewSize(aspect:)` and calls `WindowRowView.showPreview(_:size:duration:)` (`:179-194`): frame/contents/cornerRadius with actions off, icon alpha 0, then `preview.opacity = 1` in a `CATransaction` with `setDisableActions(duration == 0)` and `setAnimationDuration(duration)` — an IMPLICIT CALayer opacity animation (the preview is a standalone `CALayer`, not view-backed) of `look.previewFade` = 0.08 s. `showIconIfEmpty(duration:)` (`:197-203`) fades `iconView` back via `NSAnimationContext.runAnimationGroup` + `animator().alphaValue = 1`. `dropPreview()` (`:206-215`) clears contents/animations and resets the icon; called on every `lay` and in `emptied()` after the dismiss fade (`:93-95`).

### D. Appear and dismiss (shared `OverlayPanel`)

- `func present(appear: OverlayAppear?)` (`OverlayPanel.swift:54-82`): `isPresented = true`, `generation += 1`, removes running `"fade"` and `"appearScale"` animations on `contentView.layer`, opacity 1; with `appear` and Reduce motion off: `CABasicAnimation("opacity")` 0→1, ease-out, `appear.duration`; if `fromScale`: `CASpringAnimation("transform")` from a scale about the TOP-LEFT corner (`transform(_:scaledBy:)`, `:85-92`) to identity, `duration = settlingDuration`. Then `orderFrontRegardless()`.
  - Window switcher: `OverlayAppear(duration: 0.1, fromScale: 0.96, stiffness: 420, damping: 22)` unless Reduce motion (`WindowSwitcherPresenter.swift:72-77`, `WindowSwitcherLook` `:15-16`).
  - App switcher: `panel.present(appear: nil)` — appears at once (`SwitcherPresenter.swift:137`).
- `func dismiss()` (`OverlayPanel.swift:96-119`): no-op unless presented; `isPresented = false`, `generation += 1`; Reduce motion → `removeNow()` at once; else `CABasicAnimation("opacity")` from the presentation opacity to 0 over `fadeDuration` 0.15 s ease-out, model opacity set to 0, with a `CATransaction` completion block that calls `removeNow()` (`orderOut` + `emptied()`) only if `generation` is unchanged (a re-present during the fade wins). This is the only completion-callback cleanup in the switcher code.

### E. App switcher per frame (for comparison / shared parts)

- `Launcher.swipe(_:)` `.moved` (`Launcher.swift:349-353`) mirrors the window swipe: `open.selection.follow(travel)`, `shown = .apps(open)`, light ticks.
- `SwitcherPresenter.render(_ switcher: Switcher?)` (`SwitcherPresenter.swift:114-127`): nil → `panel.dismiss()`; reads `reduceMotion` live; `if !panel.isPresented || switcher.row != laidOutRow { open(switcher.row) }`; `panel.show(position: CGFloat(selection.position), selected: selection.selected, animatesSize: !reduceMotion)`; same stretch rule as the window switcher but `panel.springHighlight(from: CGFloat(selection.stretch) * layout.pitch)`.
- `open(_ row: [AppEntry])` (`:129-138`): `SwitcherRowLayout(iconCount:, displayWidth: screen.frame.width)`, `panel.layoutRow(row.map { icons.icon(forSwitcher: $0) }, layout:, on: screen.frame, scale: backingScaleFactor)`, `laidOutRow = row`, `lastStretch = 0`, `present(appear: nil)`.
- `SwitcherPanel.layoutRow(_ images: [NSImage], layout: SwitcherRowLayout, on screen: NSRect, scale: CGFloat)` (`SwitcherPanel.swift:32-61`): centres the panel on the screen's full frame (not `visibleFrame`); highlight `frame.size = highlightSide²`, `origin.y = centreY - highlightSide/2`; with actions off, REMOVES all icon layers and creates one fresh `CALayer` per image (`bounds = iconSide²`, `position = (centreX(at: index), centreY)`, contents a CGImage at `fullIconSide * scale` px, `contentsScale`, `.trilinear` minification), added to `iconsHost.layer`.
- `func show(position: CGFloat, selected: Int, animatesSize: Bool)` (`:65-79`): highlight `frame.origin.x = centreX(at: position) - highlightSide/2` with actions off; then in a second transaction `setDisableActions(!animatesSize)` + `setAnimationDuration(0.12)`, sets EVERY icon layer's `transform` to `CATransform3DMakeScale(s, s, 1)` with `s = SwitcherRowLayout.selectedIconScale` (1.12) for the selected index else 1. This is the "selected icon grows" animation: an implicit 0.12 s transform animation on standalone CALayers, about each layer's default centre anchor, re-issued on every render.
- `func springHighlight(from offset: CGFloat)` (`:83-94`): same additive spring but on `"position.x"`, with stiffness 420 and damping 22 HARD-CODED (not from a look struct).

## Non-Obvious Things

1. The rubber band is NOT rendered as an offset that follows the fingers. The highlight's model frame is always the clamped `position`; each render where `stretch` changed (and is non-zero) adds a fresh additive `CASpringAnimation` from `stretch * pitch` back to 0 under the key `"stretch"` (`WindowSwitcherPanel.swift:108-120`, `SwitcherPanel.swift:83-94`). So while the fingers keep moving past an end, frames keep restarting the spring near the offset; as soon as the fingers stop (stretch unchanged, no new spring) the highlight springs back to rest even though the fingers are still past the end. A card that "follows the fingers by at most 6 pt and settles back as the switcher goes" is different behaviour: it would need to HOLD the offset while the fingers are held, then animate back on dismiss.
2. Magnitudes of today's rubber band: travel is clamped to `switcherMaxOvershoot` = 0.25 items (3 mm) past an end (`SwitcherSelection.swift:26-33`), so `stretch` peaks at `0.2 × (1 − 1/(1 + 0.25/0.2)) ≈ 0.111` items, i.e. about 8.2 pt in the window switcher (pitch 74) and 11.1 pt in the app switcher (pitch 100). Reusing `stretch × pitch` for the card would overshoot the 6 pt cap; a dedicated pure mapping (e.g. in Core, next to `SwitcherSelection`) is needed.
3. `SwitcherSelection(count: 1)` is explicitly supported: "At least 1: a one-item switcher rubber-bands at both ends" (`SwitcherSelection.swift:7`). Its turn-back rule (`:31-32`: `if travelMM < 0 && moved > 0 { next = moved }`, `if travelMM > last && moved < 0 { next = last + moved }`) already gives "on a change of direction, move at once toward the new direction, passing rest and going up to the cap beyond it" — the R11 behaviour — measured in step-mm and clamped to ±3 mm. `travelMM` is `package(set)` and public-readable, so a card offset could be derived from it (or from `stretch`) purely in Core.
4. The selection always starts at item 0: `travelMM = 0` initially and there is no start-index initializer (`SwitcherSelection.swift:11-17`); `WindowSwitcher.init` doc says "starts on the first row" (`WindowSwitcher.swift:82`). Since `follow` works on deltas (`moved = reportedMM - self.reportedMM`, `:28`), starting on row k only needs `travelMM = k × switcherStepMM` with `reportedMM` left at 0. The view needs no change for it: `lay` puts the highlight on row 0 (`WindowSwitcherPanel.swift:57`) but `render` immediately calls `show(position:selected:)` in the same pass, with actions off, so the highlight lands on row k without animating. The front window is currently always row 0 by construction (`WindowList.front(front, others:, minimised:)`, `WindowSwitcher.swift:49, 102-104`); `frontWindow` (`:128-130`) exists independently of row order.
5. The window switcher lays out once per window swipe via `serial` (`WindowSwitcherPresenter.swift:47`); the app switcher has NO serial and re-lays out when `!panel.isPresented || switcher.row != laidOutRow` (`SwitcherPresenter.swift:120`), and `layoutRow` destroys and recreates every icon layer (`SwitcherPanel.swift:46-58`). Consequences for stacks: (a) anything that makes `row` change mid-swipe re-creates all layers (and would replay any rise added at layout); (b) adding window counts to `Switcher` must not be compared as part of the re-layout key, or a count arriving late would rebuild the row; (c) a one-shot rise must be added once at `open`, never in `show`.
6. The selected-icon grow is an implicit transform animation re-issued on every render for every icon layer (`SwitcherPanel.swift:71-78`): `layer.transform = CATransform3DMakeScale(...)` inside a transaction with `setAnimationDuration(0.12)`. It touches only `transform` of the layers in `iconLayers`, so an explicit, keyed rise animation on other properties/other layers is not replayed by selection moves. But if stack copies were put into `iconLayers` they would get the transform reset per frame, and each per-frame `transform` write on a layer that already carries an explicit `transform` animation would interfere.
7. Sublayers always composite ABOVE their parent layer's own `contents`. If stack copies were added as sublayers of the existing icon layer (to inherit the 1.12 grow and the shrink transform), they would draw IN FRONT of the front icon. Copies "behind" the icon need a container layer whose sublayers are the copies and the front icon (front icon last), with the selection transform moved to the container; the current code scales the icon layer itself (`SwitcherPanel.swift:74-77`) and positions it at `(centreX(at: index), centreY)` with the default centre anchor, so the grow is about the icon's centre.
8. App switcher vertical room for stacks (full size): panel height `2×22 + 92 = 136` (`SwitcherRowLayout.swift:39-41`), icon centre at 68, icon top at 108, highlight top at 114, panel top at 136. Copies peeking 6/12/18 pt reach 126 at rest (outside the highlight, inside the panel); with the 1.12 grow about the icon centre a top at 18 pt above the icon reaches about `68 + 58 × 1.12 ≈ 133` — inside, but ~3 pt from the edge, and the panel content is masked by `roundedClip` with radius 34 (`SwitcherPanel.swift:8`, `GlassClip.swift:9-11`), so the first/last slots' tall stacks run into the rounded corners. `SwitcherRowLayout`'s doc and tests promise the 22 pt padding to the highlight on every side; stacks change none of that if they only overflow upward (R5 asks spacing/highlight/panel size unchanged).
9. Reduce motion is read LIVE at each use, never cached: `SwitcherPresenter.render` reads it per render (`SwitcherPresenter.swift:119`); `WindowSwitcherPresenter.reduceMotion` is a computed property (`WindowSwitcherPresenter.swift:35`) read at render, open, and per preview; `OverlayPanel.present`/`dismiss` read it themselves (`OverlayPanel.swift:64, 100`). Under Reduce motion: no rubber-band spring, no selected-icon grow animation (scale still changes, at once), no window switcher appear animation, no dismiss fade (removed at once), previews appear at once. There is no injected `reduceMotion` closure in the switcher code (unlike `GearView.init(image:reduceMotion:)`, `GearView.swift:17`, and `UpdatePictureView`), so it is not testable without the system flag.
10. The dismiss fade is the only switcher animation with a completion callback (`OverlayPanel.swift:104-118`), guarded by `generation`. A "settle back as the switcher goes" animation on a card would run concurrently with this 150 ms fade on `contentView.layer`; under Reduce motion the panel is ordered out at once (so the card should not move anyway). After the fade `emptied()` runs (`OverlayPanel.swift:122-127`), the subclass hook for cleanup (the window switcher drops previews there).
11. `docs/architecture.md` line 21: "Animation is Core Animation keyframes, which the render server plays. Whatever an animation leaves behind is cleaned up from its completion callback… No code of ours runs per display frame, and display links are banned along with timers. Code may run per input event while the effect it serves is on screen: the switchers' highlight on trackpad frames". So: a card's finger-following offset may be set per trackpad frame (like the highlight), the rise must be a CA animation (staggered via `beginTime` = `CACurrentMediaTime() + n × 0.04`, presumably with `fillMode = .backwards`), and nothing may be driven by a timer/display link.
12. No SwiftUI in the switchers: both panels are AppKit + Core Animation (`NSGlassEffectView`, `NSView`, `CALayer`). Mixed animation APIs: explicit `CASpringAnimation`/`CABasicAnimation` (appear, dismiss, stretch), implicit `CALayer` actions (selected-icon grow 0.12 s, preview opacity 0.08 s), and `NSAnimationContext` animator (icon fade back, `WindowSwitcherPanel.swift:199-202`). The only `CAKeyframeAnimation` built from a pure Core curve is the app picker's pick animation (`AppPicker.swift:277-285` from `PickAnimation.keyframes(perSecond:)`), which is the precedent for "pure curve in Core, sampled, wrapped into CA in UI, testable".
13. Plan 023 ("app-selection-grow-animation") is NOT the switcher's selected-icon grow. It is the app picker's pick animation (`PickAnimation`) plus the tuner tabs (`plans/023-app-selection-grow-animation/plan.md:1-15`). The switcher's grow is the 1.12 implicit scale in `SwitcherPanel.show`.
14. Switcher animations are not tuned by the Debug animation tuner. `LaunchTuning` (LauncherPlatform) holds launch, bounce, pick and swipe-travel values only; its `swipe` tab is "Move like the cursor", points per step, tracking speed (`AnimationTuner.swift:298-310`). `LauncherUI` cannot import `LauncherPlatform`; the pick animation reaches the tuner only through a Debug-only closure hook on `SettingsShell` (`SettingsShell.swift:6-12, 30-39`, wired at `TrackpadLauncher/TrackpadLauncherApp.swift:88`). Window switcher numbers live in `WindowSwitcherLook.shipped` (`WindowSwitcherPanel.swift:8-19`); app switcher numbers are literals (`SwitcherPanel.swift:8, 24, 73, 90-91`). Tuning a rise or card offset would require extending that hook pattern.
15. Duplicated rather than shared: spring constants (420/22 in `WindowSwitcherLook` and literals in `SwitcherPanel`), the `show`/`springHighlight` pair, and the stretch rule in both presenters (`SwitcherPresenter.swift:123-126`, `WindowSwitcherPresenter.swift:50-53`). What IS shared: `OverlayPanel` (window, glass, present/dismiss/emptied, appear), `roundedClip`, `SwitcherSelection`, `GestureRules` constants, `Displays`, `AppIcons`.
16. Placement differs: window switcher at `visibleFrame` top-left + 12 pt margin (below the menu bar, clear of a left Dock), sized to the `visibleFrame` height (`WindowSwitcherPresenter.swift:60-69`); app switcher centred on the full `frame` and shrunk against its width (`SwitcherPresenter.swift:130-134`, `SwitcherPanel.swift:36-38`).
17. Highlight z-order: in the window switcher the highlight is added before the rows (`WindowSwitcherPanel.swift:39-40`) so it sits under the row content; in the app switcher it is added before `iconsHost` (`SwitcherPanel.swift:26-27`). The window highlight's radius 14 = panel 22 − padding 8 ("concentric", `:9-10`).
18. Constraints for a card variant in `WindowSwitcherPanel`:
    - Rows are ten pre-created `WindowRowView`s; `lay(out:…)` takes `[WindowSwitcher.Row]` and one `icon`; there is no slot for non-row content. A card would be a new view (or row-view mode) and a new branch in `lay`/`render` keyed by a new model case; `WindowSwitcher.Row` is a two-case enum and `WindowSwitcher.Content` requires 2+ windows (`WindowSwitcher.swift:145-165`), so a card cannot be expressed today.
    - Titles are single-line by design (`maximumNumberOfLines = 1`, truncating tail) with `fontSize = 13 × scale`, weight `.medium`. A bold first line + regular second line is new text styling; the title column beside a 120 pt slot is only 200 pt wide (`fullTitleWidth`), so "‹App› has no other windows on this desktop." at 13 pt will not fit one line; wrapping or a different horizontal layout (icon slot narrower than 120) is a design decision. `WindowColumnLayout(rowCount: 1, …)` gives an 88 pt tall, 360 pt wide panel.
    - The highlight is always shown at `rowFrame(at: position)`; for a card the presenter/panel would need to hide it or treat the card as row 0.
    - The card's finger offset must be applied per render with actions disabled (as the highlight is), and its settle-back added in the `nil` branch of `render` alongside `panel.dismiss()`; `WindowSwitcherPresenter.render(nil)` currently only cancels capture and dismisses (`:39-46`).
    - `showsPreviews`/`previewWindows` and capture are row-based; a card needs none (no capture).
19. Observation delivery: presenters consume `Observations({ ... })` (`WindowSwitcherPresenter.swift:26`, `SwitcherPresenter.swift:27`), an async sequence that delivers values asynchronously on the main actor. The window presenter's per-`serial` guard protects against coalesced values; the app presenter relies on `isPresented`/row equality. See Open Questions.

## How the UI is tested (seams)

- No snapshot tests anywhere (grep for "snapshot" only hits lifecycle-world tests in `LauncherCoreTests`).
- No tests reference `SwitcherPanel`, `WindowSwitcherPanel`, `OverlayPanel`, `SwitcherPresenter` or `WindowSwitcherPresenter` (grep over `LauncherKit/Tests`). The switcher panels and presenters are untested; Reduce motion in them is read from the system with no seam.
- The switcher seams are the pure Core types, tested in `LauncherCoreTests`:
  - `WindowColumnLayoutTests.swift` (e.g. `tenRowsKeepTheFullSizeWhenTheyJustFit` asserts `pitch == 74`, `panelSize.height == 754`, `rowTop(at: 2) == 156`; `theColumnIsThreeHundredSixtyPointsWideWhateverTheRowCount`; `theTitleColumnEndsAtTheRowsInsetAtEveryScale` asserts `titleLeading == 138`, `+ titleWidth == 338`; `theLargestPreviewWorthCapturingFillsTheSlotAtTheDisplaysBackingScale` 240×120).
  - `SwitcherRowLayoutTests.swift` (pitch 100, 22 pt padding, `selectedIconScale == 1.12` and inside the highlight at line 73-75).
  - `SwitcherTests.swift` (selection/stretch bounds, e.g. lines 42, 67, 131-146).
  - Model-level on-screen behaviour through the `World` harness: `WindowSwitcherOnScreenTests.swift` (e.g. line 14 `theWindowSwitcherAppearsOnTheFrameTheWindowSwipeBeginsWithTheFrontWindowSelected` asserts `selection.selected == 0`; lines 157-177 stretch signs), `SwitcherOnScreenTests.swift`, `WindowPreviewTests.swift`.
- `LauncherUITests` (`@testable import LauncherUI`, main-actor default isolation, `Package.swift:29-33`) test AppKit views directly through "benches": `PickerBench` drives `AppPicker` and asserts on `CALayer` animations (e.g. `noLayerAnimates`, `iconLayer.action(forKey:) == nil`, `AppPickerTests.swift:109-186`); `GearBench` puts a view in a never-ordered-in borderless `NSWindow` and injects `reduceMotion` via a closure reader (`GearBench.swift:10-32`). ## Open Questions

- `Observations` coalescing: whether `Observations({ launcher.switcher })` can skip the intermediate `nil` between two quick swipes (or skip frames). If it can, `SwitcherPresenter.render` would see a new `Switcher` with `panel.isPresented == true` and an equal `row`, and not re-lay out — a one-shot rise keyed to `open` would then not play. The window presenter is immune because it keys on `serial`. I did not verify the Swift 6.2 `Observations` delivery semantics in this repo.
- Whether setting an unchanged `transform` on the icon layers every render (`SwitcherPanel.swift:74-77`) creates a new implicit animation each frame; I did not verify Core Animation's behaviour for same-value writes here. It matters if stack layers share that layer.
- Where the Accessibility window read for counts (app switcher stacks) would surface into `Switcher`; not in my angle (see the model/AX explorers).
- How `SwitcherSelection.follow`'s `reportedMM` is produced from cursor travel (`SwipeTravel`, `PointerCurve.swift:135`, `CursorTravel.swift:37-42`): with "move like the cursor", 1 "step-mm" is not a physical millimetre, so a card cap expressed in points through travel would scale with pointer acceleration. Not traced in depth.
