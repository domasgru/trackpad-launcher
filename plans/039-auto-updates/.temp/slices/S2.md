# S2: Install the moment the update is prepared, and the trackpad knows nothing

## Goal

A held genuine update arms the restart and ends the process in the same turn: nothing waits for the trackpad, a gesture or the settings window any more. Every trace of revision 1's contact sensing and idle clock is gone from the frame path, the model, the ports, the adapters and the tests, and the source-scan test keeps update code out of the frame-path files from now on.

Repo root (a git worktree; use absolute paths): `/Users/dominykasgrubys/code/trackpad-launcher/.claude/worktrees/039-auto-updates`. A codebase map with line numbers (taken before S1) is at `plans/039-auto-updates/.temp/codebase-map.md`; sections 2, 3 ("Contact sensing on the frame path"), 5 ("SourcePolicyTests structure", "LifecycleWorld", "InMemory adapters") list every line this slice deletes.

## Requirements

- **R2 (install at once).** "When a login start finds a newer version, Trackpad Launcher MUST download it and install it as soon as the download finishes. It MUST wait for nothing else: not for the trackpad, a gesture or the settings window."
- **R22.** "The code that handles trackpad frames MUST contain no update logic in any update state. No update code MUST run for a trackpad frame. A review of the code and a source check confirm this; it is not measured."

## Design

This slice is a change on top of revision 1's `Updater` (`LauncherKit/Sources/LauncherCore/Updater.swift`); S3 rewrites `Updater` and the engine port wholesale afterwards, so keep the changes here minimal and do not pre-build S3's phases.

### `Updater`, minimally

- The `.ready` phase, `useChanged`, `idleMinutePassed`, the `clock` and the `launcher?.watchUse` lines go.
- `.held(.genuine)`: call `engine.armRestart()` in that same turn. Armed → `enter(.handedOver)`, `onHandOver?()` (which makes `Lifecycle` end the process: log `"arm restart"` then `"end"` with nothing between). Refused (false) → `engine.discardHeldUpdate()` and the phase stays, so the cycle ends `.failed` and the existing `.cycleEnded` rule decides; the process never ends without a restart armed.
- `.held(.notGenuine)` → `engine.discardHeldUpdate()`, as today.
- `init(_:engine:connection:)` loses `clock:`. The composition root (`TrackpadLauncher/TrackpadLauncherApp.swift` `makeUpdater`, L44-54) stops passing `SystemIdleClock()`.
- `start(watching:opening:)` keeps its shape for now (S3 changes it).

## Rules that apply

- `docs/architecture.md`, Concurrency: "Multitouch frames are recognised on the framework's own thread; only recognised events hop to the main actor … Nothing about updates runs on that thread or for a frame, in any update state: the source-scan test keeps every update token out of the frame-path files." "State shared with that thread lives behind a `Mutex` with one writer."
- `docs/architecture.md`, Concurrency: "No timers, no polling, no background loops: every input is a push … Time passes only on Core Animation's clock, with one exception, confined to one owner: the hand-over job's waits, which run after this process has decided to end".
- `docs/architecture.md`, Shape: "Every port has exactly two adapters: the real one in `LauncherPlatform` and an in-memory one in the tests." Deleting a port deletes both.
- `docs/domain-model.md`, Login update: "it downloads it and installs it the moment the download is prepared, waiting for nothing: not the trackpad, a gesture or the settings window. … The update adds nothing to trackpad use: no update code runs for a trackpad frame, in any update state."
- `docs/architecture.md`, Privacy: "A source-scan test in `LauncherCoreTests` fails the build on any banned API; add to its list rather than adding prose."
