# S3: The settings window hides with the others and comes back; the overlays never hide

Work only in `/Users/dominykasgrubys/code/trackpad-launcher/.claude/worktrees/032-hide-background-apps`. Do not commit: the orchestrator commits.

**Safety: never run anything that hides, activates or quits a real app. No test, script or probe of yours may call the real hide on this Mac, and do not launch the built app.**

## Goal

With the switch on, an action that hides also hides the open settings window, unless Trackpad Launcher is the frontmost app. The Dock icon stays, and any opening by hand (the Dock icon, Spotlight, Finder, a swap or a lift on Trackpad Launcher) shows the window where it was with the switch as it was. The switcher, the window switcher, the launch animation and the launch bounce keep playing through a hide, and gestures keep working while the window is hidden.

## Requirements

- R14: "An action that hides MUST hide an open settings window too, unless the settings window is the frontmost app." Scenarios: a tap on Safari with the window open hides it; a gesture while the window is hidden works as usual; a swap that brings the settings window to the front leaves it visible and hides every other app.
- R15: "Trackpad Launcher's Dock icon MUST stay while the settings window is hidden."
- R16: "Opening Trackpad Launcher from the Dock or anywhere else MUST show the hidden settings window." It "shows again at the same position with the switch still on."
- R17: "Hiding MUST NOT cut short or remove the launch animation, launch bounce, switcher or window switcher. Haptic feedback MUST stay the same." Scenarios: with the window open, a tap on a running app hides the window and the launch animation plays in full; a swipe right after hiding shows the switcher as usual.

## Design

No model change: `Launcher.window` stays open while the app is hidden, as it does while minimised, so the updater, the quit rules and the window's request count are untouched.

### `LauncherPlatform/WorkspaceActions.swift`

Today `hideOtherApps(than:)` excludes this process with a pid check in its filter, and calls `.hide()` on `NSRunningApplication`s, immediately on the next turn, or from `applicationActivated` for the deferred one.

- Include this process. Its entry in `runningApplications` is `.regular` exactly while its Dock icon shows, which is exactly while the window is open (hidden or minimised included), and the bundle-identifier filter already leaves it out when it is the kept app. So drop the pid exclusion.
- Hide this process with the app's own hide, `NSApp.hide(nil)`, never `NSRunningApplication.hide()`. One small private helper decides, used in both hide sites (compare with `NSRunningApplication.current`'s pid).
- When Trackpad Launcher is frontmost and not the kept app it takes the same deferral as any frontmost app: it is the pending hide, hidden on the kept app's activation push, dropped by the same rules.
- The activation policy is not touched, so the Dock icon stays (measured: the policy reads regular after the hide). `.hide(` stays confined to this file.
- Update `hideOtherApps`' doc text in `LauncherCore/Ports.swift`: Trackpad Launcher itself is included while its Dock icon shows, unless it is `app`.

### `LauncherUI/SettingsShell.swift`, `render(_:)`

- `.open`: unhide before ordering the window front and activating: after the `isShown` block and before `makeKeyAndOrderFront`, `if NSApp.isHidden { NSApp.unhide(nil) }`. Every opening by hand reaches this path through `openedByHand`. Measured: the window's frame is identical after hide and unhide; activation alone also unhides, so the explicit unhide documents the path and covers closing while hidden and reopening.
- `.closed`: after `window.orderOut(nil)` and `NSApp.setActivationPolicy(.accessory)`, `if NSApp.isHidden { NSApp.unhideWithoutActivation() }`, so the process is never left hidden with no window. Measured: after `orderOut` the unhide leaves the window out, the hidden state cleared and the frontmost app untouched. This is the Dock's Quit while hidden: it closes the window as today.
- A short comment on each says why. `isShown`, `centre()` and the `fit()` calls stay as they are: the window comes back where it was, and centring happens only from closed.

### Overlays: `canHide = false`

- `LauncherUI/OverlayPanel.swift`: in `init`, beside `hidesOnDeactivate = false`. Both switchers inherit it.
- `LauncherPlatform/LaunchOverlay.swift`, `makePanel`: on the panel, beside `hidesOnDeactivate`. Launch animations, the bounce row and quiet fades all come from it.
- The clock host (`LaunchClock.makeHost`) already has it. Verify; change nothing.
- Measured: a non-activating, screen-saver-level panel with `canHide` false stays visible through the app's hide, and animations added to its layer before and during the hide complete on time; a panel ordered in while the app is hidden shows whatever its `canHide`, so the flag matters exactly for the panels already up when a hide lands: the switcher fading out after a lift, and the launch animation or bounce started in the same turn as the hide.
- The Debug animation tuner's window hides with the app: it is a developer tool and comes back with the next opening. Leave it alone.
