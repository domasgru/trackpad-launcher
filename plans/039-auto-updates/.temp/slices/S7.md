# S7: The update waits for an idle minute

## Goal

A verified, held update now waits for the user to stop using the app. Trackpad contact is sensed at the frame, only while an update waits. `Launcher` learns "in use", never "update". `Updater` runs a one-minute wait exactly while the app is not in use, and asks the engine to arm the restart when the minute passes. The real `armRestart` still answers false until a later slice, so the app still installs at its next end. No main-actor hop is added in normal use.

## Requirements

R8: "After a download finishes, Trackpad Launcher MUST wait until both of these hold: no finger has made contact of any kind with any trackpad for 1 minute, and the settings window is closed. It MUST install 1 minute after the later of the last touch and the window closing."

## Design

### Why it is shaped this way

- **Contact** is read at `DeviceSession.receive` on `frame.touches`: before the recognizer's palm filter, so it sees palms and not hovers, and it reads no clock. Normal touches cost one uncontended lock per frame and, on a flip, one flag read with no hop. So "no finger down means no work" holds as today.
- **Window edges** arrive through `Launcher`'s own model, which flips before AppKit's `orderOut`. A minimised or hidden window stays `.open` and blocks.
- **One input.** Both reach `Updater` as one boolean, `inUse`. So "1 minute after the later of the last touch and the window closing" needs no timestamps: each report of "not in use" starts the minute, any report of "in use" cancels it, and at the fire `Updater` re-reads the level, so an edge still queued on main cannot lose a touch. The minute counts from the moment an update is held at the earliest.
- **The minute** is a one-shot `DispatchSource` timer in one file, not `LaunchClock`: `LaunchClock` reports a system stop as *passed*, which is wrong here. This clock stops during sleep, and the `run` at wake restarts the minute, so an install never lands the moment a lid opens.
- A dead trackpad reads as idle, which R8's "no trackpad" scenario wants. A stuck `occupied` delays the install until the next touch or `run`: it fails safe.

### LauncherCore

`Ports.swift`:

```swift
// TrackpadEvent gains, for the real adapter and the in-memory one alike:
/// Some trackpad went empty or occupied, only while `sensesContact`. Carries no data: re-read `isTouched`.
case contactChanged

// TrackpadHardware gains:
/// Contact of any kind on any running trackpad, read now: palms yes, hovers no. Reads no clock.
var isTouched: Bool { get }
/// While true, each flip pushes `.contactChanged`. Off costs one flag read per flip and no hop.
var sensesContact: Bool { get set }

/// One pending wait that does not advance while the Mac sleeps. Real: SystemIdleClock. Test: InMemoryIdleClock.
@MainActor public protocol IdleClock: AnyObject {
    /// Replaces any pending wait.
    func wait(_ duration: Duration, then passed: @escaping @MainActor () -> Void)
    func cancel()
}
```

`Launcher.swift`:

```swift
/// A finger on any trackpad, or the settings window open, minimised or hidden included.
public var isInUse: Bool   // window != .closed || hardware.isTouched

/// While set: `onChange` now with the present reading, then at each change and after each `run`. nil stops it, and
/// contact sensing with it. `Launcher` does not know why it is asked.
public func watchUse(_ onChange: (@MainActor (Bool) -> Void)?)
```

`watchUse` turns `sensesContact` on **before** it reads the present level, so a lift landing as sensing turns on is neither lost nor stuck (T11). `reportUse()` runs on `.contactChanged`, in `openedByHand` on the edge from closed only, in `closeWindow`, and after `hardware.run` in `reconcile`. The last is the reset rule: `run` replaces sessions, so an in-flight lift can vanish, and re-reading the level cannot stick. A report of "not in use" after a `run` restarts the minute, which is what a wake wants: the user has a minute to touch the pad before an install. A resting finger comes back on its next frame. The word "update" appears nowhere in `Launcher`.

`Updater.swift`. `init` gains the clock, `init(_ copy: UpdatableCopy, engine: any UpdateEngine, clock: any IdleClock)`, and `start` keeps `launcher`. Holds:

```swift
private enum Phase {
    /// Nothing to do. Sparkle's schedule, or a check, may be running.
    case resting
    /// R8. A genuine update is held and installs at this process's end, however it ends. `Launcher`'s use is watched,
    /// and the idle minute runs exactly while the app is not in use.
    case ready
    /// Terminal. The restart is armed and the process is ending in this same turn.
    case handedOver
}

private func handle(_ event: UpdateEngineEvent) {
    // .held(.genuine)     → enter(.ready)
    // .held(.notGenuine)  → nothing yet; the next slice writes it
    // .cycleEnded(any)    → enter(.resting)
}

private func useChanged(_ inUse: Bool) {
    // Only while .ready: inUse ? clock.cancel() : clock.wait(.seconds(60)) { idleMinutePassed() }
}

private func idleMinutePassed() {
    // guard .ready, launcher.isInUse == false       // the level, read now: an edge may still be queued
    // guard engine.armRestart() else { return }     // stays .ready; the next idle edge tries, so no loop
    // enter(.handedOver); onHandOver?()             // same turn, nothing can interleave
}

/// The one place a lasting effect starts or stops, so leaving a phase cannot leave one armed.
private func enter(_ next: Phase) {
    // leaving .ready   → clock.cancel(); launcher.watchUse(nil)
    // phase = next
    // entering .ready  → launcher.watchUse { useChanged($0) }
}
```

A phase never re-enters itself: a second `.held(.genuine)` while `.ready` changes nothing. Each lasting effect exists only where this table says:

| Lasting effect | Exists only in |
|---|---|
| `Launcher.watchUse`, contact pushes from the frame thread | `.ready` |
| The 60 s wait | `.ready` and not in use |

`updater` construction in the app target passes `clock: SystemIdleClock()`.

### LauncherPlatform

`FrameStream.swift`, `DeviceSession`:

```swift
/// Writer: this device's frame callback. Reader: main, through `isTouched`.
private let occupied = Mutex(false)
var isOccupied: Bool { occupied.withLock { $0 } }
// init takes `sensesContact: @Sendable () -> Bool`, as it takes `clock`, so a test owns its own flag.
// First lines of `receive`, on frame.touches, so before the recognizer's palm filter:
let touched = !frame.touches.isEmpty
let flipped = occupied.withLock { was in defer { was = touched }; return was != touched }
if flipped, sensesContact() { deliver(.contactChanged, nil) }
```

`MultitouchTrackpads.swift` holds its flag in a `Mutex`, one writer (main), and passes a closure over it to each session: the flag outlives `run`, a session does not. `sensesContact` is that flag. `isTouched` copies the sessions out and asks each, as `mergedTapState` does: never two locks at once. `.contactChanged` goes through the same `deliver` path as every other event, so a replaced session's edge is dropped by the generation guard.

New `Sources/LauncherPlatform/SystemIdleClock.swift`:

```swift
/// One-shot `DispatchSource` timer on the main queue, 1 s leeway, on the clock that stops during sleep. Cancel and fire
/// are both on main, so a cancelled wait cannot fire.
@MainActor public final class SystemIdleClock: IdleClock
```

Use `DispatchSource.makeTimerSource(queue: .main)` scheduled on `DispatchTime` (uptime, not wall time) with `leeway: .seconds(1)`. The handler checks it is still the current source, so one already queued when `cancel` runs in the same main turn still does nothing.

## Rules that apply

- `docs/architecture.md`, Concurrency: "No timers, no polling, no background loops: every input is a push... This is what keeps idle CPU at zero. Time passes only on Core Animation's clock, with these exceptions, each confined to one owner: a one-shot timer for an automatic update's idle minute, armed only while a verified update waits and nothing uses the app".
- `docs/architecture.md`, Concurrency: "State shared with that thread lives behind a `Mutex` with one writer." and "only recognised events hop to the main actor". The one new hop exists only while `sensesContact`.
- `docs/architecture.md`: "no per-frame clock read": contact reads no clock.
- `docs/architecture.md`, Concurrency: "the model, the ports and the public surface of every real adapter are `@MainActor`."
- `docs/architecture.md`, Shape: "`Launcher` knows nothing about updates." and "Every port has exactly two adapters".
- `docs/domain-model.md`, Automatic update: "A genuine update then waits until no finger has made contact of any kind with any trackpad for 1 minute and the settings window is closed, open, minimised or hidden alike: 1 minute after the later of the last touch and the window closing, and no sooner than 1 minute after the update was ready."

## Done when

- No new main-actor hop exists while `sensesContact` is off.
- Each lasting effect starts and stops in `enter`.
- `Updater` calls `armRestart` when the minute passes; the real one answers false, so the app stays running and installs at its next end.
- The app target builds: `xcodegen generate`, then `xcodebuild build -project TrackpadLauncher.xcodeproj -scheme TrackpadLauncher -configuration Debug -derivedDataPath build/dev -quiet -packageAuthorizationProvider netrc`.
- The quick gate, `Scripts/test.sh`, is green. It takes minutes: use a long Bash timeout (up to 600000 ms) or `run_in_background`.
