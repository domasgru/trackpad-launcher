# S5: Every release publishes a feed, or nothing

## Goal

`Scripts/release.sh` writes and publishes `appcast.xml`, the update list every automatic copy reads, or publishes nothing. It refuses a release with a bad build number, a mismatched update key or missing Sparkle tools before anything changes. A new release harness proves all of it in `swift test`, by running the real script in a throwaway repository with every outside tool stubbed.

## Requirements

- R4 (the feed): "A *newer version* MUST be a published full release, with a higher version than the running one, whose minimum macOS this Mac meets. When several count, Trackpad Launcher MUST take the highest."
- R7: "The release process MUST notarise every update. It MUST NOT publish one that is not notarised." Scenario: a build that fails notarisation means "nothing is published and no copy sees it".
- R16 (the release step): "Every new release MUST stay installable from the update card of versions before the first automatic-update version."

## Design

### `appcast.xml`

A committed file at the repository root on `main`, served from `raw.githubusercontent.com` at the address already in `project.yml`'s `SUFeedURL`. It starts as an empty channel, with `</channel>` on its own line:

```xml
<?xml version="1.0" encoding="utf-8"?>
<rss version="2.0" xmlns:sparkle="http://www.andymatuschak.org/xml-namespaces/sparkle">
<channel>
<title>Trackpad Launcher</title>
</channel>
</rss>
```

Each release adds one single-line item and keeps every older one, so an older Mac still finds the newest version it can run. It is rendered by the script, not by Sparkle's `generate_appcast`, and only the script writes it, so a pre-release can never appear. Withdrawing a release is one commit removing its item.

### `Scripts/release.sh`

```bash
FEED="$ROOT/appcast.xml"
SPARKLE_BIN="$ROOT/LauncherKit/.build/artifacts/sparkle/Sparkle/bin"

# In preflight_checkout: every credential is checked before anything changes.
(cd "$ROOT/LauncherKit" && swift package --disable-keychain resolve) || fail "cannot resolve the package."
[ -x "$SPARKLE_BIN/sign_update" ] || fail "Sparkle's tools are missing from the resolved package."
[ "$("$SPARKLE_BIN/generate_keys" -p)" = "$(sed -n 's/^ *SUPublicEDKey: *//p' "$ROOT/project.yml")" ] ||
  fail "the keychain's update key is not the one project.yml ships; import the backup with generate_keys -f."
xmllint --noout "$FEED" || fail "appcast.xml is not well-formed."

# Before preflight_version. A failed publish can leave a draft nothing sees, and it would block this retry.
[ "$(gh release view "v$(read_setting MARKETING_VERSION)" --repo "$REPOSITORY" --json isDraft --jq .isDraft 2>/dev/null)" != true ] ||
  gh release delete "v$(read_setting MARKETING_VERSION)" --repo "$REPOSITORY" --yes

# In preflight_version: the feed's highest and the previous tag's, so an empty feed cannot bypass the check.
preflight_build_number() {
  local build highest tag tagged
  build="$(read_setting CURRENT_PROJECT_VERSION)"
  highest="$(sed -n 's:.*<sparkle\:version>\([0-9]*\)</sparkle\:version>.*:\1:p' "$FEED" | sort -n | tail -1)"
  [ "$build" -gt "${highest:-0}" ] || fail "build $build is not above the feed's $highest; Sparkle would never offer it."
  tag="$(git -C "$ROOT" tag --list 'v*' | sort -V | tail -1)"
  tagged="$(git -C "$ROOT" show "$tag:Config/Version.xcconfig" | sed -n 's/^CURRENT_PROJECT_VERSION *= *//p')"
  [ "$build" -gt "${tagged:-0}" ] || fail "build $build is not above $tag's $tagged."
}

# In archive_and_check, strict mode: Sparkle's atomic swap needs Autoupdate and the update on one team.
codesign -dv "$copy/Contents/Frameworks/Sparkle.framework/Versions/B/Autoupdate" 2>&1 |
  grep -qx "TeamIdentifier=$TEAM_ID" || fail "Sparkle's installer is not signed by team $TEAM_ID."

# After the disk image is notarised: renders into $OUT, so a failure leaves the tree clean.
write_feed() {
  local attributes signature item plist="$APP/Contents/Info.plist" name
  name="$(basename "$AAR")"
  attributes="$("$SPARKLE_BIN/sign_update" "$AAR")" || fail "cannot sign the update with the update key."
  signature="$(sed -n 's/.*edSignature="\([^"]*\)".*/\1/p' <<<"$attributes")"
  "$SPARKLE_BIN/sign_update" --verify "$AAR" "$signature" || fail "the update's signature does not verify."
  item="<item><title>$EXPECTED_VERSION</title>"
  item+="<pubDate>$(LC_ALL=C date -u '+%a, %d %b %Y %H:%M:%S +0000')</pubDate>"
  item+="<sparkle:version>$(/usr/libexec/PlistBuddy -c 'Print :CFBundleVersion' "$plist")</sparkle:version>"
  item+="<sparkle:shortVersionString>$EXPECTED_VERSION</sparkle:shortVersionString>"
  item+="<sparkle:minimumSystemVersion>$(/usr/libexec/PlistBuddy -c 'Print :LSMinimumSystemVersion' "$plist")</sparkle:minimumSystemVersion>"
  item+="<enclosure url=\"https://github.com/$REPOSITORY/releases/download/v$EXPECTED_VERSION/$name\" $attributes type=\"application/octet-stream\"/></item>"
  # A version already in the feed is replaced, so --feed-only can run twice.
  awk -v item="$item" -v version="<title>$EXPECTED_VERSION</title>" \
    'index($0, version) { next } /<\/channel>/ { print item } { print }' "$FEED" > "$OUT/appcast.xml"
  xmllint --noout "$OUT/appcast.xml" || fail "the feed is not well-formed."
}

# Publishing: the asset exists before the feed names it.
gh release create "v$EXPECTED_VERSION" "$DMG" "$AAR" --repo "$REPOSITORY" --latest ...
publish_feed() {
  cp "$OUT/appcast.xml" "$FEED"
  git -C "$ROOT" add "$FEED" && git -C "$ROOT" commit --quiet -m "Feed $EXPECTED_VERSION" -- "$FEED" &&
    git -C "$ROOT" push --quiet origin HEAD:main ||
    fail "v$EXPECTED_VERSION is published but the feed is not; run release.sh --feed-only $EXPECTED_VERSION."
}
# --feed-only <version>: downloads the published .aar, unpacks it so $APP names the sealed plist, write_feed, publish_feed.
```

**Three corrections to that sketch, found while writing this brief. Build them; each has a test.**

1. `preflight_build_number`: with no `v*` tag, `git show ":Config/..."` fails and `set -e` plus `pipefail` ends the script. Guard: no tag means no previous-tag check.
2. `publish_feed`: a failed push leaves a local feed commit, so main is ahead of origin and `--feed-only`'s `preflight_checkout` would refuse ("main differs from origin"), which makes the retry the message names impossible. On a failed push, undo the local commit (`git reset --quiet --keep HEAD~1`), leaving the tree clean and the feed old, then fail with that message.
3. `publish_feed`: a second `--feed-only` in the same second can render a byte-identical file (ed25519 is deterministic), and `git commit` then fails with nothing to commit. If the rendered feed equals `$FEED`, publish nothing and succeed.

**`--feed-only <version>`:** parse it beside `--image-only` and `--archive-only`, and extend the usage line in `fail`. It runs `preflight_checkout`, sets `EXPECTED_VERSION`, `gh release download "v$version" --pattern '*.aar' --dir "$OUT" --repo "$REPOSITORY"`, sets `AAR`, unpacks it with `aa extract` into a temp folder so `APP` names `TrackpadLauncher.app` there, then `write_feed`, `publish_feed`. A version with no published release fails. Do not run the tests or a build. `$OUT` must exist.

**The order of a full release**, each step's failure leaving what the table says:

| Step, in order | Failure leaves |
|---|---|
| Preflight, now with the update key, Sparkle's tools and the feed | Nothing changed |
| Tests, bump, `preflight_version` with the build-number check | Version commit undone |
| Archive, export, notarise, staple, `stapler validate` (R7) | Undone. No `.aar` exists yet, so no feed item can exist. |
| `archive_and_check strict`, with `Autoupdate`'s team | Undone |
| `card-contract` on the stapled `.aar` (already in the script) | Undone |
| Image, sign, notarise, staple, Gatekeeper | Undone |
| `write_feed`, into `$OUT` | Undone; the tree is clean |
| Push the version commit | Nothing published; undone |
| `gh release create` | Main holds the version, nothing visible; run with no argument. A leftover draft is removed first. |
| `publish_feed` | Release public, feed not: cards see it, Sparkle copies do not yet. `--feed-only` finishes it. |

Put the feed's `xmllint`/tools/key checks in `preflight_checkout`, so `--feed-only` gets them too. The draft removal runs in the full release just before `preflight_version`. Do not rewrite `release.sh`'s header comment; the last slice does that. Add only the new usage line.

### The release harness

New test target `ReleaseTests` in `LauncherKit/Package.swift`, with no dependencies: `.testTarget(name: "ReleaseTests")`, under `Tests/ReleaseTests/`, with a `ReleaseHarness.swift` helper. Each test gets its own temp folder.

- **Repository.** A local bare `origin` with its own `main`, and a fresh clone built from real copies of the repo's `Scripts/release.sh`, `Scripts/test.sh`, `Scripts/release/dmg-background.png`, `Config/Version.xcconfig`, `project.yml`, `appcast.xml`, `.gitignore`, plus an empty `LauncherKit/`. Find them from `#filePath`. `project.yml` gets a `SUPublicEDKey` value of the throwaway public key unless a test wants otherwise. Git is hermetic: `GIT_CONFIG_GLOBAL=/dev/null`, a local identity, no signing. Set `RELEASE_OUT` to a folder in the temp dir.
- **Real tools:** `git`, `awk`, `sed`, `xmllint`, `aa`, `ditto`, `PlistBuddy`, `xattr`, and Sparkle's real `sign_update` from `LauncherKit/.build/artifacts/sparkle/Sparkle/bin` in the real repo.
- **Stubs**, shell scripts first on `PATH`, each logging its argv to one ordered file and failing on request (a pattern file or environment variable the harness sets): `gh`, `xcrun`, `xcodebuild`, `xcodegen`, `codesign`, `spctl`, `security`, `hdiutil`, `osascript`, `swift`.
  - `xcodebuild -exportArchive` creates `$OUT/export/Trackpad Launcher.app`: a directory bundle with an `Info.plist` holding `CFBundleShortVersionString`, `CFBundleVersion` (both read from the clone's `Config/Version.xcconfig`) and `LSMinimumSystemVersion` 26.0, a `Contents/MacOS` binary and `Contents/Frameworks/Sparkle.framework/Versions/B/Autoupdate`.
  - `codesign -dv` prints, to stderr, `Identifier=com.domasgru.TrackpadLauncherApp`, `TeamIdentifier=CQK27876UL`, `flags=0x10000(runtime)` and `Authority=Developer ID Application`; a test can make it answer another team for the `Autoupdate` path.
  - `xcrun` covers `notarytool submit`, `notarytool history` and `stapler staple|validate`, and must tell the app's submit (the `.zip`) from the image's (the `.dmg`).
  - `hdiutil` covers `info`, `create`, `attach` (a tab-separated line with a `/Volumes/...` path), `detach`, `convert` (which must create `-o`'s file). `osascript` answers `true`. `security find-identity` prints a `Developer ID Application` line.
  - `swift` handles `test`, `package ... resolve` and `run ... card-contract`.
  - `gh` handles `auth status`, `release list`, `release view`, `release create`, `release delete`, `release download` (copies the `.aar` that `release create` was given, so `--feed-only` reads a real archive).
- **`LauncherKit/.build/artifacts/sparkle/Sparkle/bin/` in the clone**: `sign_update`, a wrapper that passes a throwaway `--ed-key-file` to the real tool, and `generate_keys`, a stub that answers `-p` with the throwaway public key. Make the key with CryptoKit: `Curve25519.Signing.PrivateKey()`, `rawRepresentation.base64EncodedString()` for both halves. If `--verify` needs something other than `--ed-key-file` in the wrapper, handle it there.
- **Failing a push**: a real `pre-receive` hook in the bare origin, rejecting version pushes or feed pushes on request.

Nothing in the harness touches the real `origin`, keychain or GitHub. `release.sh`'s `REPOSITORY` constant is harmless because `gh` is a stub. `Process()` is fine here: the scan covers only `Sources` and the app target. Tests run real `release.sh` via `/bin/bash`.

`release.sh` runs `gh release list`; the harness's stub answers from what `release create` logged, so a second release sees the first. A real tag does not exist unless the harness makes one: T52's previous-tag row and any two-release test must create `v<version>` in the clone and origin after the first release, as GitHub would.

## Rules that apply

- `docs/architecture.md`, Distribution: "`appcast.xml`, committed at the repository's root and served by `raw.githubusercontent.com`, is the update list, a contract with every automatic copy; only the release command writes it, and each release adds an item and keeps the older ones."
- `docs/architecture.md`, Distribution: "The release command... checks every credential, the update key included, and that main is clean and equal to origin's, runs the tests, raises the version and the build number, builds, notarises and checks, and only then pushes the version commit and publishes the release, after it has uploaded both assets, and last commits the feed, so the feed never names an asset that does not exist yet; a failure before the push undoes the version commit, and a failure of the feed's push is finished by `--feed-only`. A release's version is above every earlier one's, and so is its build number, which is what Sparkle compares."
- `docs/architecture.md`, Distribution: "The same archive is Sparkle's download, signed with the update key, whose private half never enters the repository and cannot be rotated."
- `docs/architecture.md`, Distribution: "That asset name, the one bundle in it, `TrackpadLauncher.app`... are a contract"; a second matching `.aar` on a release is forbidden.
- GitHub immutable releases are on for this repository: assets cannot be added to a published release.
- Tests use Swift Testing. Do not commit: the orchestrator commits your work.
- Worktree guard: write each Bash command with literal arguments, no shell variables, `$(…)` or loops; create and edit files with Write and Edit; absolute paths. Shell syntax inside `release.sh` and in the stubs is fine.
