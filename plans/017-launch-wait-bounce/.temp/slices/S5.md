# S5: The tuner tries, previews and saves the bounce

## Goal

The animation tuner in Debug builds gains a Launch bounce section, with a control for each bounce knob and a Preview bounce button. The button bounces Finder's icon for 3 s, then floats it away. Tunings and presets save and load the bounce knobs, and an older preset keeps the shipped bounce. Release builds play the shipped bounce and show no tuner.

## Requirements

- **R17.** The bounce's feel cannot be pinned down in numbers up front, so the debug tuner lets it be tried live. Debug builds' animation tuner MUST have a launch bounce section. It MUST offer a control for each of: the jump height, the time up, the time down, the rest between bounces, the squash on landing (none by default), the resting gap above the pointer, the horizontal offset from the pointer, trailing behind the pointer (none by default), the gap between icons, and the fade out on a quiet end. Changes MUST apply to the next launch bounce. Release builds MUST play the shipped bounce and show no tuner. Scenario: tuner open, raise the jump height, make the gesture for a not-running app → its icon bounces higher.
- **R18.** The tuner's launch bounce section MUST have a preview button. It MUST bounce Finder's icon at the pointer for 3 seconds, then end it as a window showing would. Scenario: press the preview button → Finder's icon bounces above the pointer for 3 seconds, then floats away.
- **R19.** Tunings and presets MUST save and load the bounce knobs together with the existing ones. Scenario: a preset saved before the launch bounce existed → loading it gives the launch animation knobs the preset's values, and the bounce knobs keep the shipped values.

## Design

### `LaunchTuning.Bounce` tolerant decoding (Debug only, `LaunchTuning.swift`)

```swift
#if DEBUG
extension LaunchTuning.Bounce: Codable {
    /// Keys missing from an older save keep their shipped values: one `x = try value(.x, s.x)` line per field, as in
    /// `LaunchTuning`'s. `LaunchTuning.init(from:)` gains `bounce = try value(.bounce, s.bounce)` (R19).
    init(from decoder: any Decoder) throws
}
#endif
```

- Replace S2's plain synthesized `Codable` conformance on `Bounce` with this hand-written tolerant `init(from:)` (encoding stays synthesized), one line per field: `height`, `timeUp`, `timeDown`, `rest`, `squash`, `gap`, `offset`, `trailing`, `spacing`, `fadeOut`, `slide`, `pulseLow`, `pulsePeriod`.
- `LaunchTuning.init(from:)` gains `bounce = try value(.bounce, s.bounce)`.
- A forgotten decode line is not a compile error, so T27 catches it (encode-lessons-in-structure).

### `AnimationTuner` (Debug only, `AnimationTuner.swift`)

```swift
// AnimationTuner.init(preview:previewBounce:); its panel sets acceptsMouseMovedEvents (S4 did this).
// TunerView gains, before the presets:
// Section { one knob per Bounce field, e.g. knob("Jump height", \.bounce.height, 0...80, step: 1, unit: "pt");
//   Button("Preview bounce") { previewBounce() } } header: { Text("Launch bounce") }
//   footer: { Text("Applies from the next bounce. Preview bounces Finder's icon for 3 s, then floats it away.") }
```

- One `knob` per `Bounce` field, using the existing `knob` helper with nested key paths (`\.bounce.height` works with `WritableKeyPath<LaunchTuning, Double>`). Pick sensible ranges, steps, units and short hints in the style of the existing sections. At least R17's ten (height, time up, time down, rest, squash, gap, offset, trailing, spacing, fade out); include `slide`, `pulseLow`, `pulsePeriod` too, since they are knobs on the same struct.
- The preview closure: the tuner's existing "Preview at pointer" swaps the override, plays, and restores at once (`TunerModel.preview(_:play:)`); the bounce snapshots `LaunchTuning.current` when it starts, so a bounce preview through the same mechanism plays the live tuning. Follow the existing preview's wiring.
- Update the tuner's doc comment and window title if they say "launch animation" only, to cover the bounce.

### `WorkspaceActions.showAnimationTuner()` (Debug only)

```swift
tuner = AnimationTuner(
    preview: { [overlay] in overlay.play(for: finder) },
    previewBounce: { [bounces] in bounces.preview(finder, for: .seconds(3)) })   // then floats away, as a window would
```

As today's preview does, it bypasses the model. Its 3 s is the bounce's own deadline (`BounceOverlay.preview` starts a bounce with cap 3 s and ends it itself with `.launchAnimation` when the cap passes; S2 built it).

## Rules that apply

- `docs/architecture.md`, Concurrency: "Developer tools live in `#if DEBUG` and never ship. Today that is the launch animation tuner in `LauncherPlatform`: a SwiftUI window over `LaunchTuning`, whose defaults are the shipped launch animation and launch bounce." Every new tuner symbol and the bounce's `Codable` must be inside `#if DEBUG`; Release reads `LaunchTuning.shipped`.
- Source-scan bans under `LauncherKit/Sources` (comments and `#if DEBUG` included): `Timer`, `asyncAfter`, `Task.sleep`, logging, `.write(to:`, etc. The 3 s preview must use the bounce's own Core Animation deadline, never a timer.
- `docs/domain-model.md`, Launch bounce: "Debug builds' animation tuner can try other bounces and preview one with Finder's icon."
