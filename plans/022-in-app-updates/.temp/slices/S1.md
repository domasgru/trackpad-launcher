# S1: One atomic swap for the move and the update

## Goal

The administrator's swap into /Applications becomes one atomic exchange instead of two `mv`s, so a kill or restart at any instant leaves a whole copy at the destination. `ApplicationsInstaller.put(_:at:by:)` is extracted from today's `ApplicationsInstaller.copy` and becomes the one swap that the move uses today and that the in-app update (a later slice) will use. The move behaves exactly as today otherwise.

## Requirements

- **R13** (part): "Logging out, restarting and shutting down MUST still end Trackpad Launcher, leaving either the old or the new version whole in /Applications." Scenario: "**WHEN** the Mac restarts while the new version replaces the old one in /Applications **THEN** after the restart /Applications holds a whole Trackpad Launcher, either 1.0.0 or 1.1.0, that opens and works."
- **R12** (part): "Replacing the app fails: **GIVEN** the download of version 1.1.0 is genuine **WHEN** replacing the copy in /Applications fails, for example because the disk is full **THEN** /Applications still holds a whole version 1.0.0 ..."
- **R11** (part): "When the user's account cannot write to /Applications, the update MUST ask for an administrator's name and password, as the move dialog does." This slice makes the administrator path the update will share.

## Design

Files: `LauncherKit/Sources/LauncherPlatform/PrivilegedInstall.swift`, `ApplicationsInstaller.swift`, `BundleInstall.swift` (only if needed), tests in `LauncherKit/Tests/LauncherPlatformTests/`, and `LauncherKit/Tests/LauncherCoreTests/SourcePolicyTests.swift`.

```swift
extension ApplicationsInstaller {
    /// The move's and the update's one swap: `BundleInstall.swap` when /Applications and `destination` are writable,
    /// else `PrivilegedInstall.swap`, which shows the prompt. Atomic on both paths; `destination` untouched unless
    /// `.installed`. Extracted from today's `copy`, whose behaviour is otherwise unchanged.
    nonisolated static func put(_ staged: URL, at destination: URL, by administrator: any Administrator) -> InstallOutcome
}

enum PrivilegedInstall {  // the one script, now atomic, for the move and the update; the only file that may say osascript
    /// "$1" destination, "$2" staged, "$3" the exchange program; never interpolated. With something at the destination:
    /// Foundation's replaceItemAt as root, one exchange of the two directory entries; else one mv. The exit status
    /// matches what /Applications holds, and a kill at any instant leaves a whole copy there.
    static let script = """
        destination="$1"; staged="$2"; exchange="$3"
        if [ -e "$destination" ] || [ -L "$destination" ]; then
            /usr/bin/osascript -l JavaScript -e "$exchange" "$destination" "$staged" >/dev/null || exit 1
        else
            /bin/mv -- "$staged" "$destination" || exit 1
        fi
        exit 0
        """
    /// JXA: replaceItemAtURLWithItemAtURL…(argv[0], argv[1], no backup, options 0); throws on failure (exit ≠ 0).
    static let exchange: String
    /// Replaces today's swap(_:into:asideIn:by:): no aside copy any more.
    static func swap(_ staged: URL, into destination: URL, by administrator: any Administrator) -> InstallOutcome
    // .ran(0) → .installed; .ran(_) → .failed(reason: Copy.applicationsFolderNotChanged);
    // .cancelled → .cancelled; .failed → .failed(reason: Copy.cannotWriteToApplications)
}
```

Details and invariants:
- The administrator runs `/bin/sh -c script sh destination staged exchange` (the `Administrator` protocol is unchanged). The exchange program is passed as `$3`, never interpolated into the script; paths are never interpolated either.
- The JXA exchange: a probe of exactly this call is at `plans/022-in-app-updates/.temp/architect/grounding/probes/jxa-swap.sh` (output beside it). Its `run(argv)` **returns** "failed: …" on failure, which exits 0. The shipped `exchange` must instead `throw` on failure so `osascript` exits non-zero, and the script's status then matches what the destination holds. The probe also shows osascript segfaults on a missing destination, which is why the script uses one `mv` when nothing lies at the destination.
- The script no longer removes anything: no `/bin/rm`, no aside path, no "move back" branch.
- `put` decides the path: the in-process `BundleInstall.swap` when the destination's folder is writable and the destination (if present) is writable; otherwise `PrivilegedInstall.swap`. Today's `copy` checks `applications.path`; `put` has no `applications`, so check the destination's parent folder (for the move's direct-child destination these are the same; for a nested destination the parent is what a rename needs). On every outcome other than `.installed`, `put` discards the staged copy and its staging folder (`BundleInstall.discard`), and on `.installed` nothing of the staging folder remains either. So callers never clean up after `put`.
- `ApplicationsInstaller.copy` becomes: find the destination (unchanged), `BundleInstall.stage` (unchanged), then `put`. Its observable behaviour for the move stays as today.
- `put` must be `nonisolated` and callable off the main actor (it blocks on the administrator).
- `BundleInstall.swap` already does `replaceItemAt` (atomic rename, probed) or `moveItem` when nothing is there.

## Rules that apply

- `docs/architecture.md`, Privacy and permissions: "No files written other than: ... the app's own bundle copied into /Applications when the user chooses *Move to Applications*; a newer version, unpacked ... and swapped in when the user chooses *Update now*. The unprivileged file operations of both are confined to one file. The administrator's, one atomic exchange, are confined to the one script that runs them, in one more file. A source-scan test in `LauncherCoreTests` fails the build on any banned API; add to its list rather than adding prose."
- The source scan (`SourcePolicyTests.swift`) matches substrings per line, **comments included**. `copyItem(`, `moveItem(`, `replaceItemAt(`, `removeItem(` stay confined to `BundleInstall.swift`; `/bin/mv`, `AuthorizationExecuteWithPrivileges`, `AuthorizationCopyRights` to `PrivilegedInstall.swift`. Do not write those tokens in comments elsewhere. The JXA method name `replaceItemAtURLWithItemAtURL…` does not contain `replaceItemAt(`; keep it that way.
- No logging of any kind, no timers (`Timer` substring is banned in shipped sources), no `.write(to:` in shipped sources. Tests are not scanned.
- `docs/architecture.md`, Concurrency: "`LauncherCore` and `LauncherPlatform` are nonisolated by default; the model, the ports and the public surface of every real adapter are `@MainActor`." Swift 6 strict concurrency; no new warnings.
- Tests use Swift Testing (`@Test`, `#expect`), as the existing suites do.
