# S1: `HandMode` becomes `ThumbCorner`, two corners, nothing else changes

## Goal

A prefactor with no behaviour change. The domain type `HandMode` (`.right` = thumb top-left, `.left` = thumb top-right) is replaced by `ThumbCorner`, with only `topLeft` and `topRight` in this slice. The settings record keeps writing exactly the bytes it writes today, the model, recognizer, port, both adapters, the views and every test follow the rename, and the Debug build behaves exactly as before, the *Left thumb* / *Right thumb* segmented control included.

The repository root is `/Users/dominykasgrubys/code/trackpad-launcher/.claude/worktrees/028-thumb-corner-dropdown`; the Swift package is `LauncherKit/` under it. Work only there.

## Requirements

None delivered. This slice makes the later ones (four corners, a pop-up, bottom-corner geometry) a small change.

## Design

### The domain type (`LauncherKit/Sources/LauncherCore/HandMode.swift` → rename the file to `ThumbCorner.swift`)

```swift
/// The corner of the trackpad the thumb anchors in. One global setting; default `.topLeft`.
public enum ThumbCorner: Hashable, Sendable, CaseIterable {
    case topLeft
    case topRight
    // S2 adds bottomLeft, bottomRight, after these two, in this order.
}
```

- Cases in the settings pop-up's eventual order; `CaseIterable` in that order.
- Deliberately **not** `Codable` and **no raw value**: the saved shape is the settings record's concern alone (below), so nothing can persist the corner by accident under a value an older build would refuse.
- Its geometry queries are `package`/internal (not `public`), and are what the recognizer needs. In this slice, replace `HandMode`'s two queries with corner-phrased ones:
  - how far a normalised x lies from the corner's side edge, as a fraction of the width (`topLeft`: `x`; `topRight`: `1 - x`). This replaces `fractionFromThumbSideEdge`.
  - the palm band's "hand-side edge" is the side edge opposite the corner; express it as `1 -` the above, or a second small query, whichever reads best. S2 will add "is a bottom corner" and "fraction from the corner's top or bottom edge", so keep the shape open to that (S2's final set is three queries: `isBottom`, fraction from the side edge, fraction from the top/bottom edge; you may already add the y-query returning `y` for both top corners if it makes `AnchorCorner` read naturally, but that is optional).
- `HandMode` is deleted as a public type.

### The saved record (`LauncherKit/Sources/LauncherCore/Settings.swift`)

The record's decoding rule is unchanged: a missing key decodes as the default, an unknown key is ignored, a value that does not decode fails the whole record.

- The record keeps a **private** stored field under the key `handMode`, of a **private** wire enum (it may stay named `HandMode`, or e.g. `Side`; a grep for `HandMode` must find only this private wire type and its decoder) with `String` raw values `right` and `left` exactly as every version has written them. The value is the *hand*: `right` means the thumb is on the left side (`topLeft`), `left` means the thumb on the right side (`topRight`).
- `public var thumbCorner: ThumbCorner` is a computed property over that private field (get and set). Default is `.topLeft` (wire `right`).
- The record's synthesized `Encodable` is kept (so it still writes `handMode` = `right`/`left` and nothing new); the custom `init(from:)` reads the private field with `decodeIfPresent` like every other field. Make sure the private field's `CodingKeys` case is still `handMode` and the synthesized encoding still includes it (private stored properties are encoded by synthesis).
- S2 will add a second private field `isThumbAtBottom: Bool` under a new key; do not add it now.
- `Equatable` stays.

### The model (`LauncherKit/Sources/LauncherCore/Launcher.swift`)

- `public var handMode: HandMode` → `public var thumbCorner: ThumbCorner { settings.thumbCorner }`.
- `public func setHandMode(_:)` → `public func setThumbCorner(_ corner: ThumbCorner)`, same body shape (guard unchanged, set, save, reconcile).
- The reconcile's `Run` struct's `handMode` field → `corner: ThumbCorner`, compared as today, so a corner change re-runs the trackpads with fresh recognizers exactly as a hand-mode change does today.
- The doc comment "launch, hot-plug, wake, preference, hand-mode and trust changes" → "…, thumb corner and trust changes".

### The recognizer and geometry

- `GestureRecognizer.init(handMode:surface:slides:swaps:travel:)` → `init(corner: ThumbCorner, surface:slides:swaps:travel:)` (`LauncherCore/GestureRecognizer.swift`).
- `AnchorCorner` and `EdgeContacts` (`LauncherCore/Surface.swift`) take a `ThumbCorner` in place of the `HandMode`. Behaviour identical: anchor zone is `< 20%` of the width from the corner's side edge and `< 25%` of the height from the top; band is bottom edge anywhere, or the side edge opposite the corner below `edgeBandTop` (40%), each closer than 3 mm. Comments say "the side edge opposite the thumb corner" rather than "hand side" where that reads better; keep the domain term *hand-side edge* if you use it (the glossary now defines it as "the side edge opposite the thumb corner").

## Rules that apply

- `docs/architecture.md`, *Shape*: "Modules by ownership … `LauncherCore` (domain types, pure policy, ports, the models; imports Foundation and Observation only)". `ThumbCorner` lives in `LauncherCore`, imports Foundation only.
- `docs/architecture.md`, *Shape*: "Framework and wire types never cross a port … `UserDefaults` keys … stay inside adapters and views. External data is parsed into domain types at the adapter." The wire enum is private to `Settings`; only `ThumbCorner` is public.
- `docs/architecture.md`, *Shape*: "Every port has exactly two adapters: the real one in `LauncherPlatform` and an in-memory one in the tests." Both follow the port's rename.
- `docs/architecture.md`, *Concurrency*: "`LauncherCore` and `LauncherPlatform` are nonisolated by default; the model, the ports and the public surface of every real adapter are `@MainActor`." `ThumbCorner` is a nonisolated `Sendable` value type.
- `Settings.swift` doc comment, the record's decoding rule: "a key missing from the record decodes as that field's default; a key this build does not know is ignored; a key whose value does not decode fails the whole record." Keep it true.
- `docs/domain-model.md`, *Thumb corner*: "*Top left* (the default), *Top right*, *Bottom left* or *Bottom right* … One global setting. A change applies to the next thumb that lands and is saved at once". Only the two top cases exist in this slice.
- Tests use Swift Testing (`docs/architecture.md`, *Language, platform, toolchain*).
