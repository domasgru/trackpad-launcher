# S3: The bounce ends when the app's window shows

## Goal

When a launching app's first window shows, a splash screen included, its launch bounce ends within 50 ms with the launch animation, from wherever the icon is. Without Accessibility, a window made during launch still ends it (racily, through the window list), and a later one waits for the 2 s limit after finishing. A launching app that does not answer cannot stall gestures for longer than the messaging timeout.

The model side already handles `.windowShown` (S2: `LaunchBounce.next(after: .windowShown)` ends with `.launchAnimation`; the adapter plays the hand-off). This slice only makes `LaunchWatch` *notice* windows.

## Requirements

- **R9.** When a window of the launching app first shows on screen, on any display, the bounce MUST end within 50 milliseconds. A splash screen counts as a window. The icon MUST then play the launch animation, starting from wherever it is at that moment, even mid-jump. From then on it no longer follows the pointer. Two exceptions: without the Accessibility permission, or when the app does not answer Accessibility while it starts up, a window that shows only after the app finished starting up ends the bounce through R10's 2-second rule instead. Scenarios: window shows mid-jump → the icon floats away from that spot; splash screen → the bounce ends with the launch animation at the splash.
- **R16 (here).** A hung launching app cannot stall gestures: every Accessibility call is bounded by a short messaging timeout.

## Design

### `LaunchWatch` (in `LaunchWatch.swift`, built by S2 without the look): the one look at finishing

Full shape after this slice (S2 already has `report`, `process`, `observations`, `hasFinished`, `isStopped`, `opened`, `adopt`, `wentNowhere`, `stop`):

```swift
/// Watches one launch a gesture started, from macOS's answer to `openApplication` until `stop()`: the process's
/// finishing and ending by key-value observation, which macOS pushes for every kind of app, then one look at
/// its windows and, with Accessibility, its first window created later. Reports each fact at most once,
/// nothing after `stop()`, and holds nothing once stopped. Every AX call goes to the app element it creates, whose
/// messaging timeout it sets to `messagingTimeout` itself.
@MainActor final class LaunchWatch {
    static let messagingTimeout: Float = 0.2
    private var windowObserver: AXObserver?
    // ... S2's members

    /// Invalidates the observations and removes the window observer's run-loop source. Idempotent.
    func stop()

    private func finished(_ pid: pid_t) {
        // guard !isStopped, !hasFinished; hasFinished = true
        // report(.finishedLaunching); guard !isStopped                     // the report may end the bounce
        // element = AXUIElementCreateApplication(pid); AXUIElementSetMessagingTimeout(element, Self.messagingTimeout)
        // registration = AXObserverCreate(pid, callback) + AXObserverAddNotification(element,
        //     kAXWindowCreatedNotification, refcon: Unmanaged(self).passUnretained) mapped:
        //     .success -> .registered (source added to the main run loop), .apiDisabled -> .noAccess, else -> .notAnswering
        // axWindows = registration == .registered ? count of kAXWindowsAttribute on element : 0
        // switch Self.look(registration, axWindows:, listedWindows: Self.listedWindows(of: pid))
        //     .shown -> drop the observer; report(.windowShown) · .watching -> wait · .blind -> drop the observer
        // callback (C, main run loop): MainActor.assumeIsolated { guard !isStopped; drop the observer;
        //     report(.windowShown) }
    }

    /// The pid's windows on screen now in the window list, below the status-window level: a splash counts, a
    /// status-level helper does not. Needs no permission. Racy at finishing.
    nonisolated static func listedWindows(of pid: pid_t) -> Int

    enum Registration: Equatable { case registered, notAnswering, noAccess }
    enum Look: Equatable { case shown, watching, blind }

    /// One look at a launching app's windows when it finished launching. Pure.
    /// Any window, by either count: .shown · none and .registered: .watching · none otherwise: .blind
    nonisolated static func look(_ registration: Registration, axWindows: Int, listedWindows: Int) -> Look
}
```

Lifecycle rules (the plan's steps, verbatim where it matters):

- The first `isFinishedLaunching` reports `.finishedLaunching`, then takes **one look** at the windows:
  - It tries once to register an `AXObserver` for `kAXWindowCreatedNotification`. In every probe run, registration had become possible before this push arrived.
  - If registration succeeds, it counts the app's windows in `kAXWindowsAttribute`. A splash counts.
  - Whether or not registration succeeds, `LaunchWatch.listedWindows(of:)`, a static read like `FrontmostAppWindows`' own, counts the pid's on-screen window-list entries below the status-window level (`kCGStatusWindowLevel`). That read needs no permission and is warm (`FrontmostAppWindows` paid its first call at launch).
  - Every Accessibility call goes to the app element the watch creates, and the watch sets that element's messaging timeout to 0.2 s itself, so the bound does not depend on `FrontmostAppWindows` having set the process default first.
  - The pure `look` maps the outcome: any window → `.shown` → drop the observer and report `.windowShown`; registered with no window → `.watching` → the observer's callback reports `.windowShown`; otherwise `.blind` → nothing more; R10's limit ends the bounce.
- Without Accessibility, registration simply fails (`apiDisabled`). As in `FrontmostAppWindows`, which treats any failed call as "no windows", **nothing checks trust first**, so the trust check never leaves `SystemPermissions.swift` (`AXIsProcessTrusted` is confined there by the source scan). The window-list read still catches a window made during launch; that catch is racy (one probe run listed the window 0.6 ms after `didLaunch`).
- **Nothing retries**, so the polling ban holds as written. (Accepted by the human: no AX retry.)
- `stop()` invalidates the KVO **and removes the observer's run-loop source**. Each report is the watch's last act, and a guard checks `isStopped` after it, so a report that ends the bounce re-entrantly is safe. The observer's callback also drops the observer once it has reported. Once no bounce is live, nothing observes anything.
- The AX observer callback is a C function pointer; it must not capture context. Pass `self` as refcon with `Unmanaged.passUnretained`; the watch outlives its observer because `stop()`/drop removes the source before the watch goes. Mind the source-scan ban on the substring `perform: {` (a run-loop source's perform must be a file-scope constant) and on `nonisolated(unsafe)`. Look at how `ClickTap.swift` and `FrontmostAppWindows.swift` handle C callbacks and AX elements.
- The source scan: `AXUIElement` and `CGWindowList` are confined today to `FrontmostAppWindows.swift`. Add `LaunchWatch.swift` to both entries' sets (`Confined.onlyIn` is a `Set<String>` since S1), with a rule text such as "the window reads have two readers".
- Probed facts (`plans/017-launch-wait-bounce/.temp/architect/grounding/index.md` F15–F19, `how-lifecycle.md`): windows made before or at finishing come on screen within ~1 ms of the finishing push; `AXObserverAddNotification` fails with `kAXErrorCannotComplete` until about finishing, then succeeds; a one-shot `kAXWindowsAttribute` read right after registering returned 1 whenever a window had been made during launch; for a later window, `kAXWindowCreatedNotification` arrives 1–9 ms before it is on screen. Probe source: `.../grounding/probes/p1-lifecycle.swift`.

## Rules that apply

- `docs/architecture.md`, Privacy: "Accessibility, asked for on first launch, is used only to … and to notice the first window of an app a gesture is launching, while its launch bounce shows." "… a launch bounce whose app's window shows only after the app finished launching ends 2 s after it finished rather than when that window shows" (without Accessibility). "The permission checks and their TCC push … are each confined to one file by the source-scan test; the Accessibility element API with the window list to two (the frontmost app's window read and the launch bounce's launch watch)". The code must match: AX is used only for this window notice, only while a bounce lives.
- `docs/architecture.md`, Concurrency: "No timers, no polling, no background loops: every input is a push (… only while a launch bounce shows, its launch's progress (`openApplication`'s answer, KVO on the launched process, an Accessibility window observer) …)." No retry, no polling of the window list.
- `docs/architecture.md`, Concurrency: Accessibility calls are "synchronous calls into another app, about a millisecond each, each bounded by a short messaging timeout".
- `docs/architecture.md`, Shape: "Framework and wire types never cross a port". `AXError`, `AXObserver`, `pid_t` stay inside `LaunchWatch`; the port only sees `LaunchProgress`.
- Source-scan bans under `LauncherKit/Sources` (comments included): `Timer`, `asyncAfter`, `Task.sleep`, `makeTimerSource`, `displayLink`, `DisplayLink`, `perform: {`, `nonisolated(unsafe)`, `AXUIElementSetAttributeValue`, `kAXPressAction`, any logging.
- `docs/domain-model.md`, Launch bounce: "A bounce ends with the launch animation, played from wherever the icon is, when a window of the app first shows (a splash screen counts) … Without the Accessibility permission, a window that shows after the app finished starting up ends its bounce only 2 seconds after it finished."

Notes for the platform rows:
- "Trusted" rows need the test process to be trusted for Accessibility, which this terminal is. Guard them so they are skipped (not failed) when `AXIsProcessTrusted()` is false (tests may call it; the scan covers only `Sources`).
- "First on screen" is an independent read: the probe's first on-screen window from the window list (`CGWindowListCopyWindowInfo`), polled every 2 ms **off the main actor**, in the test only, as the architect's P1 probe measured. Polling is fine in tests; never in `Sources`.
- For T47, the system default messaging timeout is reset by `AXUIElementSetMessagingTimeout(AXUIElementCreateSystemWide(), 0)` (0 = system default) and restored to 0.2 afterwards.
- No system alert may appear on the user's screen: construct `WorkspaceActions` with `promptsUser: false`, and set `promptsUserIfNeeded = false` on any `NSWorkspace.OpenConfiguration` a test uses itself.
- Put the rows in S2's serialized `LaunchBounceAdapterTests` suite (or a sibling serialized suite) using S1's `ProbeBundles` and S2's recording driver.
