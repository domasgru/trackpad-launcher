## Goal

After an in-app update the new version stays running with its window open, instead of being force-quit by loginwindow 3 s after the old one ends. The bundle stops declaring `NSSupportsSuddenTermination` (removed from `project.yml`), and a `SourcePolicyTests` manifest policy plus a Swift-source ban fail the build if the key or the run-time route comes back.

Root cause: the old version opens the new one with `NSWorkspace.openApplication`, so LaunchServices records the new process as a child of the old. When a foreground-type app dies, loginwindow looks through its children for non-visible terminatable apps. The new version at that instant is a UI element (`LSUIElement`) with no visible window and declares sudden termination, so loginwindow force-quits it 3 s later.

## Requirements

- **R1.** Trackpad Launcher MUST NOT declare sudden termination: `NSSupportsSuddenTermination` MUST NOT be in its Info.plist, so that loginwindow never counts a copy as a terminatable child of the copy that opened it. This MUST hold for the first update onto the fix, from a version that still declares it.
- **R2.** Every way the process ends MUST keep its documented behaviour, and logout, restart and shutdown MUST NOT be held up by the app. `Lifecycle` does not change: the code reading is done, and the existing suite must stay green with no quit test edited.
- **R3.** A test MUST fail if `project.yml`, the source of the Info.plist, declares `NSSupportsSuddenTermination`, naming why. The repo's way of keeping a promise like this is `SourcePolicyTests`, which fails the build instead of relying on prose. It MUST also fail if any source enables sudden termination at run time (`ProcessInfo.enableSuddenTermination`), which has the key's effect without the key.
- **R4.** `docs/architecture.md` MUST state the rule and its reason where it describes the update. Already written; verify only.

## Design

**`project.yml`.** Delete the line `        NSSupportsSuddenTermination: true` (line 40, under `info.properties`). The key is absent, not `false`. Add no comment: the scan matches the key's name on any line, a comment's included, and the reason lives in the test's rule text and the architecture doc. `TrackpadLauncher/Info.plist` and `TrackpadLauncher.xcodeproj` are git-ignored and generated from `project.yml` by `xcodegen generate`. Nothing else in production changes: `Lifecycle`, `QuitSignals`, `SystemRunningCopies`, the ports, the adapters and the shell are untouched.

**`LauncherKit/Tests/LauncherCoreTests/SourcePolicyTests.swift`**, the only test file changed:

1. A manifest policy, the new piece: a small list of Info.plist keys the bundle must never declare, with their rule, one entry today, `NSSupportsSuddenTermination`. The rule states the mechanism: loginwindow force-quits, 3 s after a foreground app ends, every child of it that is a UI element without a visible window and declares sudden termination; the new version is that child for its first moments. A parameterised test scans `project.yml`'s lines for each key and reports hits as `project.yml:<line>: <key>`, the scanner's `<file>:<line>: <token>` shape. Reuse the existing `Entry` type if it fits.
2. `project.yml` sits one level above the package root, beside the app-target directory: reach it with the same path arithmetic as `scannedRoots` (`packageRoot.deletingLastPathComponent()`). The scan takes the directory holding the manifest, so the self-checks can point it at a temporary directory.
3. A missing `project.yml` is a failure, not a skip: the scan throws. `scannedRoots` filters on existence; the manifest must not, or a moved or renamed manifest voids the check silently.
4. `banned` gains `Entry(token: "SuddenTermination", rule: ...)`, with the same rule text as the manifest entry; hold that text once. `enableSuddenTermination()` enables sudden termination at run time even without the key; `disableSuddenTermination()` is pointless without the key and a sign someone believes it is on. Both match the token.
5. The suite's header comment, which says it scans every Swift source file, widens to name the manifest. No existing test function changes. Sharing the line-matching between the existing private `scan` and the manifest scan is fine and preferred to copying it, since a helper is not a test function.

Follow the file's style for self-checks: temporary directory, `defer` removal, see `scannerFindsAPlantedHit`.
