# S1: Sparkle in the build

## Goal

`LauncherPlatform` links Sparkle 2.10.1, pinned to that exact version, and every way of building the repo resolves it without SwiftPM's keychain stall. Nothing calls Sparkle yet: no `import Sparkle` is added anywhere in this slice. The app builds with Sparkle embedded and the existing suite stays green.

## Requirements

None directly. Every later slice of the automatic-updates feature needs this one.

## Design

The branch is already rebased onto `origin/main` (done for you; do not rebase, fetch-and-merge or touch git history). Do not commit: the orchestrator commits your work.

Change these files, and only these unless a build path turns up that this list misses:

- `LauncherKit/Package.swift`: add the package-level dependency `.package(url: "https://github.com/sparkle-project/Sparkle", exact: "2.10.1")`, and add `.product(name: "Sparkle", package: "Sparkle")` to the `LauncherPlatform` target's dependencies. Not the app target, and not a new fourth library target: the adapter must stay inside `swift test`. `project.yml` is unchanged in this slice; the app embeds Sparkle automatically through `LauncherPlatform`.
- `LauncherKit/Package.resolved`: created by resolving, and committed. It is not gitignored, and `Scripts/release.sh` refuses a dirty tree, so the file must be stable: running the tests and building must leave `git status` clean.
- `Scripts/test.sh`: `exec swift test --disable-keychain "$@"`.
- Every `xcodebuild` that resolves packages passes `-packageAuthorizationProvider netrc`: the `Makefile`'s `run` target, `Scripts/perf/build.sh`, and `Scripts/release.sh`'s `xcodebuild archive`. Add it to `xcodebuild -exportArchive` in `release.sh` too. Grep the repo's `Scripts/` and `Makefile` for `xcodebuild` and `swift ` so none is missed, `Scripts/make-update-fixtures.sh` included.

**Why (the keychain stall).** SwiftPM's binary-artifact download touches the keychain: the first plain `swift test` after adding Sparkle blocked about 8 minutes in `SecItemCopyMatching`, probably on a dialog nobody could see. `xcodebuild -packageAuthorizationProvider netrc` finished. A cold `--disable-keychain` has never been proven, because the artifact now sits in this Mac's shared cache; that is why this slice proves it once.

**The cold-path proof.** Run once, with a scratch cache and scratch build path so the shared cache cannot hide the stall, and with a time limit so a stall cannot hang you:

```
swift package --package-path LauncherKit --disable-keychain --cache-path <scratch>/cache --scratch-path <scratch>/build resolve
```

with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`, and a `swift build` with the same flags after it so the binary artifact is really fetched and linked. Use `run_in_background` for it or a Bash timeout under 10 minutes. Put `<scratch>` in a fresh empty folder under `/tmp`, and delete it afterwards.

**The fallback.** If the cold path still blocks, take the vendored fallback: a `.binaryTarget(path:)` for Sparkle's XCFramework plus its command-line tools (`sign_update`, `generate_keys`), checked in, instead of the remote package. The interface every later slice sees does not change. Say plainly in your report that you took it, and why. Later slices expect Sparkle's tools at `LauncherKit/.build/artifacts/sparkle/Sparkle/bin`; if the fallback moves them, say where they are.

Nothing else: no Info.plist keys (a later slice adds them), no source using Sparkle, no scan-table changes unless the existing suite fails without one.

## Rules that apply

- `docs/architecture.md`, Language, platform, toolchain: "a local SwiftPM package holds every library and test target, Sparkle pinned to one exact version beside them; an xcodegen-generated Xcode project, written from `project.yml`, the one tracked source of the Info.plist, builds only the app bundle". So the dependency lives in `Package.swift`, not `project.yml`.
- `docs/architecture.md`, Shape: "`LauncherCore` (domain types, pure policy, ports, the models; imports Foundation and Observation only)". Sparkle goes on `LauncherPlatform` only; `LauncherCore` and `LauncherUI` stay free of it.
- `docs/architecture.md`, Distribution: "hardened runtime, no entitlements... Never sign with `--deep`; the main executable is signed last, and the export re-signs Sparkle's nested helpers." Add no signing flags and no entitlements. The bundle must keep building with the hardened runtime.
- `docs/architecture.md`, Shape: "The bundle never declares `NSSupportsSuddenTermination`, and no code enables sudden termination." Do not touch the Info.plist.
- The worktree guard: write each Bash command with literal arguments, no shell variables, `$(…)` or loops in your own commands, and create and edit files with Write and Edit. Absolute paths; do not `cd` to the main checkout. The scripts you edit may of course keep their own shell syntax.

- The quick gate, `Scripts/test.sh`, is green. It outlasts a short timeout, so use a long Bash timeout (up to 600000 ms) or `run_in_background`.
