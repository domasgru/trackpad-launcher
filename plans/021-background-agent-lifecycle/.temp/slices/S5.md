# S5: Opened outside /Applications, it moves itself there

Worktree: `/Users/dominykasgrubys/code/trackpad-launcher/.claude/worktrees/021-background-agent-lifecycle` (branch `feature/021-background-agent-lifecycle`). Swift package in `LauncherKit/`. Do not commit; the orchestrator commits your work.

Background (optional reading): `plans/021-background-agent-lifecycle/.temp/architect/grounding/index.md` Q6 (F31-F38), and `grounding/sources/letsmove-PFMoveApplication.m` (a reference move-to-Applications flow; ours differs where noted below).

## Goal

A release copy opened by hand anywhere outside /Applications shows only the move dialog. *Quit* stops it with nothing changed. *Move to Applications* copies it into /Applications, replacing any copy already there; it then hands starting at login over, removes the original when it can, and stops every other copy; last, it opens the installed copy, which does its first run or opens its window. A failure before /Applications changes shows the reason and Quit. A login start and a development build never ask.

Not in this slice (S6): the administrator prompt (an account that cannot write to /Applications), detecting the disk image a copy lies on, and ejecting it.

## Requirements

- **R18.** When the user opens Trackpad Launcher by hand from anywhere outside /Applications, it MUST first show a dialog saying it needs to be in the Applications folder, with *Move to Applications* (default) and *Quit*. ~/Applications counts as outside. Until the user answers, a copy opened this way MUST NOT start recognising gestures, ask for a permission, register for login or open the settings window. *Quit* MUST stop it with nothing changed. A release build opened by hand MUST NOT keep running from outside /Applications. R22 and R23 are the exceptions.
  - Opened straight from the disk image → the move dialog shows, and nothing else of Trackpad Launcher does.
  - Never run on this Mac, opened from ~/Downloads, *Quit* → it stops, nothing is copied, and no login item, permission prompt or settings exists afterwards that was not there before.
  - A copy in /Applications is running, the user opens another copy from ~/Downloads → the move dialog shows, and the running copy keeps recognising gestures while it does.
  - A copy in ~/Applications/Tools started at login (R22) and runs in the background; the user opens that copy by hand → the move dialog shows, and gestures keep working while it does; *Move to Applications* then installs it into /Applications as R19 and R20 say, and *Quit* stops it.
- **R19 (except ejecting the disk image).** *Move to Applications* MUST put the app in /Applications and open it from there, which goes on to its first run (R5) or opens its settings window. The copy the user opened MUST be removed from where it was. If it cannot be removed, for example on a read-only network share, the move MUST still complete and leave the original where it was. A copy on a disk image stays there.
  - From ~/Downloads for the first time → /Applications holds Trackpad Launcher, ~/Downloads no longer does, and the settings window opens with macOS asking for the Accessibility permission.
- **R20.** When /Applications already holds Trackpad Launcher, *Move to Applications* MUST stop it if it is running, replace it with the copy being moved, and open the new one with its settings window open. The copy being moved MUST replace the one in /Applications whatever their versions. Every setting MUST be kept, including the assignments and starting at login.
  - An older version runs from /Applications with Arc on the 1-finger gesture and Left thumb; the user opens a newer version from its disk image and presses *Move to Applications* → one Trackpad Launcher runs, the newer version, its settings window shows Arc and Left thumb, and a 1-finger gesture brings Arc to front.
- **R22.** A Trackpad Launcher that starts at login MUST NOT show the move dialog, wherever it lies. It MUST run silently (R9).
- **R23.** A development build (not signed for release, e.g. run from Xcode) MUST NOT show the move dialog. It MUST run where it was built.

## Design

### The route table, complete

| Opening | Placement | Older copy runs | Route |
|---|---|---|---|
| at login | any | yes | `end` |
| at login | any | no | `runSilently` (R9, R22) |
| by hand | `installed` or `development` | any | `runWithWindow`, after stopping every other copy |
| by hand | `elsewhere` | any | `askToMove` (R18) |

A reopen uses the same table (`olderCopyRuns: false`): `runWithWindow` raises the window, `askToMove` shows the dialog over a running resident (R18, last scenario), `runSilently` does nothing.

    case runSilently, runWithWindow, askToMove, end
    public init(_ opening: Opening, placement: Placement, olderCopyRuns: Bool)
}

### New Core values (`Lifecycle.swift`)

```swift
public enum MoveDialog: Equatable, Sendable {
    /// "Trackpad Launcher needs to be in the Applications folder": Move to Applications (default), Quit.
    case asking
    /// The move failed before /Applications changed: the reason, and Quit.
    case failed(reason: String)
}
public enum MoveAnswer: Sendable { case move, quit }
public enum InstallOutcome: Equatable, Sendable { case installed, cancelled, failed(reason: String) }

/// Putting this copy into /Applications. Real: ApplicationsInstaller. Test: InMemoryInstaller.
@MainActor public protocol Installer: AnyObject {
    /// Copies this copy into /Applications, replacing any Trackpad Launcher there whatever its version. Nothing there
    /// changes unless the outcome is `.installed`, and never a mix of two copies. Unprivileged, the replace is one
    /// atomic step. `done` runs once, on the main actor. The copy can block; a test holds `done`.
    /// (S6 adds: asking for an administrator's name and password the way Finder does when this user cannot write
    /// there, and that path's two-rename gap.)
    func install(then done: @escaping @MainActor (InstallOutcome) -> Void)
    /// Removes the copy the user opened (its original place when translocated), unless it is on a disk image or is the
    /// installed copy itself. A failure (a read-only share) leaves it there (R19).
    func removeOriginal()
    /// Opens the installed copy as by hand. (S6 adds passing the disk image to eject, and `eject(_:)`.)
    func openInstalledCopy()
}
```

**The move is ordered for convergence**, pinned by tests:
1. `installer.install`: stage a copy in a temporary folder on the /Applications volume, clear its quarantine, then swap it in. That swap is the first change anywhere. Unprivileged it is one atomic replace. Failure → the failure dialog.
2. `startAtLogin.suspend()`: the login item is handed over before the original can go, so a crash leaves it owed, never lost. (The installed copy's next opening by hand `resume()`s it.)
3. `installer.removeOriginal()`: unless it is on a disk image; a failure leaves it.
4. Stop every other copy, the one that ran from /Applications included (R20), so the next open starts a fresh process.
5. `installer.openInstalledCopy()`.
6. End. The installed copy is an opening by hand: first run (R5) or `resume()`.

A logout during the move ends the process (`shouldEnd(.system)` is true while moving); the order is what keeps that safe: before the swap nothing has changed, after it the installed copy is whole and the next opening by hand converges.

### `ApplicationsInstaller` (LauncherPlatform, new `ApplicationsInstaller.swift`) and `BundleInstall` (new `BundleInstall.swift`)

```swift
// The Installer adapter. Owns one install: the order below, off the main actor in a concurrent function
// (`@concurrent`/detached work); only `done` hops back to the main actor. Every file operation goes through BundleInstall.
@MainActor public final class ApplicationsInstaller: Installer {
    public convenience init(location: Location)                 // /Applications
    /// Tests: a temp dir for /Applications. (S6 adds `administrator:`.)
    init(location: Location, applications: URL)

    public func install(then done: @escaping @MainActor (InstallOutcome) -> Void) {
        // 1. destination = the bundle with this app's bundle identifier already directly inside `applications`
        //    (any name, e.g. "Trackpad Launcher Old.app"), if any, else `applications`/<location.original's last component>.
        //    The bundle identifier is read from location.running's Info.plist.
        // 2. staged = BundleInstall.stage(location.running, near: destination): a copy in the item-replacement
        //    directory of the /Applications volume (FileManager.url(for: .itemReplacementDirectory, in: .userDomainMask,
        //    appropriateFor: destination, create: true)), with quarantine cleared on every item (an unquarantined copy is
        //    never translocated); an unreadable source → .failed before anything else.
        // 3. if `applications` or destination is not writable by this user → (S6: the administrator path); in this slice
        //    discard the staged copy and return .failed(reason:) with a plain reason.
        //    else BundleInstall.swap(staged, into: destination): one atomic replace (replaceItemAt), or a move when there
        //    is none.
        // 4. any error before the swap → BundleInstall.discard(staged); .failed(localizedDescription), destination untouched.
    }
    /// BundleInstall.removeOriginal(location.original), unless location.diskImage != nil or it is the destination.
    public func removeOriginal()
    /// NSWorkspace.openApplication(at: destination, configuration: activates = true). (S6 adds the eject argument.)
    public func openInstalledCopy()
}
```

## Rules that apply

- `docs/architecture.md` § Privacy: "No network code of any kind, no logging of any kind …, no files written other than settings in `UserDefaults`, and the app's own bundle copied into /Applications when the user chooses *Move to Applications*; every file operation of that move is confined to one file. A source-scan test in `LauncherCoreTests` fails the build on any banned API; add to its list rather than adding prose."
- § Shape: "`LauncherCore` … imports Foundation and Observation only." "Framework and wire types never cross a port … External data is parsed into domain types at the adapter." "Every port has exactly two adapters: the real one in `LauncherPlatform` and an in-memory one in the tests. Concrete types that can be pointed at a temp directory … are not put behind a port, unless they deliver asynchronously: those sit behind a port so the model's tests stay synchronous." (`Installer` delivers asynchronously → a port; `BundleInstall` is tested directly over temp dirs.)
- § Shape lists Security (the code signature, Authorization, two private translocation functions) among `LauncherPlatform`'s frameworks: translocation via `dlsym`, no link flags.
- § Concurrency: "Work that would delay a click … runs off the main actor in explicitly concurrent functions …; only its results hop back." The copy runs off the main actor. "No timers, no polling …: every input is a push (… the move's install … completions …)."
- § Shape: "`LauncherUI` (the settings window shell, the move dialog and SwiftUI views …)".
- Domain model, *Move dialog*: "The dialog a release build opened by hand outside /Applications shows before anything else: Trackpad Launcher needs to be in the Applications folder, with *Move to Applications* (the default) and *Quit*. ~/Applications counts as outside. Until it is answered, the copy recognises no gesture, asks for no permission, does not register for login and opens no settings window; a copy already running elsewhere keeps its gestures. *Quit*, or cancelling the administrator prompt, stops it with nothing changed. *Move to Applications* puts the copy in /Applications, replacing and stopping any copy there whatever its version, …; it keeps every setting and starting at login as it was, removes the opened copy where it can (a copy on a disk image stays, …), and opens the installed copy. A login start never shows it."
- The move must not spend the first run in the copy about to move: the mover never saves a `settings` record and never registers.
- Core doc comments never spell a confined API name (`SecTranslocate`, `runModal`, `removeItem(` …).
