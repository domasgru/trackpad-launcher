# S5: The stacks rise into place

## Goal

Each window stack rises out from behind its icon, nearest copy first. It does this once per swipe, as soon as its count is known. With Reduce motion on, the stack shows in place instead.

Repo background: this is a macOS trackpad launcher, a SwiftPM package in `LauncherKit/`. `LauncherCore` holds the pure model, `LauncherPlatform` the adapters, and `LauncherUI` the AppKit shell.

## Requirements

**R6. A stack rises into place.**

> When a stack appears, its copies MUST start exactly behind the front icon, at the same height, and rise to their places. The rise MUST take about 0.3 s with a soft ease-out, each copy starting about 40 ms after the one in front of it. A stack MUST rise once per swipe, never again while the selection moves. With macOS's *Reduce motion* setting on, the copies MUST appear in place without moving.

Its scenarios:
- **Rise on showing.** Given Safari has three windows, when the switcher appears, then Safari's two copies rise out from behind its icon, the nearer one first, and come to rest within about half a second.
- **Moving the selection replays nothing.** When the user slides the selection on and off Safari, Safari's stack stays where it is.
- **Reduce motion.** Given *Reduce motion* is on, when the switcher appears, every stack shows in place at once.

R4 also applies here: the switcher "MUST NOT wait for any window count", and a stack "MUST appear as soon as the count is known".

## Design

### `WindowStackLayout` (LauncherCore, `SwitcherRowLayout.swift`): rise timing

Add the rise timing that S4 left out:

```swift
/// The rise (R6): seconds, the delay between neighbouring copies, and a soft ease-out as cubic Bézier control points.
public static let riseDuration = 0.3
public static let riseStagger = 0.04
public static let riseCurve: (Double, Double, Double, Double) = (0.25, 1.0, 0.5, 1.0)

public struct Copy: Equatable, Sendable {
    public let side: Double
    public let rise: Double
    /// Seconds after the stack appears that this copy starts rising: `riseStagger × k`, the nearest first.
    public let delay: Double
}
```

A tuple is not `Equatable`. If that makes `WindowStackLayout`'s `Equatable` conformance awkward, keep the curve as a static. It is already static, so this should not bite.

### `SwitcherPanel.addStack(at:copies:rises:)` (LauncherUI)

```swift
/// Inserts `copies` behind the slot's icon, sharing its image, at rest. With `rises`, each copy's `position.y`
/// animates from the icon's centre (`WindowStackLayout`'s duration, curve and delay as `beginTime`, backwards fill),
/// keyed "rise", removed on completion. Without it, the copies are in place at once (Reduce motion).
func addStack(at slot: Int, copies: [WindowStackLayout.Copy], rises: Bool)
```

With `rises` set, each copy gets a `CABasicAnimation` on `position.y`:
- **Values:** `fromValue` is the icon's centre in the container; `toValue` is the copy's place at rest. The layer's model value is set to rest.
- **Timing:** `duration` is `riseDuration`, and `timingFunction` is `CAMediaTimingFunction(controlPoints:)` from `riseCurve`.
- **Delay:** `beginTime = layer.convertTime(CACurrentMediaTime(), from: nil) + delay`, with `fillMode = .backwards`, so a waiting copy hides behind the icon.
- **Key:** `"rise"`.
- **Cleanup:** `isRemovedOnCompletion` stays true, so the animation leaves nothing behind.

Selection moves write only the container's `transform`. They never replay or cut a rise.

### `SwitcherPresenter.render` (LauncherUI)

S1 already built the presenter with `init(reduceMotion:)`. S4 added `laidOutSerial` and `shownStacks`, and adds a stack when a slot goes from `.pending` to `.stack`. Now pass `rises: !reduceMotion()`:

```swift
panel.addStack(at: slot, copies: stackLayout.copies(of: windows), rises: !reduceMotion())   // once per swipe (R6)
```

For T19, a bench must be able to build the presenter with no `Launcher`, never call `observe`, and read the panel's layers back. S3 did the same for `WindowSwitcherPresenter`: the panel became non-`final` and the presenter takes an optional `panel:`, so a test subclass skips ordering on screen. Do the same for `SwitcherPresenter` and `SwitcherPanel` if needed.

## Rules that apply

- **architecture.md, Concurrency:** "Animation is Core Animation keyframes, which the render server plays. Whatever an animation leaves behind is cleaned up from its completion callback. … No code of ours runs per display frame, and display links are banned along with timers." The stagger is `beginTime`, not a timer. `asyncAfter`, `Timer` and `Task.sleep` are banned in Sources by `SourcePolicyTests`.
- **architecture.md, Shape:** "Policy lives in pure functions and value types; the shell stays thin." The numbers live in `WindowStackLayout`, and the panel only applies them.
- **domain-model.md, Window stack:** "A stack rises out from behind its icon once per swipe, as soon as its count is known, the nearer copy first, over about 0.3 s; with the system's Reduce motion setting on it shows in place."

## Tests

**T17 (R6), Core value.**
- The rise from `WindowStackLayout`: the copies' delays are 0, 0.04 and 0.08 s, nearest first.
- The duration is 0.3 s, so the last copy is at rest by 0.38 s.
- The curve is an ease-out: its first control point lies above the diagonal, and its second is at y = 1.
- Source: R6's literals: about 0.3 s, about 40 ms, the nearer one first, at rest within about half a second, a soft ease-out.

**T18 (R6), panel bench (`LauncherUITests`; extend S4's `SwitcherStackTests.swift`).**
- `addStack(at: 1, copies:, rises: true)`:
  - Each copy has one animation, keyed "rise", on `position.y`.
  - It runs from the icon's centre to the copy's place at rest, takes 0.3 s and fills backwards.
  - The copies' begin times are 0.04 s apart, nearest first.
- Then `show(position:selected:animatesSize: true)` on each slot in turn:
  - Every copy's "rise" stays the same object.
  - No animation is added to any copy.
- `addStack(rises: false)` places the copies at rest with no animation.
- Source: R6 "start exactly behind the front icon, at the same height", "never again while the selection moves", and Reduce motion's copies "in place without moving".

**T19 (R6, R4), presenter bench.**
- Setup: a `SwitcherPresenter(reduceMotion:)`, never `observe`d. With Reduce motion off, `render(_:)` is fed four values in turn:
  1. serial 1, with stacks `.stack` of 3, `.pending`, `.alone`;
  2. serial 1, with slot 1 now `.stack` of 2 and the selection on slot 1;
  3. serial 1, with the selection on slot 2;
  4. serial 2, with no nil render between, and slot 0 `.stack` of 3.
- Expected:
  - Render 1 lays out the row, and only slot 0 rises.
  - Render 2 adds slot 1's rise and leaves slot 0's alone.
  - Render 3 adds no animation.
  - Render 4 lays out afresh, and slot 0 rises again.
- A first render with every slot `.pending` shows the row with no copies.
- With Reduce motion on, the same feed places every copy at rest with no animation.
- Build the `Switcher` values through their package inits:
  - `Switcher(frontmost:running:leavingOut:serial:trackpad:)`;
  - `take(_:at:)` with `.windows` reads;
  - `selection.follow`, to move the selection.
- Source: R6 "once per swipe, never again while the selection moves", and Reduce motion; R4 "never waits", "as soon as its count is known".

**Verified without a test (hand check).** The orchestrator reports this to the human; do not run it. With Safari at three windows, a swipe shows two copies rising out from behind its icon, the nearer one first, and still within half a second. Sliding the selection on and off Safari does not move the copies. With Reduce motion on, the copies show in place.
