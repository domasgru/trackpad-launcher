# S1: Make the change easy: one selection rule, two-axis travel, slide kinds, one permissions port, one overlay panel

## Goal

A pure prefactor with no visible change to the user. It prepares the codebase for a later "window swipe" (two fingers sliding up or down under the anchored thumb, which shows a window switcher): the app switcher's selection maths becomes a shared `SwitcherSelection`; the pointer curve returns both axes; the recognizer, hardware port and model take a set of enabled slide kinds instead of `swipes: Bool`; one `Permissions` port replaces `AccessibilityPermission`; and the app switcher's panel/presenter yield a reusable `OverlayPanel` and `Displays.screen(under:)`. Only `.swipe` exists as an enabled kind in practice in this slice: `[.swipe]` must behave exactly as `swipes: true` did, `[]` exactly as `swipes: false`.

## Requirements

- **R9 (the part this slice delivers: the pointer curve's vertical component).** "It MUST move one row for every 100 points the cursor would travel for the same finger movement, with macOS's own pointer acceleration at the user's tracking speed, whatever the rows' size on screen." This slice only makes the curve compute the y component; nothing uses it for rows yet.
- Everything else: no behaviour change. The existing suite must pass with its meaning unchanged.

## Design

Background code map (file:line pointers, written against `main` today) lives in `plans/012-window-switcher-gesture/.temp/architect/grounding/how.md`, sections "Where the window swipe meets this" and "Gotchas". Read those two sections first; you may read the rest of that file for context.

### 1. `SwitcherSelection` (LauncherCore, new; e.g. in `Switcher.swift` or its own file)

Move the app switcher's selection maths out of `Switcher` **unchanged** (today `Switcher.follow`, `selected`, `position`, `stretch`, `travelMM` and the private reported travel). `Switcher` then holds one.

```swift
/// Where the fingers have taken a switcher's selection along its fixed list: the nearest item; hard stops at both
/// ends; a rubber band of at most a quarter step, forgotten the moment the fingers turn back (no dead zone).
public struct SwitcherSelection: Equatable, Sendable {
    /// At least 1: a one-row switcher rubber-bands at both ends.
    public let count: Int
    public package(set) var travelMM: Double = 0
    private var reportedMM: Double = 0
    package init(count: Int)
    /// Takes the slide's absolute travel. Returns how many items the selection crossed: one light tick each.
    @discardableResult package mutating func follow(_ reportedMM: Double) -> Int
    public var selected: Int
    public var position: Double
    public var stretch: Double
}
```

- `Switcher` keeps `row`, `startsOnFrontmost`, `selectedApp`, `selectsFrontmost` and `trackpad`; its maths moves into `public package(set) var selection: SwitcherSelection`. **No forwarding properties**: callers (the model, `SwitcherPresenter`, tests) read `switcher.selection.selected` etc.
- `follow` returns the number of items crossed; the model's tick loop uses it (today the model computes ticks from the before/after `selected`; replace that with the return value, same count).
- If `Switcher` today has a starting offset (e.g. starting on the frontmost vs the second item), keep that behaviour exactly; how it maps onto `SwitcherSelection` is your call, as long as `SwitcherSelection` stays the generic maths over `count` items.
- The existing `SwitcherTests` rows move onto `SwitcherSelection` unchanged and keep the exact 6 mm boundary.
- Fix the stale comments: `Switcher.travelMM`'s doc ("trackpad millimetres") and `switcherMaxOvershoot`'s comment in `GestureRules.swift` should say step millimetres (12 per item) and match the code.

### 2. Two-axis pointer travel (LauncherCore `PointerCurve.swift`)

```swift
extension PointerCurve {
    /// Cursor points the pointer moves along x and y for one report of finger movement: the HID system scales the
    /// whole delta by one speed-dependent multiplier (y by symmetry with x). Replaces `cursorPoints`.
    public func cursorMove(dxMM: Double, dyMM: Double, interval: Double) -> (x: Double, y: Double)
}

public enum SwipeTravel: Equatable, Sendable {
    case linear
    case cursor(PointerCurve, pointsPerStep: Double)
    /// 100 cursor points per step: the app switcher's icon pitch, and (later) the window switcher's row. For rows the
    /// cursor match is not literal, by requirement ("whatever the rows' size on screen").
    public static let shippedPointsPerStep = 100.0
    /// `.linear`: the millimetres along the slide. `.cursor`: the cursor's points along it ÷ pointsPerStep × 12.
    func travel(along kind: SlideKind, dxMM: Double, dyMM: Double, interval: Double) -> Double
}
```

- `cursorMove` computes the speed from `hypot(dx, dy)` as `cursorPoints` does, and returns `(dx * m / v, dy * m / v)` with the same multiplier (today `cursorPoints` returns only the x of that). Delete `cursorPoints`.
- `SwipeTravel.cursor(_:pointsPerStep:)`, `shippedPointsPerStep` and `travel(along:dxMM:dyMM:interval:)` replace today's icon-named forms (whatever they are called now, e.g. `pointsPerIcon`). `.swipe` picks the x component, `.windowSwipe` the y component. `.linear` returns `dxMM` for `.swipe` and `dyMM` for `.windowSwipe`. 12 is today's step in mm (`GestureRules.switcherStepMM`); use the constant.
- Sign convention: swipe travel is positive to the right in both hand modes (as today); window-swipe travel is positive **downwards** in both hand modes. Check the trackpad's y axis in `Touch.swift`/`Surface.swift` (normalised y grows downward from the top edge if the code treats y=0 as the top, which `EdgeContacts`/anchor corner suggests) and make "down" positive.
- `CursorTravel` and `LaunchTuning` in `LauncherPlatform` (and the Debug `AnimationTuner`, if it touches it) follow the rename to `pointsPerStep`.
- The recognizer's `.swiping` accumulation becomes `travel = swipe.travelMM + self.travel.travel(along: swipe.kind, dxMM: dxMM, dyMM: dyMM, interval: interval)`.

### 3. `SlideKind` and `slides: Set<SlideKind>` (LauncherCore)

```swift
/// What two fingers sliding under an anchored thumb start. Decided once, on the frame the farthest-moved finger passes
/// 3 mm, and held until both fingers lift.
public enum SlideKind: Hashable, Sendable {
    /// More sideways than up or down: the app switcher. Travel is positive to the right in both hand modes.
    case swipe
    /// More up or down than sideways: the window switcher. Travel is positive downwards in both hand modes.
    case windowSwipe
}
```

- `GestureRecognizer.init(handMode:surface:slides:swaps:travel:)` replaces `swipes: Bool` with `slides: Set<SlideKind>` ("the kinds whose setting is on. Empty: a pair's drag spoils like any drag, as with both settings off").
- In `.tapping`: `let pair = slides.isEmpty ? nil : Pair(tap, joining: joining)` (today: `swipes ? … : nil`); `.resting` likewise exists while `!slides.isEmpty`.
- `beginOrSpoil` stays the one place a slide's direction is decided. In this slice add `Move.slide`:
  `var slide: SlideKind? { abs(dxMM) > abs(dyMM) ? .swipe : abs(dyMM) > abs(dxMM) ? .windowSwipe : nil }` (strict both ways, so a tie spoils, as `isSideways` does today; replace `isSideways`). Guard: `guard let pair, let kind = move.slide, slides.contains(kind) else { return (.spoiled(anchor), nil) }`.
- `Swipe` gains `let kind: SlideKind`, set at begin.
- **Event emission in this slice:** there is no `.windowSwipe` event case yet (S2 adds it). Since `slides` can only contain `.swipe` from any production or test caller in this slice, keep emitting `.swipe(phase)` for `.swipe`-kind swipes. Do not add the `.windowSwipe` event case or `Recognition.windowSwipe` yet. If you need the window-swipe branch to compile, it is acceptable for `beginOrSpoil` to treat `.windowSwipe` exactly as spoiled until S2 (i.e. only `.swipe` begins), but `SlideKind.windowSwipe` itself must exist.
- `TrackpadHardware.run(_:handMode:blockClicks:slides:swaps:)` replaces `swipes: Bool` with `slides: Set<SlideKind>` in `Ports.swift`; both adapters follow (`MultitouchTrackpads.run(slides:)` in LauncherPlatform, `InMemoryTrackpads` in the tests).
- The model's `Run` value holds `slides: Set<SlideKind>` instead of `swipes: Bool`.
- `Settings` gains a derived, never stored `public var slides: Set<SlideKind>`; in this slice it is `isSwipeOn ? [.swipe] : []` (S2 adds the window swipe setting).
- Every recognizer driver in the tests takes `slides:` (default `[.swipe]` in this slice; S2 will widen the default to both kinds). Every recognizer construction site in the tests changes (`Fixtures.swift`, `ClickBlockingRecognizerTests`, `EdgeContactRecognizerTests`, `SwapRecognizerTests`, `DockSwipeBlockingRecognizerTests`, `GestureRecognizerTests`; see how.md item 33). Today's vertical-spoil rows (`SwipeRecognizerTests` `movingUpOrDownFirstIsNeverASwipe…`, the strict-sideways boundary, `ScrollSuppressionTests` vertical slide) run under `slides: [.swipe]`, explicitly, so they keep pinning "window swipe off" behaviour when S2 changes the default.

### 4. Fix the stale `SwipePhase` comments (`Gesture.swift`)

```swift
/// A swipe's or a window swipe's progress; the event case says which.
public enum SwipePhase: Equatable, Sendable {
    /// One of two fingers under an anchored thumb moved past 3 mm. Travel is 0 here: the 3 mm do not count.
    case began
    /// Travel along the slide since `began`, in step millimetres (12 per item), absolute. Sent only when it changed.
    case moved(travelMM: Double)
    /// Both fingers have lifted.
    case ended
    /// A third finger landed outside the anchor corner while both were down, or a click reached apps.
    case cancelled
}
```

### 5. One `Permissions` port (LauncherCore `Ports.swift`; LauncherPlatform; tests)

```swift
public enum Permission: Hashable, Sendable { case accessibility }   // S4 adds .screenRecording

/// The permissions macOS grants the app. Real: SystemPermissions. Test: InMemoryPermissions.
@MainActor public protocol Permissions: AnyObject {
    /// On the main actor after a permission changed, and only then. Carries no data: re-read.
    var onChange: (@MainActor () -> Void)? { get set }
    /// Read fresh. Never prompts.
    func isGranted(_ permission: Permission) -> Bool
    /// The system's prompt for it. Returns at once; the prompt belongs to another process.
    func ask(_ permission: Permission)
}
```

- Replaces `AccessibilityPermission`. `Launcher.init`'s `access: any AccessibilityPermission` becomes `permissions: any Permissions`; nothing else in the init changes. `start()` sets `permissions.onChange = { reconcile() }` (as today's access callback) and the first-launch prompt becomes `permissions.ask(.accessibility)`; `reconcile` reads `permissions.isGranted(.accessibility)`.
- `SystemPermissions` (LauncherPlatform, `SystemPermissions.swift`, renamed from `SystemAccessibilityPermission.swift` with `git mv`) replaces `SystemAccessibilityPermission`. Keep its behaviour: the TCC Darwin notification (`notify_register`), re-read on each post, `onChange` only when the grant changed. Give it the injectable read, shaped for S4:
  ```swift
  @MainActor public final class SystemPermissions: Permissions {
      public init(trusted: @escaping @Sendable () -> Bool = { AXIsProcessTrusted() })   // S4 adds `capturing:`
      public var onChange: (@MainActor () -> Void)?
      public func isGranted(_ permission: Permission) -> Bool
      /// .accessibility: AXIsProcessTrustedWithOptions with the prompt key.
      public func ask(_ permission: Permission)
  }
  ```
  If the existing class already injects its read differently, keep the existing test working; the point is a single module that owns the one TCC registration.
- Tests: `InMemoryPermissions` replaces `InMemoryAccessibilityPermission` (in `InMemoryAdapters.swift`): `set(_:granted:)` changes a grant and pushes `onChange` only on a change; `set(_:granted:push: false)` changes it silently (a withheld TCC broadcast); `asks: [Permission]` lists each `ask(_:)`; `onAsk: (() -> Void)?` runs inside `ask`. `World.permissions` replaces `World.access` (or whatever it is called). `AccessibilityTests` read `permissions.asks`. `SystemAccessibilityPermissionTests.swift` becomes `SystemPermissionsTests.swift` against `SystemPermissions`.
- `SourcePolicyTests`: the confined rows that named `SystemAccessibilityPermission.swift` follow the rename to `SystemPermissions.swift`.
- App target (`TrackpadLauncher/TrackpadLauncherApp.swift`): `SystemPermissions()` in place of `SystemAccessibilityPermission()`.

### 6. `OverlayPanel` and `Displays` (LauncherUI)

Extract from `SwitcherPanel` and `SwitcherPresenter`; the app switcher must look and behave exactly as before.

```swift
/// Both switchers' window: borderless, non-activating, click-through, screen-saver level on every Space and beside
/// full-screen apps, never key. Its content is Liquid Glass under `roundedClip`. Presents at once or with a short
/// appear animation; dismisses with a 150 ms fade (at once with Reduce motion) unless presented again meanwhile.
class OverlayPanel: NSPanel {
    init(cornerRadius: CGFloat, content: NSView)
    func present(animated: Bool)
    func dismiss()
    /// Runs once the panel is out (after the fade). Subclasses override to drop what they hold.
    func emptied() {}
}

/// AppKit's rule for which display holds the pointer, the nearest when none does. Moved out of SwitcherPresenter.
enum Displays { static func screen(under pointer: NSPoint) -> NSScreen? }
```

- Move into `OverlayPanel` only what `SwitcherPanel` has that is panel-generic (style mask, level, collection behaviour, ignoresMouseEvents, canBecomeKey false, the glass content under `roundedClip`, the present/fade-out logic). The row/icon/highlight layout stays in `SwitcherPanel`. If the app switcher's appear has no animation today, `present(animated:)` may ignore its flag for that caller; keep today's look exactly.
- `SwitcherPanel` subclasses `OverlayPanel`; `SwitcherPresenter` uses `Displays.screen(under:)` and reads `switcher.selection`.

## Rules that apply

- `docs/architecture.md` Shape: "`LauncherCore` (domain types, pure policy, ports, the model; imports Foundation and Observation only)". No AppKit/CoreGraphics in core.
- `docs/architecture.md` Shape: "Framework and wire types never cross a port … `NSImage` stay inside adapters and views." "Every port has exactly two adapters: the real one in `LauncherPlatform` and an in-memory one in the tests."
- `docs/architecture.md` Language: "Swift 6 language mode with complete strict concurrency … Tests use Swift Testing."
- `docs/architecture.md` Concurrency: "`LauncherCore` and `LauncherPlatform` are nonisolated by default; the model, the ports and the public surface of every real adapter are `@MainActor`. `LauncherUI` and the app target use main-actor default isolation." "No timers, no polling, no background loops … display links are banned along with timers."
- `docs/architecture.md` Privacy: "No logging of any kind (`print`, `NSLog`, `os_log`, `Logger`) … A source-scan test in `LauncherCoreTests` fails the build on any banned API." The scan reads comments too, and is substring-based: any identifier or comment containing `Timer`, `print(`, `dump(`, `KeyDown` or `scrollWheel` fails it. Confined names (e.g. `AXIsProcessTrusted`, `notify_register`) may appear only in their one file, comments included: do not spell them in doc comments elsewhere.
- `docs/domain-model.md`: use the glossary's words (swipe, window swipe, switcher, window switcher, anchored thumb, light tick, …) in names and comments. "Swipe: … A slide's direction is decided once, by that first movement past 3 mm, and holds until both fingers lift."
