## What the human asked for

Verbatim: "actually, maybe we could block system input when a user does our gesture (if we can spot it first, before system input) - that would be the best case, because sometimes now i click accidentaly when doing gesture 1, or right click on things when doing gesture 2. If we can spot our gesture before the system input, then I would like to consider blocking native system input for few seconds after holding the thumb on the corner - this is a fine solution too." And: "i sometimes fail to do a gesture 3 or 4, maybe i don't place all the fingers just at the right time, maybe we could slightly make it more sensetive / forgiving at how well in time i put those fingers".

Follow-up answers: Accessibility permission optional, asked on first launch, hint in the menu bar window otherwise; block clicks only (not pointer or scroll); block for the first 3 seconds after the thumb anchors; a blocked press counts as a tap; tap limit 400 ms; count every finger that touched; no grace delay after lift, the app must open instantly; skip recording real taps for now. The requirements R1–R11 and the non-goals in the plan are the contract; design nothing a requirement does not ask for.

## What the design must address

1. **Click blocking (R4, R5, R6, R9).** An Accessibility-gated active session event tap (`CGEvent.tapCreate`, `.cgSessionEventTap`, `.defaultTap`; probed: nil without the permission) in `LauncherPlatform` that drops trackpad button presses while *blocking is in effect* and passes everything else. The mask holds only mouse-button types (no keyboard, no scroll, no move); say how a `dragged` event during a blocked press is treated; leave room for the pressure type (34) if the Force Click manual check needs it. A press is dropped or passed whole: the mouse-up carrying the same `kCGMouseEventNumber` as a dropped down is dropped, every other up passes. Name the run loop the tap callback runs on and why, and handle `tapDisabledByTimeout` / `tapDisabledByUserInput` by re-enabling.
2. **The blocking predicate (R4).** "A thumb is anchored, less than 3 seconds have passed since it anchored, and at least one other non-thumb finger is down." It is a function of the recognizer's state and the frame clock, so decide it per frame on the frame thread (frames flow while the thumb rests, so expiry is observed within a frame; no timer), share the decision with the tap callback behind a `Mutex` with one writer, combine it across trackpads, and reset it whenever `run` restarts the devices. Blocking applies only while gestures are active and access is granted (R4 "No blocking while gestures are inactive", R9 "Declined"). State exactly how the recognizer learns that the anchor time restarts after a reconcile (grounding: a resting thumb is re-adopted by a fresh recognizer) and whether that is acceptable.
3. **A blocked press counts as a tap (R8).** Whether `CGEventSource.buttonState` still reads a dropped press as down is an open question. The recognizer must not need the answer: give it the fact "blocking is in effect for this device right now" (an input it can derive or receive) so a press inside a blocked window never spoils and a press outside one spoils as today.
4. **Forgiving taps (R1, R2, R3).** Count the distinct non-thumb `TouchID`s that touched during the tap (a tap begins when a non-thumb finger lands while none is down and ends when the last lifts); more than four fires nothing; 400 ms from first landing to last lift; fire on the lift frame with no wait. Keep every other recognizer rule (anchor corner, drag threshold, thumb-before-fingers, spoil recovery) as it is.
5. **The permission (R7, R9, R10, R11).** A port for Accessibility trust with a push: the Darwin notification `com.apple.tcc.access.changed` through `notify_register_dispatch` (probed: delivered 30 ms after a TCC change on the main queue), re-reading `AXIsProcessTrusted()` and reporting only real changes. The first-launch prompt once (`AXIsProcessTrustedWithOptions` with `kAXTrustedCheckOptionPrompt`; it returns at once) with the window open afterwards, derived from the same "first launch" fact as today (no new stored field). The hint below the gesture hint or the trackpad settings notice with the exact copy from R11, its "Grant access…" button opening `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility` from the shell (the existing `LauncherActions` pattern), live within 5 s both ways, the menu bar icon untouched by the permission (keep it out of `GestureActivity`), and the panel refitting if the hint toggles while the window is open.
6. **Lifecycle.** When the tap is created and torn down relative to trust and to gesture activity; what happens on revoke (tear down yourself; do not rely on macOS stopping delivery), on grant without relaunch, on `run([])`, on wake. Idempotent under repeated reconciles.
7. **Rules as structure.** Revise `SourcePolicyTests.banned`: remove only the permission tokens the design uses (`AXIsProcessTrusted`, `tapCreate`, `CGEventTapCreate`), keep `IOHIDManager` and the Input Monitoring tokens, add what R9 needs (for example the keyboard event types in a mask); keep every timer and polling token. Name the `docs/architecture.md` sentence that changes. `LauncherCore` still imports only Foundation and Observation: `CGEvent`, `CFMachPort`, notify tokens and AX calls stay in `LauncherPlatform`; parse them into domain types at the adapter.
8. **Test handles.** A test must be able to drive, synchronously: the permission state (an in-memory adapter whose setter invokes the port callback, like `InMemoryTrackpadPreferences.set`), the blocking predicate frame by frame, the tap's pass/drop decision (a pure function or a recorded fake), the prompt request (recorded), the real permission adapter's push (`notify_post` of the same Darwin name from the test), and the recognizer's "blocking in effect" input. Name the seam each R1–R11 scenario runs at, and which are manual. Mind that `World` builds `Launcher` in two places and the composition root in a third.

## Facts to design against (see the grounding index for standing and sources)

- Probed: an active tap for mouse-button events needs Accessibility; a listen-only one is created disabled without a permission; `com.apple.tcc.access.changed` is the push on TCC changes (`com.apple.accessibility.api` was not posted). Open: whether a real grant in System Settings posts it (manual check); whether a dropped press still reads as down in `buttonState`; whether trackpad clicks carry mouse subtype 3; whether Force Click's Look up needs the pressure type dropped; whether a bouncing finger keeps its ID; whether `FrameTime` and `CGEventTimestamp` share a base (do not compare them).
- Sourced: matching down/up share `kCGMouseEventNumber`; `CGEventSetType` can rewrite an event; the tap callback runs on the run loop its source is added to; the two disabled notices and `CGEvent.tapEnable(tap:enable:)`.
- Code: the recognizer's exact rules, the reconcile reset, the `sessions` registry, the shell's three refit triggers, the fixtures' limits, the policy scanner's substring matching, all in `how.md`. The reasons behind the rules being replaced, and what to preserve, in `why.md`.
