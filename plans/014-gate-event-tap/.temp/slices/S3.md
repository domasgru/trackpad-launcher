# S3: The behavioural suite sees the gate

Worktree: `/Users/dominykasgrubys/code/trackpad-launcher/.claude/worktrees/014-gate-event-tap` (branch `feature/014-gate-event-tap`). Swift package in `LauncherKit/`. Do not commit; the orchestrator commits your work.

## Goal

Nothing the user can see changes. The test adapter `InMemoryTrackpads` (`LauncherKit/Tests/LauncherCoreTests/InMemoryAdapters.swift`) stops owning its own `ClickFilter` / `ScrollFilter` and instead wraps one real `TapFilters` (from S2), modelling the window server's side of the two ports the real tap will have: press-port events always delivered while a tap exists, gated-port events only while `isGatedPortOn`. `scroll(_:)`, `pressVerdicts` and `isBlockingClicks` keep their meaning, so every existing World row passes unchanged, and new World rows prove the gate is closed during ordinary use, open on the thumb's frame, held through everything in flight, reconciled on a notice per port, reset by every `run`, and show the one divergence between the fake's exact knowledge and the real tap's estimate.

Background: the real click tap (built in S4) will have a *press port* over mouse downs/ups (on for the tap's whole life) and a *gated port* over drags, pressure, scrolls and the system's gesture/Dock events (`TapEvent.ridesGatedPort`), which only the tap thread switches, on `TapFilters`' say-so. Frame threads wake the tap thread when their trackpad's `Blocking.wantsTap` flips; the tap thread then calls `follow(context)` and applies the returned `GateChange`. Every close we issue echoes a "disabled by user input" notice back, handled by `portsWereDisabled`. The system can also disable either port (timeout), which arrives as the same notice. The fake models all of that synchronously, with "turns" (tap-thread work) run at once unless held by `withLateWakes`.

## Requirements

- R1. "While no trackpad's recognizer is in a state that may need blocking (no thumb anchored, no swipe or window swipe in progress, no swap series) and no filter has a press, scroll gesture (including its momentum) or Dock swipe still withheld or altered in flight, the app MUST NOT be sent scroll, drag, pressure or system gesture/Dock control events (types 6, 7, 27, 34, 22, 29, 30)." Scenario: "GIVEN gestures are active, Accessibility is granted, and click blocking is armed WHEN the user moves the pointer and scrolls a web page for 40 s without ever touching the anchor corner THEN the app receives none of those scroll or gesture events."
- R2. "Every press, drag, pressure event, scroll event and Dock swipe that the shipped build blocks, stills or rewrites MUST still be blocked, stilled or rewritten the same way, and everything it passes MUST still pass, including the races the existing plans accepted (a thumb and a finger landing on the same frame, a thumb landing under resting fingers). Every existing behavioural test MUST keep passing, and the behavioural suite MUST also hold with the tap's gating modelled."
- R3. "The gating MUST NOT deliver to apps the start of a press, scroll gesture or Dock swipe and then withhold its end, nor withhold its start and then deliver the rest. Once the shipped build would withhold part of one, the rest MUST stay withheld until it ends … even if the recognizer has returned to a state that needs no blocking."
- R4. "A tap disabled by the system (timeout or user input) MUST recover as it does today, without turning on a tap the gating wants off. Revoking Accessibility, a hot-plug, wake, a hand-mode or setting change MUST leave no tap enabled or event withheld that the shipped build would not have."

## Design

### The fake's new surface (all in `InMemoryAdapters.swift`, `InMemoryTrackpads`)

```swift
extension InMemoryTrackpads {
    enum Delivery: Equatable { case noTap, notSent, decided(TapVerdict) }
    enum Port: Hashable { case presses, gated }
    /// An event as the window server would hand it: `.noTap` with no tap; `.notSent` while its port is off.
    /// Never appends to `pressVerdicts` (the frames' presses do).
    func offer(_ event: TapEvent) -> Delivery
    /// Wakes and notices queue while `body` runs, then run in order: the open latency, made visible.
    func withLateWakes(_ body: () -> Void)
    /// The system's disable of one or both ports: each goes off and its notice is queued (run at once unless inside
    /// `withLateWakes`).
    func systemDisables(_ ports: Set<Port> = [.presses, .gated])
    /// false (the default): the context is exact, built from what the fake withheld. true: built as the real tap builds
    /// it, `TapContext.estimated(from:)`, so one row can show the divergence (a bare `began` under a thumb that landed
    /// on resting fingers reads `.passStill`, as on hardware) without touching the existing tests.
    var usesEstimatedContext = false
    /// Whether the gated port is on (false with no tap).
    private(set) var isGatedPortOn: Bool
}
```

`World.hardware` is the `InMemoryTrackpads`; tests reach these as `world.hardware.offer(...)` etc.

### Internal model (what replaces `clickFilter`, `scrollFilter`, `blocking: [TrackpadID: Bool]`)

- `private var tap: TapFilters?` — armed iff the last `run` asked for click blocking with trackpads (today's rule for `clickFilter`). `isBlockingClicks` is `tap != nil`.
- `private(set) var isGatedPortOn`, `private var isPressPortOn`.
- `private var levels: [TrackpadID: Blocking]` — each running trackpad's latest `recognition.blocking`. Merged level = `levels.values.max() ?? .none`.
- `private var scrollUnderWayUnseen: Bool` — the fake's exact knowledge: set by an unsent (`.notSent`) `.scroll(.fingers(.mayBegin | .began | .changed))`, cleared by an unsent `.scroll(.fingers(.ended | .cancelled))`. Not reset by `run` (it describes the system's event stream, not the tap).
- `context()` = `usesEstimatedContext ? TapContext.estimated(from: merged) : TapContext(blocking: merged, scrollMayBeUnderWay: scrollUnderWayUnseen)`. Built when the decision or turn runs, never captured earlier.
- A queue of pending turns; `withLateWakes` holds it. A turn is one of: a *wake* (`apply(tap.follow(context()))`) or a *notice* (`apply(tap.portsWereDisabled(pressPortIsOn: isPressPortOn, gatedPortIsOn: isGatedPortOn, in: context()))`, then `isPressPortOn = true` if it read off — the caller re-enables the press port whenever it read off). Ports are read when the notice runs.
- `apply(_ change: GateChange?)`: `.open` → `isGatedPortOn = true`; `.close` → `isGatedPortOn = false` and queue a notice (the echo of our own close); nil → nothing.

### Lifecycle

- `run(...)`: as today for recognizers, `deaf`, press bookkeeping; drop any pending turns (they belonged to the removed tap); `levels = [:]`; if armed: `tap = TapFilters()` (closed), `isPressPortOn = true`, `isGatedPortOn = false`, then one wake turn (the tap thread's first `follow`). Else `tap = nil`, both ports off.
- `touch(frames, on:)` per frame, as today: the press edge is delivered first, decided on the previous frame's level (as today), through the press port (below); then the frame's press is re-sampled through `tap?.holding`; then step; then `levels[id] = recognition.blocking`; if that trackpad's `wantsTap` flipped versus its previous level (missing = `.none`), queue a wake turn (runs at once unless inside `withLateWakes`). Event delivery and the window-swipe answer as today.
- `sleep()` as today (frames dropped; the level latches; the gated port may stay on). `wake()` as today (the model's `run` replaces the tap).

### Deliveries

- `offer(event)`: `tap == nil` → `.noTap`. The event's port (`event.ridesGatedPort ? gated : press`) is off → update `scrollUnderWayUnseen` for an unsent fingers scroll as above, return `.notSent`. Otherwise `let d = tap.decide(event, in: context())`, `apply(d.gate)`, return `.decided(d.verdict)`.
- Press edges (`deliverPressEdge`): built as today (`PressID(button: 0, number: next)`), delivered through the same path as `offer(.pointer(.press(p)))` / `.release(p)`; `pressVerdicts` appends the pointer verdict, and `.pass` when not sent (an untapped event reaches apps as is).
- `scroll(_ event: ScrollEvent) -> ScrollVerdict?` keeps its meaning: `offer(.scroll(event))` mapped `.noTap → nil`, `.notSent → .pass`, `.decided(.scroll(v)) → v`.

### Why existing tests still pass (keep this true)

An unsent `began` under no thumb followed by a thumb landing and a `changed` used to read `touching(.passed)` then `.passStill`; now the unsent `began` sets `scrollUnderWayUnseen`, the open resumes the scroll filter to `.unseen`, and `changed` under the flag reads `.passStill`: the same. `SwapTests` around line 324 (fingers rest, thumb tap, slide, a bare `began` expected `.drop`) offers no `mayBegin`, so the fake's exact context is false, the open resumes to nil, and `began` drops: still `.drop`. If any existing test fails, the fake's model is wrong, not the test: re-check it against this section and the rules in `TapFilters` before anything else; do not edit an existing `@Test` body.
