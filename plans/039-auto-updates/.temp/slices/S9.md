# S9: The silent hand-over

## Goal

When the idle minute passes, the old copy leaves a one-shot launchd job and ends itself. Sparkle installs at that end, and the job opens whichever whole copy /Applications holds, silently, with `--after-update`. A failed install brings the old copy back the same way. *Quit* and logout answer as the table below says in every phase.

## Requirements

- R8 (the install): "It MUST install 1 minute after the later of the last touch and the window closing. Logging out, restarting or shutting down before that MUST NOT delay the system. The update MAY install then. Otherwise the next start keeps the update waiting, or a later check downloads it again, and it installs under the same conditions."
- R9: "After installing, the new version MUST run with no settings window, no Dock icon, no dialog and no permission prompt. It MUST stop the old version. Gestures MUST work again within 10 seconds."
- R10: "Every setting, starting at login and the Accessibility and Screen Recording permissions MUST carry over to the new version."
- R11: "At every moment /Applications MUST hold either the whole old version or the whole new one. A failed install MUST end with a working copy running again within 10 seconds. The user MUST see nothing, and a later check MUST try again."
- R13: "*Quit Trackpad Launcher* MUST stop the app at once, in any update state, and an update MUST NOT start the app again afterwards. Every other way to quit MUST keep closing only the settings window."
- R14: "Logging out, restarting and shutting down MUST end the app without asking and with no delay from an update."

## Design

### Why a job at all

Sparkle cannot recover from a failed swap: after the host has ended, `Autoupdate` exits and nothing restarts the app. Only something outside the old process, created before it ends, can. The glossary's "never relaunches itself after a crash or a force quit" still holds: the job is only ever created in the same turn as a deliberate end.

### Order of effects

Steps 1 to 3 run in one main-actor turn, so nothing can interleave.

| # | Effect | If the process or a helper dies right after it |
|---|---|---|
| 1 | Minute passes; level re-read | Held update installs at the end, no relaunch. |
| 2 | `armRestart`: remove a stale job, `SMJobSubmit` the one-shot with old pid, bundle, old build | Job carries on and finishes the hand-over. `armRestart` false: stay `.ready`, keep running, try on the next idle edge. The update still installs at the next end. No loop. |
| 3 | `.handedOver`, `Lifecycle.end()`: `.ending`, `NSApp.terminate` | As step 2. `shouldEnd` answers yes in `.ending`, so the old copy cannot refuse. |
| 4 | `Updater.app` sees the exit; `Autoupdate` runs stage 3 | Installer killed before the swap: bundle untouched; job's budget runs out; old copy returns. |
| 5 | `renamex_np(RENAME_SWAP)` | Atomic: one whole copy on disk. |
| 6 | Job sees the build change; `open -g -a <bundle> --args --after-update` | Job killed (only logout does): nothing runs until login, and the login item is intact. |
| 7 | `.afterUpdate`, `.runSilently`, stop others, resident, no check at start | New version crashes: nothing runs until the next login or opening. Accepted; rollback is a non-goal. |

**On failure**, the job's budget runs out, at least 5 s and at most 6 s from the old pid's exit on **wall time** (an earlier probe that counted rounds took 7.4 s for an intended 5), and it opens whatever is there with the same `--after-update`: the old copy, silent. That start does not check: a check there would loop (check, download, a minute, fail) for ever. Sparkle's schedule retries within 24 hours of the stamped check, which is R11's "a later check". One argument serves both ends, because a process needs to know only that it should start silently. The cost is that a successful update does not check at start; the next check comes at the 24-hour mark.

### LauncherCore

`Lifecycle.swift`:

```swift
public enum Opening: Equatable, Sendable {
    case atLogin
    case byHand
    /// The hand-over job started this process, `--after-update`: the new version, or the old one after a failed install.
    case afterUpdate
}

public enum Route: Equatable, Sendable {
    case runSilently, runWithWindow, askToMove, end
    /// The new rows are compile-forced. The argument means something only where an update lands; anywhere else it reads
    /// as an opening by hand, so "every other opening still reaches .byHand" holds by the table.
    public init(_ opening: Opening, placement: Placement, olderCopyRuns: Bool) {
        switch (opening, placement, olderCopyRuns) {
        case (.atLogin, _, true): self = .end
        case (.atLogin, _, false): self = .runSilently
        case (.afterUpdate, .installed, _): self = .runSilently        // silent, and `replace` stops everyone: R9
        case (.byHand, .elsewhere, _), (.afterUpdate, .elsewhere, _): self = .askToMove
        case (.byHand, .installed, _), (.byHand, .development, _), (.afterUpdate, .development, _):
            self = .runWithWindow
        }
    }
}
```

A process in `--after-update` must not pose as `.atLogin`: `Route(.atLogin, _, olderRuns)` is `.end`, and it needs "silent, and stop everyone". `Lifecycle.handedOver()` already exists from S4 and uses `end()`, never `quit()`, so it makes no login-item call. The `.afterUpdate` route never runs `openedByHand`, so no first run, no `resume` and no ask. `shouldEnd`'s table does not change.

`Updater.swift`, `start`:

```swift
/// Once, from a resident only. Starts the engine and, unless this process is the hand-over's, checks in the same
/// turn. A failed install must not check at once, or it would hand over once a minute for ever.
public func start(watching launcher: Launcher, opening: Opening)
```

`Updater.idleMinutePassed` from S7 already does the order in one turn. Do not write anything to `UserDefaults` from `Updater`: "Persisted state: none of ours."

### LauncherPlatform

`LaunchdJob.swift` gains:

```swift
/// The hand-over job. `allowed` is 5 s in production; a test passes its own, and a stub for `open`.
static func handOverArguments(oldPID: Int32, bundle: URL, build: String, allowed: Int, open: String) -> [String]
static let handOverScript = "…"
```

The script, verbatim. The arguments are `["/bin/sh", "-c", script, "handover", pid, bundle path, build, allowed, open]`:

```sh
# launchd: /bin/sh -c "$script" handover <pid> <bundle> <build> <allowed> <open>
old=$1; bundle=$2; build=$3; allowed=$4; open=$5
# Never open while the old process lives: it would only show its window. It ends in this same turn; if it hangs, the
# wait holds until it goes, so a late end still installs and still comes back.
while /bin/kill -0 "$old" 2>/dev/null; do /bin/sleep 0.05; done
gone=$(/bin/date +%s)
while [ $(( $(/bin/date +%s) - gone )) -le "$allowed" ]; do
  now=$(/usr/bin/plutil -extract CFBundleVersion raw -o - "$bundle/Contents/Info.plist" 2>/dev/null)
  if [ -n "$now" ] && [ "$now" != "$build" ]; then break; fi
  /bin/sleep 0.1
done
exec "$open" -g -a "$bundle" --args --after-update
```

The version comparison couples to nothing of Sparkle's. `open -g` leaves focus alone.

`SparkleEngine.swift`:

- `init` also reads `CFBundleVersion` from the `bundle` URL now: after a swap, `Bundle.main` reads the new bundle.
- `armRestart()`: `LaunchdJob.submit(label:, arguments: LaunchdJob.handOverArguments(oldPID: getpid(), bundle: bundle, build: build, allowed: 5, open: "/usr/bin/open"))`. Label: `"\(signer.identifier).hand-over"`. False when the build could not be read, or the submit failed.

`ThisCopy.swift`: `launch` reads `--after-update` from `arguments` and gives `.afterUpdate`, beside `--eject-disk-image`. Update the doc comment. `opening(of:)`, used for a reopen, still reads only the event. An unknown argument stays ignored.

`TrackpadLauncher/TrackpadLauncherApp.swift`: only what the compiler forces; `showAnimationTuner(for:)` already compares with `.byHand`.

### Quitting, in every phase

Nothing is left armed, because only two things could restart the app and neither can be pending after a quit. Sparkle's relaunch flag is set only by the immediate handler, which is never called. The job is submitted only in the turn that ends the process.

| Way of quitting | Nothing, or a check or download running | Verified update waiting |
|---|---|---|
| *Quit Trackpad Launcher* | `suspend`, `end`, at once. The download dies with the process. | Same. Sparkle installs at exit with no relaunch; the app stays stopped until opened. |
| ⌘Q, close, Escape, Dock's Quit, window open | Window closes only | Window closes only; the idle minute may start |
| `.other`, window closed (script, Activity Monitor) | Ends | Ends; installs at exit; no restart |
| `.system` | Ends at once | Ends at once; Sparkle may install; no job exists, no restart |
| Crash, force quit, another copy's stop | Ends | Installs at exit; no restart |

### `SourcePolicyTests.swift`

- `/bin/sh` confined to `LaunchdJob.swift` and `PrivilegedInstall.swift`, rule naming both scripts. `Process()`, `posix_spawn` and the rest of "no child processes" are untouched: the job is launchd's, not a child.
- The "nothing relaunches the app" tokens stay. Their rule reads: "nothing relaunches the app after a crash or a force quit; the hand-over job opens it once after an update".

## Rules that apply

- `docs/architecture.md`, Shape: "An update never opens the new version itself: the old copy leaves a one-shot launchd job and ends, Sparkle installs at that end, and the job opens whichever copy /Applications holds, silently, with `--after-update`."
- `docs/architecture.md`, Shape: "`Lifecycle` starts it once the process is resident and ends the process when it asks".
- `docs/domain-model.md`, Hand-over: "The opened copy starts silently: no window, no Dock icon, no dialog and no permission prompt, and the keyboard focus stays in the user's app. It stops any other copy, makes no update check of its own, and gestures work again within 10 seconds. Opening it by hand afterwards opens the settings window as usual. Only an update's idle minute starts a hand-over, so a Quit, a logout or a crash never does."
- `docs/domain-model.md`, Starting at login: "Trackpad Launcher never relaunches itself after a crash or a force quit; only a *hand-over* opens it, once, after an automatic update."
- `docs/domain-model.md`, Update check: "A *hand-over* makes no check of its own."
- `docs/architecture.md`, Concurrency: "the hand-over job's bounded wait, which runs after this process has ended."
- No logging. The `plist`-reading and `/bin/sleep` live in the script, never in Swift: `asyncAfter` and `Task.sleep` stay banned.
- Do not commit: the orchestrator commits your work.
- Worktree guard: write each Bash command with literal arguments, no shell variables, `$(…)` or loops; create and edit files with Write and Edit; absolute paths.

## Starting point

- S4: `Lifecycle.handedOver()` exists and is wired to `updater?.onHandOver`. `Stage.replacingOthers` carries the opening, and `othersExited` calls `updater?.start(watching: launcher, opening: opening)`.
- S7: `Updater.idleMinutePassed` guards the level, calls `engine.armRestart()`, stays `.ready` when refused, and otherwise `enter(.handedOver); onHandOver?()`. `InMemoryIdleClock`, `process.touch(.finger)`, `process.lift()`.
- S8: `LaunchdJob.swift` has `remove(label:)` and `submit(label:arguments:)`, both `@discardableResult`. `SMJob` is confined to it. `SparkleEngine.armRestart()` still returns false; `SparkleEngine.init(bundle:signer:)` reads `TLUpdateDownloads` from `Bundle(url: bundle)`.

## Done when

- `handedOver` uses `end()`, never `quit()`.
- Arming and ending happen in one main-actor turn.
- An after-update start makes no check of its own.
- The app target builds: `xcodegen generate`, then `xcodebuild build -project TrackpadLauncher.xcodeproj -scheme TrackpadLauncher -configuration Debug -derivedDataPath build/dev -quiet -packageAuthorizationProvider netrc`.
- The quick gate, `Scripts/test.sh`, is green. It takes minutes: use a long Bash timeout (up to 600000 ms) or `run_in_background`.
