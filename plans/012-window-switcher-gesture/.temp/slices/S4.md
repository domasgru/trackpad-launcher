# S4: Window previews and the screen recording hint

## Goal

Rows of visible windows show a picture of each window as it looked when the window swipe began, once Trackpad Launcher has the Screen Recording permission; until a picture is ready, without the permission, and always for minimised windows, the app icon. The launcher window shows the screen recording hint while the permission is missing and the window swipe setting is on: its button asks macOS the first time and opens the Screen Recording page of System Settings after that; the hint goes once the permission is granted. A window swipe never asks. Pictures live only in memory and only while their window switcher is on screen.

## Requirements

Quoted from the plan, cut to what this slice delivers.

- **R6 (previews).** "Each row MUST show a preview of its window 60 points tall, keeping the window's proportions, at most 120 points wide … Previews MUST show the window as it looked when the window swipe began. A minimised window's row MUST show the app icon in place of a preview. The switcher MUST appear in the same movement that starts the window swipe. Previews MAY fill in afterwards; until a row's preview is ready, that row MUST show the app icon."
- **R7.** "While Trackpad Launcher lacks the Screen Recording permission, each row MUST show the app's icon in place of the preview, with the title unchanged. A window swipe MUST never ask for the permission. Once the permission is granted, the next window swipe after any relaunch macOS requires MUST show previews."
- **R8.** "While Trackpad Launcher lacks the Screen Recording permission and the window swipe setting is on, the launcher window MUST show a hint saying window previews need Screen Recording. The hint MUST have a button. The first press MUST ask macOS for the permission. Any later press while the permission is still missing MUST open the Screen Recording page of System Settings. The hint MUST disappear once the permission is granted." Scenarios: ask for the permission; denied earlier → System Settings opens on the Screen Recording page; permission granted → the hint disappears; setting off hides the hint.
- **R17.** "Window previews MUST be captured only while a window swipe begins, MUST be kept only in memory, and MUST be discarded when the window swipe ends. They MUST never be written to disk." (Checked in code review: when a window swipe ends, no preview of any window remains held by Trackpad Launcher.)

## Design

Background: `plans/012-window-switcher-gesture/.temp/architect/grounding/index.md` facts F25 to F37 (ScreenCaptureKit costs and behaviour, the TCC broadcast, preflight/request, the Settings URL scheme), probed on this machine; `.../grounding/probes/probe-3-capture.swift` has working `SCShareableContent` / `SCScreenshotManager` code, `probe-6-tcc-notification.swift` the TCC broadcast. `.../architect/checks/check-1-preflight-cost.*`: a Screen Recording preflight costs about 4 ms on the calling thread, so the model never reads it on a gesture.

### Permissions (LauncherCore port; LauncherPlatform adapter; test adapter)

```swift
public enum Permission: Hashable, Sendable { case accessibility, screenRecording }

@MainActor public protocol Permissions: AnyObject {
    /// On the main actor after either permission changed, and only then. Carries no data: re-read.
    var onChange: (@MainActor () -> Void)? { get set }
    /// Read fresh. Never prompts. Screen Recording's read costs about 4 ms, so the model reads it on pushes,
    /// never on a gesture.
    func isGranted(_ permission: Permission) -> Bool
    /// The system's prompt for it. Returns at once; the prompt belongs to another process.
    func ask(_ permission: Permission)
}

/// Permissions over AX trust, screen-capture access and tccd's one broadcast (about 30 ms after a change, main queue,
/// no payload, no service named): both are re-read on every post, and `onChange` runs only when either changed. The
/// only file that may name `AXIsProcessTrusted`, `notify_register` or `ScreenCaptureAccess`.
@MainActor public final class SystemPermissions: Permissions {
    /// Both reads are injectable for the adapter's own test, which flips them and posts the notification itself.
    public init(
        trusted: @escaping @Sendable () -> Bool = { AXIsProcessTrusted() },
        capturing: @escaping @Sendable () -> Bool = { CGPreflightScreenCaptureAccess() }
    )
    public var onChange: (@MainActor () -> Void)?
    public func isGranted(_ permission: Permission) -> Bool
    /// .accessibility: AXIsProcessTrustedWithOptions with the prompt key. .screenRecording: CGRequestScreenCaptureAccess().
    public func ask(_ permission: Permission)
}
```
`InMemoryPermissions` already handles any `Permission`; make sure `.screenRecording` defaults sensibly (granted in `windowWorld` unless a row says otherwise; check what other worlds should default to so existing rows are unaffected).

### The shell (LauncherUI; no test target)

- `SettingsPane.screenRecording` beside the Accessibility pane: `x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture`.
- `LauncherView`, after the Accessibility hint:
  ```swift

      SettingsNotice(message: Copy.screenRecordingHint, button: Copy.screenRecordingButton(hint)) {

  ```
  Adapt to `SettingsNotice`'s real signature (extend it with a button title if it has none). `MenuBarShell` adds `screenRecordingHint` to the refit observation tuple so the window resizes when the hint appears or goes.
- `PreviewCapture.swift` (new), the one file that captures the screen, for previews only:
  ```swift
  /// Pictures of windows, taken off the main actor. The one file that captures the screen, for previews only.
  enum PreviewCapture {
      /// Yields each window's picture as it is taken: SCShareableContent once (on-screen windows, about 14 ms), then one
      /// SCScreenshotManager capture per window, concurrently, through SCContentFilter(desktopIndependentWindow:),
      /// sized to the window's proportions within `fitting` pixels, with `scalesToFit`, no cursor and no shadow. A window
      /// that cannot be captured yields nothing. Cancelling the consuming task stops the captures. Called only for a
      /// window switcher whose `showsPreviews` is true, so it never prompts.
      nonisolated static func pictures(of windows: [WindowID], fitting: (width: Int, height: Int))
          -> AsyncStream<(WindowID, CGImage)>
  }
  ```
- `WindowSwitcherPanel` gains:
  ```swift
  /// Crossfades the row's slot from the icon to the picture, sized by `layout.previewSize(aspect:)`.
  func setPreview(_ picture: CGImage, row: Int, animated: Bool)
  override func emptied() { /* every slot layer's contents = nil */ }
  ```
  Pictures sit in the 120 × 60 slot with radius 6 (`WindowSwitcherLook.previewRadius`), crossfade 0.15 s (`previewCrossfade`), at once with Reduce motion. A picture must be held only in the slot layers' `contents`: no other property, cache or static holds a `CGImage`.
- `WindowSwitcherPresenter` captures once per serial:
  ```swift
  private func render(_ switcher: WindowSwitcher?) {
      guard let switcher else {
          capture?.cancel()
          shownSerial = nil
          panel.dismiss()                                   // fades, then `emptied()` drops every picture (R17)
          return
      }
      if switcher.serial != shownSerial { open(switcher) }  // one layout and one capture per window swipe
      … // as S2
  }

  private func open(_ switcher: WindowSwitcher) {
      … // S2's layout, using the screen's backingScaleFactor:
      let scale = screen?.backingScaleFactor ?? 2
      …
      panel.present(animated: !reduceMotion)
      capture?.cancel()
      guard !switcher.previewWindows.isEmpty else { return }
      let serial = switcher.serial, rows = switcher.rows, pixels = layout.previewPixels(scale: Double(scale))
      capture = Task { [weak self] in
          for await (window, picture) in PreviewCapture.pictures(of: switcher.previewWindows, fitting: pixels) {
              guard let self, shownSerial == serial, let row = rows.firstIndex(where: { $0.window == window }) else { return }
              panel.setPreview(picture, row: row, animated: !reduceMotion)
          }
      }
  }
  ```
  When a new serial opens over a still-fading panel, the previous slots' pictures must be cleared too (lay-out resets every slot to the icon).

### Source policy (`SourcePolicyTests`)

- Confined: `AXIsProcessTrusted`, `notify_register` and `ScreenCaptureAccess` only in `SystemPermissions.swift`; `ScreenCaptureKit`, `SCShareableContent` and `SCScreenshotManager` only in `PreviewCapture.swift`.
- Banned: `SCStream(` and `SCRecordingOutput` (pictures, never a stream or a recording; `SCStreamConfiguration(` does not match `SCStream(`), `CGImageDestination`, `representation(using` and `tiffRepresentation` (a picture is never encoded or written).
- Every "R9 only Accessibility" rule label becomes "no Input Monitoring or event posting".
- The scan reads comments: no other file may spell a confined name, even in a doc comment.

## Rules that apply

- `docs/architecture.md` Shape: "`LauncherUI` (menu bar shell and SwiftUI views, plus the window previews it captures with ScreenCaptureKit, a rendered asset like the icons it draws)". "Framework and wire types never cross a port: … `NSImage` stay inside adapters and views." No `CGImage` or image bytes in `LauncherCore`.
- `docs/architecture.md` Concurrency: "Window previews are captured off the main actor inside `LauncherUI`, and only the pictures hop back." "No timers, no polling, no background loops: every input is a push (… the TCC Darwin notification …)."
- `docs/architecture.md` Privacy: "Screen Recording, asked for only from the screen recording hint's button and never by a gesture, is used only to take one picture of each listed visible window when a window swipe begins; the pictures are kept in memory and dropped when the window swipe ends, never streamed, recorded, encoded or written to a file. … without Screen Recording the window switcher shows app icons instead of previews. The permission checks and their TCC push, … screen capture … are each confined to one file by the source-scan test." "No logging of any kind … no files written other than settings in `UserDefaults`."
- `docs/domain-model.md` Screen recording hint: "shown while Trackpad Launcher lacks the Screen Recording permission and the window swipe setting is on, that says window previews need Screen Recording. Its button asks macOS for the permission the first time it is pressed, and opens the Screen Recording page of System Settings on any later press while the permission is still missing. It disappears once the permission is granted. A window swipe never asks for the permission."
