# S1: The read says what happened, held to 0.2 s in all

## Goal

A slow or hung frontmost app now declines a slide up or down within 0.2 s, where today it can hold the main actor for seconds. A read that stops partway declines it too. Everything else behaves as today. This slice is also the groundwork for slices S2 to S5:
- it renames two types;
- it reshapes the read into a three-case value;
- it puts the adapter's Accessibility calls behind an internal seam, so the deadline can be tested;
- it splits the two presenters into build, observe and render;
- it gives the test twins one window set per app.

Background for this repo: a macOS trackpad launcher written as a SwiftPM package in `LauncherKit/`. Its targets are `LauncherCore` (pure model and ports), `LauncherPlatform` (real adapters), `LauncherUI` (AppKit shell), and tests under `LauncherKit/Tests/`. A map of the current code is in `plans/042-window-stacks-switcher-order/.temp/exploration.md`; read it first.

## Requirements

- **R13 (this slice's part).** "When there is no frontmost app, or the frontmost app does not answer (it has not reported its windows within 0.2 s), the slide MUST be no window swipe: nothing shows, and the slide scrolls as an ordinary two-finger slide, as today. Without the Accessibility permission, the same MUST hold."
  - Here that means two things. The frontmost read is held to 0.2 s **in all**, not 0.2 s per call. And a read that cannot complete partway counts as no answer.
- **R4 (this slice's part).** "An app that has not reported its windows within 0.2 s does not answer." Here that means only the adapter's deadline arithmetic (`ReadBudget`). The stacks themselves come in S4.

### LauncherCore: what a read says

Put these beside the window types in `WindowSwitcher.swift`, or in a new `WindowRead.swift`.

```swift
/// One app's windows as one read found them.
public struct AppWindows: Equatable, Sendable {
    /// On the current Space, front to back. Panels, palettes, sheets and other helpers are left out.
    public let visible: [AppWindow]
    /// Minimised, in the order the app lists them.
    public let minimised: [AppWindow]
    public init(visible: [AppWindow], minimised: [AppWindow])
}

/// What one read of one app's windows came to.
public enum WindowRead: Equatable, Sendable {
    /// Every call into the app answered within the read's deadline.
    case windows(AppWindows)
    /// No answer within the deadline, a call that could not complete partway (what was read so far is dropped), an
    /// immediate refusal, no Accessibility, or the app no longer running.
    case unanswered
    /// Trackpad Launcher itself, never read: its one window is the settings window.
    case ownProcess
}

/// One launch of a running app: equal for the same process, different after the app quits and opens again. Opaque:
/// the adapter makes it from the process id and the kernel's start time for that process; Core only compares it.
public struct AppLaunch: Hashable, Sendable {
    package init(_ token: String)
}

/// One read of the frontmost app's windows.
public enum FrontmostWindows: Equatable, Sendable {
    case noApp
    case app(AppEntry, AppLaunch, WindowRead)
}

extension WindowRead {
    /// How many windows a window swipe into the app lists: `WindowPick`'s count, ten at most; one for Trackpad
    /// Launcher's settings window; nil when the app did not answer.
    public var windowCount: Int? {
        switch self {
        case .windows(let windows): WindowPick(windows).count
        case .ownProcess: 1
        case .unanswered: nil
        }
    }
}

/// The windows a window swipe into the app lists, picked from one answered read: the window in front, the
/// other visible windows front to back, then the minimised ones in the app's order, `windowSwitcherMaxRows` at most. A
/// full-screen front window is picked alone; other full-screen windows never.
struct WindowPick: Equatable, Sendable {
    let front: AppWindow?
    let others: [AppWindow]
    let minimised: [AppWindow]

    init(_ windows: AppWindows) {
        // today's `Content.init?` cut, without its two-row guard:
        //   front = visible.first; if front?.isFullScreen == true { others = []; minimised = [] }
        //   else others = visible.dropFirst().filter { !$0.isFullScreen }.prefix(limit - 1)
        //        minimised = windows.minimised.prefix(limit - (front == nil ? 0 : 1) - others.count)
    }

    var count: Int { (front == nil ? 0 : 1) + others.count + minimised.count }
    /// The picked visible windows, front to back: what a lift on the front window restores.
    var zOrder: [WindowID] { ((front.map { [$0] } ?? []) + others).map(\.id) }
    var windows: [AppWindow] { (front.map { [$0] } ?? []) + others + minimised }
}

extension GestureRules {
    /// The most one read of one app's windows may take from the moment it is asked for (R4, R13).
    package static let windowReadDeadline = Duration.milliseconds(200)
}
```

Note one change from today's `Content.init?`. Today a full-screen front window makes the whole content nil. Under `WindowPick`, a full-screen front window is picked alone, so the count is 1, and the two-window guard below still declines the slide. The behaviour is unchanged.

`WindowSwitcher.Content` is now built on `WindowPick`, and **still requires two windows** in this slice. S3 replaces that guard with the card.
- `Content.init?(_ read: FrontmostWindows)` gives nil for `.noApp`, `.unanswered`, `.ownProcess`, and a pick of fewer than 2.
- Otherwise it gives today's rows: visible windows first, then minimised ones, from `WindowPick`.
- You may reshape `Content`'s internals, for example to keep the pick in place of `WindowList`. Its public face (`app`, `rows`, `frontWindow`, `previewWindows`, `selectedVisibleWindow`) and today's behaviour stay.

`WindowSwitcher.lift(now:)` keeps today's rules against the new read:
- `.app(sameApp, _, .windows(w))` behaves exactly as today, with `w.visible` as "on screen now".
- `.noApp`, another app, `.unanswered` or `.ownProcess` gives `WindowLift.nothing`, with no raise and no haptic.

### LauncherCore: the port and the model

In `Ports.swift`, `SystemActions.frontmostWindows()` becomes:

```swift
/// The frontmost app's windows, read now on the main actor and held to `deadline` in all: each call into the app
/// waits at most what is left, and a read that ends past it is `.unanswered`. Never reads Trackpad Launcher
/// (`.ownProcess`). The windows it lists are the only ones a later `raiseWindows` may name, until the next read.
func frontmostWindows(within deadline: Duration) -> FrontmostWindows
```

In `Launcher.windowSwipe`, both reads pass `GestureRules.windowReadDeadline`: the one at `.began` and the one at the lift in `.ended`. Nothing else in `Launcher` changes.

### LauncherPlatform: the reader and its seam

Everything below goes in `AppWindowReader.swift`. That file and `LaunchWatch.swift` are the only files allowed `AXUIElement` and `CGWindowList`.

```swift
@MainActor final class AppWindowReader {
    /// The process default for any element that sets none, as today; every read here sets its own per call.
    static let messagingTimeout: Float = 0.2
    private var listed: [WindowID: AXUIElement] = [:]
    private var isUnanswering = false

    /// As today: the process default, the private window-number function resolved once (into a `Sendable` holder, so
    /// later off-main reads in S4 can call it), and the window list warmed off the main actor.
    init()

    /// The frontmost app's read, held to `deadline`; replaces the raise handles with the listed windows' elements.
    func readFrontmost(within deadline: Duration) -> FrontmostWindows
    //   listed = [:]; isUnanswering = false
    //   NSWorkspace frontmost → .noApp; launch = AppLaunch(pid + sysctl kp_proc.p_starttime); own pid → .app(entry, launch, .ownProcess)
    //   let (read, elements) = Self.read(Target(pid: pid), budget: ReadBudget(from: .now, within: deadline), calls: AXWindowCalls())
    //   listed = elements; isUnanswering = read == .unanswered

    func raise(_ frontToBack: [WindowID])   // unchanged

    /// One app's whole read, on the calling thread, through `calls`: kAXWindows; one multiple-attribute call per window
    /// (role, subrole, title, minimised, full screen, position, size); the window's number; the on-screen window list for
    /// order (and the full list only for the frame fallback when the number cannot be had). Before each call into the
    /// app, the element's messaging timeout is set to `budget.timeout(at: calls.now())`.
    /// - kAXWindows: success lists; no value is no windows; anything else is `.unanswered`.
    /// - A window's attributes: `cannotComplete` is `.unanswered`; any other failure skips that window, as today.
    /// - A window's number: `cannotComplete` is `.unanswered`; any other failure (the private function missing
    ///   included) falls back to `number(of:among:)` over `calls.listedWindows(of:)`, copied once per read only when
    ///   needed; no single match leaves the window out, as today.
    /// - No time left before a call, or a read `budget` does not admit when it ends: `.unanswered`, whatever was read.
    /// Returns the listed windows' elements, for the one caller that raises.
    nonisolated static func read<Calls: WindowCalls>(_ target: Target, budget: ReadBudget, calls: Calls)
        -> (read: WindowRead, elements: [WindowID: Calls.Element])

    nonisolated static func sort(_ windows: [RawWindow], onScreen: [UInt32]) -> (visible: [AppWindow], minimised: [AppWindow])   // unchanged
    nonisolated static func number(of window: RawWindow, among listed: [ListedWindow]) -> UInt32?                              // unchanged

    struct Target: Sendable { let pid: pid_t }   // S4 adds `isHidden`
}

/// The read's calls into one app, and the clock: an internal seam with two adapters, the real `AXWindowCalls` (in this
/// file, over the Accessibility element API, the private window number and the window list) and a scripted double in
/// `LauncherPlatformTests` that answers, refuses, stalls past the budget or advances the clock per call.
protocol WindowCalls: Sendable {
    associatedtype Element
    func now() -> Uptime
    /// Sets the element's messaging timeout for its next call (always positive: the budget never hands out zero).
    func setTimeout(_ seconds: Float, on element: Element)
    func appElement(_ pid: pid_t) -> Element
    func windows(of app: Element) -> Result<[Element], WindowCallError>
    func attributes(of window: Element) -> Result<RawWindow, WindowCallError>   // number not yet filled
    func number(of window: Element) -> Result<UInt32, WindowCallError>
    func onScreenNumbers(of pid: pid_t) -> [UInt32]
    /// Every normal-layer window of the pid, with frame and name: only for the frame fallback.
    func listedWindows(of pid: pid_t) -> [ListedWindow]
}

/// How a call into the app failed, parsed from the Accessibility error at the seam.
enum WindowCallError: Error, Equatable { case cannotComplete, noValue, other }

/// What is left of one read's deadline on the process's monotonic clock. Pure: tests pass the time.
struct ReadBudget: Equatable, Sendable {
    let deadline: Uptime
    init(from start: Uptime, within: Duration) { deadline = start + within }
    /// The messaging timeout for a call made at `now`: what is left, always positive; nil at or past the deadline, so no
    /// further call is made (a zero timeout would mean "the global 0.2 s" to Accessibility).
    func timeout(at now: Uptime) -> Float?
    /// Whether a read that ended at `now` answered in time.
    func admits(endedAt now: Uptime) -> Bool { now <= deadline }
}
```

- **The clock.** `AXWindowCalls.now()` reads `Uptime.now`, the process's one monotonic clock read in `UptimeNow.swift`.
- **AppLaunch.** Build the token from the pid and `sysctl`'s `KERN_PROC_PID` `kp_proc.p_starttime`, for example `"\(pid)-\(sec).\(usec)"`. Do not use `NSRunningApplication.launchDate`: apps launched outside LaunchServices lack it.
- **No timers.** The deadline is never armed. It is stamped once and compared, so nothing fires at the deadline.
- **Number vs. fallback.** Today a missing private function and a failed number call both give `nil` and trigger the frame fallback. Keep that, except a `cannotComplete` number is now `.unanswered`. The private function missing maps to `.other`.
- **Calls not into the app.** `onScreenNumbers` and `listedWindows` go to the window server, not the app, so they get no timeout. The end-of-read `admits` check still covers them.

In `WorkspaceActions`:
- It owns an `AppWindowReader`.
- `frontmostWindows(within:)` forwards to `readFrontmost(within:)`.
- `raiseWindows` is unchanged.

### Test twins (test code only, `LauncherKit/Tests/LauncherCoreTests/InMemoryAdapters.swift` and `World.swift`)

`RecordingSystemActions`:
- **`func windows(of app: AppEntry) -> FakeWindows`** gives one `FakeWindows` per running location (`AppEntry.url`).
- **`var windows: FakeWindows { windows(of: frontmost) }`** is the frontmost app's set, so today's tests keep working. Decide what it gives with no frontmost app; today's tests set windows before making an app frontmost, so look at how `windowWorld` uses it.
- **`var ownApp: AppEntry?`** names the app whose reads are `.ownProcess` (Trackpad Launcher's entry). `World.openSettings()` sets it up so the settings window as frontmost reads `.ownProcess`, as the real adapter does.
- **`private(set) var frontmostDeadlines: [Duration]`** records each `frontmostWindows(within:)` call's deadline.
- **`frontmostWindows(within:)`** answers:
  - `.noApp` with no frontmost app;
  - `.app(entry, fake.launch, read)` otherwise, where `read` is `.ownProcess` for `ownApp`, `.unanswered` when the fake is `.held` or `.never`, or `.windows(...)` as today.

`FakeWindows`:
- **`enum Answering { case now, held, never }`** and **`var answering: Answering = .now`**, settable through `set(…, answering:)`. This replaces today's `answers: Bool`; port every use. For the frontmost read, `.held` and `.never` both read `.unanswered`. S4 gives `.held` its meaning for the row reads.
- **Window numbers are given when a window is created**: by `set`, in list order, or by `open`. They come from one counter shared by every `FakeWindows` of the system, so numbers rise in creation order as the window server's do. Today ids are minted per title. Keep `id(_ title:)` answering a window's id by title. One title per app stays unique; across apps titles may repeat, so the counter must be shared and not keyed by title.
- **`var launch: AppLaunch`** is the app's current launch, which its frontmost reads carry. It gets a fresh, unique value per fake. You need a package or test-visible way to make an `AppLaunch` from the tests: `package init(_ token: String)` is visible to `LauncherCoreTests` through `@testable` or package access; check how the tests import `LauncherCore`.

## Rules that apply

- **architecture.md, Shape:** "`LauncherCore` (domain types, pure policy, ports, the models; imports Foundation and Observation only)". So `AppLaunch` stays opaque, with no `pid_t` and no Darwin in Core.
- **architecture.md, Shape:** "Framework and wire types never cross a port: `MTTouch`, `CFTypeRef`, `CGEvent`, `CFMachPort`, `UserDefaults` keys, `NSRunningApplication`, `NSImage` stay inside adapters and views. External data is parsed into domain types at the adapter." So `AXError` is parsed into `WindowCallError` at the seam, and `AXUIElement` never leaves `AppWindowReader.swift`.
- **architecture.md, Shape:** "Every port has exactly two adapters: the real one in `LauncherPlatform` and an in-memory one in the tests." So the port change lands in `WorkspaceActions` and in `RecordingSystemActions` together. `WindowCalls` is an internal seam, not a port: real `AXWindowCalls` plus the test double.
- **architecture.md, Concurrency:** "`LauncherCore` and `LauncherPlatform` are nonisolated by default; the model, the ports and the public surface of every real adapter are `@MainActor`. `LauncherUI` and the app target use main-actor default isolation." `read` is `nonisolated static`, and the window-number function holder is `Sendable`. Swift 6 strict concurrency must build clean.
- **architecture.md, Concurrency:** "No timers, no polling, no background loops … And a window read's 0.2 s: stamped on the same clock when the read is asked for, carried into each Accessibility call as its messaging timeout, and compared when the read ends, a read that ends late counting as unanswered." `SourcePolicyTests` bans `asyncAfter`, `Timer`, `Task.sleep` and similar in Sources.
- **architecture.md, Privacy:** "the Accessibility element API with the window list to two (the switchers' window reads and the launch watch)", enforced by `SourcePolicyTests`' `confined` list.
- **architecture.md, Language:** "Tests use Swift Testing."
- **domain-model.md, Window swipe:** "It exists whenever the frontmost app's windows are known when the slide's direction is decided … that app reports its windows within 0.2 s. Otherwise the slide is no window swipe: nothing shows, nothing pulses, and it behaves exactly as with the window swipe setting off." In S1 the window swipe still needs two windows too, since the card comes in S3.
- **domain-model.md:** the term "window stack" now means the icons behind an app's icon in the switcher. Hence the `RaiseOrder` rename.

## Tests

**T12 (R4, R13), platform static, `LauncherPlatformTests`.**
- Setup: `ReadBudget(from: 10 s, within: 200 ms)`.
- `timeout(at:)` is 0.2 at 10 s and 0.05 at 10.15 s, compared with a small float tolerance. It is nil at 10.2 s and at 10.25 s, and never 0 or negative.
- `admits(endedAt:)` is true at 10.15 s and at 10.2 s, and false at 10.2001 s.
- Source: R4's and R13's 0.2 s; R4's 150 ms. `AXUIElement.h` says a timeout of 0 on an element "makes that element use the current global timeout value", and timeout values "must be positive".

**T14 (R4, R13), platform adapter over the `WindowCalls` double, `LauncherPlatformTests`.**
- Setup: `read(_:budget:calls:)` over the scripted double, with a 200 ms budget stamped at 0 ms on the double's clock. The double records every timeout it is handed and every call it answers, in order.
- **(a) Calls of 50 ms each.** Every call into the app (`windows(of:)`, `attributes(of:)`, `number(of:)`) takes 50 ms.
  - With one window, the double is handed timeouts of 0.2, 0.15 and 0.1 before the three calls, and the read answers `.windows` with that window.
  - With two windows, it is handed 0.2, 0.15, 0.1 and 0.05, no fifth call is made, and the read answers `.unanswered`.
- **(b) A late answer.** `windows(of:)` answers with one window, but only at 210 ms. The read answers `.unanswered` and makes no further call.
- **(c) Instant calls and the error rules.**
  - `windows(of:)`: `.noValue` answers `.windows` with no windows; `.cannotComplete` or `.other` answers `.unanswered`.
  - The second window's `attributes(of:)` or `number(of:)` failing `.cannotComplete` answers `.unanswered`. The first window is dropped too.
  - Its `attributes(of:)` failing `.other` lists the other windows.
  - Its `number(of:)` failing `.other` takes the number from the one `listedWindows(of:)` entry with the same frame, and the window is listed under that number. With no matching entry, the window is left out and the others are still listed.
- **(d) Elements.** On `.windows`, the returned elements are exactly the listed windows'.
- Source: R4's and R13's 0.2 s; R13 "has not reported its windows" (a partial read); the read-error rules above; per-element timeouts cap the next call (probed); `_AXUIElementGetWindow` is an IPC call that can time out (probed).

**T42 (R13), World, `LauncherCoreTests`.**
