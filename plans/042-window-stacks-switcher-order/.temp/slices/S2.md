# S2: A stable window order

## Goal

The window switcher lists each app's windows in that app's *window order*:
- The first window swipe into a launch of the app sets the order. It lasts until the app quits or Trackpad Launcher stops.
- Windows that open later join its end, even after every remembered window has closed.
- The selection starts on the window in front.
- The lift still restores the z-order from the start of the swipe.

Repo background: a macOS trackpad launcher, a SwiftPM package in `LauncherKit/`. Its targets:
- `LauncherCore`: pure model and ports;
- `LauncherPlatform`: the real adapters;
- `LauncherUI`: the AppKit shell.

`plans/042-window-stacks-switcher-order/.temp/exploration.md` maps the code as it was before S1. S1 then changed it, as described under Starting point.

## Requirements

**R7. Each app keeps one window order.**

> The window switcher MUST list an app's windows in that app's window order. The first window swipe into an app MUST set its order as today's list: the window in front, then the other visible windows front to back, then the minimised windows in the order the app lists them. Every later window swipe into that app MUST keep the order. Only these MUST change it: a window opening joins the order at its end, a window closing leaves it, and the app quitting or Trackpad Launcher stopping forgets it. Nothing else changes it. Lifting, clicking, ⌘`, the Window menu, Mission Control, the Dock, minimising, restoring and hiding the app MUST NOT change it. A minimised window keeps its place in the order, and shows dimmed and badged as today. A window that is not on the current Space MUST NOT be listed, but MUST keep its place in the order. When it is back on the current Space, it MUST be listed in that place again. The order MUST NOT be saved.

**R8. The selection starts on the window in front.**

> The selection MUST start on the row of the window in front when the window swipe begins. When every window is minimised, it MUST start on the first row. Lifting MUST keep today's rules: the selected window stays in front, restored if minimised, with the window that was in front just behind it; the gesture haptic plays only when the window in front changed or a minimised window was restored.

**R9. More than ten windows.**

> When an app has more than ten windows, the window switcher MUST pick ten by today's rule: the window in front, the other visible windows front to back, then the minimised windows. It MUST list those ten in the app's window order.

## Design

### `WindowOrders` (LauncherCore, new file `WindowOrders.swift`)

```swift
/// Each app's window order, by the app's location, for one launch of the app and as long as Trackpad Launcher runs;
/// never saved. Owned by `Launcher`, written only when a window swipe starts.
package struct WindowOrders: Equatable, Sendable {
    private struct Remembered: Equatable, Sendable {
        let launch: AppLaunch
        var windows: [WindowID]
    }
    /// One entry per app location: a later launch of the app replaces it, so memory is bounded by the apps window-swiped.
    private var orders: [URL: Remembered] = [:]
    package init() {}

    /// What a slide up or down shows, from the read at its start, after bringing the app's order up to date with an
    /// answered read. nil (no window swipe) for no frontmost app, for an app that did not answer, and — in this slice —
    /// for a count below two (S3 turns that into the card). Otherwise the rows: the R9 pick in the app's order, the
    /// front window's row noted. `stillOpen` answers which of the given windows the window server still holds; it is
    /// asked only when the order remembers a window the read did not list. Idempotent: the same read twice leaves the
    /// same order and gives the same content.
    package mutating func list(
        _ read: FrontmostWindows, stillOpen: (Set<WindowID>) -> Set<WindowID>
    ) -> WindowSwitcher.Content? {

        //   if case .windows(let windows) = windowRead {

        //       orders[app.url] = Remembered(launch: launch, windows: Self.updated(remembered, with: windows, stillOpen: stillOpen)) }
        //   guard count >= 2, case .windows(let windows) = windowRead else { return nil }     // S3: the card here
        //   return Content(app: app, rows: Rows(app: app, pick: WindowPick(windows), order: orders[app.url]!.windows))
    }

    /// The app's order now, for this launch; [] before its first window swipe.
    package func order(of app: AppEntry) -> [WindowID] { orders[app.url]?.windows ?? [] }

    /// The order brought up to date with one answered read. Pure but for `stillOpen`, which a test passes.
    /// - No order for this launch (`nil`: the first window swipe into this launch of the app): today's list, visible front
    ///   to back, then the minimised ones.
    /// - A remembered window the read did not list stays in its place if `stillOpen` holds it (another Space, a
    ///   full-screen Space), and leaves otherwise: it closed (numbers are never reused).
    /// - Listed windows the order lacks join at its end, in the order they opened (rising window numbers), even when
    ///   nothing remembered is left (the app's windows all closed, or it had none at its first window swipe).
    static func updated(
        _ order: [WindowID]?, with windows: AppWindows, stillOpen: (Set<WindowID>) -> Set<WindowID>
    ) -> [WindowID] {
        //   let listed = (windows.visible + windows.minimised).map(\.id); let listedSet = Set(listed)
        //   guard let order else { return listed }
        //   let missing = Set(order).subtracting(listedSet)
        //   let open = missing.isEmpty ? [] : stillOpen(missing)
        //   let kept = order.filter { listedSet.contains($0) || open.contains($0) }
        //   return kept + listed.filter { !kept.contains($0) }.sorted { $0.rawValue < $1.rawValue }
    }
}
```

Order is updated for **every answered read**, including one with fewer than two windows, even though that slide is still declined in this slice. S3 makes those slides card window swipes, and its tests rely on the order having been set there. A read of `.ownProcess` or `.unanswered` never touches the order.

The design's invariants:
- the update is idempotent;
- `WindowOrders` is not `Codable` and `SettingsStore` never names it;
- `stillOpen` is never asked when nothing remembered is missing.

### Rows (LauncherCore, `WindowSwitcher.swift`)

`WindowSwitcher.Content` becomes `{ app: AppEntry; rows: Rows }`. S3 will wrap it into `List { .rows(Rows), .card(...) }`. Drop S1's `Content.init?(_ read:)`: `WindowOrders.list` is now the one parse.

```swift
public struct Rows: Equatable, Sendable {
    /// Top to bottom, in the app's window order. `Row` is unchanged; a window titled "" reads "‹App› — Window N",
    /// N its 1-based row, as today.
    public let rows: [Row]
    /// The app's window in front when the window swipe began; nil when every listed window is minimised.
    public let frontWindow: WindowID?
    /// The listed visible windows, front to back, at the start: a lift restores this order behind the selected
    /// window. Kept apart from the row order, which no longer follows the z-order.
    let zOrder: [WindowID]
    /// The pick sorted by `order`, every picked window being in it; a row is `.visible` for a picked visible window and
    /// `.minimised` for a picked minimised one; titled by `Copy.untitledWindow` and `WindowTitleRule` as today.
    init(app: AppEntry, pick: WindowPick, order: [WindowID])
    /// The front window's row; 0 when there is none (R8).
    var startRow: Int
}
```

`WindowSwitcher` keeps its public face:
- `rows: [Row]` is now `content.rows.rows`.
- `frontWindow` comes from `Rows`.
- `previewWindows` and `selectedVisibleWindow` are as today.
- Its init sets `selection = SwitcherSelection(count: rows.count, startingAt: rows.startRow)`.

### The lift, restated against the order (`WindowLift.swift`)

The lift is computed from the start's rows and a second read. It is pure. These are the rules of plan 012, restated against the order:
- **No answer.** For no app, another app, `.unanswered` or `.ownProcess`, the lift is `.nothing`.
- **Selected window gone.** The selected window has closed or left this Space, so the second read lists it neither visible nor minimised. There are no raises. The haptic plays iff a window is in front now and it is not `frontWindow`.
- **Otherwise.** The target is the selected window, then `zOrder` without it, and without any window the second read did not list. The raises are `RaiseOrder.raises(current: visible now, target:)`. The haptic plays iff the selected window is not `frontWindow`, which covers restoring a minimised window. Every raised id comes from the second read, so nothing on another Space is raised.

### Port: `openWindows(among:)` (LauncherCore `Ports.swift`, both adapters)

```swift
/// Which of `windows` the window server still holds, on any Space, minimised or not: about 0.2 ms. Window numbers
/// are never reused, so one missing here has closed (or its app quit).
func openWindows(among windows: Set<WindowID>) -> Set<WindowID>
```

- **Real adapter.** Implement it in `AppWindowReader` as `CGWindowListCreateDescriptionFromArray` over just these numbers, and forward it from `WorkspaceActions`. `CGWindowList` is confined to `AppWindowReader.swift` (and `LaunchWatch.swift`).
- **Fake.** It answers with the fakes' windows that are still open on any Space, and records every argument in `openWindowsQueries`, in order.

### Launcher (`Launcher.swift`)

/// Each app's window order. Written only by `windowSwipe(.began)`; survives reconciles; never saved.

### Test harness (test code only: `InMemoryAdapters.swift`, `World.swift`)

**`FakeWindows`** gains:
- `focus(_ title:)`: the user brings a window to the front with a click, ⌘`, the Window menu, Mission Control or the Dock. A minimised window is also restored.
- `moveToAnotherSpace(_:)` and `returnToThisSpace(_:)`. A window on another Space is not read, but is still open for `openWindows`.
- `hide()` and `show()`. Hiding and showing change no window's z-order. S4 gives the hidden state its meaning for count reads; here it only has to exist and change nothing in the window order.
- `launch` becomes mutable, or the fake is replaced, so that a relaunch carries a new `AppLaunch`.

Window numbers already come from one shared, rising counter, handed out when a window is created (S1). `set` gives numbers in list order. A relaunch must be able to choose its creation order separately from its z-order.

**`RecordingSystemActions`** gains:
- `openWindows(among:)`;
- `openWindowsQueries: [Set<WindowID>]`.

**`World`** gains:
- `windows(of name:)`.
- `quit(_ name:)`: the app is no longer running, and its windows are gone.
- `relaunch(_ name:, created: [String], front: [String])`, or a similar shape. It mints a new `AppLaunch` and recreates the app's windows under new numbers, in the given creation order and z-order.

Today's `relaunch()` stays as it is: it restarts Trackpad Launcher.

## Rules that apply

- **architecture.md, Shape:** "`LauncherCore` (domain types, pure policy, ports, the models; imports Foundation and Observation only)". `WindowOrders` is a pure value, keyed by `URL`.
- **architecture.md, Shape:** "Every port has exactly two adapters: the real one in `LauncherPlatform` and an in-memory one in the tests." `openWindows(among:)` lands in both.
- **architecture.md, Shape:** "Framework and wire types never cross a port". The real adapter parses `CFArray`/`CFDictionary` into `Set<WindowID>`.
- **architecture.md, Privacy:** "the Accessibility element API with the window list to two (the switchers' window reads and the launch watch)". `SourcePolicyTests` confines `CGWindowList` to `AppWindowReader.swift` and `LaunchWatch.swift`.
- **architecture.md, Concurrency:** "No timers, no polling, no background loops".
- **architecture.md, Privacy:** "No files written other than: settings in `UserDefaults` …". The order is never saved, so it never touches `SettingsStore`.
- **domain-model.md, Window order:** "Afterwards only three things change it: a window that opens joins it at its end, a window that closes leaves it, and the app quitting or Trackpad Launcher stopping forgets it. Bringing a window forward in any way …, minimising, restoring and hiding change nothing. A window on another Space is not listed but keeps its place, and is listed there again once it is back on the current Space. It is never saved."
- **domain-model.md, Window switcher:** "The lift orders the windows on screen, never the window order." Also: "Lifting leaves the selected window in front with the keyboard focus, restoring it if it is minimised, and orders the windows: the selected window, then the front window, then the others as before".
- **domain-model.md, Front window:** "The frontmost app's window in front when a window swipe begins, on whichever row the window order puts it; the selection starts on its row. There is none when every window of the app is minimised: the selection then starts on the first row".
