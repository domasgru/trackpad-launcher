# S1: Debug builds carry their own identifier and still replace the release copy

Repo root (a git worktree; stay in it, use absolute paths):
`/Users/dominykasgrubys/code/trackpad-launcher/.claude/worktrees/026-separate-debug-bundle-id`

Do not commit; the orchestrator commits your work. Do not edit `docs/`, `README.md` or anything under `plans/` (they are already updated and committed).

## Goal

A Debug build runs under `com.domasgru.TrackpadLauncherApp.debug`, so System Settings lists it apart from the installed release and neither's Accessibility / Screen Recording grants cross. Opening either build by hand still stops the other, so only one copy ever reacts to gestures. The release and the perf build keep `com.domasgru.TrackpadLauncherApp`, and the release command refuses to ship anything else.

Background: macOS stores each TCC grant under the bundle identifier together with the designated requirement of the copy that was granted. Debug (Apple Development) and release (Developer ID) builds shared one identifier, so granting one refused the other. The single-instance rule (`SystemRunningCopies.others()`) lists running copies by `Bundle.main.bundleIdentifier`; separating the identifiers alone would let both copies run at once, both reacting to every gesture.

## Requirements

- **R1. Debug builds have their own bundle identifier.** The Debug configuration MUST build the app with bundle identifier `com.domasgru.TrackpadLauncherApp.debug`. The Release configuration (the notarized release and the perf build of `Scripts/perf/build.sh`) MUST keep `com.domasgru.TrackpadLauncherApp`, so installed users keep their grants, settings and login item.
- **R2. A Debug copy and a release copy are still one app at runtime.** Every copy of Trackpad Launcher, Debug or release, MUST count the other's running copies as its own when deciding which copy stays (today's single-instance rule, unchanged otherwise): opening a Debug build while a release copy runs MUST stop the release copy, and the reverse, so only one copy ever reacts to gestures.
- **R3. Nothing else that matches by bundle identifier changes behaviour for users.** Release builds MUST behave exactly as before. Other matches by the app's own bundle identifier (such as the move-to-Applications installer replacing a copy with the same identifier) stay per identifier.

## Design

Exactly these files change (R3 is checked by `git diff main --stat`; touch nothing else):

1. **`project.yml`** (xcodegen spec). In target `TrackpadLauncher`, remove `PRODUCT_BUNDLE_IDENTIFIER` from `settings.base` and set it per configuration under `settings.configs`:
   ```yaml
   settings:
     base:
       GENERATE_INFOPLIST_FILE: NO
       ...
     configs:
       Debug:
         PRODUCT_BUNDLE_IDENTIFIER: com.domasgru.TrackpadLauncherApp.debug
       Release:
         PRODUCT_BUNDLE_IDENTIFIER: com.domasgru.TrackpadLauncherApp
   ```
   Nothing else in the build changes. Do NOT put the identifiers in `Config/*.xcconfig`: xcodegen's `bundleIdPrefix` option fills in a `PRODUCT_BUNDLE_IDENTIFIER` for a target whose settings set none, and target settings shadow xcconfig values; per-configuration target settings are the one level nothing shadows. A prototype confirmed the generated project then carries exactly those two settings for the key. `TrackpadLauncher.xcodeproj` is git-ignored and regenerated by `xcodegen generate`.

2. **`LauncherKit/Sources/LauncherPlatform/SystemRunningCopies.swift`** (the real adapter of the `RunningCopies` port).
   - Add a pure static function (in the existing `extension SystemRunningCopies`, beside `started(_:before:)`, internal visibility so `@testable` tests reach it) mapping one bundle identifier to the `Set<String>` of identifiers of every build of that app: the release identifier (the given one with a trailing `.debug` component removed, when it has one) and that release identifier with `.debug` appended. E.g. `family(of: "com.domasgru.TrackpadLauncherApp")` and `family(of: "com.domasgru.TrackpadLauncherApp.debug")` both return `["com.domasgru.TrackpadLauncherApp", "com.domasgru.TrackpadLauncherApp.debug"]`. This function is the only code that knows the `.debug` convention. Name it as you see fit in the codebase's style; give it a short doc comment.
   - The adapter reads its own identifier through its initialiser, defaulting to the main bundle's, in the manner of `ApplicationsInstaller`'s test initialiser: keep `public init()` for the composition root (it uses `Bundle.main.bundleIdentifier`), and add an internal init taking `bundleIdentifier: String?` for tests (one may delegate to the other). The composition root (`TrackpadLauncher/TrackpadLauncherApp.swift`, `SystemRunningCopies()`) must not change.
   - `others()` becomes one flat map over the whole family: list `NSRunningApplication.runningApplications(withBundleIdentifier:)` for each identifier in the family, then drop this process by pid as today, then map to `RunningCopy` exactly as today (same `startedEarlier` computation). A process with no identifier (nil) lists no copies, as today.
   - `stop` and `endThisCopy` are unchanged.

3. **`LauncherKit/Sources/LauncherCore/Ports.swift`** — only the doc comment on `RunningCopies.others()`. Today: `/// Every other process with this bundle identifier, read now.` It must no longer say "with this bundle identifier"; it comes to read along the lines of "Every other running Trackpad Launcher, Debug or release, read now." The protocol, `InMemoryRunningCopies` (test adapter) and `Lifecycle` are otherwise untouched. No core change, no new port, no new type.

4. **`Scripts/release.sh`** — the release guard. In `archive_and_check` (around lines 176–222), `$after` holds the sorted `Identifier=` and `TeamIdentifier=` lines of `codesign -dv --verbose=2` on the unpacked copy, and the Team ID check is `grep -qx "TeamIdentifier=$TEAM_ID" <<<"$after"`. Add a check that fails when the code-signing `Identifier` is not exactly `com.domasgru.TrackpadLauncherApp`: a whole-line match (`grep -qx "Identifier=com.domasgru.TrackpadLauncherApp"`), so `com.domasgru.TrackpadLauncherApp.debug` fails it. Put the identifier in a variable near `TEAM_ID`/`APP_NAME` at the top (e.g. `BUNDLE_ID="com.domasgru.TrackpadLauncherApp"`, not overridable from the environment). The check is **fatal in both modes**, including `--archive-only` (lenient) mode, since it needs no credential; the failure message names the expected identifier (and ideally what was found). Update the comment above `archive_and_check` ("With mode "lenient" the stapler and Team ID checks are reported instead of fatal.") if needed, and the usage text at the top (lines ~26–29: "Here the stapler and Team ID checks are only reported; in the full release they are fatal") so it also says the bundle identifier check is fatal in that mode too. Rationale for a comment if you add one: under another identifier a release would be a different app to macOS (fresh grants, settings and login item) and no installed copy would accept it as an update, since the update's genuineness check pins the signer's identifier.

5. **New test file** `LauncherKit/Tests/LauncherPlatformTests/RunningCopiesFamilyTests.swift` (name may vary slightly) holding T1–T3.

Nothing else follows the identifier: the installer (`ApplicationsInstaller`), the code signature, the updater, the running-app parsers, the quit signals, settings, the login item are all untouched.

## Rules that apply

- architecture.md, Shape: "Framework and wire types never cross a port: `MTTouch`, `CFTypeRef`, `CGEvent`, `CFMachPort`, `UserDefaults` keys, `NSRunningApplication`, `NSImage` stay inside adapters and views." — the family logic stays inside `SystemRunningCopies`; the port keeps returning `[RunningCopy]`.
- architecture.md, Shape: "Every port has exactly two adapters: the real one in `LauncherPlatform` and an in-memory one in the tests." — no new port or adapter.
- architecture.md, Shape: "Policy lives in pure functions and value types; the shell stays thin." — the family derivation is a pure static function.
- architecture.md, Concurrency: "`LauncherCore` and `LauncherPlatform` are nonisolated by default; the model, the ports and the public surface of every real adapter are `@MainActor`." — the adapter class is already `@MainActor`; the pure static function may stay nonisolated-friendly like `started(_:before:)` (it lives in an extension of a `@MainActor` class, so test suites are `@MainActor` as `RunningCopiesOrderTests` is).
- architecture.md, Privacy: "No logging of any kind (`print`, `NSLog`, `os_log`, `Logger`)." and the source-scan test in `LauncherKit/Tests/LauncherCoreTests/SourcePolicyTests.swift` confines `forceTerminate` and `.terminate(` to `SystemRunningCopies.swift` — keep them there; the test file must not call them.
- architecture.md: "Tests use Swift Testing."
- The plan: no existing test may be edited.
