# S1: Sparkle from its pinned source, without its UI

## Goal

The app links a Sparkle 2.10.1 built by one script of ours from the pinned tag's source, with its user interface and legacy parts off, vendored in the package as a local binary target beside its two signing tools (`sign_update`, `generate_keys`) and a manifest. The framework loads neither WebKit nor AppKit. The remote Sparkle package, its pin and the keychain/netrc flags revision 1 added for it are gone, and `release.sh` signs with the vendored tool.

Repo root (a git worktree; use absolute paths): `/Users/dominykasgrubys/code/trackpad-launcher/.claude/worktrees/039-auto-updates`. A codebase map with line numbers is at `plans/039-auto-updates/.temp/codebase-map.md` (sections 1, 3, 5 and "Local Sparkle checkout" matter here).

## Requirements

- **R23 (the WebKit and interface half).** "Trackpad Launcher MUST NOT load WebKit, and MUST show no updater interface of its own."

## Design

### The build script

New script `Scripts/build-sparkle.sh` (bash, `set -euo pipefail`, `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`), run by a person when the pin changes; its output is committed. It:

1. Shallow-clones `https://github.com/sparkle-project/Sparkle` at tag `2.10.1` (`git clone --depth 1 --branch 2.10.1`) into a fresh scratch folder (e.g. under `mktemp -d`), and records the commit (`git rev-parse HEAD`; for 2.10.1 it is `ab7d71291238df6e0492143b120c9b696a35f603`). A full checkout of the same commit already sits at `LauncherKit/.build/checkouts/Sparkle` if you want to read sources or `Configurations/ConfigCommon.xcconfig` while writing the script; the script itself must clone.
2. Builds Sparkle's own `Sparkle` scheme from `Sparkle.xcodeproj`, configuration Release, universal (`arm64 x86_64`, `ONLY_ACTIVE_ARCH=NO`), ad hoc signed (`CODE_SIGN_IDENTITY=-`), with these build-setting overrides:
   - `SPARKLE_BUILD_UI_BITS=0`
   - `SPARKLE_BUILD_LEGACY_SUUPDATER=0`
   - `SPARKLE_BUILD_LEGACY_DSA_SUPPORT=0`
   - `SPARKLE_BUILD_LEGACY_DELTA_SUPPORT=0`
   - `SPARKLE_EMBED_DOWNLOADER_XPC_SERVICE=0`
   - `SPARKLE_EMBED_INSTALLER_LAUNCHER_XPC_SERVICE=1` (kept on purpose)
   `ConfigCommon.xcconfig` L43-46 notes that turning legacy delta / package support off also needs the matching `-D` flags out of `OTHER_SWIFT_FLAGS_COMMON`; handle that if the build needs it. The planning session proved this build succeeds on 2.10.1: the framework is about 2.2 MB and links Foundation, Security, ServiceManagement, SystemConfiguration and libcompression only.
3. Packs the built `Sparkle.framework` into `Sparkle.xcframework` (`xcodebuild -create-xcframework -framework …`), preserving the framework's symlinks.
4. Builds `sign_update` and `generate_keys` from the same clone with Sparkle's default flags (no overrides), Release.
5. **Fails** (non-zero exit, message naming the library) if `otool -L` of the framework binary lists `WebKit` or `AppKit`.
6. Replaces the vendored folder `LauncherKit/Vendor/Sparkle/` with: `Sparkle.xcframework/`, `bin/sign_update`, `bin/generate_keys`, and `manifest.json` recording `tag` (`"2.10.1"`), `commit`, `flags` (the array of the six `NAME=value` overrides above, exactly as passed), and `xcode` (the `xcodebuild -version` output's version and build). Keep the JSON's shape simple so a test can decode `tag` and `flags`.
7. Removes its scratch clone.

Run the script once and commit its output with the slice. If the cold clone or the build fails for a reason outside our control (network), report it rather than vendoring the prebuilt package.

What the framework still nests, and must keep: `Autoupdate` (the installer), `Updater.app` (its agent) and the installer launcher XPC service (`XPCServices/Installer.xpc`, AppKit-linked in its own process, which is fine: only the framework binary's own load commands are checked). The downloader XPC service must not be in it. The UI headers stay in the umbrella header and compile to nothing.

### Why the launcher service is kept

The in-process installer launcher runs the administrator prompt synchronously on the main queue, which would freeze gestures, Quit and a logout while the prompt is up. The XPC service runs it in its own process that exists only while the installer is launched. The downloader service (a process per download) stays out.

## Rules that apply

- `docs/architecture.md`, Language, platform, toolchain: "Build: a local SwiftPM package holds every library and test target, with Sparkle built from its pinned source by one script, its user interface, legacy parts and downloader service left out and its installer launcher service kept …, and vendored in the package as a binary target beside its two signing tools and a manifest of the tag and flags; an xcodegen-generated Xcode project, written from `project.yml`, the one tracked source of the Info.plist, builds only the app bundle".
- `docs/architecture.md`, Distribution: "Never sign with `--deep`; the main executable is signed last, and the export re-signs Sparkle's nested helpers." "The same archive is Sparkle's download, signed with the update key by the vendored `sign_update`, whose private half never enters the repository".
- `docs/architecture.md`, Shape: "what depends on its private behaviour sits in one type, proven against one pinned version." (`SparkleInternals`.)
- `SourcePolicyTests` scans `LauncherKit/Sources` and `TrackpadLauncher/`; `import Sparkle` stays confined to `SparkleEngine.swift`. Do not weaken any scan row other than the one key move described above.
- Tests use Swift Testing.
