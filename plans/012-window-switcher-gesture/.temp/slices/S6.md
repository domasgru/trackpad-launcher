# S6: A slide up or down is a window swipe only with two or more windows

## Goal

Over an app with two or more windows, and with Accessibility, a slide up or down is a window swipe as before. In every other case nothing shows and nothing pulses, and the slide behaves exactly as with the window swipe switch off. Those cases are:
- one window
- an only window minimised
- no windows
- a full-screen front window
- no frontmost app
- an app that does not answer
- no Accessibility

Such a slide scrolls once the blocking window has passed and never becomes a swipe. A thumb tap under its resting fingers may swap. It stays no window swipe if a window opens before the fingers lift. The "No open windows" and "Allow Accessibility" message rows go away entirely. All paths are under `LauncherKit/` unless they start with `docs/` or `plans/`.

## Requirements

- **R1 (part):** "A window swipe MUST start only when the frontmost app has at least two windows (R13). Deciding this MUST add no delay the user can notice: the switcher MUST appear within 50 ms of the movement that starts the window swipe. The window count MUST be the number of rows the switcher shows, so a switcher never appears with fewer than two rows. … Gestures being active does not need the Accessibility permission; the window swipe does (R14)."
- **R2 (part):** "The first movement past 3 mm MUST decide whether a slide is sideways (a swipe) or up or down (a window swipe when R13 and R14 allow; otherwise as R16 describes with the setting off). The decision MUST hold until both fingers lift."
- **R3 (part):** "When the front window is full screen, it MUST count as the app's only window, so there is no window swipe (R13)."
  - Scenario: Safari is frontmost, its front window full screen, with two other windows, and the thumb landed just now. The user anchors the thumb, slides two fingers down and lifts. Then no window switcher appears, the page does not scroll, no tap gesture fires and nothing changes.
- **R6 (part):** "A window with no title MUST show the app's name, followed by " — Window N", N being its position in the list." This now always applies, since there are always at least two rows.
- **R12 (part):** no haptic without a window swipe.
- **R13 (whole):** "When the frontmost app has fewer than two windows (R4) at the moment a slide's direction is decided, or there is no frontmost app (as the glossary defines it, such as while Trackpad Launcher itself is active), the slide MUST NOT be a window swipe. A switcher MUST NOT appear and a haptic MUST NOT play. The slide MUST then behave exactly as it does with the window swipe setting off (R16): it scrolls once the blocking window has passed, and it never becomes a swipe, since its first movement was up or down. The count MUST be fixed when the direction is decided: a window that opens later in the slide does not start a window swipe, and a window that closes during a window swipe does not end it."
  - Scenarios: one window; no windows; one visible and one minimised window (two rows); only window minimised; sideways after down stays no swipe; one window scrolls after the blocking window; window opens mid-slide.
  - "A haptic MUST NOT play" is read as "the slide itself plays none". A thumb tap under the declined slide's resting fingers is a swap with its own gesture haptic, as it is with the window swipe setting off. This is open question 17, kept at its default.
- **R14:** "While Trackpad Launcher lacks the Accessibility permission, a slide up or down MUST NOT be a window swipe, as in R13. The launcher window's existing Accessibility hint MUST also say that switching windows needs the permission."
  - Scenarios: Accessibility missing, so no switcher; Accessibility granted later, so the next slide shows the switcher; the hint names switching windows.

## Design

### The model (`Sources/LauncherCore/Launcher.swift`)

`windowSwipe(_:)` becomes the following. S5 left an unconditional `hardware.confirmWindowSwipe(on:)` at the top of `.began`; replace it.

```swift
/// The one place a window swipe becomes effects. Never the launch animation.
private func windowSwipe(_ event: SwipeEvent) {
    switch event.phase {
    case .began:
        // A slide up or down is a window swipe only when the one read lists two or more rows (R1, R13). Unconfirmed,
        // the recognizer makes it the slide the setting off would have made, before its next frame.
        guard activity.isActive, let content = WindowSwitcher.Content(system.frontmostWindows()) else { return }
        hardware.confirmWindowSwipe(on: event.trackpad)
        // One switcher at a time: a second trackpad's window swipe runs its course with none, as its swipe would.
        guard shown == nil else { return }
        windowSwipesBegun += 1
        // The grant as the last TCC push left it (R7): a fresh preflight would cost about 4 ms here.
        shown = .windows(WindowSwitcher(
            content, showsPreviews: isScreenRecordingGranted, serial: windowSwipesBegun, trackpad: event.trackpad))
    case .moved(let travel):
        // unchanged
    case .ended:
        guard case .windows(let open)? = shown, open.trackpad == event.trackpad else { return }
        shown = nil
        // The second read: the plan follows the windows as they are now, whatever the raises while sliding did.
        let lift = open.lift(now: system.frontmostWindows())
        if lift.playsHaptic {
            hardware.playFeedback(.gesture, on: event.trackpad)
            window = .closed
        }
        system.raiseWindows(lift.raises)
    case .cancelled:
        // unchanged: the windows stay as they are, no reordering, silent (R15).
    }
}
```

The `listsWindows` guard goes, because every shown switcher lists windows. `activity.isActive` is checked before the read, so an inactive or injected start reads nothing (T41 keeps passing).

`reconcile()`: `Run.slides` is `settings.slides` minus `.windowSwipe` while Accessibility is missing (R14). Without it no window can be read, so a slide up or down spoils on its first frame past 3 mm exactly as with the setting off. Nothing is read and nothing hops. A grant already re-runs the trackpads (because `blockClicks` changes), so the window swipe returns with the next slide.

```swift
let run = Run(
    trackpads: active ? connected : [], handMode: settings.handMode, blockClicks: active && granted,
    slides: granted ? settings.slides : settings.slides.subtracting([.windowSwipe]), swaps: settings.isSwapOn)
```

### The core (`Sources/LauncherCore/WindowSwitcher.swift`, `WindowLift.swift`, `Copy.swift`)

```swift
public struct WindowSwitcher: Equatable, Sendable {
    /// What a window swipe lists: the frontmost app and two to ten of its windows. One exists only for a window swipe.
    public struct Content: Equatable, Sendable {
        /// Whose windows these are; their rows show its icon.
        public let app: AppEntry
        public let windows: WindowList
    }

    /// Two to `GestureRules.windowSwitcherMaxRows` windows in all.
    public enum WindowList: Equatable, Sendable {   // unchanged
        case front(AppWindow, others: [AppWindow], minimised: [AppWindow])
        case minimisedOnly(first: AppWindow, rest: [AppWindow])
    }

    public enum Row: Equatable, Sendable {
        case visible(WindowID, title: String)
        case minimised(WindowID, title: String)
        public var window: WindowID { … }   // no longer optional; .message is gone
        public var title: String { … }
    }

    // content, selection, showsPreviews, serial, trackpad: unchanged.
    /// The selection count is `rows.count` (two to ten) and starts on the first row (R9, R11).
    package init(_ content: Content, showsPreviews: Bool, serial: Int, trackpad: TrackpadID)

    /// Whose windows these are and whose icon the rows show: `content.app`.
    public var app: AppEntry                  // no longer optional
    /// Top to bottom, two to ten. A window titled "" reads as the app's name followed by " — Window N", N its 1-based
    /// row (`Copy.untitledWindow`; R6).
    public var rows: [Row]
    public var frontWindow: WindowID?         // nil when every listed window is minimised
    public var previewWindows: [WindowID]     // unchanged
    public var selectedVisibleWindow: WindowID?  // unchanged
    // `listsWindows` is removed.
}

extension WindowSwitcher.Content {
    /// The one parse from what the system read to what the switcher lists, and so whether a slide up or down is a
    /// window swipe at all (R1, R13):
    /// - A full-screen front window is the single row; other full-screen windows are left out.
    /// - Visible windows come before minimised ones, and the list is cut at 10.
    /// - nil for `.noApp`, and for fewer than two rows after these rules: one window, an only window minimised, no
    ///   windows, a full-screen front window, or an app that did not answer (its read lists nothing).
    package init?(_ read: FrontmostWindows)
}
```

Other core changes:
- `lift(now:)` in `WindowLift.swift` keeps its rules. Only its guard simplifies, because `app` and `Row.window` are no longer optional.
- `Copy.untitledWindow(of:position:)` always numbers ("Preview — Window 2"). The `rows:` parameter goes.
- `Copy.noOpenWindows` and `Copy.accessibilityForWindows` are deleted.
- `Copy.accessibilityHint` becomes "Clicks and scrolling aren't blocked during gestures, and windows can't be switched. Allow Accessibility access to do both."

### The shell (`Sources/LauncherUI/`)

`WindowSwitcherPresenter` and `WindowSwitcherPanel` take the non-optional app and window:
- In `open(_:)`, the icon is `icons.icon(forSwitcher: switcher.app)`, with no `.map`.
- `rows.firstIndex(where: { $0.window == window })` stays as written, now comparing non-optionals.
- Drop any handling that existed only for a nil app or a message row. A nil icon from `AppIcons` may still need the existing `iconView.isHidden` handling, so keep that if the icon can still be nil.

`LauncherView` shows `Copy.accessibilityHint` unchanged in code; only the text changes.

### Tests: the reference for "exactly as with the setting off"

For R13 and R14, the oracle is a **second world built the same way with the window swipe setting off** (`world.launcher.setWindowSwipe(on: false)` after building), played the same hand frame by frame. That world's behaviour is today's, pinned by T37. Expected values come from it, never from the decline code.

The per-frame probe is `world.hardware.scroll(.unphased)`. It is decided on the merged blocking flag alone and has no state of its own, so it makes per-frame blocking visible. Use the generic `World.playFrameByFrame(_:on:observing:)` to record, after every frame, `(windowSwitcher, switcher, scroll(.unphased))`. At the end, compare press verdicts (`hardware.pressVerdicts`), pulses (`hardware.pulses`), apps brought to front (`system.broughtToFront`), raises (`system.windows.raised`) and fired gestures. A fired gesture shows as `broughtToFront` plus a pulse when assigned.

`InMemoryTrackpads.windowSwipeAnswers` (added in S5) logs each start's answer in order.

World helpers (`Tests/LauncherCoreTests/World.swift`):
- `World.windowWorld(visible:minimised:fullScreenFront:untitled:frontmost:accessGranted:screenRecording:attached:)`. `frontmost: nil` means no frontmost app, and `"Finder"` is the CoreServices copy.
- `world.windowSwipe(_ slidesMM: Double..., lift:)`.
- `world.play(_:)` delivers only frames newer than those already delivered, so one hand can be played in pieces.
- `world.window(_:)`.
- `system.windows`: `set(...)`, `open(_:)`, `close(_:)`, `answers`, `reads`, `raised`, `onScreenTitles`, `minimisedTitles`.
- `permissions.set(_:granted:)`.
- `TouchScript`: `thumb(atMM:)`, `land(fingers:atMM:)`, `slide(byMM:)`, `wait(_:)`, `press()`, `lift()`, `thumbTap()`.

Add helpers where a row needs them; for example, a builder that makes the two worlds of a pair.

## Rules that apply

- `docs/architecture.md` Shape: "`LauncherCore` (domain types, pure policy, ports, the model; imports Foundation and Observation only)". "Policy lives in pure functions and value types; the shell stays thin." The two-row rule lives in the one parse `Content.init?`, not in the model or the shell.
- `docs/architecture.md` Concurrency: "Every slide up or down reads the frontmost app's windows when it starts … through the Accessibility API on the main actor". There is one read per start, and it is never repeated within the slide (T71: `reads == 1` until it lifts).
- `docs/architecture.md` Privacy: "Without Accessibility everything works except click blocking, scroll suppression, Dock swipe blocking and switching windows". Without Accessibility nothing is read (T72).
- `docs/domain-model.md` *Window swipe*: "It exists only when there is something to switch to: the frontmost app has at least two windows, counted as the window switcher would list them, when the slide's direction is decided, and Trackpad Launcher has the Accessibility permission … Otherwise the slide is no window swipe: nothing shows, nothing pulses, and it behaves exactly as with the window swipe setting off, scrolling once the blocking window has passed and never becoming a swipe; a window that opens later in the slide does not make it one."
- `docs/domain-model.md` *Window switcher*: "holding one column of 2 to 10 rows".
- `docs/domain-model.md` *Accessibility hint*: "says clicks and scrolling are not blocked during gestures and windows cannot be switched".
- The source scan (`Tests/LauncherCoreTests/SourcePolicyTests.swift`) reads comments, so no comment in core may spell a confined API name (`AXUIElement`, `CGWindowList`, and so on).

## Starting point

S1 to S5 are committed on this branch. What S5 built:
- `GestureRecognizer` begins a slide up or down unconfirmed: its phases are reported, and it blocks only by the thumb rules. `answerWindowSwipe(began:isWindowSwipe:)` settles it: true blocks from the next frame, and false turns it into exactly the setting-off state.
- `TrackpadHardware.confirmWindowSwipe(on:)` is a protocol requirement, and `WindowSwipeConfirmation` in `LauncherCore` holds the main-actor rule for it.
- Both adapters hand every event through it. `InMemoryTrackpads` gives the answer to the running recognizer between frames and logs it in `windowSwipeAnswers`.
- The model currently confirms **every** start unconditionally at the top of `windowSwipe(_:)`'s `.began`. This slice replaces that with the rule above.
- The recognizer test drivers take `answering: Bool? = true`.

What exists from S2 to S4 that this slice changes:
- `WindowSwitcher.Content` is an enum `windows(of:_:)` / `noWindows(of:)` / `accessibilityNeeded(for:)`, with a non-failable `package init(_ read:)`.
- `Row` has `.message(String)`, with an optional `window`. `app` is optional, and `listsWindows` exists.
- `Copy.untitledWindow(of:position:rows:)` names a lone untitled window without a number.
- The model's `.began` builds `.accessibilityNeeded` when Accessibility is missing.
- `.ended` guards on `listsWindows`.
- `Run.slides` is `settings.slides` regardless of the grant.
- `WindowSwitcherPresenter.open(_:)` maps an optional app to its icon.
- `WindowRowView.fill` in `WindowSwitcherPanel.swift` has no `.message` branch of its own.

Earlier departures to keep in mind:
- `FakeWindows.set` takes `untitled:`.
- The vertical `ScrollSuppressionTests` rows turn the window swipe setting off to pin today's behaviour.
- Local `main` is stale; the branch's base is `origin/main`.
