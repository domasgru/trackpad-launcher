# S3: One Trackpad Launcher at a time

Worktree: `/Users/dominykasgrubys/code/trackpad-launcher/.claude/worktrees/021-background-agent-lifecycle` (branch `feature/021-background-agent-lifecycle`). Swift package in `LauncherKit/`. Do not commit; the orchestrator commits your work.

Background (probed facts, optional reading): `plans/021-background-agent-lifecycle/.temp/architect/grounding/index.md` F4-F6, F15, F16, F20. In short: LaunchServices turns an open of the running copy's own bundle into a reopen (`rapp`); any other open (another place, or a bundle replaced at the same path, whatever its version) starts a **second process**. A peer's `terminate()` arrives exactly like the Dock's Quit, so asking a peer to quit is unreliable; the menu bar version has no delegate and vetoes nothing.

## Goal

Opening Trackpad Launcher by hand while another build, or a copy from another place, runs stops that copy. The opened copy starts gestures and its window only once that copy has exited. This includes the menu bar version. When two copies start at login, the older one keeps running and the newer one ends.

## Requirements

- **R2.** At most one Trackpad Launcher MUST recognise gestures at any moment. Opening the copy in /Applications while Trackpad Launcher runs MUST NOT start a second one that recognises gestures. It MUST open the running one's settings window instead.
- **R3.** When the user opens the copy in /Applications by hand while a different build of Trackpad Launcher runs, or the same build from another place, Trackpad Launcher MUST stop the running one and start the opened one with its settings window open. One Trackpad Launcher MUST run afterwards, and it MUST be the opened version. This holds when the user dragged a newer version over a running one in Finder, and when they upgraded from the menu bar version. The old menu bar icon MUST be gone without logging out.
  - Scenario: the menu bar version runs from /Applications and shows its menu bar icon; the user drags this version over it in Finder and opens it from Launchpad → the menu bar icon disappears, the settings window opens, and Activity Monitor lists one Trackpad Launcher process, which is the new version.

## Design

### Decision: other copies are stopped, not asked

`RunningCopies.stop` calls `forceTerminate()` and waits for KVO on `isTerminated` (with `.initial`), a push. A copy cannot refuse, hang, show its own dialog or be mistaken for the Dock's Quit, and no handshake binds versions together, the menu bar version included. A copy has nothing to flush: every setting is saved when it changes. Gestures start only after every other copy has exited (R2). Which copy started earlier is one strict total order, a pure rule in the adapter: launch date, a missing date counting as latest, then pid. Two login starts therefore compute mirror-image answers and converge on one copy.

### The route table (this slice adds `end` and `olderCopyRuns`)

| Opening | Older copy runs | Route |
|---|---|---|
| at login | yes | `end` (two login starts converge on the older) |
| at login | no | `runSilently` |
| by hand | any | `runWithWindow`, after stopping every other copy |

(S5 later adds a `placement:` parameter and `askToMove` for a release copy outside /Applications; keep the shape so that is an addition.) A reopen uses the same table with `olderCopyRuns: false`: `runWithWindow` raises the window, `runSilently` (a login start reaching the running copy) does nothing.

### LauncherCore (`Lifecycle.swift`) additions

```swift
public enum Route: Equatable, Sendable {
    case runSilently, runWithWindow, end
    /// `olderCopyRuns` matters only at login: two login starts converge on the older copy.
    public init(_ opening: Opening, olderCopyRuns: Bool)
    // (.atLogin, true) → .end; (.atLogin, false) → .runSilently; (.byHand, _) → .runWithWindow
}

public struct CopyID: Hashable, Sendable {
    public let rawValue: Int32
    public init(rawValue: Int32)
}
/// Another running Trackpad Launcher process: any build, any place, the menu bar version included.
public struct RunningCopy: Hashable, Sendable {
    public let id: CopyID
    /// Launched before this process, by the adapter's one total order (launch date, a missing date counting as latest,
    /// then pid). At login, this process defers to such a copy.
    public let startedEarlier: Bool
    public init(id: CopyID, startedEarlier: Bool)
}

@MainActor public protocol RunningCopies: AnyObject {
    /// Every other process with this bundle identifier, read now.
    func others() -> [RunningCopy]
    /// Stops each at once without asking: a copy can neither refuse, nor ask its user, nor hang the stop. Calls
    /// `exited` once, on the main actor, when every listed copy has exited; synchronously when none still runs. The
    /// signal is the processes' own termination, never a wait or a poll.
    func stop(_ copies: [RunningCopy], then exited: @escaping @MainActor () -> Void)
    /// AppKit's terminate for this process; `Lifecycle.shouldEnd` has already agreed (stage `.ending`).
    func endThisCopy()
}
```

### LauncherPlatform: `SystemRunningCopies.swift`

- `others()`: `NSRunningApplication.runningApplications(withBundleIdentifier: Bundle.main.bundleIdentifier)` minus this process's pid, each mapped to `RunningCopy(id: CopyID(rawValue: pid), startedEarlier: Self.started((app.launchDate, app.processIdentifier), before: (own.launchDate, ownPID)))`, `own` being `NSRunningApplication.current`.
- `stop(_:then:)`: for each listed copy still resolvable by pid, `forceTerminate()` and observe `isTerminated` with KVO `[.initial, .new]`; when every listed copy has exited (or none could be resolved: it already exited), call `exited` once on the main actor. Keep the observations alive until then and release them after. The KVO change handler may fire off the main thread: hop to the main actor (e.g. `DispatchQueue.main.async` / `Task { @MainActor in … }`), without `asyncAfter` or any delay. Guard against calling `exited` twice.
- `endThisCopy()`: `NSApp.terminate(nil)` (as in S1).
- The pure start order, tested on its own:

### Tests: `InMemoryRunningCopies` (in `LifecycleWorld.swift` / `InMemoryAdapters.swift`, wherever S1 put it)

## Rules that apply

- `docs/architecture.md` § Shape: "At most one Trackpad Launcher runs gestures: an opening by hand stops every other running copy and waits for their exit."
- § Shape: "Framework and wire types never cross a port: … `NSRunningApplication` … stay inside adapters and views." Only `RunningCopy`/`CopyID` cross the port.
- § Shape: "Every port has exactly two adapters: the real one in `LauncherPlatform` and an in-memory one in the tests." "Concrete types that … deliver asynchronously … sit behind a port so the model's tests stay synchronous."
- § Concurrency: "No timers, no polling, no background loops: every input is a push (… the termination of other running copies …)." `Timer`, `asyncAfter`, `Task.sleep` are source-scan banned.
- § Concurrency: "`LauncherCore` and `LauncherPlatform` are nonisolated by default; the model, the ports and the public surface of every real adapter are `@MainActor`."
- § Privacy: "A source-scan test in `LauncherCoreTests` fails the build on any banned API; add to its list rather than adding prose."
- Domain model, *Trackpad Launcher*: "At most one Trackpad Launcher recognises gestures at any moment."
- Domain model, *Opened by hand*: "Opened by hand from inside /Applications, at any depth, or as a development build, it stops every other running Trackpad Launcher (another build, a copy from another place, the menu bar version) and then runs with its settings window open; opening the running copy again brings that same window to the front."
- Accepted tradeoffs (do not "fix"): a copy that survives `forceTerminate()` leaves the opened copy waiting with nothing shown until it exits (no deadline, since timers are banned); two copies opened by hand at the same instant stop each other.
