## Goal

Opening the app by hand from Finder or Spotlight while it is not running leaves its settings window in front, key, with the app active; the move dialog of a copy outside /Applications likewise. The activation that overrides the app in front lives in one helper with its reason, both call sites use it, and the source-policy test confines it, with the `.activate()` entry written first so it fails on today's two plain calls.

Root cause, measured: the app is `LSUIElement`, so a cold launch does not make it active. `SettingsShell.render` then calls `NSApp.activate()`, which since macOS 14 is cooperative: a request the system may refuse unless the active app yielded. It is refused here, 12 of 12 under Finder and 12 of 12 under Calculator. `activate()` on the next run-loop turn, 150 ms later, and `NSRunningApplication.current.activate(options:)` all fail the same way, 3 of 3 in each cold mode. `NSApp.activate(ignoringOtherApps: true)` succeeds, 3 of 3 in each cold mode.

## Requirements

- **R1.** When the app is opened by hand while its process is not running, the settings window MUST end up as the frontmost window, key, with the app active.
- **R2.** A copy opened by hand outside /Applications MUST show its move dialog in front of other windows, with the app active.
- **R3.** Reopening with the window closed, and reopening with the window open behind another app, MUST still bring the window to the front. A login start MUST still show no window and take no focus.
- **R4.** The activation that overrides other apps MUST live in one place that states why plain `NSApp.activate()` is not enough, so nobody restores the plain call, and a source-policy test MUST confine it there.

## Design

- **`AppActivation.activateOverOtherApps()`**, new file `LauncherKit/Sources/LauncherUI/AppActivation.swift`. An enum with one static function and no parameters, internal to `LauncherUI`. Its implementation is the one call, `NSApp.activate(ignoringOtherApps: true)`, a direct Swift call, never a selector or `perform`. No window ordering, no policy change.
- **Its doc comment is the reason, and is the artefact R4 asks for.** It must say, in substance, each of these:
  1. the app is `LSUIElement`, so an opening by hand that starts the process does not make it active;
  2. since macOS 14 `activate()` is cooperative, a request the system grants only when the active app yielded, and on a cold launch nothing yielded, so the window stays under the app in front;
  3. `activate(ignoringOtherApps: true)` is marked for a future deprecation but is the one call that works, 3 of 3 in each cold mode of plan 034's harness, where `activate()`, a deferred `activate()` and `NSRunningApplication.current.activate(options:)` (whose `.activateIgnoringOtherApps` option the SDK says has had no effect since macOS 14) each failed 3 of 3;
  4. a reopen arrives already active, where the call changes nothing.
- **Call sites.** `SettingsShell.render` `.open` (`LauncherKit/Sources/LauncherUI/SettingsShell.swift:159`) and `MoveDialogPresenter.run` (`LauncherKit/Sources/LauncherUI/MoveDialogPresenter.swift:37`) call it in place of their `NSApp.activate()`, at the same point. The shell still orders the window front and then activates, on every render of `.open`; the presenter still activates and then runs the alert modally. No other line of either changes. The model is untouched.
- **Source-policy test.** In `LauncherKit/Tests/LauncherCoreTests/SourcePolicyTests.swift`, add two entries to the `confined` table, each with a `rule` string in the table's voice:
  - `ignoringOtherApps`, `onlyIn: ["AppActivation.swift"]`: the override has one home.
  - `.activate()`, `onlyIn: ["AnimationTuner.swift"]`: the plain call is refused on a cold launch, and lives only in the Debug tuner, whose click-time call is user intent the system accepts.
- **Not in scope.** `AnimationTuner.swift`'s `NSApp.activate()` stays. No port and no fake: the failure is in the system's answer to an AppKit call.

## Rules that apply

- `SourcePolicyTests` matches **substrings of whole lines, comments included**. So `.activate()` with its leading dot must not appear in any comment outside `AnimationTuner.swift`, `AppActivation.swift`'s doc comment included: write `activate()` there, never `NSApp.activate()`. `ignoringOtherApps` must not appear in a comment outside `AppActivation.swift`.
- docs/architecture.md, Shape: "Policy lives in pure functions and value types; the shell stays thin."
- docs/architecture.md, Concurrency: "`LauncherUI` and the app target use main-actor default isolation."
- docs/architecture.md, Privacy: "No logging of any kind (`print`, `NSLog`, `os_log`, `Logger`)." The shipped source gets no instrumentation.
- The package compiles with no warnings today and must stay so. The SDK declares `activateIgnoringOtherApps:` `API_TO_BE_DEPRECATED`, so the compiler is silent about it.
