# S2: The tuner shows one tab at a time and tunes the pick animation

Repo root (worktree): `/Users/dominykasgrubys/code/trackpad-launcher/.claude/worktrees/023-app-selection-grow-animation`. Package: `LauncherKit/`. Run tests with `Scripts/test.sh` (wraps `swift test`). Do not commit; the orchestrator commits.

## Goal

The Debug-only animation tuner opens on the tab it last showed (Launch the first time) with a segmented control for Launch, Bounce, Pick and Swipe and only that tab's settings below it. The Pick tab's four sliders shape the next pick in the settings window; *Preview in settings* plays the pick animation on the open settings window's pickers; *Reset to shipped* resets the shown tab alone; presets cover every tab and old ones load with the shipped pick values. All of it is inside `#if DEBUG`.

## Requirements

- **R4 (exception).** In Debug builds, the tuner's preview (R14) and preset previews (R16) also play the pick animation.
- **R9 (tuner half).** In Debug builds, the tuner's *Simulate Reduce motion* switch, when on, MUST make picks and the Pick tab's previews play no animation: GIVEN the switch is on, WHEN the user picks an app, or the developer previews the Pick tab, THEN the icons show at once at full size.
- **R11. The tuner shows one tab at a time.** The tuner MUST show a segmented control at its top with four tabs: Launch, Bounce, Pick and Swipe. The segmented control, the presets, *Reset to shipped* and the preview button (where R14 shows it) MUST show on every tab. Everything else MUST be the chosen tab's.
  - Launch: the launch animation's sliders.
  - Bounce: the launch bounce's style, sliders and *Preview bounce* switch.
  - Pick: the pick animation's sliders.
  - Swipe: the switcher swipe's settings.
  The *Simulate Reduce motion* switch MUST show on the Launch, Bounce and Pick tabs.
  - Scenario: GIVEN the Launch tab, WHEN the developer picks Pick, THEN the pick sliders and *Simulate Reduce motion* show, with the segmented control, the presets, *Reset to shipped* and *Preview in settings*, and no other tab's sliders.
- **R12. The tuner remembers its tab.** The tuner MUST open on the tab it last showed, across quits. With no remembered tab it MUST show Launch.
- **R13. Pick tab sliders.** A slider each for: the start size (share of the icon's side), the peak size (share of the icon's side), the grow time (pick to peak), the settle time (peak to rest). Shipped values 40%, 110%, 0.2 s and 0.15 s. A change MUST apply from the next pick. Scenario: grow time 0.5 s, pick an app → the icon takes 0.5 s to reach its peak.
- **R14. Preview plays the shown tab.** The preview button MUST play the shown tab's animation.
  - On Launch it reads *Preview at pointer* and plays the launch animation at the pointer, as today.
  - On Pick it reads *Preview in settings*. It plays the pick animation on every picker in the open settings window that shows an installed app's icon. Pickers that show the "not found" icon or "Choose app…" do not play it. Assignments do not change. The button is disabled while the settings window is closed or no picker shows an installed app's icon.
  - On Bounce and Swipe it is hidden.
- **R15. Reset to shipped resets the shown tab.** Only the shown tab's values reset; the other tabs keep theirs. Scenario: launch duration and pick grow time changed, *Reset to shipped* on Pick → pick values shipped, launch duration keeps its change.
- **R16. Presets cover every tab.** Presets stay one shared list, shown under every tab. Saving, updating, loading and previewing a preset cover all four tabs' values together, as today. A preset saved before this feature MUST load with the shipped pick values. A preset's play button MUST play the shown tab's animation with that preset's values. On Pick it plays on the pickers as *Preview in settings* does, and is disabled under the same conditions. On Bounce and Swipe it is hidden.

## Design

### D7. Tuner model and view (`LauncherKit/Sources/LauncherPlatform/AnimationTuner.swift`, `LaunchTuning.swift`)

- A `TunerTab` enum (`launch`, `bounce`, `pick`, `swipe`; `String` raw values, `CaseIterable`), Debug-only. `TunerModel` holds `var tab: TunerTab` and persists it in `UserDefaults.standard` as `AnimationTuner.tab`, beside the existing `AnimationTuner.current` / `.presets` / `.selected` keys; with nothing (or an unknown value) saved it is `.launch`.
- The view: a segmented `Picker` at the top bound to `model.tab`; below it, only the tab's sections:
  - Launch: today's "Size & timing", "Pop", "Rise", "Shrink", "Fade", "Sway", "Tilt" sections, then *Simulate Reduce motion*.
  - Bounce: today's `bounceSection` (style picker, its sliders and *Preview bounce*), and *Simulate Reduce motion*.
  - Pick: four sliders (below), and *Simulate Reduce motion*.
  - Swipe: today's "Switcher swipe" section (three settings). No *Simulate Reduce motion*.
  - The presets section on every tab.
  - Bottom bar: *Reset to shipped* on every tab. The preview button: *Preview at pointer* on Launch (plays the launch animation, as today), *Preview in settings* on Pick (calls the pick preview; disabled while `canPreviewPick()` is false), absent on Bounce and Swipe.
  - Each preset row's play button (and the Shipped row's) follows the same per-tab rule: on Launch it previews at the pointer as today; on Pick it previews in settings with that preset's values and is disabled when `canPreviewPick()` is false; hidden on Bounce and Swipe. Update its `.help` text per tab.
  - Leaving the Bounce tab ends a running bounce preview and turns *Preview bounce* off (today `isPreviewingBounce` is view `@State`; the toggle's `onDisappear` stops the bounce but would leave the state true, so set it false on leaving Bounce, e.g. `onChange(of: model.tab)`), so the switch never shows on with nothing bouncing.
  - The panel's title becomes "Animation tuner". Update `AnimationTuner`'s doc comment to cover the pick animation and tabs.
- Pick tab sliders bind to `LaunchTuning.pick`'s four fields with the existing `knob` helper (it takes `WritableKeyPath<LaunchTuning, Double>`, so `\.pick.startScale` works), each with its "back to shipped" button: *Start size* `\.pick.startScale` 0.1…1, *Peak size* `\.pick.peakScale` 1…1.6 (shares of the icon's side; hints such as "share of the icon's side; 0.4 = 40%"), *Grow time* `\.pick.growTime` 0.05…1 s, *Settle time* `\.pick.settleTime` 0.05…1 s. Pick sensible steps (0.01). Footer text e.g. "Applies from the next pick in the settings window."
- `LaunchTuning` gains `var pick: PickAnimation = .shipped` (`PickAnimation` is the public Core type from S1: `startScale`, `peakScale`, `growTime`, `settleTime`, `static let shipped`, `Equatable`, `Sendable`, not `Codable`). Its JSON conformance is declared in `LaunchTuning.swift`'s `#if DEBUG` block, beside `LaunchTuning.Bounce: Codable`, as a retroactive conformance of the Core type (`extension PickAnimation: @retroactive Codable` — check what the compiler wants), with `CodingKeys` for the four fields, decoding missing-or-shipped field by field with the existing `decode(_:or:)` helper, as the bounce does, plus `encode(to:)`. `LaunchTuning`'s decoder gains `pick = try c.decode(.pick, or: s.pick)`. Because `LaunchTuning`'s `Codable` is synthesised for `CodingKeys`/`encode` from its stored properties, make sure `pick` is encoded.
- `LaunchTuning` gains a pure `func resettingToShipped(_ tab: TunerTab) -> LaunchTuning` (Debug-only, since `TunerTab` is): the shipped values for that tab's fields only. The partition: Launch is the fourteen flight knobs (`iconSide`, `duration`, `popSize`, `popTime`, `rise`, `riseCurve`, `shrink`, `shrinkCurve`, `fadeCurve`, `maximumSway`, `minimumSway`, `swayCurve`, `maximumTilt`, `tiltCurve`); Bounce is `bounce`; Pick is `pick`; Swipe is `swipeFollowsCursor`, `swipePointsPerStep`, `swipeTrackingSpeed`. `forceReduceMotion` (*Simulate Reduce motion*) belongs to no tab and is never reset by the button.
- The model: *Reset to shipped* becomes `model.tuning = model.tuning.resettingToShipped(model.tab)` and keeps `selected` (so a selected preset then shows "(modified)" when it differs). The Shipped row's *Load* still loads the whole shipped tuning and clears `selected` (split today's `resetToShipped()` into the two). Saving, updating and loading presets keep covering the whole tuning; `isModified` is unchanged.
- Previewing a preset (`TunerModel.preview(_:play:)`), on any tab, swaps the preset's values in with `forceReduceMotion` as it is now in `model.tuning`, not as the preset saved it, then restores; the switch belongs to no tab, and with it on no preview animates.

### D5/D6. Wiring the settings window to the tuner (Debug only)

What S1 built (in `LauncherKit/Sources/LauncherUI/SettingsShell.swift`): inside `#if DEBUG`, `public var pickTuning: (() -> (animation: PickAnimation, simulateReduceMotion: Bool))?` on `SettingsShell`, read at every pick via `actions.pickAnimation`, which calls the pure `SettingsShell.pickAnimation(reduceMotion:tuned:)` (nil under system Reduce motion; tuned animation unless `simulateReduceMotion`; `.shipped` when no hook). Nothing sets the hook yet.

This slice adds:
- `WorkspaceActions` (`LauncherKit/Sources/LauncherPlatform/WorkspaceActions.swift`), inside its existing `#if DEBUG` block: a public read of the tuner's current pick tuning, e.g. `public var pickTuning: (animation: PickAnimation, simulateReduceMotion: Bool)` returning `(LaunchTuning.current.pick, LaunchTuning.current.forceReduceMotion)` (`LaunchTuning.current` reads `tunerOverride`, which the tuner model writes on every change and swaps during a preset preview, so a preset's pick preview plays the preset's values). `showAnimationTuner` takes two more closures, `previewPick: @escaping @MainActor () -> Void` and `canPreviewPick: @escaping @MainActor () -> Bool`, passed through `AnimationTuner` to `TunerView`.
- `SettingsShell`, inside `#if DEBUG`: `public func previewPickAnimation()` and `public var canPreviewPickAnimation: Bool`.
  - Preview asks `actions.pickAnimation()` (the same supplier picks use, so system and simulated Reduce motion apply; keep the `LauncherActions` value, or the closure, on the shell to call it) and, if it gives an animation, walks the settings window's view tree (`window.contentView`, recursively through `subviews`) for every `PickerView` whose `iconLayer` is not hidden (that is exactly "shows an installed app's icon": S1 hides it for "Choose app…" and "not found") and calls its `play(_:)` (S1's `PickerView.play(_ animation: PickAnimation)`). No assignment is touched. Does nothing when the window is closed.
  - `canPreviewPickAnimation` is `launcher.window` is `.open(_)` and some `launcher.rows` entry's `app` is `.present`, read from the model's `@Observable` state so the tuner's SwiftUI button follows it live (Observation tracks it when the tuner view's body calls the closure).
- Composition root (`TrackpadLauncher/TrackpadLauncherApp.swift`), inside `#if DEBUG`: in `makeResident`, set `shell.pickTuning = { [unowned actions] in actions.pickTuning }` (or weak), and in `showAnimationTuner()` pass `previewPick: { [weak shell] in shell?.previewPickAnimation() }` and `canPreviewPick: { [weak shell] in shell?.canPreviewPickAnimation ?? false }` (the shell is an optional property; adapt). Release builds never set the hook and carry none of this.

## Rules that apply

- architecture.md, Concurrency: "Developer tools live in `#if DEBUG` and never ship. Today that is the animation tuner in `LauncherPlatform`: a SwiftUI window over `LaunchTuning`, whose defaults are the shipped launch animation, launch bounce and pick animation. The settings window's pick animation reads the tuner through one Debug-only hook on the shell that the composition root wires; Release builds never set it." Every new tuner symbol, the hook's wiring, the preview functions and the pick decoding must be inside `#if DEBUG`.
- architecture.md, Shape: "`LauncherUI` … and the app target (composition root and the app delegate only)." `LauncherUI` and `LauncherPlatform` do not depend on each other; only the composition root connects them, with closures.
- architecture.md, Concurrency: "Animation is Core Animation keyframes … No code of ours runs per display frame." "No timers, no polling" (the source-scan test bans `Timer`, `asyncAfter`, `Task.sleep`, `print(` in sources).
- architecture.md, Shape: "Framework and wire types never cross a port: … `UserDefaults` keys … stay inside adapters and views."
- architecture.md, Language: "Tests use Swift Testing." Swift 6 strict concurrency.
