## Flow

### A. Prepare (icon pass), before any gesture
1. `Launcher.resolveRows()` (LauncherKit/Sources/LauncherCore/Launcher.swift:330-338) builds rows, collects the unique *present* assigned apps (dedup by URL, gesture order) and calls `system.prepareLaunchAnimations(for: present)`. Called from `start()` (l.111), `setAssignment` (l.123), `openWindow()` (l.185). Prepared regardless of the launch-animation setting (test `iconsAreStillPreparedWhileTheLaunchAnimationIsOff`).
2. `WorkspaceActions.prepareLaunchAnimations` -> `LaunchOverlay.prepare(for:)` (LaunchOverlay.swift:26-32):
   - `pixels = Self.pixels(at: Self.highestScale)`; `highestScale` = max `NSScreen.screens.backingScaleFactor`, default 2 (l.91-93); `pixels(at:)` = `Int((LaunchFlight.peakSide * scale).rounded())` (l.96-98). Shipped: `peakSide = iconSide * (1 + popSize) = 60 * 1.2 = 72 pt` -> 144 px at 2x.
   - `Task { icons = await Self.renderOffMain(urls, pixels: pixels) }` - the whole dictionary is **replaced** with the new set (last pass to finish wins).
3. `renderOffMain` is `@concurrent private static func ... async -> [URL: CGImage]` (l.82-89): `DispatchQueue.concurrentPerform` over URLs, results in a `Mutex<[URL: CGImage]>`.
4. `renderIcon(of:pixels:)` (`nonisolated static`, l.102-114): Display P3 `CGContext` of `pixels x pixels`, 8 bpc, `premultipliedLast`, `interpolationQuality = .high`; wraps it in `NSGraphicsContext(cgContext:flipped:false)` and draws `NSWorkspace.shared.icon(forFile: app.path)` into the full rect; returns `context.makeImage()`.
   - Cache: `private var icons: [URL: CGImage]` keyed by **bundle URL only** (l.12-13). No appearance or modification stamp (unlike `AppIcons`).

### B. Play, at gesture time
1. `Launcher.fire(_:)` (Launcher.swift:234-244): guard active/assigned/located -> `hardware.playFeedback(.gesture, ...)` -> `system.bringToFront(app)` -> `if settings.isLaunchAnimationOn { system.playLaunchAnimation(for: app) }` -> `window = .closed`. Comment: the animation is requested after bring-to-front so its cost lands on the icon, never on the app (test asserts this order, LauncherTests.swift:10-29). Only `fire` plays it; swipe, window swipe and swap never do.
2. `LaunchOverlay.play(for:)` (LaunchOverlay.swift:34-69):
   - **Reads at call time**: `let pointer = NSEvent.mouseLocation` (l.35) - Cocoa global coords, y up, origin at the bottom-left of the primary display, same space as `NSScreen.frame`, so **no coordinate flip anywhere**. No `CGEvent` location is used. `displays = NSScreen.screens.map { LaunchDisplay(frame: $0.frame, scale: $0.backingScaleFactor) }` (l.36). Reduce motion = `NSWorkspace.shared.accessibilityDisplayShouldReduceMotion || LaunchTuning.current.forceReduceMotion` (l.37-38), read fresh, never observed.
   - `let flight = flights.next(draw: .random(in: -1...1), reduceMotion:)` (l.39). The randomness is drawn in the shell; the pure code takes it as a parameter.
   - `guard let stage = flight.staged(at: pointer, among: displays), case let (panel, host)? = Self.makePanel(frame: stage.frame) else { return }` (l.40-42). Silent no-op on nil.
   - `playingPanels.insert(panel)`; `panel.orderFrontRegardless()` (l.43-44).
   - One `CATransaction` with `setDisableActions(true)` (l.46-47) and a completion block (l.48-53): `MainActor.assumeIsolated { panel.close(); self?.playingPanels.remove(panel) }` (captures `panel` strongly, `self` weakly).
   - New `CALayer` icon (l.54-60): `bounds = iconSide x iconSide` (60 pt), `position = stage.iconCentre`, `contents = bitmap(for: app, scale: stage.scale)`, `contentsScale = stage.scale`, `minificationFilter = .trilinear`, `allowsEdgeAntialiasing = true`. `contentsGravity` left at default (`.resize`), so the 72-pt-sized bitmap is minified to 60 pt at rest and exact at the pop peak.
   - For each staged animation: set the model value to `animation.values?.last` via `setValue(_:forKeyPath:)` so nothing snaps back when the animation is removed, then `icon.add(animation, forKey: keyPath)` (l.61-66). `host.addSublayer(icon)`; commit (l.67-68).
3. `bitmap(for:scale:)` (l.73-79), the at-gesture-time fallback: `pixels = pixels(at: stage.scale)`; return cached if `cached.width >= pixels`; otherwise render **synchronously on the main actor** with `renderIcon` and store it in the cache. Triggers: app moved since prepare (URL miss), a sharper display connected since prepare, or the prepare `Task` not finished yet. docs/architecture.md:19 documents this exception.
4. The render server plays the keyframes; no code of ours runs during play. On completion the panel is closed and dropped from `playingPanels`.

### C. Staging (pure geometry), LaunchFlight.swift
- `LaunchFlights.next(draw:reduceMotion:)` (l.37-44):
  - Reduce motion -> `LaunchFlight(motion: .fadeInPlace)`, **without touching `lastSides`** (does not count toward a streak).
  - `side = draw < 0 ? .left : .right` (zero goes right). `if lastSides.count == 2, lastSides.allSatisfy({ $0 == side }) { side = side.opposite }`. `lastSides = Array((lastSides + [side]).suffix(2))`.
  - Magnitude: `size = minimumSway + (1 - minimumSway) * min(abs(draw), 1)`; `motion = .sway(side.sign * size * maximumSway)`. Shipped `maximumSway = 0.26` drift per point of rise, `minimumSway = 0.1` (share of max), so every moving flight veers.
  - One `LaunchFlights` instance per `LaunchOverlay` (l.11), shared by real plays and DEBUG tuner previews.
- `LaunchFlight.pose(at u:)` (l.83-108), `u` in 0...1 of duration:
  - `.fadeInPlace`: offset 0, side = iconSide, rotation 0, opacity `1 - u^fadeCurve`.
  - `.sway`: `popShare = popTime / duration` clamped to 0...0.9 (0 if `popSize` is 0). Pop phase (`u < popShare`): side = `iconSide * (1 + popSize * (1 - (1-p)^2))` (ease-out swell), in place, opaque. Flight phase with `u` renormalised: `rise = rise * u^riseCurve`; `offset = (sway * rise * u^swayCurve, rise)`; `side = peak * (1 - shrink * u^shrinkCurve)`; `rotation = -(sway / maximumSway) * maximumTilt * u^tiltCurve` (negative = clockwise, leaning toward a rightward drift); `opacity = 1 - u^fadeCurve`.
- `steps = max(10, Int((duration * 240).rounded()))` - 240 samples/s, 82 steps at 0.34 s (l.67).
- `staged(at:among:)` (l.116-129):
  - `display(for:among:)` (l.132-135): first display with `NSMouseInRect(pointer, frame, false)` (AppKit's rule: top edge inside, bottom edge outside), else nearest by point-to-rect distance.
  - Start point pixel-snapped: `(pointer * scale).rounded() / scale` per axis (l.118-120).
  - `reach` = union over all poses of each pose's rotated bounding square (`bounds(of:from:)`, l.144-148: half = side/2 * (|cos| + |sin|)), `.integral`.
  - `frame = reach.intersection(display.frame)` - **clipping, not clamping**: near an edge the panel is cut by the display; the icon never slides. Nil if empty.
  - `centre = start - frame.origin` (window coords, y up). The icon starts **centred on the pointer tip** (not above it).
- `animations(_:from:)` (l.150-173): three `CAKeyframeAnimation`s, no group: `"position"` (`NSValue(point:)` centre + offset), `"transform"` (`CATransform3DScale(CATransform3DMakeRotation(rotation, 0,0,1), s, s, 1)` with `s = side / iconSide`), `"opacity"` (`NSNumber`). All share `keyTimes = i/steps`, `duration = LaunchTuning.duration`, `calculationMode = .linear`. **No timing functions**: the easing is baked into the dense 240 Hz sampling of the power curves.
- Shipped numbers (LaunchTuning.swift:8-38): iconSide 60, duration 0.34, popSize 0.2, popTime 0.075, rise 70, riseCurve 1.8, shrink 0.55, shrinkCurve 1.4, fadeCurve 4, maximumSway 0.26, minimumSway 0.1, swayCurve 1.8, maximumTilt 4 deg, tiltCurve 1, forceReduceMotion false.

### D. Panel (makePanel, LaunchOverlay.swift:120-139)
- `NSView(frame: size)` content with `wantsLayer = true`; `host = content.layer` (nil -> no panel). Plain, **non-flipped**, so the y-up keyframes apply to sublayers directly.
- `NSPanel(contentRect: frame, styleMask: [.borderless, .nonactivatingPanel], backing: .buffered, defer: false)`.
- `isOpaque = false`, `backgroundColor = .clear`, `hasShadow = false` (icon art has its own shadow), `ignoresMouseEvents = true`, `level = .screenSaver`, `collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary, .stationary, .ignoresCycle]`, `hidesOnDeactivate = false`, `animationBehavior = .none`, `isReleasedWhenClosed = false`.
- No `canBecomeKey` override (a plain `NSPanel` that is borderless cannot become key by default; it is only ever `orderFrontRegardless`'d). `OverlayPanel` in LauncherUI does override `canBecomeKey/Main` to false.
- **One panel per play**, sized to that flight's reach on one display (roughly 100-150 pt square in the middle of a display), positioned once; never moved, never reused, no pool. Overlapping plays are fully independent (own panel, own layer, own transaction completion). `playingPanels: Set<NSPanel>` exists only to keep them alive and because AppKit keeps closed panels in `NSApp.windows` (l.14-15).
- Warm-up: `init()` creates and immediately closes a 1x1 panel (l.17-21) because a process's first window-server window costs ~27 ms vs ~1 ms afterwards.

- The click tap (LauncherPlatform/ClickTap.swift, the only `CGEvent.tapCreate` user, confined there by policy) masks `pressTypes` (mouse downs/ups) and `gatedTypes` (drags, pressure type 34, scrollWheel, Dock-swipe gesture types) (ClickTap.swift:170-181). `mouseMoved` is **not** in any mask; `.mouseMoved` appears only as a rewrite target for `.passAsMove` (l.287-293). - No `CADisplayLink`, `NSView/NSScreen.displayLink`, `CVDisplayLink`, `Timer`, `DispatchSourceTimer`, `asyncAfter`, `Task.sleep`, `perform(afterDelay:)`, clocks, `CACurrentMediaTime` anywhere in shipped sources (grep confirmed). All timed ends today come from `CATransaction.setCompletionBlock` (LaunchOverlay l.48; OverlayPanel l.103) i.e. Core Animation's own clock.
- Existing animation idioms: `CAKeyframeAnimation` (launch), `CABasicAnimation` opacity fades (OverlayPanel l.63, l.109; 150 ms dismiss), `CASpringAnimation` (OverlayPanel l.70, SwitcherPanel l.85, WindowSwitcherPanel l.107), implicit animations via `CATransaction.setAnimationDuration` (SwitcherPanel l.71-78: 0.12 s; WindowSwitcherPanel l.186-190), `NSAnimationContext.runAnimationGroup` (WindowSwitcherPanel l.196). `OverlayPanel.dismiss` starts its fade `fromValue: layer.presentation()?.opacity` (l.110), an existing "continue from the in-flight presentation value" precedent.

## Boundaries
- In: `Launcher.fire` -> `SystemActions.playLaunchAnimation(for: AppEntry)`; `Launcher.resolveRows` -> `prepareLaunchAnimations(for: [AppEntry])`. `AppEntry` carries `bundleID`, `name`, `url` only (no pid, no `NSRunningApplication`).
- Reads from the system at play time: `NSEvent.mouseLocation`, `NSScreen.screens` (frame, backingScaleFactor), `NSWorkspace.shared.accessibilityDisplayShouldReduceMotion`, `NSWorkspace.shared.icon(forFile:)`, `LaunchTuning.current`.
- Out: a window-server panel at `.screenSaver` level per play; nothing is reported back to the model (no callbacks, no handle).
- `bringToFront` (WorkspaceActions.swift:16-20) is the only launch trigger and discards `openApplication`'s completion (which would yield the `NSRunningApplication?` / `Error?`). Existing workspace notifications are observed elsewhere: `didActivateApplicationNotification` (LauncherPlatform/ActivationTracker.swift:11-18), `didLaunch`/`didTerminateApplicationNotification` (LauncherUI/SwitcherPresenter.swift:51-60), `didWakeNotification` (MultitouchTrackpads.swift:48-49). None feeds the overlay.
- Debug tuner: `AnimationTuner(preview:)` calls `overlay.play(for: finder)`. `TunerModel.preview(_ tuning:play:)` (AnimationTuner.swift ~l.92-96) sets `tunerOverride` to the preset, calls `play()`, then **immediately restores** the live tuning; this only works because `play` reads `LaunchTuning.current` synchronously while staging.

## Non-Obvious Things
1. The launch overlay does **not** use `AppIcons` (module boundary: LauncherPlatform cannot import LauncherUI). It has its own `[URL: CGImage]` cache, rendered at peak size x highest backing scale, Display P3, no appearance/mtime stamp, wholesale-replaced on each prepare.
2. The icon bitmap is sized to the pop *peak* (72 pt), not the resting 60 pt, so it is never upscaled; at rest it is minified (trilinear). A bounce that only ever shows the icon at 60 pt would still be served by the same cache (`cached.width >= pixels` check passes).
3. The fallback draw is synchronous on the main actor (can exceed 100 ms for a first render), and it also happens if a gesture fires before the off-main prepare `Task` finishes (icons dict still old/empty).
4. Coordinates are Cocoa global y-up end to end (`NSEvent.mouseLocation`, `NSScreen.frame`, non-flipped layer-backed content view); there is no Quartz y-down conversion anywhere. The start point is pixel-snapped to the display's scale.
5. Display edges: the panel frame is the flight's reach **intersected** with the pointer's display, so near an edge the icon is cut off, never moved. There is no sideways clamping today (017's R6 asks for a sideways slide at left/right edges, cut-off only at top).
6. The icon is centred **on** the pointer tip at the start; 017's R5 wants the resting bounce icon's bottom 8 pt above the tip.
7. The panel is fixed in place for its life; nothing ever moves an overlay window today. Following the pointer would be the first per-event or per-frame code path in the app, which the documented architecture (no code of ours per frame, display links banned) and the `displayLink`/`Timer` bans currently forbid. The policy test does not ban a `mouseMoved` global monitor by token, but architecture.md's "every input is a push" is compatible with event monitors while "no code of ours runs per frame" is in tension with re-positioning per mouse event.
8. No `CAAnimationGroup` and no `CAMediaTimingFunction` in the launch animation: three parallel keyframe animations with identical keyTimes and dense linear sampling. Removal-safety comes from setting model values to the last keyframe before adding.
9. Overlap support is structural: every play gets its own panel + transaction + completion, and nothing references a previous play except the shared `LaunchFlights` streak memory and the icon cache. The port contract says "never cancels, restarts or reuses one already playing" (Ports.swift:65-68). There is no API to end an animation early or to start one from a given position (017's "float away from wherever it is, even mid-jump" needs a start-point input that `staged(at:)` already has, but also a panel that may be a different size/frame than the bounce's).
10. The completion block captures `panel` strongly and `self` weakly; cleanup does not depend on the overlay surviving. Plan 004 measured the completion firing 9-19 ms after a 300 ms animation ends.
11. "Every input is a push" means a time-based end (2 s no-window, 10 s cap) has no existing mechanism except the codebase's idiom of letting a Core Animation animation's duration be the clock (completion block). A repeating keyframe bounce (e.g. `repeatCount`/`repeatDuration` capped at 10 s) with a transaction completion would be the house-style equivalent of a timer; I did not find any existing use of `repeatCount`/`repeatDuration`.
12. The sway streak memory is shared between real gestures and DEBUG tuner previews.
13. `LaunchTuning` also hosts unrelated switcher swipe knobs (`swipeFollowsCursor`, `swipePointsPerStep`, `swipeTrackingSpeed`) and is read by `CursorTravel.travel(curves:)`; adding bounce knobs there follows existing precedent. The DEBUG `Codable` init must be extended per key (missing keys fall back to shipped).
14. docs/architecture.md:19 and the plan 004 text still say the bitmap is 46 pt and rendered on the main thread; the code now renders at `peakSide` (72 pt) off the main actor. Plan docs are historical.

## Open Questions
- Whether `NSPanel.setFrameOrigin` per mouse event on a `.screenSaver`-level, `.stationary` panel is smooth enough (no probe in the codebase). Alternative shapes (a display-sized panel with the layer moved inside it; one panel per display) have no existing precedent here.
- Whether an `NSEvent` global `mouseMoved` monitor needs any permission or runs while a full-screen app is front: no code in the repo exercises it, so I could not confirm from the codebase. (Global monitors miss events delivered to Trackpad Launcher's own windows; a local monitor would also be needed when the launcher window is under the pointer. The launch panels themselves ignore mouse events.)
- How the first-window signal would be observed (CGWindowList is confined to FrontmostAppWindows.swift; AX to the same file). Not part of this angle; flagged because the confinement rules constrain where that code can live.
