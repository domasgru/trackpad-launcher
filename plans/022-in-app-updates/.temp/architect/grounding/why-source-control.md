#### E. Stopping other running copies, and waiting for their exit

#### F. The move into /Applications: order of effects and crash convergence
- **Commit 1d53d4d** (2026-10-27 19:57): "Opened by hand outside /Applications, Trackpad Launcher asks to move itself there first". PR #28 body: "Opened by hand from outside /Applications, the app asks to move itself there, asking for an administrator password when needed and replacing an older copy."
- **Code comment** (Lifecycle.swift:254-256, from 1d53d4d per blame): "The order converges after a crash at any point: the swap inside `install` is the first change anywhere, the login item is handed over before the original can go, and every other copy stops before the installed one opens, so that open always starts a fresh process."
- **Port contract** (Ports.swift:173-178): "Copies this copy into /Applications, replacing any Trackpad Launcher there whatever its version. The copy can block; a test holds `done`."
- **Tests encoding the order**: `movingOverAnOlderCopyKeepsEverySettingAndHandsStartingAtLoginOver` asserts `world.log.entries == ["install", "unregister", "removeOriginal", "stop", "openInstalledCopy"]` and that `openInstalledCopy` waits for the earlier copy's exit (MoveToApplicationsTests.swift:131-158). `aKillAnywhereInAFirstMoveConverges` / `aKillAnywhereInAMoveOverAnOlderCopyConverges`, whose doc comment reads: "Whatever the move does, a kill between any two of its effects leaves either the Mac as it was before, with the original opened again, or an installed copy that converges on the uncrashed run's end state when opened." (MoveToApplicationsTests.swift:242-285). LifecycleWorld.swift:6-7: "A process that gets no further intent has crashed or been force-quit".
- **Login-item handover**: StartAtLogin's doc (Lifecycle.swift:67-71): "Its one fact is its own key in the app's defaults domain, beside the `settings` record and never inside it, so a move and the running copy never write the same record." `suspend()` (Lifecycle.swift:91-92): "Remembering comes first, so a crash before the unregister leaves it on and remembered, and resuming converges." Test `movingKeepsStartingAtLoginOffWhenTheUserTurnedItOff`.
- **Relevance**: The ordering and the convergence tests are the explicit defensive rationale. The key constraint for any later replace-and-relaunch: "every other copy stops before the installed one opens, so that open always starts a fresh process."
