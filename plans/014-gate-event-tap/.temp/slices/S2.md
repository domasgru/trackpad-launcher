# S2: The click tap's mind as one pure value

Worktree: `/Users/dominykasgrubys/code/trackpad-launcher/.claude/worktrees/014-gate-event-tap` (branch `feature/014-gate-event-tap`). Swift package in `LauncherKit/`. Do not commit; the orchestrator commits your work.

## Goal

Nothing the user can see changes. All the click tap's policy (routing each event to its filter, the gate predicate over a future "gated port", the rules for resuming after a stretch with that port off, and telling the system's disable of a port from the echo of our own close) moves into one pure, clock-free, device-free value in `LauncherCore`: `TapFilters`. `TapEvent` moves into `LauncherCore` (CG-free) with a Dock swipe carrying its stream. The real `ClickTap` keeps working exactly as today (one tap, one mask, three filters); a later slice (S4) makes it drive `TapFilters` and split into two ports, and S3 makes the in-memory adapter wrap `TapFilters`.

Background the code does not tell you: the design will give the click tap two ports. The *press port* (event types 1, 2, 3, 4, 25, 26: mouse downs and ups) is on for the tap's whole life. The *gated port* (types 6, 7, 27 drags, 34 pressure, 22 scroll, 29 gesture, 30 Dock control) is on only while `TapFilters.gateIsOpen`. While the gated port is off, the app is sent none of those events, so the filters miss them. `TapFilters` must therefore (a) keep the gate open whenever any trackpad might need blocking or any filter still has something withheld/altered in flight, and (b) when the gate reopens, adjust filter memory for what may have been missed.

## Requirements

- R1. "While no trackpad's recognizer is in a state that may need blocking (no thumb anchored, no swipe or window swipe in progress, no swap series) and no filter has a press, scroll gesture (including its momentum) or Dock swipe still withheld or altered in flight, the app MUST NOT be sent scroll, drag, pressure or system gesture/Dock control events (types 6, 7, 27, 34, 22, 29, 30)." (This slice: the pure gate predicate that decides it.)
- R2. "Every press, drag, pressure event, scroll event and Dock swipe that the shipped build blocks, stills or rewrites MUST still be blocked, stilled or rewritten the same way, and everything it passes MUST still pass." (This slice: the reopen rules reproduce today's outcomes; every existing filter test stays green.)
- R3. "The gating MUST NOT deliver to apps the start of a press, scroll gesture or Dock swipe and then withhold its end, nor withhold its start and then deliver the rest. Once the shipped build would withhold part of one, the rest MUST stay withheld until it ends, as plan 006's 'never relaxes' rule requires, even if the recognizer has returned to a state that needs no blocking."
- R4. "A tap disabled by the system (timeout or user input) MUST recover as it does today, without turning on a tap the gating wants off." (This slice: the pure notice rule.)

### Vocabulary (new file in `LauncherCore`, e.g. `Sources/LauncherCore/TapEvent.swift`; Foundation only)

```swift
/// The two gesture event types a Dock swipe may arrive as; each has its own filter.
public enum DockSwipeStream: Hashable, Sendable { case gesture, dockControl }   // types 29, 30

/// Everything the click tap is told about, parsed. No event-system type crosses.
public enum TapEvent: Equatable, Sendable {
    case pointer(PointerEvent)
    case scroll(ScrollEvent)
    case dockSwipe(DockSwipePhase, DockSwipeStream)
    /// Presses and releases ride the press port; drags, pressure, scrolls and Dock swipes ride the gated port.
    /// `TapEventTests` pins both masks to this.
    public var ridesGatedPort: Bool
}

public enum TapVerdict: Equatable, Sendable { case pointer(PointerVerdict), scroll(ScrollVerdict), dockSwipe(DockSwipeVerdict) }

/// What to do to the gated port now.
public enum GateChange: Equatable, Sendable { case open, close }

public struct TapDecision: Equatable, Sendable {
    public let verdict: TapVerdict
    /// nil: leave the gated port as it is. Applied before the verdict returns to the window server.
    public let gate: GateChange?
    // public init(verdict:gate:) so tests can build expected values
}

/// The trackpads as the tap's thread reads them when it acts.
public struct TapContext: Equatable, Sendable {
    /// The highest level of any running trackpad.
    public let blocking: Blocking
    /// Whether a scroll gesture may be under way that the gated port was never sent. Read only when the gate opens.
    public let scrollMayBeUnderWay: Bool
    public init(blocking: Blocking, scrollMayBeUnderWay: Bool)
    /// The real tap's view: it cannot see what it was not sent, so it takes fingers down beside a thumb (the openings
    /// with no warning frame) as "a scroll may be under way". The in-memory adapter knows what it withheld instead.
    public static func estimated(from blocking: Blocking) -> TapContext {
        TapContext(blocking: blocking, scrollMayBeUnderWay: blocking >= .dockSwipes)
    }
}
```

The rules behind it, in words:
- **Gate.** Wanted iff `blocking.wantsTap || click.isWithholding || scroll.isSuppressing || any dock.isDropping`. Every entry point settles against that predicate: an open first resumes the filters; a close happens only when nothing is altered in flight, so R3 holds by the predicate itself. `decide` settles before deciding (a press or straggler arriving before a pending wake opens the gate first, with the reopen rules) and again after (a release, a momentum end or a swipe end may close it), returning the net change.
- **Reopening.** The gate closes only on non-load-bearing memory (scroll nil, `.unseen`, `.coasting(.passed)` or `.touching(.passed)`; Dock nil or `.pass`), so the open overwrites exactly the stale state and never touches a gesture in flight. The scroll filter's `resume(scrollMayBeUnderWay:)` sets the stage to `.unseen` when a scroll may be under way, else nil (a suppressed gesture is kept; the gate never closes on one, but `resume` is total anyway). The Dock filter's `resume()` keeps a `.drop` and forgets a `.pass`.
- **Notices.** A disabled notice is a prompt to reconcile, not a command, and counts nothing. The press port reading off is the system's doing: held presses are forgotten (the caller re-enables it). The gated port reading off while `gateIsOpen` is true is the system's doing: the scroll and Dock filters forget (stage nil, today's reset, not `.unseen`) and the gate settles, reopening only if wanted now. Otherwise the notice is the echo of our own close (the port reads off after it, or on if we reopened before the echo arrived): nothing is forgotten, nothing switched beyond what the level asks. Forgetting is per port: a gated-port timeout never releases a withheld press's mouse-up.

## Rules that apply

- `docs/architecture.md`, Shape: "Framework and wire types never cross a port: `MTTouch`, `CFTypeRef`, `CGEvent`, `CFMachPort` … stay inside adapters and views. External data is parsed into domain types at the adapter." No `CGEventType`/`CGEvent` in core; the parser and masks stay in `ClickTap.swift`.
- `docs/architecture.md`, Shape: "Policy lives in pure functions and value types." `TapFilters` has no clock, no device, no locks.
- Source policy (`Tests/LauncherCoreTests/SourcePolicyTests.swift`): the token `scrollWheel` is confined to `ClickTap.swift` and `ScrollWheel` is banned everywhere; `tapCreate` is confined to `ClickTap.swift`. Do not write those tokens in core files or comments.
