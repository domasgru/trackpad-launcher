# S3: The swell flows on the render server

## Goal

On a selection change, the swell flows from the old icon to the new one within 200 ms, ends with a small wobble, and goes still within a second. A change during a running flow retargets it rather than queuing. The motion is staged whole at the input event, as sampled additive keyframe tracks that the render server plays on the layers AppKit mirrors the glass views into. When that mirror is missing or stale, the swipe falls back to S2's jump (the Reduce Motion look). Lifting never waits.

## Requirements

- **R6.** When the selection changes, the swell MUST flow from the old icon to the new one and wrap it, while the old icon's liquid drains back to a bead. The swell MUST reach the new icon within 200 ms of the change, ending with a small wobble. A selection change that arrives while a flow is still running MUST retarget that flow to the newest selected icon rather than queue behind it. *One step right:* the liquid flows to the second icon, swells around it, and the first icon is left in a bead. *Steady slide across five apps, a change about every 150 ms:* the swell is always around or flowing into the currently selected icon, never two icons behind, and does not play catch-up after the fingers stop.
- **R7.** When the selection crosses several apps at once, the liquid MUST end around the app finally selected. *Fast flick to the fourth app:* the liquid ends in a swell around the fourth icon, and the first three icons are left in beads.
- **R9.** When the fingers stop moving, the liquid MUST settle with a small wobble within one second. Once settled, the liquid MUST NOT move again until the fingers move. *Pause mid-swipe for two seconds:* the liquid has stopped moving, with the swell around the third icon.
- **R11 (this slice's part).** The switcher MUST appear the moment the swipe begins, already settled. No motion carries over from one swipe to the next, and a re-open during the close fade is clean.
- **R12.** Lifting MUST bring the selected app to the front and start closing the switcher at once, even while the liquid is flowing. *Lift during a flow* (from the first to the fourth app): the fourth app comes to the front immediately and the switcher closes.
- **R13 (the fallback).** With Reduce Motion on, or when the mirror is not live, there is no flow or wobble: the swell jumps straight to the newly selected icon.
- **R15 (sampling).** The liquid MUST respond without visible lag, and its motion MUST stay smooth at the display's full refresh rate, including 120 Hz displays, with ten apps in the row.
- **R16 (this slice's part).** While the liquid is settled and while the switcher is hidden, it MUST NOT redraw or run animation work. Every track ends by itself, and nothing staged outlives the switcher.

Out of scope here: the lean toward the fingers between changes and the end pull (S4), and the wave through the beads (S5). Between selection changes, and past an end, `follow` under `.flowing` still returns an empty frame in this slice.

## Design

### Why this shape

Only `NSGlassEffectView`s merged by an `NSGlassEffectContainerView` read as Liquid Glass, and AppKit animates the merged shape on the render server only through its private `CASDFElementLayer` mirror of each glass view. An additive animation on a mirrored element survives AppKit's re-sync; a direct write does not. Every public way to animate it runs per display frame in our process at 30 to 100 times the CPU, which `docs/architecture.md` forbids. The mirror's lifecycle, as probed:

- **K1.** A panel created with `defer: true` has no layer, and so no mirror, until it is first ordered front. Right after `orderFrontRegardless()` it still has none. After `CATransaction.flush()` the `CASDFElementLayer`s exist, one per glass view.
- **K3.** With a fixed set of 12 glass views matched once by frame while every frame was distinct, the matched layers stayed live and at their views' frames across order-out, re-layout by frame sets only, and order-in.
- **K4.** `isHidden = true` on one glass view drops its element. Unhiding creates a new element object, so the matched layer is no longer live.
- **K9.** AppKit mirrors a glass view frame set into its element during our transaction's commit, not at the setter. So a view frame set and an additive track added in the same transaction reach the render server together. Offsets must be computed from the view's new rest, never read back from the element inside the transaction.
- **K11.** Finished, filled-forward additive animations cost nothing at rest.
- **K12.** A deferred panel ordered front once with its content layer at opacity 0, then flushed, builds the mirror and shows nothing. All 12 elements match uniquely by frame. After order-out, re-layout for a 4-app row (spares exactly over the band) and order-in at opacity 1, the match stays live.

Working code for each of these is in `plans/024-fluid-app-switcher/.temp/architect/checks/`: `c6-zero-opacity-prewarm.swift` (pre-warm, `allLayers`/`elements` walk by `NSStringFromClass`, the 0.5 pt frame match, liveness), `c5-keyframe-tracks.swift` (additive `CAKeyframeAnimation`s on element layers for `position.x`, `bounds.size.width` and `bounds.size.height`), and `c2-mirror-identity.swift` (the hide/show trigger). Read them; they ran on this machine.

### LauncherCore: `.flowing` in `Liquid` (`Sources/LauncherCore/Liquid.swift`)

Motion state per swipe: the last selection fed, two `EdgeCurve`s (the swell's left and right edges, in panel points), and the mode. The swell's rest is derived from `selected` and never stored.

```swift
/// One swell edge: a Hermite approach from (x, v) to (target, arrival) over `approach`, then a damped sine around the
/// target, windowed to end at the target ≤ settleBound after `start`.
struct EdgeCurve: Sendable {
    func value(at t: LiquidTime) -> Double
    func velocity(at t: LiquidTime) -> Double
    mutating func retarget(to target: Double, arriving: Double, over approach: Double, at t: LiquidTime)
}
```

`EdgeCurve` is the single motion primitive, and it stays private to Core. S4 reuses it for the finger follow, the spring-back and the end pull. Its rules:

- **Approach.** For s = t − start in [0, a]: the cubic Hermite from the position and velocity the curve had at `start` to (target, arrival).
- **Tail.** For u = s − a in [0, E − a], with E = `settleBound` (1 s): target + (arrival / ω_d) × e^(−ζωu) × sin(ω_d u) × w(u).
  - ω = 2π × `wobbleHz`. ζ = `wobbleDamping`, clamped to [0, 0.95]. ω_d = ω√(1 − ζ²).
  - w is a smooth window from 1 at u = 0 down to 0 at u = E − a, so the curve ends exactly at the target. Pick w with w'(0) = 0 (for example 1 − smoothstep), so the velocity stays continuous at the arrival.
- **After E,** the value is the target and the velocity is 0.
- **Bounded tail.** The arrival velocity is clamped to |arrival| ≤ `wobble` × scale × ω_d, so the tail stays within `wobble` of the target (R9's small wobble).
- **Retarget** restarts from the curve's own value and velocity at `t`, so there is no velocity kink and no queue.

**`follow` under `.flowing`:**

- **First call:** as in S2. The settled opening: `swell(at: selected)`, icon at once (duration 0), no tracks. Both edges rest at that swell's left and right edges with velocity 0.
- **Repeated value:** returns `.empty`.
- **Selection changed** (the new value's `selected` differs from the last fed):
  - The new rest R = `layout.swell(at: selected)`. The frame carries `swell: R`; the panel jumps the view there in the same commit as the tracks.
  - T = min(`flowTime`, `flowBound` = 0.2 s). The **leading** edge, on the side the selection moved toward, retargets to R's matching edge over `leadShare × T`. The **trailing** edge retargets to R's other edge over T. Mid-flow the drop spans both icons, then ends on the new icon with a wobble.
  - Arrival velocities point in the direction of the move, at the clamp bound or below it. A natural choice is direction × min(1.5 × |distance| / approach, bound).
  - The icon grows over the leading edge's arrival: `IconChange(selected:, duration: leadShare × T)`.
  - A flick across three apps is one jump of the rest and one flow; the middle icons are never targeted (R7).
- **Selection value changed but `selected` did not:** `.empty` in this slice. S4 adds the lean and the end pull here.
- **Under `.still`:** unchanged from S2.

**Tracks** (the `LiquidTrack`s in the frame) are additive offsets against the **new** rest R, sampled at `sampleRate` = 120 Hz (step 1/120 s) from the call's time to the moment both edges end (at most `settleBound` after the call), with at least two samples. Three swell channels per selection change:

- `.centreX`: (L + Rt) / 2 − R's centre;
- `.width`: (Rt − L) − R's width;
- `.height`: h − R's height, where h = R's height − `thinning` × max(0, (Rt − L) − R's width), clamped to [`selectedIconBody` + 4 × scale, R's height]. This is the swell thinning as it stretches. The plan lists thinning under S4; build it here because the height channel exists now. Tell the next slice it is done.

Here L and Rt are the left and right edges' values at each sample. A track whose last offset is 0 does not hold, and is removed on completion. Every flow track in this slice ends at 0. Each new track replaces its channel's running one, and starts where and as fast as that channel is at the call's time. That falls out of sampling the retargeted curves.

**`shape(at:)`** evaluates the same closed forms: the band and the real beads at rest, and the swell from the two edges' values and the clamped height, centred on `centreY`. It is valid for times at or after the last call that returned a non-empty frame, and constant once settled.

The private constants `flowBound = 0.2`, `settleBound = 1.0`, `endPullBound = 0.2` and `sampleRate = 120` already exist on `Liquid`. They are the requirement bounds: no look can break them (T14).

### LauncherUI

New files: `Sources/LauncherUI/LiquidKeyframes.swift` and `Sources/LauncherUI/GlassMirror.swift`. Change `SwitcherPanel.swift`. `SwitcherPresenter` already selects `.flowing` when Reduce Motion is off and `checkMirror()` returns true; leave it as is.

```swift
/// Pure staging, read back by tests like LaunchFlightTests: additive, linear calculation, values = offsets, duration
/// from step and count; filled forwards and not removed when the track holds.
enum LiquidKeyframes {
    static func key(_ channel: LiquidChannel) -> String   // "liquid.swell.width", "liquid.bead.3.height", …
    static func animation(_ track: LiquidTrack, beginTime: CFTimeInterval) -> CAKeyframeAnimation
}
```

- **Key paths:** `.centreX` stages `position.x`, `.width` stages `bounds.size.width` and `.height` stages `bounds.size.height`.
- **The animation:** `isAdditive = true`, `calculationMode = .linear`, `values` = the offsets as `NSNumber`, `duration = step × (count − 1)`, `beginTime` as given.
- **A holding track** gets `fillMode = .forwards` and `isRemovedOnCompletion = false`. Any other track is removed on completion.
- **Keys** all share the `liquid.` prefix and are distinct per channel. The Core Animation key string belongs to this adapter alone: Core knows only the channel.

```swift
/// The one file that knows how AppKit mirrors Liquid Glass; the source scan confines `CASDFElementLayer` here.
/// Matched once by class name and frame, then kept by identity.
struct GlassMirror {
    /// nil when the class is missing, the element count differs from the views', or any view matches no single element.
    static func matched(in container: NSGlassEffectContainerView, views: [(LiquidElement?, NSGlassEffectView)]) -> GlassMirror?
    /// Each view matched to exactly one element by frame within 0.5 pt, else nil. Pure, so tests drive the fallback.
    static func match(elements: [CGRect], views: [CGRect]) -> [Int]?
    /// Every matched layer still in the container's tree, at its view's frame.
    var isLive: Bool
    func layer(for element: LiquidElement) -> CALayer
}
```

- **What it touches.** It only reads the layer tree, finding `CASDFElementLayer` by `NSStringFromClass(type(of:))` under the container's layer. It adds and removes only public `CAAnimation`s. No `dlsym`, no private properties, no direct writes to element properties.
- **The views it matches.** The band is passed with a `nil` element (it never animates, but it must still match, so the count is twelve). The ten beads are `.bead(i)` and the swell is `.swell`.
- **`match(elements:views:)`** returns, for each view, the index of its element. It returns nil when the counts differ, when a view has zero or two or more elements within 0.5 pt on every one of minX, minY, width and height, or when two views would take the same element.
- It also needs a way to remove every `liquid.`-keyed animation from the matched layers: `removeLiquidAnimations()` or similar.

**`SwitcherPanel` changes:**

```swift
private var mirror: GlassMirror?
/// The mirror for this swipe, set by `checkMirror()` and cleared by `lay(out:)`; nil: the rests alone show.
private var liveMirror: GlassMirror?
```

- **`init()` pre-warms.** Lay out a ten-icon template, built with `SwitcherRowLayout(iconCount: 10, displayWidth: 0)`, so all twelve frames are distinct: ten real beads, the band and the swell at icon 0. Set the content (root) layer's opacity to 0 and order the window front. `CATransaction.flush()`. Match with `GlassMirror.matched`. Order out. `present` already sets the content layer's opacity back to 1. The pre-warm also pays the first window's cost ahead of any swipe.
- **`checkMirror()`** runs once per swipe, after `present`. It does `CATransaction.flush()`, so every element holds its view's frame (K9). Then `liveMirror = mirror?.isLive == true ? mirror : nil`, returning whether it is set. The answer holds for the whole swipe. Liveness is never read inside `apply`'s transaction.
- **`lay(out:…)`** additionally removes every `liquid.` animation from the mirror's layers and clears `liveMirror`, so laying out twice is harmless.
- **`apply(_ frame:)`** runs in one transaction with actions disabled, as now:
  - the swell view's frame, if set, is public and mirrored at this commit together with the tracks (K9);
  - the icon grow, as now;
  - then, only if `liveMirror` is set, each track goes on `liveMirror.layer(for: track.channel.element)` under `LiquidKeyframes.key(track.channel)`, with `beginTime: layer.convertTime(track.begin.seconds, from: nil)`. A channel's key replaces its running track, so motion never queues.
  
  With no live mirror, the view frames alone show the correct resting shape.
- **`emptied()`** runs after the fade. It removes every `liquid.` animation and puts the swell at its rest, as now. Then it checks `mirror?.isLive` itself, never `liveMirror`, which stays nil all swipe under Reduce Motion. It re-runs the pre-warm only when the mirror is not live. So a Reduce Motion swipe does no work while hidden, and motion never latches off: a failed check costs that one swipe its motion.
- `CACurrentMediaTime` and `beginTime` are new to the codebase. They are read once per input event, on Core Animation's own clock. That is Core Animation's time, not a timer.

## Rules that apply

- `docs/architecture.md`, Concurrency: "Animation is Core Animation keyframes, which the render server plays. Whatever an animation leaves behind is cleaned up from its completion callback. No code of ours runs per display frame, and display links are banned along with timers. Code may run per input event while the effect it serves is on screen: the app switcher's liquid and the window switcher's highlight on trackpad frames." No timer, display link, run-loop polling or `asyncAfter` anywhere, including the pre-warm. `SourcePolicyTests` bans timers.
