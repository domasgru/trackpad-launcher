# S2: Sliding up or down shows the frontmost app's windows

## Goal

With the new *Swipe up or down to switch windows* switch on (the default), two fingers sliding up or down under an anchored thumb start a **window swipe**: a **window switcher** appears in the top-left corner of the pointer's display listing the frontmost app's windows (front window first, then the other visible ones front to back, then minimised ones, cut at 10), each row with the app's icon and the window's title, or a single "No open windows" / "Allow Accessibility to switch windows" row. A glass highlight follows the fingers one row per 100 cursor points with a light tick per row and a rubber band at both ends; clicks, scrolling and system swipes stay blocked for the whole window swipe; it ends when both fingers lift (the switcher disappears; **lifting changes nothing yet**) and is cancelled by a third finger or a click. Raising windows (S3) and previews/Screen Recording (S4) are later slices.

## Requirements

Quoted from the plan, cut to what this slice delivers.

- **R1.** "While the window swipe setting is on and gestures are active, a window swipe MUST start when the thumb is anchored first, exactly two fingers land, and one of them moves more than 3 mm, more up or down than sideways. The start rules MUST otherwise match the swipe's. There MUST be no time limit. Edge contacts (as the glossary defines them) MUST neither start nor join a window swipe. Once a window swipe has started, the thumb may stay, lift, leave the corner or land again, and nothing MUST change. The window swipe MUST work in both hand modes. "Gestures are active" is the glossary's term: Trackpad Launcher is running, a trackpad is connected, and no conflicting setting is on. It does not need the Accessibility permission." Scenarios: slide down starts it; left-hand mode (thumb top-right); fingers first then thumb → no switcher; three fingers → no switcher; a 2-finger tap that drifts 2 mm down stays a tap (Mail comes to front, no switcher).
- **R2.** "The first movement past 3 mm MUST decide whether a slide is a swipe (more sideways) or a window swipe (more up or down). The decision MUST hold until both fingers lift. A window swipe MUST never turn into a swipe, nor a swipe into a window swipe."
- **R3 (the list).** "The window switcher MUST list the windows of the frontmost app at the moment the window swipe begins. It MUST list the visible windows front to back, the front window first, then the minimised windows in the order the app lists them, and cut the list at 10. When the front window is full screen, the switcher MUST show that window as its single row, with its title [and preview]. The list MUST be fixed when the window swipe begins: a window that opens during it is not added, and one that closes stays listed."
- **R4.** "A *window* MUST be one of the app's normal document or app windows on the current Space, or one of its minimised windows. Panels, palettes, popovers, sheets, toolbars and other floating helpers MUST NOT be listed. Windows on other Spaces and full-screen windows other than the front window MUST NOT be listed. Minimised windows MUST come after the visible ones, shown dimmed with a "Minimised" badge and the app icon in place of a preview."
- **R5.** "The window switcher MUST be a Liquid Glass panel in the top-left corner of the display that holds the pointer, just below the menu bar, with a small margin, in both hand modes. It MUST hold one vertical column of rows. When the column would not fit the display's height, the rows MUST shrink by one factor so the whole column fits. It MUST never take focus or receive clicks, and MUST disappear when the window swipe ends."
- **R6 (titles, the icon in place of a preview, appearing in the movement that starts it).** "Each row MUST show a preview of its window 60 points tall, keeping the window's proportions, at most 120 points wide [S4], with the window's title to its right on one line, truncated at the end. A window with no title MUST show the app's name, followed by " — Window N" when the list has more than one row, N being its position in the list. The selected row MUST carry a glass highlight. … A minimised window's row MUST show the app icon in place of a preview. The switcher MUST appear in the same movement that starts the window swipe. … until a row's preview is ready, that row MUST show the app icon." (In this slice every row shows the app icon; S4 adds pictures. Leave the 120 × 60 slot so pictures can land later without moving titles.)
- **R9.** "The selection MUST start on the front window, or on the first row when there is no front window. Sliding down MUST move it to the next row, and sliding up back towards the first, in both hand modes. It MUST move one row for every 100 points the cursor would travel for the same finger movement, with macOS's own pointer acceleration at the user's tracking speed, whatever the rows' size on screen. The selected row MUST be the nearest one, so the selection changes halfway to the next row. Travel MUST be counted from the movement that starts the window swipe, so the 3 mm that start it do not count towards the selection, as in the app switcher. The ends MUST be hard stops with a small rubber band that adds no dead zone, as in the app switcher."
- **R12 (ticks).** "Each change of the selection MUST give one light tick. … The window swipe MUST never play the launch animation."
- **R13 (the rows).** "The window switcher MUST appear on every window swipe. With one window it MUST show that one row, selected, with the rubber band at both ends. When the frontmost app has no windows, it MUST show one row with the app's icon and "No open windows". When there is no frontmost app, it MUST show one "No open windows" row without an app icon."
- **R14 (the row).** "While Trackpad Launcher lacks the Accessibility permission, a window swipe MUST show one row with the frontmost app's icon and "Allow Accessibility to switch windows". … The launcher window MUST keep showing the existing Accessibility hint. Without the permission, clicks and scrolling are not blocked during a window swipe."
- **R15.** "Click blocking MUST apply for the whole of a window swipe, as for a swipe: clicks, scrolling and the system's trackpad swipes are blocked, and the blocking window is held open until both fingers lift. A window swipe MUST end when both fingers lift, and a finger that loses contact and lands again while the other finger is still down, as in a swipe, MUST rejoin it. The thumb lifting during a window swipe MUST change nothing: the switcher stays and the selection keeps following the fingers. It MUST be cancelled when a third finger lands outside the anchor corner while both are down, or a click reaches apps; a cancelled window swipe MUST keep the window in front as it is at that moment, without the lift's reordering, and be silent."
- **R16.** "The *Swipe up or down to switch windows* switch MUST sit in the launcher window's switcher section, below *Thumb tap to swap apps*, and be on by default. While it is off there MUST be no window swipe: two fingers sliding up or down under an anchored thumb scroll once the blocking window has passed, as today, and a slide's direction rules MUST be exactly today's, with no change to the swipe. It MUST be independent of the swipe and swap settings. A change MUST apply to the next slide and be saved at once, so it survives a quit, a force-quit or a Mac restart. Upgrading from a version without the setting MUST leave it on and change no other setting."
- **R17 (the switcher's lifetime).** The window switcher value exists only for the duration of one window swipe and is cleared on lift, cancel and any reconcile.

### Recognition (LauncherCore, frame thread)

- `beginOrSpoil` now lets `.windowSwipe` begin when `slides.contains(.windowSwipe)` (remove any S1 stop-gap). `Swipe.kind` is fixed at begin and every phase is emitted in its kind's event case. `.swiping` is unchanged, so blocking (`if case .swiping = state`), rejoin, thumb memory, cancel and end apply to both kinds by construction.
- New event case and accessors:
  ```swift
  // Recognition.Event gains, beside .fired, .swipe and .swap:
  //     case windowSwipe(SwipePhase)
  extension Recognition.Event {
      static func slide(_ kind: SlideKind, _ phase: SwipePhase) -> Self {
          kind == .swipe ? .swipe(phase) : .windowSwipe(phase)
      }
  }
  extension Recognition {
      public var windowSwipe: SwipePhase? { … }          // like `swipe`
      /// This frame began a swipe or a window swipe: the frame thread installs the cursor travel now.
      public var beginsSlide: Bool { swipe == .began || windowSwipe == .began }
  }
  ```
- `.swiping` accumulates `travel(along: swipe.kind, …)`: a window swipe's travel is the y component, positive downwards; sideways drift adds nothing (R2).
- The frame thread's per-begin travel hook (`FrameStream.swift`, `DeviceSession.receive`: `if recognition.swipe == .began`) becomes `if recognition.beginsSlide`.
- `TrackpadEvent` (Ports.swift) gains `case windowSwipe(SwipeEvent)`; `TrackpadEvent.init(_:on:)` maps `.windowSwipe(phase)` to it. The hop, the generation check and the event order are the same code as the swipe's.
- `Settings.slides` (derived) becomes: `.swipe` if `isSwipeOn`, `.windowSwipe` if `isWindowSwipeOn`. A pair and `.resting` exist while any kind is on (swipe off + window swipe on must work); with one kind on, the other axis spoils exactly as today.
- Test drivers: every recognizer driver's `slides:` default becomes both kinds `[.swipe, .windowSwipe]` (the shipped default). Rows that pin today's vertical spoil must keep passing `slides: [.swipe]` explicitly. Add `windowPhases(_:handMode:surface:slides:)` beside `phases`, and make `perFrame` return `(swipe, windowSwipe, blocks)`.

### Settings and the model (LauncherCore)

- `Settings`: `public var isWindowSwipeOn = true`, decoded with `decodeIfPresent ?? true` so an upgrade leaves it on (R16). Encoded like the other fields.
- `Launcher`:
  ```swift
  // private enum ShownSwitcher: Equatable { case apps(Switcher), windows(WindowSwitcher) }
  // private var shown: ShownSwitcher?        // written only by swipe(_:), windowSwipe(_:) and reconcile()
  // @ObservationIgnored private var windowSwipesBegun = 0
  public var switcher: Switcher?              // derived from shown

  public var windowSwitcher: WindowSwitcher?  // derived from shown
  public var isWindowSwipeOn: Bool

  public func setWindowSwipe(on: Bool)        // the pattern of setSwipe(on:)
  ```
  `switcher` today is a stored property; it becomes derived from `shown`, and `swipe(_:)` writes `shown = .apps(…)`. `reconcile` clears `shown` with one write (`shown = nil`) where it clears `switcher` today. `reconcile`'s `Run.slides = settings.slides`. `start()`'s `onEvent` routes `.windowSwipe(let e)` to `windowSwipe(e)`.
- The model handler, **as this slice builds it** (S3 adds raises and the lift's plan; S4 adds `showsPreviews`):
  ```swift
  /// The one place a window swipe becomes effects.
  private func windowSwipe(_ event: SwipeEvent) {
      switch event.phase {
      case .began:
          guard shown == nil, activity.isActive else { return }
          windowSwipesBegun += 1
          let read = system.frontmostWindows()
          let content = isAccessibilityGranted ? WindowSwitcher.Content(read) : .accessibilityNeeded(for: read.app)
          shown = .windows(WindowSwitcher(content, serial: windowSwipesBegun, trackpad: event.trackpad))
      case .moved(let travel):
          guard case .windows(var open)? = shown, open.trackpad == event.trackpad else { return }
          let crossed = open.selection.follow(travel)
          shown = .windows(open)
          for _ in 0..<crossed { hardware.playFeedback(.lightTick, on: event.trackpad) }
      case .ended, .cancelled:
          // S2: the lift changes nothing yet; both clear the switcher, silently.
          if case .windows(let open)? = shown, open.trackpad == event.trackpad { shown = nil }
      }
  }
  ```
  `isAccessibilityGranted` is whatever the model already holds from `reconcile` (the pushed grant). The app swipe handler's begin guard must also become `shown == nil` (at most one switcher of either kind at a time: a `.swipe(.began)` from another trackpad during a window swipe, or a `.windowSwipe(.began)` during an app switcher, is ignored, T40).

### Window types (LauncherCore)

```swift
    case noApp
    /// `visible`: its windows on the current Space, front to back; panels, palettes, sheets and other helpers left
    /// out. `minimised`: its minimised windows, in the order the app lists them. Both empty when it has none, when
    /// Accessibility is missing, or when the app did not answer in time.
    case app(AppEntry, visible: [AppWindow], minimised: [AppWindow])

    public var app: AppEntry? { … }

/// The window switcher during one window swipe. Its content is fixed when the window swipe begins: a window that opens
/// later is not added, and one that closes stays listed. The selection follows the travel.
public struct WindowSwitcher: Equatable, Sendable {
    public enum Content: Equatable, Sendable {
        case windows(of: AppEntry, WindowList)
        /// "No open windows", with the app's icon when there is a frontmost app.
        case noWindows(of: AppEntry?)
        /// "Allow Accessibility to switch windows", with the frontmost app's icon.
        case accessibilityNeeded(for: AppEntry?)
    }

    /// At most `GestureRules.windowSwitcherMaxRows` windows in all.
    public enum WindowList: Equatable, Sendable {
        /// The front window, the other visible windows front to back, then the minimised ones in the app's order.
        /// A full-screen front window is alone.
        case front(AppWindow, others: [AppWindow], minimised: [AppWindow])
        /// Every listed window is minimised: there is no front window.
        case minimisedOnly(first: AppWindow, rest: [AppWindow])
    }

    public enum Row: Equatable, Sendable {
        /// Its preview, or the app icon until the preview is ready, and its title.
        case visible(WindowID, title: String)
        /// Dimmed, with the app icon, its title and the "Minimised" badge.
        case minimised(WindowID, title: String)
        /// The single row of a window switcher with nothing to switch.
        case message(String)

        public var window: WindowID? { … }
        public var title: String { … }
    }

    public let content: Content
    public package(set) var selection: SwitcherSelection
    /// The window swipes since launch. Tells one window swipe's switcher from the next, so the presenter lays out
    /// once per window swipe (and, in S4, captures once) and nothing taken for one ever shows in another.
    public let serial: Int
    public let trackpad: TrackpadID

    /// The selection count is `rows.count` (one for a message) and starts on the first row (R9, R11).
    package init(_ content: Content, serial: Int, trackpad: TrackpadID)

    /// Whose windows these are and whose icon the rows show. nil: no frontmost app.
    public var app: AppEntry? { … }
    /// Top to bottom. A window titled "" reads as the app's name, plus " — Window N" when there is more than one row,
    /// N its 1-based row (`Copy.untitledWindow`).
    public var rows: [Row] { … }
    /// The app's window in front when the window swipe began. nil when every window is minimised, or for a message.
    public var frontWindow: WindowID? { … }
    /// Windows are listed, so a lift can change something. false for a message.
    public var listsWindows: Bool { … }
}

extension WindowSwitcher.Content {
    /// The one parse from what the system read to what the switcher lists:
    /// - `.noApp`, or an app with no windows, reads as `.noWindows`.
    /// - A full-screen front window is the single row; other full-screen windows are left out.
    /// - Visible windows come before minimised ones, and the list is cut at 10.
    package init(_ read: FrontmostWindows)
}
```

- "A full-screen front window is the single row": if `visible.first?.isFullScreen`, the content is `.front(that, others: [], minimised: [])`. Otherwise full-screen windows among `visible` other than the first are dropped.
- `GestureRules.windowSwitcherMaxRows = 10`.
- `Copy` gains: `noOpenWindows` ("No open windows"), `accessibilityForWindows` ("Allow Accessibility to switch windows"), `minimisedBadge` ("Minimised"), `untitledWindow(of:position:rows:)` (the app's name, plus " — Window N" when `rows > 1`; the dash is an em dash with spaces). Message rows carry the copy text.

### Column geometry (LauncherCore, pure; like `SwitcherRowLayout`)

```swift
/// Where the window switcher's rows and highlight sit: one column of `rowCount` rows on a display whose visible frame
/// is `displayHeight` points tall. The column fits when the panel's height plus `margin` above and below it is at most
/// `displayHeight`; when it would not, rows, gaps, padding and fonts shrink by the one factor that makes it fit (R5).
public struct WindowColumnLayout: Equatable, Sendable {
    public static let margin = 12.0, panelPadding = 8.0, rowGap = 2.0, rowInset = 6.0
    public static let previewWidth = 120.0, previewHeight = 60.0, iconSide = 44.0, titleGap = 12.0
    public static let minTitleWidth = 180.0, maxTitleWidth = 320.0, titleSize = 13.0
    public let rowCount: Int
    /// 1 when the column fits at full size, otherwise below 1.
    public let scale: Double
    public init(rowCount: Int, widestTitle: Double, displayHeight: Double)
    /// Row height plus gap: the highlight's travel per row.
    public var pitch: Double
    public var panelSize: (width: Double, height: Double)
    /// The top of a row, measured down from the panel's top edge, for a position counted in rows.
    public func rowTop(at position: Double) -> Double
    /// A picture of a window `aspect` (width ÷ height) wide, in the slot: 60 pt tall, or less when 120 pt wide would
    /// not hold it (R6), times `scale`. The slot stays 120 pt wide, so titles never move when a picture lands.
    public func previewSize(aspect: Double) -> (width: Double, height: Double)
    /// The largest picture worth capturing, in pixels at a display's backing `scale`.
    public func previewPixels(scale: Double) -> (width: Int, height: Int)
}
```
A row is 72 pt tall at full size (60 pt slot + 2 × `rowInset`). Panel width = padding + inset + 120 slot + titleGap + title width clamped to 180...320 + inset + padding. `previewSize` and `previewPixels` are used by S4, but T13 tests them here.

`LauncherPlatform/FrontmostAppWindows.swift` (new), the only file that may name `AXUIElement` (and so `_AXUIElementGetWindow`) or `CGWindowList`:

```swift
@MainActor final class FrontmostAppWindows {
    static let messagingTimeout: Float = 0.2
    /// Sets the messaging timeout once on the system-wide element (process-wide; set on any other element it covers
    /// that element only), resolves `_AXUIElementGetWindow` with dlsym, and pays the window list's first-call cost
    /// (about 50 ms) off the main actor now, not at the first window swipe.
    init()
    func read() -> FrontmostWindows {
        // 1. NSWorkspace.frontmostApplication, not this process → RunningApp.entry(for:) (or however the codebase makes
        //    an AppEntry from an NSRunningApplication), else .noApp.
        // 2. AXUIElementCreateApplication(pid), kAXWindowsAttribute. Any error (not trusted, cannot complete) →
        //    .app(entry, [], []).
        // 3. Per window, one AXUIElementCopyMultipleAttributeValues: role, subrole, title, minimised, AXFullScreen,
        //    position, size. Stop at the first cannot-complete (the app stopped answering).
        // 4. Number: _AXUIElementGetWindow, else Self.number(of:among:) against the pid's window-list entries.
        // 5. On screen: CGWindowListCopyWindowInfo([.optionOnScreenOnly, .excludeDesktopElements]), the pid's layer-0
        //    numbers, front to back.
        // 6. Self.sort(raw, onScreen:). (S3 will also keep [WindowID: element] for the listed windows, for raises;
        //    you may store it now if convenient, but no raise method in this slice.)
    }

    /// The adapter's internal seam, pure: R4's filter and R3's order from raw facts. Visible: role AXWindow, subrole
    /// AXStandardWindow, not minimised, on screen now (so on this Space), in the window list's order. Minimised:
    /// kAXMinimized alone, because a minimised window reports AXDialog, in AX order. A window with no number is left out.
    nonisolated static func sort(_ windows: [RawWindow], onScreen: [UInt32]) -> (visible: [AppWindow], minimised: [AppWindow])
    /// The fallback without the private symbol, pure: the pid's window-list entry with the same frame, and the same
    /// title where the list names windows. nil when none, or more than one, matches.
    nonisolated static func number(of window: RawWindow, among listed: [ListedWindow]) -> UInt32?
}

struct RawWindow: Sendable {
    var number: UInt32?; let title: String; let role: String?; let subrole: String?
    let isMinimised: Bool; let isFullScreen: Bool; let frame: CGRect?
}
struct ListedWindow: Sendable { let number: UInt32; let frame: CGRect; let name: String? }
```
- `WorkspaceActions`: `private let windows = FrontmostAppWindows()`; `frontmostWindows()` → `windows.read()`, as it delegates `runningApps()` to `RunningAppsReader`.
- Do not use the private symbol through anything other than `dlsym(RTLD_DEFAULT/ the loaded image, "_AXUIElementGetWindow")` cast to `@convention(c) (AXUIElement, UnsafeMutablePointer<CGWindowID>) -> AXError`, resolved once; follow `LaunchServicesOrder.swift`'s precedent.
- `sort`/`number` are tested in `LauncherPlatformTests` (`@testable import LauncherPlatform`), so make them internal (not private).

Presenter loop (the app switcher's presenter pattern; S4 adds the capture):
```swift
for await shown in Observations({ launcher.windowSwitcher }) { render(shown) }

private func render(_ switcher: WindowSwitcher?) {
    guard let switcher else { shownSerial = nil; panel.dismiss(); return }
    if switcher.serial != shownSerial { open(switcher) }  // one layout per window swipe
    panel.show(position: switcher.selection.position, selected: switcher.selection.selected)
    if switcher.selection.stretch != lastStretch, switcher.selection.stretch != 0, !reduceMotion {
        panel.springHighlight(fromY: switcher.selection.stretch * layout.pitch)
    }
    lastStretch = switcher.selection.stretch
}

private func open(_ switcher: WindowSwitcher) {
    let screen = Displays.screen(under: NSEvent.mouseLocation)
    let visible = screen?.visibleFrame ?? .zero
    layout = WindowColumnLayout(
        rowCount: switcher.rows.count, widestTitle: panel.widestTitle(switcher.rows), displayHeight: visible.height)
    panel.lay(out: switcher.rows, icon: switcher.app.map(icons.icon(forSwitcher:)), layout: layout,
              topLeft: NSPoint(x: visible.minX + WindowColumnLayout.margin, y: visible.maxY - WindowColumnLayout.margin))
    shownSerial = switcher.serial
    lastStretch = 0
    panel.present(animated: !reduceMotion)
}
```

## Rules that apply

- `docs/architecture.md` Shape: "One `@MainActor @Observable` model owns every decision. Platform adapters sense and act behind small ports; the AppKit/SwiftUI shell renders the model's state and forwards user intents. Policy lives in pure functions and value types; the shell stays thin." "`LauncherCore` … imports Foundation and Observation only." "`LauncherUI` (menu bar shell and SwiftUI views …)" cannot import `LauncherPlatform` (Package.swift).
- `docs/architecture.md` Shape: "Framework and wire types never cross a port: `MTTouch`, `CFTypeRef`, `CGEvent`, `CFMachPort`, `UserDefaults` keys, `NSRunningApplication`, `NSImage` stay inside adapters and views. External data is parsed into domain types at the adapter." (`AXUIElement`, `CGRect` from the window list stay in the adapter; `WindowID` is the identity that crosses.) "Every port has exactly two adapters: the real one in `LauncherPlatform` and an in-memory one in the tests."
- `docs/architecture.md` Concurrency: "Multitouch frames are recognised on the framework's own thread; only recognised events hop to the main actor: a fired tap, a swap, and a swipe's or a window swipe's begin, moves and end, in frame order on the main queue and never from a session a later `run` replaced. State shared with that thread lives behind a `Mutex` with one writer."
- `docs/architecture.md` Concurrency: "A window swipe reads the frontmost app's windows and raises them through the Accessibility API on the main actor: synchronous calls into another app, about a millisecond each, each bounded by a short messaging timeout …; the window list's first call in the process (about 50 ms) is paid off the main actor at launch."
- `docs/architecture.md` Concurrency: "No timers, no polling, no background loops: every input is a push … Animation is Core Animation keyframes, which the render server plays. Whatever an animation leaves behind is cleaned up from its completion callback. No code of ours runs per frame, and display links are banned along with timers."
- `docs/architecture.md` Privacy: "A window's number comes from the private `_AXUIElementGetWindow`, resolved the same way [dlsym] and confined to the window adapter's file; when it is missing, windows are matched to the window list by their frames, and a window that matches none is not listed." "The permission checks and their TCC push, the Accessibility element API with the window list, screen capture, the event tap and the scroll-event API are each confined to one file by the source-scan test." "No logging of any kind."
- Source scan hazards: any identifier or comment containing `Timer`, `print(`, `dump(`, `KeyDown`, `keyDown`, `scrollWheel`, `asyncAfter`, `Task.sleep` fails the build.
- `docs/domain-model.md` Window switcher: "holding one column of at most 10 rows: the frontmost app's windows as the window swipe begins, the front window first, then its other visible windows front to back, then its minimised windows in the order the app lists them … a window with no title reads as the app's name, followed by " — Window N" when there is more than one row … It never takes focus or receives clicks."
- `docs/domain-model.md` Window swipe setting: "While it is off there is no window swipe: … the slide scrolls once the blocking window has passed, exactly as before the window swipe existed. Independent of the swipe and swap settings."
- `docs/domain-model.md` Feedback / Light tick: "the *light tick*, a lighter pulse, each time the switcher's or the window switcher's selection changes … one per icon or row the highlight crosses, none while the selection stays put." Launch animation: "a swipe, a window swipe and a swap never do."
- Tests use Swift Testing; World rows go through the real `Launcher`, recognizer and filters.
