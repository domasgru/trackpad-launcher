# S6: The look is tuned in one place

## Goal

In DEBUG builds, the existing animation tuner gets a "Liquid switcher" section over `LaunchTuning.liquid`, saved with its presets. The app target injects `{ LiquidTuning.current }` into `SettingsShell`, which hands it to `SwitcherPresenter`. The presenter already reads it once per swipe. Release builds always play `LiquidLook.shipped`.

## Requirements

- **R17.** The swell's size, the bead and neck shape, the wave's strength and reach, and the wobble MUST each be adjustable in one place. Making the swell subtle MUST take changing one setting in that place. *Make the swell subtle:* a developer lowers the swell size there. The swell rises only a few points beyond the band, and nothing else about the switcher changes.

## Design

- **LauncherCore** (`Sources/LauncherCore/LiquidLook.swift`): `extension LiquidLook: Codable` inside `#if DEBUG` only.
  - It needs a hand-written `init(from:)` in which every key falls back to the shipped value when missing, so saved tuner presets survive new knobs.
  - Encoding may be synthesised.
  - Write one `decode` line per stored property, all of them. A property missing from a hand-written `init(from:)` silently decodes as its default, and no compiler warns.
  - The `decode(_:or:)` helper on `KeyedDecodingContainer` lives in LauncherPlatform's `LaunchTuning.swift` (DEBUG). Core cannot see it, so write the fallback in Core (`decodeIfPresent(...) ?? shipped.x`), or a private equivalent there.
- **LauncherPlatform** (`Sources/LauncherPlatform/LaunchTuning.swift`, `AnimationTuner.swift`):
  - `LaunchTuning` gains `var liquid = LiquidLook.shipped`, nested as `bounce` is. Its hand-written `init(from:)` gets the matching line: `liquid = try c.decode(.liquid, or: s.liquid)`.
  - Add a new public type:
    ```swift
    public enum LiquidTuning { public static var current: LiquidLook }
    ```
    It returns the tuner's override (`LaunchTuning.current.liquid`) in DEBUG and `.shipped` in Release, mirroring `LaunchTuning.current`'s `#if DEBUG` branches.
  - **`TunerView` gets a "Liquid switcher" section** with one knob per `LiquidLook` property. The existing `knob(_:_:_:step:unit:hint:)` takes `WritableKeyPath<LaunchTuning, Double>`, so `\.liquid.swellRise` works. "Swell rise" is the first knob, with a hint that 3 is subtle. Group the rest as shape, stretch/flow/pull, wobble and wave. Choose sensible ranges around the shipped values. The footer says it applies from the next swipe.
- **LauncherUI** (`Sources/LauncherUI/SettingsShell.swift`): `SettingsShell.init` gains `liquidLook: @escaping () -> LiquidLook = { .shipped }` and passes it to `SwitcherPresenter(launcher:liquidLook:)`, which already has that parameter.
- **App target** (`TrackpadLauncher/TrackpadLauncherApp.swift`): `shell = SettingsShell(launcher: launcher, liquidLook: { LiquidTuning.current }, quit: { [unowned self] in lifecycle.quit() })`. Release then plays `.shipped` through `LiquidTuning.current`'s Release branch.
- **Nothing else moves:** `swellRise` is the one swell setting, `waveMax` the wave's own cap, and the requirement bounds stay private constants of `Liquid`, which no look can break.

## Rules that apply

- `docs/architecture.md`, Concurrency: "Developer tools live in `#if DEBUG` and never ship. Today that is the launch animation tuner in `LauncherPlatform`: a SwiftUI window over `LaunchTuning`, whose defaults are the shipped launch animation and launch bounce." The `Codable` conformance and the tuner section are DEBUG-only. Only `LiquidTuning.current` and the init parameter exist in Release. Leave that doc text alone unless it becomes false. It still is true: the tuner is still over `LaunchTuning`.
- `docs/architecture.md`, Shape: "`LauncherCore` … imports Foundation and Observation only". And the module list: `LauncherUI` depends on `LauncherCore` only (it cannot see `LauncherPlatform`). That is why the closure is injected from the app target.
- `docs/architecture.md`, Shape: "the app target (composition root and the app delegate only)."
