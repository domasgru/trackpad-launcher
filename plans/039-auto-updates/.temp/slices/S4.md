# S4: The card

## Goal

Each opening of the settings window makes one update check. When it finds a newer version, an update card shows as the window's first group, its arrow drifting while its tray stays still. *Update now* downloads, installs at once and opens the new version with its settings window; a failure returns the card. Closing the window drops a running check or the card, and keeps the card through an update.

Repo root (a git worktree; use absolute paths): `/Users/dominykasgrubys/code/trackpad-launcher/.claude/worktrees/039-auto-updates`. A codebase map with line numbers (taken before S1 to S3, so line numbers have drifted, and its sections 2 and 3 describe revision 1's update model, which S3 replaced) is at `plans/039-auto-updates/.temp/codebase-map.md`; its section 4 (LauncherUI, the composition root, assets) is the useful part here.

## Requirements

- **R5.** "When the settings window goes from closed to open, a copy signed with a Developer ID in /Applications MUST make one update check, unless an update is already under way (R4, R13). The window MUST open at once, without waiting for the check. Restoring a minimised or hidden window or bringing it to the front MUST NOT check. A check still running when the window closes MUST be dropped. Every opening starts with no card: the card appears only after that opening's check finds a newer version."
- **R6.** "A check from the settings window MUST download nothing until the user presses *Update now*."
- **R8 (the card half).** "A development build, a copy outside /Applications and a copy showing the move dialog MUST make no update request and MUST show no update card."
- **R11.** "When the current opening's check finds a newer version, the settings window MUST show the update card as its first group, as in the design: *Update available* above an *Update now* button, with a large tray-and-arrow picture clipped at the card's right side, and a thin border. Otherwise the card MUST NOT show. The card MUST NOT be dismissable." Scenario "Failed check": offline → "no card and no error show, and the next opening checks again".
- **R12.** "While the card shows, the picture's arrow MUST drift up and down by about 4 points, about every 3 seconds. The tray MUST stay still. The arrow MUST stay inside the card's clip. The motion MUST stop while the window is closed. When *Reduce motion* is on, the arrow MUST NOT move."
- **R13.** "Pressing *Update now* MUST grey the button out and change its label to *Updating…*. Closing and reopening the window during the update MUST show the card the same way, with no check. Trackpad Launcher MUST download the version and install it as soon as the download finishes, then open the new version with its settings window open and stop the old one. The new version MUST make no update check at that start. There MUST be no progress bar and no *Cancel*."
- **R14.** "When a download or install started by *Update now* fails, the card MUST return to *Update available* with *Update now*, and show no error. The running version MUST keep working. When the install fails after the old version stopped, a working copy MUST run within 10 seconds of that stop, with its settings window open."
- **R19 (the card half).** "Its settings window MUST check and show the card as usual. *Update now* MUST ask for an administrator's name and password after the download. Cancelling that prompt MUST return the card to *Update available*, with nothing changed and no error."
- **R20, R21 (the card phases).** "*Quit Trackpad Launcher* MUST stop the app at once, in any update state. An update MUST NOT start the app again afterwards." "Logging out, restarting and shutting down MUST end the app with no dialog and no delay from an update."

## Design

### Decision 4: `Updater`, the card's part (`LauncherCore/Updater.swift`)

S3 built `Updater` as `@MainActor @Observable` with phases `resting`, `awaitingConnection(spent:)`, `updatingAtLogin(retry:dropped:)`, `handedOver`, the `card: UpdateCard?` property (nil everywhere so far), and the transition function. Add the remaining phases, inputs and `updateNow()`:

```swift
/// R1's debt, carried through the phases a login start's wait for a connection can pass through: none; owed with this
/// reading's retry unmade; owed with it made, so only a drop and a return earn another.
enum RetryDebt: Equatable { case none, owed(spent: Bool) }

// added to Phase:
/// R5. The window's check runs. `debt`: what a login start's wait it interrupted still owes; any check that
/// completes settles it.
case probing(debt: RetryDebt)
/// The window closed during its check. The check still runs, its answer is ignored, and no second check starts
/// until it has come: one cycle at a time.
case droppedProbe(debt: RetryDebt)
/// R11. The card shows *Update available*. Nothing of Sparkle exists.
case offering
/// R13. *Update now*'s cycle runs; the card shows *Updating…*, window open or closed.
case updatingFromCard
```

| Lasting effect | Exists only in |
|---|---|
| The connection watch | `.awaitingConnection`, `.updatingAtLogin(retry: true, _)` |
| An `SPUUpdater`, inside the engine | `.updatingAtLogin`, `.probing`, `.droppedProbe`, `.updatingFromCard` |
| The card | `.offering` (*Update available*), `.updatingFromCard` (*Updating…*) |
| The hand-over job | `.handedOver`, which lasts one turn |

No phase asks the engine for a cycle while one of the four above runs; the in-memory engine's `overlaps` counts any call that breaks it.

Inputs and what they do (the whole table; S3's rows are repeated so the set reads whole):

- **`start(watching:opening:opensWindow:)`**: `.atLogin` and the copy can replace itself → `.updatingAtLogin(retry: false, dropped: false)`, `update()`, whatever the window (R4). `.atLogin` and it cannot, or `.byHand`, **with a window** → `.probing(debt: .none)`, `probe()`. (Without a window → `.resting`.) `.afterUpdate` → `.resting`, whatever the window: R3 and R13. `start` also sets `launcher.onWindowEdge` (below). The start's own `openedByHand()` happens before `start`, so that opening never arrives as an edge.
- **The window opens** (closed to open): `.resting` → `.probing(.none)`, `probe()`; `.awaitingConnection(spent)` → `.probing(.owed(spent: spent))`, `probe()`, the watch stops; `.droppedProbe(debt)` → `.probing(debt)` with no engine call: the running check answers, and the card is nil until it does. In `.updatingAtLogin`, `.updatingFromCard` and `.handedOver` nothing happens: R4, R13.
- **The window closes**: `.probing(debt)` → `.droppedProbe(debt)`; `.offering` → `.resting`. In `.updatingFromCard` nothing: the card persists.
- **`updateNow()`**: only in `.offering` → `.updatingFromCard`, `update()`.
- **`.held`**: in `.updatingAtLogin` → `armRestart(opensWindow: launcher.isWindowOpen)`; in `.updatingFromCard` → `armRestart(opensWindow: true)`. Armed → `.handedOver`, `onHandOver()`, in the same turn. Refused → `discardHeldUpdate()` and the phase stays, so the cycle ends `.failed` and the rule below decides.
- **`.cycleEnded(outcome)`** in `.updatingAtLogin(retry, dropped)`: `.requestFailed` → `.awaitingConnection(spent: retry && !dropped)`; anything else → `.resting`. In `.probing(debt)`: `.found` → `.offering`; `.requestFailed` → `.awaitingConnection(spent)` if the debt is owed, else `.resting`; `.nothingNew` or `.failed` → `.resting`. In `.droppedProbe(debt)`: `.requestFailed` → `.awaitingConnection(spent)` if owed, else `.resting`; anything else → `.resting`, a found update included, since nobody is looking. In `.updatingFromCard`: `.nothingNew` → `.resting` (the release went away); anything else → `.offering` if the window is open, else `.resting`, so an opening never meets a stale card and always checks. Elsewhere ignored.
- **A connection reading**: as S3 built it (only `.awaitingConnection` and `.updatingAtLogin(retry: true, _)` react).
- **`card`**: `.available` in `.offering`, `.updating` in `.updatingFromCard`, nil elsewhere.

The transition function is unchanged: entering `.awaitingConnection` always (re)starts the watch; leaving it for anything but `.updatingAtLogin(retry: true, _)` stops it; leaving `.updatingAtLogin(retry: true, _)` for anything but `.awaitingConnection` stops it. No other effect lives in it. Write the phase before calling the engine: it may answer inside the call.

A probe cannot be cancelled: a window closed within a second of opening still lets the in-flight feed request complete; its answer is ignored, and no later request follows.

### Decision 5: the window's edges reach `Updater` through one closure on `Launcher`

`Launcher` gains `public var onWindowEdge: (@MainActor (Bool) -> Void)?`: called with true when the window goes from closed to open, false from open to closed, never on a re-front (an `openedByHand()` while already open, a restore from minimised or hidden). `Updater.start` sets it; `Launcher` knows nothing about updates (no reference to `Updater`, no update vocabulary beyond the closure).

### The shell and the view (decision 9)

- The composition root (`TrackpadLauncher/TrackpadLauncherApp.swift`) keeps the `Updater` it builds (`makeUpdater`) and hands it to the shell: `SettingsShell(launcher:updater:quit:)` with `updater: Updater?`; the shell passes it to `SettingsView(launcher:updater:actions:)`.
- `SettingsView`: when `updater?.card` is non-nil, `UpdateCardView(card:updateNow:)` is the first part of the window's column, above the Accessibility hint, with the same horizontal padding the hint uses (16). `updateNow` calls `updater?.updateNow()`.
- The shell's `Fit` (`SettingsShell.swift`, the struct the `Observations` loop compares) gains the card (`UpdateCard?`), so the window refits when it appears, changes or goes.
- The Quit button is never disabled, in any card state.
- `UpdateCard` and the three `Copy` strings (`updateAvailable` "Update available", `updateNowButton` "Update now", `updatingButton` "Updating…") were added in S3 (check; add them if missing). The view reads the button's title and enabled state from the `UpdateCard` value.

### The card's look: Figma node 2200:2979, measured in the planning session

These measurements were read from the design and override the plan's earlier guesses (13 pt medium text, solid accent button):

- Group: its own rounded group, corner radius 12 (`GroupStyle.cornerRadius`), fill `rgba(0,0,0,0.03)` like the other groups (`GroupStyle.fill`), plus a 1 pt border `#DEDEDE` that the other groups lack (the Accessibility hint card's `border`). Horizontal padding 10 (`GroupStyle.sideInset`). Clips its content (the picture) to its shape.
- Row: a vertical stack, spacing 8, vertical padding 8, at least 42 pt tall; leading-aligned.
  - *Update available*: SF Pro Regular 11 pt, line height 14, primary label colour.
  - *Update now*: the same button as *Close* in `SettingsView` (`.buttonStyle(.bordered)`, `.buttonBorderShape(.roundedRectangle(radius: 6))`; 24 pt tall, horizontal padding 16, fill `rgba(0,0,0,0.08)`, SF Pro Medium 13 pt). While the card is `.updating` it is disabled and reads *Updating…*.
- Picture (node 2200:2983, `square.and.arrow.down.fill`, drawn as `plans/039-auto-updates/assets/update-card-symbol.svg`): 71 × 89 pt, fill `#DEDEDE`, placed at x = 203 and y = −8 within the group's padded content (the group is 274 pt wide inside its padding in the design, which matches this window's 326 pt width less 2 × 16 and 2 × 10), so it is clipped at the top and the bottom. - The window's other groups follow below at the column's usual spacing.
- No dismiss control, no version text, no progress bar, no *Cancel*, no error text.

Follow `AccessibilityHintCard.swift` for structure (shape, background, clip, overlay border, a picture behind the content).

### Decision 10: the picture, where the arrow and its hole move together

Rendered, the design's symbol is a solid rounded tray whose arrow is a knockout where the two overlap, with the arrow's shaft filled above the tray (the compound path's two subpaths wind in opposite directions). So "only the arrow moves" means the filled shaft and the tray's arrow-shaped hole move as one.

The tray layer's mask is a layer whose contents is a solid rectangle with the arrow knocked out, drawn once at view creation from the arrow image with a destination-out blend, 4 pt taller than the canvas at the top and the bottom (71 × 97) so the moving hole never uncovers an edge. The arrow layer sits above the tray. The mask layer and the arrow layer carry the same animation under one key: `position.y` by −4 pt, 1.5 s, ease-in-out, autoreversing, repeating for ever, not removed on completion. The tray layer never animates.

The animation exists while the view is in a window whose occlusion state is visible and Reduce motion is off; it is removed when the view leaves the window, when the window's occlusion state loses visibility (`NSWindow.didChangeOcclusionStateNotification`, so a closed window stops it as R12 asks, while the card persists through a close during *Updating…*), or when Reduce motion turns on (the workspace's `accessibilityDisplayOptionsDidChangeNotification`, as the gear does); and added again on the reverse. Both readers are injected, as the gear's Reduce motion reader is (`GearView(image:reduceMotion:)`), so a bench can drive them: an on-screen reader (the real one reads `window.occlusionState.contains(.visible)`) and a Reduce motion reader. A repeated notification leaves the same animation object in place (add only when none is present). The contents follow the backing scale, as the gear's do (`viewDidChangeBackingProperties`). Only the render server plays it; no code of ours runs per frame. Disable implicit actions on the layers as `GearView` does.
