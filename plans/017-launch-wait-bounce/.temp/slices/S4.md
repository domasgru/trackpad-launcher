# S4: The icon follows the pointer, onto any display

## Goal

While any launch bounce shows, the row of bouncing icons stays glued above the pointer on every move and drag. It re-frames onto another display and re-scales its icons there. An ended icon no longer follows. Once the last bounce has ended, nothing of ours reads the pointer. The trailing knob, set by hand in the tuner, makes the row lag for experiments.

## Requirements

- **R7.** While it bounces, the icon MUST move with the pointer on every frame, with no lag the user can see. With the shipped tuning it MUST not trail behind the pointer; the tuner may set trailing for experiments. It MUST follow the pointer onto another display. Scenario: Figma's icon is bouncing; the user moves the pointer across the screen and onto a second display → the icon stays just above the pointer the whole way, and keeps bouncing on the second display.
- **R9 (here).** Once the bounce ends, the icon no longer follows the pointer. Scenario: the window shows mid-jump → the icon floats away from that spot, and moving the pointer afterwards does not move it.
- **R13 (here).** When one ends, the others slide to their new places over about 0.2 s, also while the pointer moves (the slide composes with moves).
- **R16 (here).** The bouncing icon never takes focus or receives clicks; clicks, scrolling and every gesture work exactly as when no icon shows. The monitors are passive.
- **R17 (here).** The trailing knob ("trailing behind the pointer, none by default") makes the row lag.
- **R4 (here).** No blur at any point, also after crossing to a display with another scale.

## Design

### `BounceOverlay` (in `BounceOverlay.swift`, built by S2 without monitors)

```swift
    private var monitors: [Any] = []

    // start(...): after row.append(...): if row.count == 1 { follow() }
    // end(...):   if row.isEmpty { unfollow(); close the row panel }

    private func follow() {
        // global + local NSEvent monitors for [.mouseMoved, .leftMouseDragged, .rightMouseDragged, .otherMouseDragged];
        // each handler (MainActor.assumeIsolated) -> moved(screen()); the local one returns its event.
    }

    private func unfollow()   // removes both monitors; idempotent

    private func moved(_ read: ScreenRead) {
        // layout = BounceRow(count: row.count, pointer: read.pointer, among: read.displays, ...,
        //                    tuning: row.last.tuning.bounce)
        // display changed: re-frame the panel, set each icon's contentsScale to the new display's scale (R4, R7)
        // one CATransaction, actions disabled: each slot.position = its rest in panel coordinates, or with
        //     trailing > 0 an ease-out from its presentation position over `trailing`
    }
```

Rules:

- **Following.** `NSEvent` global and local monitors for moves and drags are installed when the first bounce starts and removed when the last ends. Handlers read only `NSEvent.mouseLocation` (through the injected `screen()` read, `ScreenRead.now` in the app). Each event, in one transaction with actions disabled (about 0.04 ms measured): recompute the pure `BounceRow`; re-frame the panel if the display changed; set each slot's position. A global monitor does not see events sent to our own windows; the local monitor covers those (it must return the event unchanged).
- With a non-zero `trailing` (from the newest bounce's tuning snapshot, the one the row's geometry uses), each slot animates from its presentation position to its new rest over `trailing`, ease-out, instead of jumping.
- **Re-flow during moves.** S2's re-flow slide is an additive position animation from old rest minus new rest to zero; additive animations compose with the model-position updates the moves make, so a slide in progress keeps sliding while the row follows the pointer. Keep that working.
- **Crossing displays.** The row panel is the size of the pointer's display. When the pointer's display changes, the panel is re-framed once to the new display's frame, positions are recomputed in the new panel's coordinates, and each icon's `contentsScale` is set to the new display's scale. The bitmap is the overlay's prepared one at the highest scale, so it stays sharp. If the new display's scale is higher than the cached bitmap's, fetch the bitmap again through `LaunchOverlay.bitmap(for:scale:)`.
- **An ended icon no longer follows**: endings already lift the icon into its own panel (S2); make sure nothing in `moved` touches ended icons or the fade/flight panels.
- **Nothing left behind**: after the last bounce ends there is no monitor, no row panel. Moving the pointer then runs no code of ours.
- **R16**: the monitors are passive (they observe, never consume or alter events); the panel ignores mouse events; the click tap is untouched.
- **D1 reading** (accepted by the human): no code of ours runs per *display* frame. Code may run per *input event* while the effect it serves is on screen.
- **D2** (signed off by the human): pointer *position* is read only while a bounce shows, only to place the icon, and never kept.
- Probed (`plans/017-launch-wait-bounce/.temp/architect/grounding/index.md` F20–F22, `probes/p2-pointer-follow.swift`): NSEvent global monitors for `.mouseMoved` and drags install and deliver without Input Monitoring; median 3.5 ms from event timestamp to handler; a zero-motion posted move (CGEvent mouse-moved at the current location) makes the monitors fire, which is how tests trigger a re-read without moving the user's pointer.

### `AnimationTuner` (Debug only)

- Its panel (`TunerPanel`) sets `acceptsMouseMovedEvents = true`, so a bounce (the tuner's preview in S5) follows the pointer over the tuner too: the local monitor sees moves only over our windows that accept them.

## Rules that apply

- `docs/architecture.md`, Concurrency: "No timers, no polling, no background loops: every input is a push (… user events, and, only while a launch bounce shows, its launch's progress … and pointer moves)." "Animation is Core Animation keyframes, which the render server plays … No code of ours runs per display frame, and display links are banned along with timers. Code may run per input event while the effect it serves is on screen: the switchers' highlight on trackpad frames, the launch bounce's row on pointer moves."
- `docs/architecture.md`, Privacy: "The app never asks for Input Monitoring or any other permission and never reads keyboard events. It reads the pointer's position only while a launch bounce shows, to keep the icon above it, through NSEvent monitors that exist only then; it keeps nothing it reads." "… pointer-move events to the launch bounce's overlay (and the click tap, which only rewrites to one); the NSEvent monitors to the launch bounce's overlay and the launcher window's outside-click monitor."
- Source-scan bans under `LauncherKit/Sources` (comments included): `keyDown`, `keyUp`, `KeyDown`, `KeyUp`, `flagsChanged`, `FlagsChanged`, `ScrollWheel`, `.post(tap:`, `CGEventPost`, `postToPid`, `Timer`, `asyncAfter`, `Task.sleep`, `displayLink`, `DisplayLink`, `nonisolated(unsafe)`, logging. Do not monitor any event type beyond moves and drags.
- `docs/architecture.md`, Concurrency: "the public surface of every real adapter are `@MainActor`." NSEvent monitor handlers run on the main thread; use `MainActor.assumeIsolated`.
- `docs/domain-model.md`, Launch bounce: "It follows the pointer on every move, onto any display."
