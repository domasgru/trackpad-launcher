## Goal

The release command (`Scripts/release.sh`) refuses a version that is not above every earlier release. It archives the stapled app as `TrackpadLauncher-<version>-macOS-<minimum>.aar`, self-checks the archive the way an older copy will, and creates a **draft** GitHub release carrying the archive and the disk image. `LSMinimumSystemVersion` comes from the deployment target, so the declared minimum has one source.

**Do not run the release, notarise, create a tag, or create or publish a GitHub release.** Those need the human's credentials and are the human's deliberate steps. Everything you can check without them (syntax, the preflight's refusal paths, the archive/self-check step on a local ad-hoc app), check; report the rest as pending.

## Requirements

- **R14.** "Each release made with the release process MUST be found by the update check of every older version that has the update check, at its next settings-window opening. Each release MUST declare its minimum macOS and carry a downloadable app, signed and notarised. A release MUST carry a version higher than every earlier release." Scenario: the developer raises the version to 1.1.0, runs the release process and publishes the release → opening 1.0.0's settings window shows "Version 1.1.0 is available", and *Update now* installs 1.1.0.

## Design

The contract with every shipped version (already parsed by `GitHubReleases.archiveName` / `parse` in `LauncherKit/Sources/LauncherPlatform/GitHubReleases.swift`; read them so the script matches exactly):
- releases are GitHub releases on `github.com/domasgru/trackpad-launcher`, tagged `v<version>`;
- each carries the asset `TrackpadLauncher-<version>-macOS-<minimum>.aar` (an Apple Archive of the stapled app, with `TrackpadLauncher.app` at its top) and the disk image `TrackpadLauncher.dmg` (the name stays, so `.../releases/latest/download/TrackpadLauncher.dmg` is stable);
- `<version>` and `<minimum>` are dotted whole numbers (`^[0-9]+(\.[0-9]+)*$`).

`Scripts/release.sh` changes (the rest stays as today):

```sh
# Preflight (before building): gh auth status; a clean worktree whose HEAD is on origin; VERSION from
# Config/Version.xcconfig (MARKETING_VERSION) matches ^[0-9]+(\.[0-9]+)*$, has no tag v$VERSION, and is above every
# v* tag (sort -V) and every release, drafts included (gh release list).
# ... archive, export, verify, notarise and staple the app: as today ...
VERSION=$(/usr/libexec/PlistBuddy -c 'Print :CFBundleShortVersionString' "$APP/Contents/Info.plist")
MIN_MACOS=$(/usr/libexec/PlistBuddy -c 'Print :LSMinimumSystemVersion' "$APP/Contents/Info.plist")
# both must match the numeric pattern, and VERSION must equal the preflight's
AAR="$OUT/$APP_NAME-$VERSION-macOS-$MIN_MACOS.aar"
aa archive -d "$OUT/export" -subdir "$APP_NAME.app" -exclude-field uid,gid,xat,acl,flg -o "$AAR"
# Self-check, as an older version will: unpack the archive, then codesign --verify --strict --deep,
# stapler validate, and the identifier and TeamIdentifier from codesign -dv.
# ... disk image: as today ...
gh release create "v$VERSION" "$DMG" "$AAR" --draft --target "$(git rev-parse HEAD)" \
  --title "Trackpad Launcher $VERSION" --notes "Requires macOS $MIN_MACOS or later."
echo "Draft v$VERSION created. Publish with: gh release edit v$VERSION --draft=false --latest"
```
- Put the self-check in a function that can be run on its own against an existing app (like today's `--image-only <app>` mode), e.g. `--archive-only <app>`: it writes the `.aar` and runs the unpack + checks, without notarising or touching GitHub, so the archive step is testable by hand. In that mode, the `stapler validate` and Developer ID checks may be reported rather than fatal only if you make that explicit in the usage text; the full release keeps them fatal.
- The `-exclude-field uid,gid,xat,acl,flg` matters: no build-machine owners or extended attributes ship (the app's unpacker refuses nothing for them, but they must not carry provenance or quarantine).
- Update the header comment's usage and outputs (the `.aar` and the draft release).
- `project.yml`: `LSMinimumSystemVersion: $(MACOSX_DEPLOYMENT_TARGET)` (today a literal `"26.0"`); `MACOSX_DEPLOYMENT_TARGET` is set in `Config/Base.xcconfig`. The version comes from `Config/Version.xcconfig` (`MARKETING_VERSION`, `CURRENT_PROJECT_VERSION`), already wired into `CFBundleShortVersionString` / `CFBundleVersion`.

Publishing is a separate, deliberate step (`gh release edit vX --draft=false --latest`): the script stops at a draft so the developer can inspect the assets before every older copy sees them. (The plan's open question 4 asks the human whether to keep this; keep the draft as designed.)

## Rules that apply

- `docs/architecture.md`, Distribution: "Direct download only, as a disk image: the app and the image are each signed with Developer ID, notarized with `notarytool` and stapled; hardened runtime, no entitlements. One command builds it from the repository. Never sign with `--deep`; the main executable is signed last." "Releases are GitHub releases on the public repository, tagged `v<version>`, each carrying the disk image and `TrackpadLauncher-<version>-macOS-<minimum>.aar`, an Apple Archive of the stapled app. That asset name and the repository's path are a contract with every shipped version's update check. The release command creates the release as a draft, and publishing it is a separate, deliberate step. A release's version is above every earlier one's." (`codesign --verify --deep` for *verification* is fine; never *sign* with `--deep`.)
- The script runs with `set -euo pipefail`; keep it failing loudly and early (preflight before any build).
