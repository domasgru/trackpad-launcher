# S6: Real builds prove the path

## Goal

`Scripts/update-e2e.sh` puts two real, patched builds of Trackpad Launcher through a real Sparkle update against a local server, and writes a report. This slice builds the script's whole frame (two patched builds, signing, notarising, the local server, the sampler, the feed, cleanup, the report) and the rows that need no hand-over. A later slice adds the hand-over rows to the same frame. A person with the Developer ID, the notary profile and `sudo` runs it; you do not. Its build step and report must hold up without credentials.

## Requirements

R16's archive check ("Every new release MUST stay installable from the update card..."), and the proof on real builds of R1, R2, R3, R4, R5, R12 and R13:

- R1: "MUST check for a newer version when it starts, at login or by hand, and every 24 hours while it runs. The 24 hours are clock time."
- R2: "A development build, a copy outside /Applications and a copy showing the move dialog MUST make no network request for updates."
- R3: "Every request the updater makes, including the download, MUST carry nothing that identifies the user, the Mac, the app's version or the macOS version. Their headers MUST be the same on every Mac and every version."
- R4: only a newer full release that runs on this Mac counts, and the highest is taken.
- R5: "MUST download a newer version with no user action. The download MUST show nothing to the user."
- R12: "A copy that cannot write to its own bundle MUST make no update check and no download, and MUST NOT ask for a password."
- R13: "*Quit Trackpad Launcher* MUST stop the app at once, in any update state, and an update MUST NOT start the app again afterwards."

## Design

### Why real builds

Fakes hid the bugs of two earlier update plans, so the in-memory world tests prove decisions and this script proves Sparkle's behaviour on the wire and on screen. Neither stands in for the other. The gate cannot be faked: `developerIDSigner()` reads this process's real signature, so the builds must be Developer ID signed and notarised. Apple Development signing passes nothing in the app's gate.

### Shape

`Scripts/update-e2e.sh`, in bash, plus helpers beside it in `Scripts/update-e2e/`. Scratch work and the report live under `build/update-e2e/` (gitignored by `build/`).

```text
Scripts/update-e2e.sh               all rows; needs a person with credentials
Scripts/update-e2e.sh <row>...      only those rows, e.g. T58 T59
Scripts/update-e2e.sh --check       no credentials: the build, the feed, the server and the report, every row SKIPPED
```

Each row is one shell function in one table, so the next slice adds rows without touching the frame. A row ends in PASS or FAIL with one line of evidence; with no Developer ID identity, or under `--check`, it is SKIPPED with the reason. A row failing does not stop the others. Each row starts from a clean state (the spike's `scenario.sh` shows the reset list). The report, `build/update-e2e/report.md`, lists every row, its result and its evidence, the date, the commit, and the macOS and Xcode versions. The exit is non-zero if any row failed. Cleanup runs from an `EXIT` trap, on Ctrl-C too, and leaves no `.e2e` copy, launchd job, defaults domain, login item, cache or server process.

### Two builds from a patched spec

Copy the tree into a scratch folder and patch `project.yml` there; never edit the real one. In the patched copy:

- bundle identifier `com.domasgru.TrackpadLauncherApp.e2e` in Release;
- `SUFeedURL` and `TLUpdateDownloads` at the local server (`http://127.0.0.1:<port>/...`), with `TLUpdateDownloads` ending `/`;
- `SUPublicEDKey` the throwaway key's public half;
- `NSAppTransportSecurity: { NSAllowsLocalNetworking: true }`.

Build v1 and v2 with `xcodebuild archive` then `-exportArchive`, exactly as `Scripts/release.sh` does (its flags, `-packageAuthorizationProvider netrc`, developer-id export, no `--deep`), with `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` passed on the command line: v1 `1.0.0` build `1000`, v2 `2.0.0` build `2000`. Then notarise and staple each, as `release.sh` does, with `NOTARY_PROFILE`. Cache the built copies by commit in `build/update-e2e/`, because notarising takes minutes and a rerun of one row must not repeat it.

Each update archive is made with the release's own flags and inner name:

```bash
aa archive -d "$source" -subdir TrackpadLauncher.app -exclude-field uid,gid,xat,acl,flg -o "$aar"
```

named `TrackpadLauncher-<version>-macOS-26.0.aar`. Under `--check`, build with `CODE_SIGN_IDENTITY=-`, skip notarising, and carry on to the feed and server.

### The update key

A throwaway Ed25519 pair made by the script, in the scratch folder. The real key does not exist yet, and the script must not touch the keychain. Sparkle's `sign_update` takes `--ed-key-file`. Key format, from the spike's `keygen.swift`: `Curve25519.Signing.PrivateKey()`, its `rawRepresentation.base64EncodedString()` for each half.

### The feed

Not a template of its own: **the feed comes from `release.sh --feed-only`**, so Sparkle reads what a release publishes. Run it in a throwaway clone with a local bare origin, stubs first on `PATH` for `gh` (its `release download` copies the local `.aar`), `xcrun`, `security`, `swift`, `xcodegen`, and wrappers for Sparkle's `sign_update` and `generate_keys` at `LauncherKit/.build/artifacts/sparkle/Sparkle/bin/`. `LauncherKit/Tests/ReleaseTests/ReleaseHarness.swift` already does exactly this from Swift; read it and do the same in shell. Then replace only the address (`https://github.com/domasgru/trackpad-launcher/releases/download`) with the local server's, and serve the result. Items for one row's feed (T59 needs several versions, one needing macOS 99.0) come from extra `--feed-only` runs, or by editing `minimumSystemVersion` after rendering, then re-signing nothing: the item's signature covers the archive, not the feed.

### The local server

`Scripts/update-e2e/server.py`, started with `python3 -I -B`. It mirrors what the real hosts do: the feed at `/domasgru/trackpad-launcher/main/appcast.xml` as `text/plain; charset=utf-8` with `ETag` and `Cache-Control: max-age=300`, like `raw.githubusercontent.com`; the asset at `/domasgru/trackpad-launcher/releases/download/v<version>/<name>` answering 302 to a second path, as `github.com` does, and offering `Set-Cookie: probe=abc123; Max-Age=31536000; Path=/` to prove none comes back. It logs every request's line and exact headers to a file, one record per request, so a row reads the wire from the log. A control file or path lets a row change its behaviour without a restart (answer 503, hold a body mid-way, reset the connection, serve only the feed); the next slice uses those, so build the switch. Working starting points: `plans/039-auto-updates/.temp/architect/grounding/probes/sparkle-spike/server.py` and `server-redirect.py`, and `build.sh`, `scenario.sh`, `applications.sh`, `cleanup.sh` beside them, which run these same steps by hand.

### The sampler

`Scripts/update-e2e/sampler.swift`, compiled by the script, since a shell loop cannot read these at 100 ms. Every 100 ms it records one line: every process's on-screen windows (`CGWindowListCopyWindowInfo`), the frontmost app, the app's activation type (`NSRunningApplication.activationPolicy`), and /Applications' copy: `CFBundleVersion` and whether the executable is there. Rows read its file afterwards. This Mac's frontmost app flips between other apps on its own, so a row asserts only that the app and Sparkle's helpers (`Updater`, `Autoupdate`) **never become frontmost**, never that the frontmost app stays the same. The app logs nothing, so the server's log, the sampler, `launchctl` and the disk are the record.

### A person stands in for what nothing can synthesise

Rows that need a press or a finger print one instruction, wait on Return, and time from there: the script cannot press *Quit Trackpad Launcher* or touch the trackpad. Keep these to the rows that say "the person".

### Rows of this slice

As in Tests below. Copies install under `/Applications` as `Trackpad Launcher E2E.app`, or one folder deep where a row needs it. Row T60 uses `sudo` for the `root:*` owners, prompted at its start. `--after-update` is implemented by a later slice, so T61 passes only once that lands; write it now, and the person runs everything after the last code slice.

Use a `defaults write <id> SULastCheckTime -date "<date>"` shift for rows on the 24-hour mark, as T60 and T61 say. Sparkle's 24-hour timer cannot be owned, so only `--after-update`, which makes no check of its own, leaves the timer as the only source of a request.

**Do not run anything here that signs with the Developer ID, submits to Apple, uses `sudo`, or writes to /Applications.** Run `--check` only.

## Rules that apply

- `docs/architecture.md`, Distribution: "Never sign with `--deep`; the main executable is signed last, and the export re-signs Sparkle's nested helpers."
- `docs/architecture.md`, Shape: the app's real rules hold for `.e2e` too; nothing in `Sources` changes for this script. **Do not add test hooks, arguments or environment checks to the app.** If a row seems to need one, the row changes.
- The Scripts tree is not under the source scan, so `python3` and `Process` are fine here.
- Downloaded or generated archives go in their own new empty folder; run Python with `-I`.
- Do not commit: the orchestrator commits your work.
- Worktree guard: write each Bash command with literal arguments, no shell variables, `$(…)` or loops; create and edit files with Write and Edit; absolute paths. Shell syntax inside the scripts you write is fine.

## Done when

- `bash -n` passes on the script, and `python3 -I -m py_compile` on the server.
- `Scripts/update-e2e.sh --check` runs on this Mac with no credentials: it builds v1 and v2, renders the feed through `release.sh --feed-only`, starts the server, fetches the feed and the asset through it with `/usr/bin/curl` to prove its paths, redirect and request log, runs the sampler for a second, writes the report with every row SKIPPED, cleans up, and exits 0.
- The feed comes from `release.sh --feed-only`, not from a template of its own.
- Cleanup leaves no `.e2e` copy, job, defaults domain or login item.
- The row table is one place, so the next slice can add rows.
- Not yours to do: a person runs the script, and its report is attached to the PR. Say in your report that this is still open.
- The quick gate, `Scripts/test.sh`, is green if you changed anything it covers.
