# S3: The engine on demand, and the login path with its window

## Goal

A login start of a copy that can replace its own bundle reads the update list, downloads the newest version, refuses an archive that is not genuine before any installer exists, prepares it and hands over at once: silently, or with its settings window when one is open at that moment. A start by hand or after an update makes no check at start (the window's check arrives in S4). The engine builds one `SPUUpdater` per cycle on Sparkle's user-initiated driver, with the same request headers and policies on each, and drops it at the cycle's end; no schedule exists. A failed login check retries when a connection returns. A failed install reopens the old copy the same way. `Updater` becomes `@Observable` with a `card` property that is always nil until S4 makes its card phases reachable.

The app links the vendored build at `LauncherKit/Vendor/Sparkle/` (built without UI).

## Requirements

- **R1.** "A copy signed with a Developer ID in /Applications that can write to its own bundle MUST check for a newer version once when macOS starts it at login, restart included. A check that fails for lack of a network connection MUST run again each time a connection returns, until a check completes."
- **R2.** "When a login start finds a newer version, Trackpad Launcher MUST download it and install it as soon as the download finishes. It MUST wait for nothing else: not for the trackpad, a gesture or the settings window. A login download that fails MUST NOT retry until the next login start or the card."
- **R3.** "After a login install, unless R4's window was open, the new version MUST run with no settings window, no Dock icon, no dialog and no permission prompt. It MUST make no update check at that start. Gestures MUST work again within 10 seconds of the old version stopping."
- **R4.** "While a login start downloads or installs an update, opening the settings window MUST make no check and MUST show no card. The update MUST carry on. When the window is open at the moment the old version stops, the new version MUST open with its settings window."
- **R7.** "Trackpad Launcher MUST make no update request outside R1, R5 and a download from R2 or *Update now*. It MUST run no update schedule or timer."
- **R8 (the login half).** "A development build, a copy outside /Applications and a copy showing the move dialog MUST make no update request … A development build is one not signed with a Developer ID."
- **R9.** "Every request the updater makes, including the download, MUST carry nothing that identifies the user, the Mac, the app's version or the macOS version. Headers MUST be the same on every Mac and every version from this one on. Trackpad Launcher MUST send no system profile, setting or usage data."
- **R10.** "A *newer version* MUST be a published full release, with a higher version than the running one, whose minimum macOS this Mac meets. When several count, Trackpad Launcher MUST take the highest. It MUST never install an older version."
- **R15.** "Trackpad Launcher MUST install a download only when it carries a signature made with the publisher's update key and is signed with the same Developer ID and bundle identifier as the running copy. Otherwise it MUST install nothing. At login it MUST show nothing".
- **R18.** "At every moment /Applications MUST hold either the whole old version or the whole new one. A failed install MUST end with a working copy running within 10 seconds, with nothing shown. Trackpad Launcher MUST NOT try again until the next login start or the card."
- **R19 (the login half).** "A copy that cannot write to its own bundle MUST make no check, download or prompt at a login start."
- **R20.** "*Quit Trackpad Launcher* MUST stop the app at once, in any update state. An update MUST NOT start the app again afterwards."
- **R21 (the login phases).** "Logging out, restarting and shutting down MUST end the app with no dialog and no delay from an update."
- **R23 (the on-demand half).** "The updater MUST exist in memory only during a check or an update, and during R1's wait for a connection."

## Design

### Decision 2: one Sparkle path, used on demand (`LauncherPlatform/SparkleEngine.swift`, rewritten)

`SparkleEngine` creates an `SPUUpdater` when a cycle starts and drops its reference inside `didFinishUpdateCycle`, so the object dies when Sparkle's own stack unwinds; between cycles the engine holds a delegate and a user driver and nothing else. Two kinds of cycle, each one Sparkle call on a fresh updater after `start()`:

- **A probe** (`checkForUpdateInformation`): Sparkle's probing driver reads the feed, runs `shouldProceedWithUpdate` (the enclosure pin, `isPinned`, unchanged), reports `didFindValidUpdate` and aborts the moment it has an answer. Nothing downloads. (Built and tested here at the platform seam; `Updater` first asks for it in S4.)
- **An update** (`checkForUpdates`): Sparkle's user-initiated driver over this app's silent user driver. It reads the feed again, records the offer at `didFindValidUpdate`, and `showUpdateFound` is answered by the state's stage: *install* for an update not yet downloaded or downloaded, *skip* for one whose installer is already running, which can only follow a crash and would otherwise send Sparkle's own relaunch. Write that as a pure rule over an internal mirror enum of `SPUUserUpdateStage` so a test can call it. The download runs. Then, in the order Sparkle calls them:
  1. **`didDownloadUpdate`**, after the download and before any installer exists: the engine finds the downloaded archive (Sparkle's persistent download, a private layout under the user's caches, owned by the user on every account: `PersistentDownloads/<random>/<file>` under the app's Sparkle cache; confirm the exact path and file name rule in `Downloader/SPUDownloader.m` and `SPULocalCacheDirectory`), expands it into a scratch folder of its own, runs `CodeSignature.isGenuine` on the one bundle inside against the offer (`ExpectedUpdate(version: item.displayVersionString, build: item.versionString, minimumMacOS: item.minimumSystemVersion ?? "")`, as revision 1 built it), and removes the scratch folder. A genuine verdict is remembered. A refused one removes the downloaded archive, so Sparkle's own extraction fails and the cycle ends `.failed`; no installer was ever launched for it, so no quit, crash or termination can install it. All of it synchronous, on the main actor, once per release.
  2. The installer is launched through the launcher service, with interaction allowed: a copy this user cannot replace gets the administrator prompt here, after the download and before extraction, in that service's process. Extraction and preparation follow.
  3. **`showReady(toInstallAndRelaunch:)`** is the hold point. The reply closure is kept and `.held` is pushed; with no genuine verdict remembered the reply is *skip* instead, which cannot happen but costs one line. A held update never gets a reply: `Updater` arms the restart and ends the process in that same turn. `discardHeldUpdate()` replies *skip*, which cancels the installer in either launchd domain and is not a skipped version in Sparkle's sense; the cycle then ends `.failed`. A *dismiss* would refuse nothing: Sparkle's header says the update may still install at the application's end.

Why this holds at the process's end: Autoupdate commits to the installation (`_willCompleteInstallation`) when it starts, listens for the host's termination through its agent, and installs on that termination with no UI and no relaunch, since the UI and relaunch flags travel only in a stage-2 message this app never sends.

The archive code is a copy of the frozen `CardContract` extraction (`LauncherKit/Sources/CardContract/CardContract.swift`, `BundleInstall.extract(_:into:)`, `admitted`, `unpack`, `admits`, `MemoryStream`), kept apart from it on purpose, in **one new `LauncherPlatform` file** (e.g. `UpdateArchive.swift`) that expands an `.aar` into a scratch folder and names the one bundle inside (`TrackpadLauncher.app`). Do not import or change `CardContract`; it stays frozen.

Why one driver: the automatic driver cannot prompt (R19), and for a copy this user can replace, the user-initiated driver over a silent user driver shows nothing either. **Goes**: the automatic path, `willInstallUpdateOnQuit`, `checkForUpdatesInBackground`, `sessionInProgress`, the pending-check flag and `willScheduleUpdateCheckAfterDelay`, the extraction-layout lookup (`SparkleInternals.extractedUpdate`), the installer-job label and veto (`installerJob`, `veto`), and Sparkle's scheduler. Every fresh updater gets `userAgentString = "TrackpadLauncher"`, `httpHeaders = ["Accept-Language": "en", "Accept-Encoding": "gzip"]`, and the cookie and cache policy revision 1 set (`HTTPCookieStorage.shared.cookieAcceptPolicy = .never`, `URLCache.shared = URLCache(memoryCapacity: 0, diskCapacity: 0)`); `start()` throwing (an empty key) is `.cycleEnded(.failed)`, and the updater reference is dropped. The download runs in the foreground on both paths. The enclosure pin (`isPinned` in `shouldProceedWithUpdate`) and Sparkle's own selection (pre-releases, minimum macOS, highest version) are untouched: R9, R10.

A probe cannot be cancelled. The engine never suppresses an answer and never runs two cycles.

`SparkleEngine`'s init takes the host bundle it builds updaters for (the app passes `.main`'s; T21 passes a temporary bundle), and exposes, for tests only (internal), a weak reference to the current `SPUUpdater`. Its public surface stays free of Sparkle types: the delegate and user driver are private objects, `internal import Sparkle`. `SparkleEngine.canReplace` (public nonisolated static) stays as the read-only mirror of Sparkle's rule.

Correct the engine's comment that claims "never a prompt": the login path's no-prompt rule rests on `canReplace` agreeing with Sparkle's own test of the bundle; where a temporary failure makes them disagree, the launcher service shows the system's prompt once at login, in its own process, and a cancel ends the cycle `.failed`.

`SparkleInternals` keeps `provenOn` and `canReplace`, gains the persistent download's lookup (a pure function over a caches folder, so tests can point it at a temp folder in Sparkle's layout), loses `extractedUpdate`, `installerJob` and `veto`.

### Decision 3: the `UpdateEngine` port, revised (`LauncherCore`)

```swift
public enum CycleOutcome: Equatable, Sendable {
    /// A probe found a newer version. Never an update's outcome.
    case found
    case nothingNew
    /// The feed's request failed: what a lost connection looks like, and what earns a login start's retry.
    case requestFailed
    /// Anything after the feed was read: a download that failed, a refused enclosure, a cancelled prompt, a bad
    /// signature, a discarded update.
    case failed
}

public enum UpdateEngineEvent: Equatable, Sendable {
    /// A genuine update is extracted and prepared; it installs at this process's end. Pushed inside Sparkle's
    /// callback, so nothing else runs on the main actor first.
    case held
    /// A cycle ended. For a probe, its one answer.
    case cycleEnded(CycleOutcome)
}

@MainActor public protocol UpdateEngine: AnyObject {
    var onEvent: (@MainActor (UpdateEngineEvent) -> Void)? { get set }
    /// Reads the feed and downloads nothing. Answers once, `.cycleEnded(.found | .nothingNew | .requestFailed | .failed)`.
    /// Never asked while a cycle runs.
    func probe()
    /// Reads the feed, downloads the newest version, refuses one that is not genuine before any installer exists, asks
    /// for an administrator when this user cannot replace the bundle, prepares it and pushes `.held`; the update
    /// installs at this process's end. `.cycleEnded` follows only when `.held` is never reached or the held update is
    /// discarded. Never asked while a cycle runs.
    func update()
    /// Stops the held update: the installer is cancelled, then Sparkle's cycle ends `.failed`.
    func discardHeldUpdate()
    /// Arms the job that opens whichever copy /Applications holds once this process has ended: silently, or with its
    /// settings window. The caller ends the process in the same turn. False: nothing is armed.
    func armRestart(opensWindow: Bool) -> Bool
}
```

`HeldUpdate` and the engine's `start()`/`check()` go. The engine's outcome function takes the cycle's kind and two facts its delegate records, whether the feed was read (`didFinishLoadingAppcast`) and whether an update was found (`didFindValidUpdate`, which also records the offer):

| Kind | Sparkle's error | Outcome |
|---|---|---|
| probe | none, found | `.found` |
| probe | none, not found; `SUNoUpdateError` (1001) | `.nothingNew` |
| probe | `SUDownloadError` (2001) | `.requestFailed` |
| probe | anything else | `.failed` |
| update | `SUNoUpdateError` | `.nothingNew` |
| update | `SUDownloadError`, feed not read | `.requestFailed` |
| update | everything else: none (an abort after a skip), `SUDownloadError` after the feed, 3001 (the extraction of a removed archive), 4004, 4005, 4007, 4008, another domain | `.failed` |

### Decision 4: `Updater`, rewritten (`LauncherCore/Updater.swift`), the login part

`Updater` is `@Observable` again (`@MainActor @Observable public final class`), because the card renders it from S4. Its public surface: an initializer, `start(watching:opening:opensWindow:)`, `onHandOver`, `card` (type `UpdateCard?`, see below; nil in every phase this slice builds). S4 adds `updateNow()`, the window's edges and the card phases. Each lasting effect belongs to a known set of phases and starts and stops in one transition function.

The full phase set (S4 adds the starred ones; build this slice so S4 adds them without reshaping):

```swift
private enum Phase: Equatable {
    case resting
    /// R1. The login check failed for the network; the path monitor runs.
    case awaitingConnection(spent: Bool)
    /// R2. The login cycle runs: the check, the download, the preparation. `retry`: a returned connection started it,
    /// so the watch stays through it; `dropped`: the connection fell during that retry, so its network failure owes a
    /// fresh retry rather than a spent one.
    case updatingAtLogin(retry: Bool, dropped: Bool)
    // * probing(debt:), droppedProbe(debt:), offering, updatingFromCard: S4
    /// Terminal: the restart is armed and the process ends in this turn.
    case handedOver
}
```

| Lasting effect | Exists only in (this slice) |
|---|---|
| The connection watch | `.awaitingConnection`, `.updatingAtLogin(retry: true, _)` |
| An `SPUUpdater`, inside the engine | `.updatingAtLogin` |
| The hand-over job | `.handedOver`, which lasts one turn |

No phase asks the engine for a cycle while one runs: that is the "one updater at a time" guarantee, and the in-memory engine counts any call that breaks it.

Inputs (this slice's):

- **`start(watching:opening:opensWindow:)`**, once, from `Lifecycle` after the resident exists and after the start's own `openedByHand()`. Wires the engine and the connection. `.atLogin` and the copy can replace itself → `.updatingAtLogin(retry: false, dropped: false)`, `update()`, whatever the window (R4). `.atLogin` when it cannot → `.resting`, no engine call. `.byHand` → `.resting` with no engine call in this slice (S4 makes it probe). `.afterUpdate` → `.resting`, whatever the window: R3 and R13.
- **`.held`**: in `.updatingAtLogin` → `armRestart(opensWindow: launcher.isWindowOpen)`. Armed → `.handedOver`, `onHandOver()`, in the same turn. Refused → `discardHeldUpdate()` and the phase stays, so the cycle ends `.failed` and the rule below decides; the process never ends without a restart armed. Elsewhere ignored.
- **`.cycleEnded(outcome)`** in `.updatingAtLogin(retry, dropped)`: `.requestFailed` → `.awaitingConnection(spent: retry && !dropped)`; anything else → `.resting`. Elsewhere ignored (in this slice).
- **A connection reading**: in `.awaitingConnection(spent)`, not connected clears `spent`; connected and not spent → `.updatingAtLogin(retry: true, dropped: false)`, `update()`. In `.updatingAtLogin(retry: true, _)`, not connected sets `dropped`; connected is ignored. Elsewhere ignored. Entering `.awaitingConnection` restarts the watch, which pushes the present reading: connected and spent means nothing until a real drop and return; not connected clears the debt; connected and not spent retries at once, which is the flap case, a drop and a return inside the retry that then fails.

The transition function: entering `.awaitingConnection` always (re)starts the watch; leaving it for anything but `.updatingAtLogin(retry: true, _)` stops it; leaving `.updatingAtLogin(retry: true, _)` for anything but `.awaitingConnection` stops it. No other effect lives in it. Write the phase before calling the engine or the watch: either may answer inside the call.

Quit, logout, restart and shutdown need no table: `Lifecycle` keeps its one `shouldEnd` switch with no update guard. A quit before the download has completed kills the download with the process and no installer exists; one after the genuineness check and before `.held` lets Sparkle's installer, already committed, install a genuine update at that end with nothing to restart the app, which R15 and R20 allow; one after `.held` cannot land, since the process ends in that same turn.

`UpdateCard` (new, `LauncherCore`, a value type): `.available` and `.updating`, with its button's title and enabled state as values: `.available` → title *Update now*, enabled; `.updating` → *Updating…*, disabled; the card's text is *Update available* for both. `Copy` gains `updateAvailable = "Update available"`, `updateNowButton = "Update now"`, `updatingButton = "Updating…"`. (T38, the test of these, is S4's; you may define the type now since `card` needs it.)

### Decision 6: the gate splits in two (`UpdatableCopy`)

`UpdatableCopy` keeps its initializer `init?(placement:developerIDSigned:canReplaceItself:)` and fails only for a copy not signed with a Developer ID or not in /Applications; `canReplaceItself` becomes a stored public fact. ### Decision 7: the hand-over can bring the window

- `Opening.afterUpdate` gains `withWindow: Bool` (`case afterUpdate(withWindow: Bool)`).
- `Route`: `(.afterUpdate(withWindow: false), .installed)` → `.runSilently`; `(.afterUpdate(withWindow: true), .installed)` → `.runWithWindow`; the `.elsewhere` (→ `.askToMove`) and `.development` (→ `.runWithWindow`) rows are unchanged for either. Every `.atLogin` and `.byHand` row is unchanged.
- `ThisCopy.launch(event:arguments:)` parses `--with-window` beside `--after-update` (`--after-update` alone → `.afterUpdate(withWindow: false)`; with `--with-window`, in either order and beside `--eject-disk-image <volume>`, → `.afterUpdate(withWindow: true)`; `--with-window` alone is ignored), and `--at-login`, which makes a start read as a login start for the hand tests (the E2E script cannot send the login item's event): `--at-login` gives `.atLogin` with no event. The reopen (`ThisCopy.opening(of:)`, used by `openedAgain`) still reads only the event.
- `LaunchdJob.handOverArguments` takes one more argument (the window), and the hand-over script opens with `-g` only without the window, so the shell's own activation gives the window the focus when there is one: without the window `"$open" -g -a "$bundle" --args --after-update`; with it `"$open" -a "$bundle" --args --after-update --with-window`. The script's waits and its wall-time budget are unchanged. `LaunchdJob.remove` stays (for stale labels). `SparkleEngine.armRestart(opensWindow:)` submits it.
- `Lifecycle` passes `opensWindow` to `Updater.start`; `Stage.replacingOthers` already carries both. `Lifecycle` already calls `launcher.openedByHand()` before `updater?.start(...)` in `othersExited()`; keep that order.
- A failed install from the card reopens the old version with its window and no check (R14); a failed login install reopens it silently (the script opens whichever copy /Applications holds, with the flags it was armed with).

## Rules that apply

- `docs/architecture.md`, Shape: "`Updater` owns every update decision … It exists only in a copy truly signed with a Developer ID that lies in /Applications; only one that can replace its own bundle updates at a login start. `Lifecycle` starts it once the process is resident and ends the process when it asks; `Launcher` reports the settings window's edges through one closure and knows nothing about updates. Sparkle sits behind one port, built on demand for one check or one update and released at its end, and what depends on its private behaviour sits in one type, proven against one pinned version. An update never opens the new version itself: the moment the update is prepared, the old copy leaves a one-shot launchd job and ends, Sparkle installs at that end, and the job opens whichever copy /Applications holds with `--after-update`: silently, or with its settings window when the window was open or the card asked." "The bundle never declares `NSSupportsSuddenTermination`, and no code enables sudden termination".
- `docs/architecture.md`, Shape: "Framework and wire types never cross a port". "Every port has exactly two adapters: the real one in `LauncherPlatform` and an in-memory one in the tests." `LauncherCore` "imports Foundation and Observation only".
- `docs/architecture.md`, Concurrency: "`LauncherCore` and `LauncherPlatform` are nonisolated by default; the model, the ports and the public surface of every real adapter are `@MainActor`." "The update's signature check is one exception: it runs on the main actor, with the expansion of the downloaded archive into a scratch folder before it and, for a refused update only, the archive's removal after it, all inside Sparkle's download-finished callback, before any installer exists, and once per release".
- `docs/architecture.md`, Concurrency: "No timers, no polling, no background loops … Sparkle arms no timer: its schedule is declared off, and no updater object outlives its one check or update." Timer tokens are banned (S2).
- `docs/architecture.md`, Privacy: "a fixed address with no query string of ours, fixed headers that name neither the user, the Mac nor any version, cookies refused and nothing cached. No logging of any kind in our code (`print`, `NSLog`, `os_log`, `Logger`)". Files written: "Sparkle's own: its update cache under `~/Library/Caches`, its keys in the app's defaults domain, and an empty cookie jar under `~/Library/HTTPStorages`; a scratch folder the update's signature check expands the downloaded archive into, removed inside the same call."
- `docs/architecture.md`, Distribution: the `.aar` asset name, the one bundle in it `TrackpadLauncher.app`, and `CardContract` frozen: "`CardContract` and its `card-contract` tool hold a frozen copy … the app never links them." Your copy of its extraction lives in `LauncherPlatform`, not shared.
- `docs/domain-model.md`, Hand-over: "the moment the update is prepared, the old copy leaves a one-shot job with the system and ends, and the update installs at that end. Once the install has finished, or within a few seconds if it failed, the job opens whichever whole copy /Applications holds. After a login update whose settings window was closed, the opened copy starts silently … After a login update whose window was open at that moment, and always after *Update now*, it opens with its settings window … Either way it stops any other copy, makes no update check of its own".
- `docs/domain-model.md`, Login start: "For the hand tests, a release copy started with `--at-login` reads as a login start."
- Tests use Swift Testing.
