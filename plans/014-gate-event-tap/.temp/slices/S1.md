# S1: One ordered blocking level per frame

Worktree: `/Users/dominykasgrubys/code/trackpad-launcher/.claude/worktrees/014-gate-event-tap` (branch `feature/014-gate-event-tap`). Swift package in `LauncherKit/`. Do not commit; the orchestrator commits your work.

## Goal

Nothing the user can see changes. Each recognizer frame yields one ordered `Blocking` level (`.none < .possible < .dockSwipes < .clicks`) in `Recognition.blocking`, replacing the two Bools `blocksClicks` / `blocksDockSwipes`, which stay as derived properties so every existing recognizer test compiles and passes unchanged. `DeviceSession` publishes one `Mutex<Blocking>` per frame, `mergedBlocking()` replaces the two per-flag merges, and today's `ClickTap.handle` reads the merged level once per event and derives both flags from it.

Context (why): a later slice turns the click tap's high-volume event port on only while some trackpad "wants the tap". `.possible` is the new information that lets it open one frame before any blocking verdict can appear. This slice only introduces the level; nothing yet reads `.possible` for behaviour.

## Requirements

- R1 (the part this slice delivers: the level the gate will read). "While no trackpad's recognizer is in a state that may need blocking (no thumb anchored, no swipe or window swipe in progress, no swap series) … the app MUST NOT be sent scroll, drag, pressure or system gesture/Dock control events."
- R2. "Every press, drag, pressure event, scroll event and Dock swipe that the shipped build blocks, stills or rewrites MUST still be blocked, stilled or rewritten the same way, and everything it passes MUST still pass … Every existing behavioural test MUST keep passing."

## Design

### `Blocking` (new, `LauncherCore`, beside `Recognition` in `Sources/LauncherCore/GestureRecognizer.swift`)

```swift
/// How far one trackpad's blocking reaches after a frame. Ordered: each level includes those below it, so
/// `blocksClicks ⇒ blocksDockSwipes ⇒ wantsTap` holds by construction.
public enum Blocking: Int, Comparable, Sendable {
    /// No thumb in the corner, no slide, no swap series: nothing on this trackpad can block before its next frame.
    case none
    /// A thumb anchored alone, or a slide awaiting its confirmation: nothing is blocked, but a verdict can appear on
    /// the next frame with none between, so the gated port must already be receiving events.
    case possible
    /// A thumb with another contact down, its 3 s over or its landing unknown: the system's swipes are blocked.
    case dockSwipes
    /// Inside the blocking window, a confirmed swipe or window swipe, or a swap series: everything is blocked.
    case clicks

    public static func < (a: Self, b: Self) -> Bool { a.rawValue < b.rawValue }
    public var wantsTap: Bool { self >= .possible }
    public var blocksDockSwipes: Bool { self >= .dockSwipes }
    public var blocksClicks: Bool { self == .clicks }
}
```

### Tail of `GestureRecognizer.step`

Replaces today's two flags (lines ~182-200). Same truth table for the two flags as today, plus `.possible`:

```
confirmed swipe (.swiping with isConfirmed) or a series (.rest with isSeries)   -> .clicks
thumb = state.thumb, another contact down:
      landing time known (book.landingTime(of: thumb)) && frame.time - landedAt < GestureRules.clickBlockingWindow
                                                                                -> .clicks
      otherwise                                                                 -> .dockSwipes
thumb = state.thumb, no other contact down (a thumb alone)                      -> .possible
.swiping, unconfirmed, its thumb gone (swipe.thumb == nil)                      -> .possible
otherwise (idle, a rest with no thumb)                                          -> .none
```

Note `state.thumb` for an unconfirmed `.swiping` is the swipe's thumb (nil once gone), for `.rest` the rest's thumb, otherwise the anchor. "Another contact down" means `down.keys.contains { $0 != thumb }`, `down` being the post-edge-filter contacts, as today. A thumb plus only edge contacts in the bottom band therefore reads `.possible`.

Properties the level must have (from the design): in every thumb-first flow `.possible` is up at least one frame before a verdict (`>= .dockSwipes`) can appear; the only entries with no warning frame are (1) thumb and finger landing on one frame (`.clicks` on that frame), (2) a thumb landing under resting fingers (`.none` then `.clicks`), (3) a resting thumb already `.down` on a fresh recognizer's first frame with a finger (`.dockSwipes` on the first frame, since its landing is unknown).

## Rules that apply

- `docs/architecture.md`, Shape: "`LauncherCore` (domain types, pure policy, ports, the model; imports Foundation and Observation only)". `Blocking` lives in `LauncherCore` and imports nothing new.
- `docs/architecture.md`, Concurrency: "State shared with that thread lives behind a `Mutex` with one writer." The level has one writer (its device's frame callback) and one `Mutex`.
- `docs/architecture.md`, Concurrency (the tap merge): never hold two locks at once; copy the sessions out of `sessions` before reading any session's level.
- `docs/architecture.md`, Concurrency: "no frame thread enables or disables a tap." Nothing in this slice touches `tapEnable` outside today's code.
- Type-system discipline: the ordering is the construction that makes `blocksClicks ⇒ blocksDockSwipes ⇒ wantsTap` true; do not reintroduce independent Bools.
